## 一、目标（1 件事）

> 解散群要**一次清干净**：主表 + 派生键 + 线下痕迹 + **向量池**全清，  
> 只清这个 `groupId` 的，别的群一个字节都不能动。

现状（勘察确认）：

- `Sleepy.groupStore.removeGroup(id)`（core-group.js:205）**只清三张主表**（groups / groupMembers / groupMessages），  
  漏了：`groupPending:<gid>` / `groupInner:<gid>` / `sumCursor:g:<gid>` / 两张线下数组里的行 / **向量池 `group:<gid>` 的块**。
- 唯一调用点是 `page-chat.js:1109`（群列表长按「解散」），没有其它入口 —— 入口收敛成本很低。

| 数据    | 键 / 证据                                                 | 现状               | 处置                            |
| ----- | ------------------------------------------------------ | ---------------- | ----------------------------- |
| 主表    | `groups` / `groupMembers` / `groupMessages`（sandbox 章） | removeGroup 已清 ✅ | 保留（**最后**清）                   |
| 线上派生  | `groupPending:<gid>`（数组）/ `groupInner:<gid>`（对象 map）   | **未清**           | `store.remove()`              |
| 群线下游标 | `sumCursor:g:<gid>`                                    | **未清**           | `store.remove()`              |
| 群线下会话 | `groupOfflineSessions`（sandbox 章，行内 `groupId`）         | **未清**           | tombstone → 按行过滤              |
| 线下交接单 | `offlineHandoffs`（sandbox 章，行内 `groupId`）              | **未清**           | 按行过滤                          |
| 向量池   | `group:<gid>`（块带 `groupId` + `sandboxId`）              | **未清**           | `memoryVec.forget({groupId})` |

## 二、勘察结论（钉死的事实）

1. **入口唯一**：`removeGroup` 只被 `page-chat.js:1109` 调用，`Sleepy.groupStore.removeGroup` 是唯一对外导出。  
   改法二选一（见 §三 ⑤）：要么把 `removeGroup` 从导出摘掉、只留 `purgeGroup`；要么把 `purgeGroup` 设成唯一公开入口、`removeGroup` 收成内部私有（不对外导出、smoke 反向断言它不在 `groupStore` 上）。
2. **向量清理已经可用**：`memoryVec.forget({groupId})` 全程已通——
   - `ownerKeyFor({groupId})` → `groupKey(groupId)` = `group:<gid>`（memory-vec.js:1697/1709）；
   - `forgetHit` 有 `groupId` 维度：`b.groupId === filter.groupId`（memory-vec.js:906）；
   - 群块建块时 **`groupId` 和 `sandboxId` 都盖了章**（buildRecs memory-vec.js:1159/1161）。  
     → **不需要为项目3 动向量底层**，直接调 `forget({groupId})` 就按群精确清。✓
3. **派生键是裸 group 键，不在 scoped 名单**（core.js:246-261 的 scoped 数组没有 `groupPending`/`groupInner`/`sumCursor`）：  
   删房（clearSandbox）清不到它们，`purgeGroup` 必须自己 `store.remove` —— 这是项目3 独有责任。  
   但 `sumCursor:g:<gid>` 是**裸键**（不 scoped），同 gid 只此一份，直接 `remove` 安全。
4. **两张线下数组都是 sandbox 章数组、行内才有 groupId**：`groupOfflineSessions`（page-group-offline.js:33）/ `offlineHandoffs`（page-group.js:2068）。  
   必须**按行 `groupId` 过滤**，不能用 `store.remove(key)`（会误删整座岛其它群/会话）。
5. **群线下会话要先 tombstone 再删**（避免「正在进行的线下群见面」被打断成幽灵）：设计稿要求先 `status='ended'`，再过滤。  
   （离线数组当前无该群的**进行中**会话时，tombstone 那步可跳过，只过滤。）

## 三、施工清单（改 2 文件 + smoke）

### ① core-group.js —— 新增 `purgeGroup`（或改造 `removeGroup`）

```js
/* 解散群：唯一公开入口。主表最后清，先清派生/线下/向量。 */
function purgeGroup(id) {
  var g = findGroup(id);
  if (!g) return { ok: false, message: '找不到这个群' };
  var S = store, MV = Sleepy.memoryVec;

  /* 1. tombstone 群线下进行中的会话（保留它结束给 UI 看，过滤在下一步）
     2. 清线上派生键（裸 group 键，不在 scoped 名单，删房清不到，必须自己清） */
  S.remove('groupPending:' + id);
  S.remove('groupInner:' + id);
  S.remove('sumCursor:g:' + id);

  /* 3. 清向量池 group:<id>（块带 groupId + sandboxId，精确按群清，不碰别的池） */
  var p = MV && MV.forget ? MV.forget({ groupId: id }) : Promise.resolve(0);

  /* 4. 过滤两张线下数组（按行 groupId，不整键删） */
  var off = arr(S.get('groupOfflineSessions'))
    .map(function (s) {
      if (s && s.groupId === id && s.status === 'active') { s.status = 'ended'; return s; }
      return s;
    })
    .filter(function (s) { return !(s && s.groupId === id); });
  S.set('groupOfflineSessions', off);

  var ho = arr(S.get('offlineHandoffs'))
    .filter(function (x) { return !(x && x.groupId === id); });
  S.set('offlineHandoffs', ho);

  /* 5. 最后删主表（三张） */
  S.set('groups', allGroups().filter(function (x) { return x.id !== id; }));
  S.set('groupMembers', allMembers().filter(function (x) { return x.groupId !== id; }));
  S.set('groupMessages', allMessages().filter(function (x) { return x.groupId !== id; }));

  return p['catch'](function () { return 0; }).then(function () {
    return { ok: true };
  });
}
```

> `store.remove` 需先确认 `Sleepy.store` 有 `remove` 方法（与 `wipeAll` 同栈，均有）。  
> 若 `MV` 未就绪（无向量模块），`forget` 短路成 `Promise.resolve(0)`，不阻塞解散。

### ② 入口收敛（在 ① 内或单独）

把 `removeGroup` 从 `Sleepy.groupStore` 导出**摘掉**，只留 `purgeGroup`；  
`page-chat.js:1109` 的 `Sleepy.groupStore.removeGroup(g.id)` 改为 `Sleepy.groupStore.purgeGroup(g.id).then(...)`（它是 async，UI 用 Promise）。

### ③ smoke 反向护栏（scripts/smoke.js）

- `Sleepy.groupStore.removeGroup` **必须不存在**（反向断言，不许再注册回来）。
- `Sleepy.groupStore.purgeGroup` 存在且是 function。
- 新建一条群解散端到端桩断言（若 smoke 支持 IDB 建块，则验向量池；无 IDB 时用 `why:'off'` 短路护栏 + `forget({groupId})` 的 `ownerKeyFor` 映射护栏）。

## 六、边界 / 回滚

- **只动本群**：`forget({groupId})` 有 `groupId` 维 + `ownerKeyFor` 归 `group:<id>`，天然只清本群；  
  `sumCursor:g:<id>` 是裸键同 gid 单份，`remove` 安全。无跨群误删面。
- **不可逆**：解散即物理删（主表 + 向量块不可恢复）。保持现有交互（长按→confirm danger），**不加「可恢复」**；  
  若将来要可恢复，得走 tombstone 方案（超出本批范围，不启用）。
- **失败可见**：`forget` 失败（`why:'embed'` 等）不吞 —— `purgeGroup` 返回 `{ok:false, why}` 并保留主表待重试；  
  但主表删除与向量删除**不强绑定事务**（向量层是 IndexedDB、主表是 localStorage，无法跨存储事务），  
  记录：极端下可能「主表已删、向量块残留」→ 靠 `purgeGroup` 幂等重跑清掉（forget 对已删源也安全）。
