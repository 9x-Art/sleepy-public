### 1.3 false→true 边沿接入（待施工）

在 `setCharConfig` @112 内，写库后加判断：

```js
function setCharConfig(charId, patch) {
  var root = rootIdOf(charId);
  var raw = islandRaw();
  raw.byChar = raw.byChar || {};
  raw.byChar[root] = raw.byChar[root] || {};
  var before = charConfig(charId).enabled;          // 含 NPC 默认关语义
  Object.keys(patch).forEach(function (k) { raw.byChar[root][k] = patch[k]; });
  raw.byChar[root].updatedAt = nowIso();
  store.set('memoryIsland', raw);
  /* 项目 2：false→true 边沿 → 定向作废该 root 私有池游标（重开记忆 → 从头重扫） */
  var has = patch && Object.prototype.hasOwnProperty.call(patch, 'enabled');
  if (has && before === false && patch.enabled !== false) {
    var mv = Sleepy.memoryVec;
    if (mv && typeof mv.invalidateCursorsFor === 'function') {
      mv.invalidateCursorsFor(root);
    }
  }
}
```

边沿判定矩阵（与 §二 文档规则严格一致）：

| patch.enabled | before | after | 调 invalidate？ |
|---|---|---|---|
| false | true | false | **否**（关闭不清游标不删块） |
| true | true | true | **否**（重复开不重扫） |
| true | false | true | **是**（false→true，rootEpoch +1 一次） |

> 依赖方向：`page-memory.js` → `Sleepy.memoryVec.invalidateCursorsFor`，与现有 `vecCall` 同款运行时访问 `Sleepy` 全局，无初始化循环问题。

## 二、文档边沿规则修正（第二点）

方案卡 §七 已改为**三态定稿**（消除旧"每次+1但重复开不作废"的矛盾表述）：

| 转换 | rootEpoch | 调 `invalidateCursorsFor` |
|---|---|---|
| false → true | **+1（一次）** | 是 → 定向重扫该 root 私有池 |
| true → true | **不变** | 否 |
| true → false | **不变** | 否（不清游标、不删块） |

**重扫口径（修正矛盾）**：`invalidateCursorsFor` **不是数学幂等函数，而是可重复安全执行**（重复调用只会 +1）；
实际**只有** `setCharConfig` 的 false→true 调它一次。rootEpoch 失配后 `readCursor` 返回 0，
实际行为是**从头重扫该 root 的私有池**（含关闭前内容，**不承诺**只计算关闭期间新增内容）；**不影响其他 root，
不影响群/岛/账号/我的日记等共享池，不做全局重扫**。

### 发现并修复的真 bug / 缺陷（静态护栏测不出来的）

**① 重开重扫去重（核心，memory-vec.js `sweepSource`）**
- 修复前原生实测：块数 2→2→**4→6**、embedding 增量 2→0→**2→2**、重复段 `chatR|R_0|R_7`、`chatR|R_8|R_15`
  —— 相同源内容随开关次数**线性增副本**（重开重扫 from=0，旧段被当新内容重算）。
- 最小修复：入库前按 `sourceId|fromId|toId` 指纹去重，已存在段跳过（不建块不 embedding、
  **不占 SWEEP_MAX 配额**）。未用全库 wipeAll。
- 修复后实测：块数 2→2→**3→5**、embedding 增量 2→0→**1→2**、重复段 0 —— 重扫只算真正新增。
- **如实说明费用（2026-09-26 实测修正）**：重开记忆会**从头遍历历史源**（含关闭前内容）；
  已有段在指纹去重时跳过、**不重新 embedding、不收费**（原生实测 M新7：旧块→关→开、无新增消息，
  重扫 `added=0`、embedding 增量 `0`、块数不变）。**仅新增/未命中段才 embedding（$）**。
  遍历（免费）≠ 重算（收费）；「定向扫描」≠「不会重复建块」——已靠指纹去重避免重复建块。

**② 关闭消费旁路（memory-vec.js `lastOf` 过滤范围过宽）**
- 现象：关闭记忆后不重新 prefetch，装配端 `compileRecall→text→lastOf` 仍读到开启时预热的
  旧私有块缓存 → 关闭未立即生效。
- 最小修复：`prefetchInto` items 补带 `ownerKey`，`lastOf` 关闭分支**只滤当前 root 私有块**
  （`items.filter(it => it.ownerKey !== root)`）。
  ⚠️ **不能整体 `return []`**：私聊召回池是 [root, island:*, user:*]，旧缓存混着岛/账号块，
  一刀切会把共享内容一起毙掉（原生 Edge M新5 点出）。
  原生实测：关闭后 `text` 不带旧私有记忆，岛/账号池仍可消费，通过。

**③ refresh/reindex 写旁路（memory-vec.js `reindexItem`）**
- 现象：`refreshMem`/`refreshPhone`/`refreshMoment`/`refreshDiary` 都汇聚 `reindexItem`，但
  `reindexItem` **没有 charMemOff** → 角色关闭时编辑素材仍会调 embedding + 写新私有块。
- 最小修复：算得 ownerKey 后加 `if (charMemOff(key)) return {why:'memoff'}` —— 私有池裸键关时短路
  （不删旧块、不 embedding、不写块）；带前缀的岛/账号/群池查不到配置 → 不误伤。
  原生实测 M新6：关闭时 refreshMem/refreshPhone 返回 memoff、embedding 0、私有块数 0；共享账号池照常。

### 群注入边界（单次请求内 A/B 双注入）

线上群（`page-group-ai.js` `entLines` @208-227）与群线下（`page-group-offline.js` `presentParts` @213-230）
**同一次装配调用**里，对每个实体/参与者调 `groupTextFor(groupId, ownerId)` 逐成员注入：
- A（关）→ `groupTextFor` 返回 `''`，该成员段/行**不含群池摘要**；
- B（开）→ 有内容；
- 这是**段级消费软隔离**（隔离单位是**段/行**：同一模型上下文里 A 段没有群池，但 B 段有），
  **不是模型上下文硬隔离**。
- 若需硬隔离（关 A 的段根本不进模型上下文），需拆请求或全员关闭策略 —— 本轮**未拆**（按用户要求先补证）。
