## ⑪ 帷境 T6 · 谢幕五路 + 两张聊天卡片（2026-09-22 下午）

**新文件** `page-wj-curtain.js`（谢幕页 + 两种卡片 + 弹层）。入口在
`page-wj-work.js` 的 hero 按钮排（开始阅读 / 邀请同席 / **谢幕**）。

**五路**（判据 = Demo 底注，**别合并**：收藏 ≠ 分享 ≠ 共读 ≠ 公开 ≠ 定史）：

| route | 标签 | 实际做了什么 |
|---|---|---|
| ticket | 收藏纪念 | 写 `wjTickets`（**一作品一张**），收藏馆里多一段「票根」 |
| share | 改变知情 | 往聊天里发一张 `wj-share` 卡。**不创建同席**（有断言守） |
| coread | 创建邀请 | `createInvite` + 发 `wj-invite` 卡 → `judgeInvite` 让 TA 回应 → 写回那条消息 |
| forum | 改变公开范围 | 这一版只做「仅自己可见」占位，账号/板块两档 disabled |
| history | 可能改变现实 | 只做说明 + 「T7 再做」，不放假按钮 |

**幂等**三处：票根（`ticketFor` 命中就直接返回）、每路记账（`markCurtain`
不刷新已有时间戳）、卡片投递（查聊天记录里有没有同 workId 的同型卡 ——
**查数据本身**而不是再存一个布尔，两份记录迟早对不上）。

**数据**：票根在 `wjTickets`（**全局不 scoped**，跟 `wjWorks` 同理 ——
群岛作品不归属单岛，删岛不该删票根）；另三路记在 `work.curtain`
（`shared` / `coreadInvited` / `forumPublished` / `sealedAt`）。
收藏馆渲染时把**两个来源并起来**（聊天收藏按岛 + 票根全局），分两段列。

**卡片**：`wj-share`（书脊 + 标题 + 字数 + 附言）/ `wj-invite`（深色 +
meta 两格 + 四个回答）。渲染函数在 `page-wj-curtain.js` 里导出
（`Sleepy.wjCurtainUI`），聊天页**惰性取**（page-chat.js 先加载）。
邀请卡上那四个回答**不是给 user 点的** —— 回答的人是 TA，未回应时写
「等 TA 回应」，回应后对应那个亮起来 + 显示 TA 那句话。做成可点就变成
user 替 TA 决定（OOC 操纵），不做。

**顺带修了一个一直坏着的东西**：`wjCoread` 原来只有 `_transport` 注入点，
**没有真机兜底** —— 生产环境里 `judgeInvite` / `react` 永远返回
「没有可用的模型连接」，也就是 T5 的共读邀请发出去以后 TA 永远不回应。
现在照 `wjEngine` 那份补了 `apiTransport`（`Sleepy.api.runChat`，非流式）。

**四种调用类型、五处装配**：线上私聊（`assembleOnline`）、线下私聊
（`assembleOffline`）、主动消息（`page-proactive`）、群聊（`page-group-ai`）、
群线下（`page-group-offline`）。后三处**不走槽位矩阵**、各拼各的 ——
这次查出来的缺口全在这三处。

| # | 缺什么 | 影响 |
|---|---|---|
| ① | 线下装配没有 `custom` 槽 | 用户在预设里写的卡，**一进线下叙事就一句都不生效** |
| ② | 主动消息只有 proactive 卡 + content 原文 | 没有共享外壳（`[角色声音]`）、没有 K01 短字段、没有 I01 —— 而这条路**要直接产出发给 user 的那句话**，最需要「像这个人」。v84 写的「F1/F2/主动消息三类共用」对它是落空的 |
| ③ | 群聊 `[ENTITY_KNOWLEDGE]` 只给 content，`speech` 还只在 NPC 分支给 | 群里的大号全是一个腔调 |
| ④ | 群线下 `[PARTICIPANTS]` 同上 | 同一个人在私聊里「说话短、在整理旧书」，进了群线下只剩一段人设原文 |

②③④ 统一走**新导出**的 `compileCharacter` / `charMetaLines`（一份实现，
别再散出去）；`prompt-engine.js` 的导出面新增这两个 + `compileI01`。
① 的位置与世界书一致：K 区（worldbook 之后）、S 区（narrative 之前）。

**查完判定「不是缺口」的**：
- 线下没有独立的 `i02 时间事实` —— 线下 `scene` 里有【现实时间】，出处同一份
  （`calendar`）。线上 I02 多给的「当天公共日期状态」线下确实没有，但线下有时段/
  天气/地点，够用。

**没做、留着的**：
- **线下 `drop`（掉马事件）**：`compileDrop` 里会 `markDropEventsSeen`
  **消费一次性事件**，线上线下都调就是互相抢（谁先装配谁吃掉）。要加得先定
  「哪条路径负责消费」，不是加一行槽位的事。
- 主动消息加 K01/I01 让单次调用多约 **1.2k tokens**（它按 char 扫，2 分钟节流 +
  有候选才调）。真聊下来觉得不值再摘。

**新增 6 条冒烟断言**（通查①②③④ + 会话置顶 `withPinnedFirst` + 角色卡上架）——
这四处都是「肉眼看不出来」的类型。
