## ⑭ 帷境 T7 · 正史审阅台（v95）

**新文件** `wj-canon.js`（数据 + 状态机 + 候选提取 + 写入）+
`page-wj-canon.js`（四步 UI）。入口在谢幕页「进入正史审阅」那一张卡。

**四步**：候选事实 → 冲突确认 → 人物认知 → 最终写入。

**三条红线怎么落地的**：
- **只写结构化事实**：候选是模型挑的一句话事实（≤40 字），正文一个字不进现实；
- **冲突没处理完不许往下走**：`blockers()` 是硬闸门（按钮 disabled + 说明原因）；
  模型只**报告**冲突，`fixed` 是**人打的勾**（必须写一句处理方式）；
- **幂等**：`written` 一置就不再写；重新提取且候选真的变了才解锁。

**落点**：`memoryStore.writeMemoryItems`（`source:'other_app'`、`status:'active'`、
`evidenceType:'confirmed_event'`；认知档位写在正文开头，如「他清楚地记得：…」）；
带 `date` 的 `place_time` / `shared_event` 额外落一条 `calendar.addEvent`。
写入成功后作品 `reality` → `canonized`。

**认知六档**：前四档（清晰记忆 / 片段记忆 / 情绪残留 / 角色隐瞒）写进那个人的记忆；
「本人未知」「完全不知情」**不写** —— 写进去就自相矛盾了。
**批准一条 ≠ 所有人知情**：没定认知的人（默认「完全不知情」）一条都不写。

**真机抓到的坑**：闸门用的是 `paint()` 那一刻的 rec 快照（`store.get` 是深拷贝），
认知页改完档位不重画就永远卡在「一个人都没定」。改成 `liveRec()` 实时取 +
改完就地刷新闸门（不重画，免得滚动位置跳回顶部）。

**非正史候选的作品进不来**：普通故事 / 平行世界在开帷时就承诺过「不进任何人的现实记忆」，
审阅台直接挡下并告诉用户要先回开帷流程改性质。

### 一、授权：**不用新造框架**

先把现有的翻了一遍，发现**日历本来就带事件级可见性**，所以「授权」主要是接线：

- **日历**：`visibility` 四档（`private` / `shared_busy` / `shared_detail` /
  `participants`）+ `createdBy`。L1.5 直接尊重它 —— 这正是 v5 §5 第 6 条要的
  「细分类别权限」，比全局开关更细，**不用另造一套**。
  ⚠️ `shared_busy` 那档**只给「那会儿有事」、不给标题**，且措辞里明说
  「你并不知道具体是什么」—— 不说的话模型会自己编一个内容填上。
  另：`char_schedule`（作息表）不收，那是日常背景不是临近事项。
- **日记**：`author:'char'`（TA 代笔）天然可见；`author:'user'`（你写的）**默认关**，
  开关在聊天设置页「TA 能知道我的什么」抽屉里（存 `lifeShare:<charId>`）。
- **朋友圈**：新增 **char 视角的镜像 `canCharSee`**（`page-moments.js`，已导出）。
  原来 `canSee` 的朋友权限那一闸只对 `kind === 'user'` 判，char 视角是**没判的** ——
  照抄会得到「角色偷看你设了私密的东西」。**方向最容易写反**：
  挡「他看我的动态」= `iHideFromChar` + `charHidesFromMe`；
  `iHideChar` 是「我不看他发的」，完全另一个方向。冒烟里专门守了这条。

抽屉标题也从「朋友圈权限」改成「**TA 能知道我的什么**」（现在不只朋友圈了），
那行的小字会同时报朋友圈和日记的状态。

### 二、L4 向量记忆（新文件 `memory-vec.js` + 槽 **K03c**）

方案（`docs/方案-向量记忆-v1.md` §3）落地成三件：

| 件 | 怎么做 |
|---|---|
| **存** | IndexedDB（`sleepy-vec`）。1536 维一条 6KB，localStorage 几百条就爆。照 `media.js` 那套写 |
| **写** | 每收完一条回复后台 `sweep`（每次最多 2 块，不 await、不挡聊天）。游标 `vecCursor:<chatId>` 保证幂等 |
| **读** | 发送前 `prefetch`（和主请求并行，超时 1.5s 就放弃这轮）→ 缓存 → 槽位同步读 |

- **切块**：8～12 条 / 600～1000 字（v5 §8.2）。
- **重排**：v5 那六个权重表砍成「语义 0.8 + 时间 0.2」两条 —— 但**只动 `rank()` 一处**，
  将来补实体/未完成承诺/关注队列都在那里（方案 §3.5 留的钩子）。
- **块里存一份原文文本**：方案写过「向量是索引不是副本」，这里**刻意例外** ——
  召回必须回填**原文块**才准，而且消息会被删/被编辑/会话会被清，
  只存 id 的话召回时可能什么都取不回来。
- **不回落主 API**：没配「向量记忆 API」就是不工作（对话模型喂 `/embeddings` 只会 404）。
- **去重**：比近期原文窗口更新的块不召回 —— 否则同一段话出现在两个槽里，模型会当成两件事。

**接了三层**：线上私聊、线下、主动消息。
`assembleOnline` / `assembleOffline` 都是**同步**函数，所以三处都得先异步预取再装配 ——
线上拆了 `requestReply` / `runReply`，线下拆了 `requestTurn` / `go`；
**主动消息是例外**：它没有「当前输入」，用上一次预取的结果（滞后一轮）不 await。

**顺带修**：主动消息的 `buildSystem` 是**手拼**的（不走槽位矩阵），
这轮又漏了召回 —— 和 v84 漏掉共享外壳是同一个病根。建议做成 `PROACTIVE_SLOTS` 表（没做，记进地图 §8）。

### 三、设置

「向量记忆 API」页里多了**用不用**的开关 + 索引条数（让用户看得见它在不在干活）。
开关**立即生效**（它不是一个接口配置，是行为本身）。

真机验过：切块/余弦/重排/去重、写入幂等、召回命中、三层装配都有这段、
关掉总开关就完全不工作、线下拆完能正常走完一轮（模型调用确实发出去了）。

### 四、v100 补丁：外部评审后的收口（同一天）

拿这份交接 + 地图给外部模型看了一遍，它提了几条「文档说做了、链路没闭」。
逐条核实：**两条是真缺口（已修）、三条是文档口径（已改）、两条是它只看摘要**。

**真缺口：向量召回没做身份隔离。** core 的记忆层一直按身份隔离
（`memoryViewFor`：有认知屏障时只给「同皮套 + 同马甲」），
但向量层**只按 charId 过滤** —— 角色对两个马甲开了屏障时，
用大号说话会召回到小号聊过的内容（「它怎么知道我在小号说过的话」）。已照 core 补齐：

- 块上记 `rootId`（哪个大脑）+ `charId`（哪张皮）+ `userId`（面对谁）；
- 召回改按 `rootId` 取 + 按 `cognitionOf().barrier` 决定隔离粒度；
- 判据抽成纯函数 `visibleTo`，冒烟守着它和 core 一致；
- 维护类（条数/裁剪/清空）走 `allOfRoot` —— **不受身份隔离影响**，
  否则大号聊的块永远裁不掉、能无限涨。
- **DB V1 → V2 升级即重建**（老块没这两个字段，留着就串记忆），
  游标键换 `vecCursor2:` 前缀作废老的。

**真缺口：两处文档口径。** ① 方案 §3 写「只存 blockId/vec/meta、原文仍在存档里」，
而实现里块**存了一份 text** ——「向量是索引不是副本」只对一半，已改成
「索引里那份原文是本地缓存，不能脱离原始消息独立存在」；
② 方案 §4 还挂着「还没定：切块/注入位置/上限/开关」，三条都已落地，
已改成已定 + **状态分层表**（基础设施 ✅ / 链路已通 ✅ / 端到端待验收 ⏳）。

**它说对但我已经做了的**：去重、失败重试、线下未写入（§8 早有）、开关与上限。
**它没看代码的部分**：它要求的 meta 字段（worldId/conversationId/messageIds）
实现里已有（叫 sandboxId/chatId/fromId+toId）；它建议「原文回源读」我刻意不做
（消息会被删/编辑，且召回有 1.5s 超时）—— 它自己留的折中表述采纳了。

**教训**：我写「✅ 已完成」的时候把「链路通了」和「验收完了」混成了一句。
以后凡是这种跨阶段的东西，**一律按三层写**（基础设施 / 链路 / 端到端）。

## ⑱ L1.5 近期生活动态（v98，已部署）——「角色知道你最近发了什么」

v5 分层里的 L1.5，是那九层里最后空着的一层（L4 向量还没做，但 L4 是「检索」，
这一层是「近期视野」，两件事）。用户能感觉到的现象：**我刚发的朋友圈，TA 聊天时完全不提。**

**做了什么**：新文件 `life-feed.js` + `prompt-engine` 新槽位 **K03b**
（紧跟 K03 relation —— 排位照 v5，L1.5 本来就在 L1 与 L2 之间）。
三层装配都接了：**线上私聊 / 线下 / 主动消息**。
最后一层最要紧 —— 少了它，TA 永远不可能「主动提起你昨天发的那条」，只能干等
`[TRIGGER_CANDIDATES]`。

**v1 只做朋友圈**（取舍，不是偷懒）：
- 它是唯一「发出来就是给人看的」源；日历 / 待办 / 日记属于 user 私密内容，
  v5 §5 明说「默认不对角色开放，需细分类别授权」—— 那要先有授权概念，是另一件事；
- 三道闸（账号隔离 / 朋友权限 / 可见范围）**已经存在**（`page-moments.js canSee`），
  这次新增的是**镜像版 `canCharSee`**（char 视角）。**方向千万不能反**：
  挡「他看我的动态」的是 `iHideFromChar` + `charHidesFromMe`；
  `iHideChar` 是「我不看他发的」，那是另一个方向。冒烟里专门守了这条；
- 只收「我发的」和「他自己发的」——别的角色/NPC 发的属于他自己的世界，
  模型本来就知道，再注一遍只是白烧 token。

**窗口** 10 天 / 12 条（v5 §6.2 建议 7～14 天、10～20 个包）。
**文案里写死一句**「不必逐条回应，也别当成刚刚发生，已经聊过的就不用再提」——
v5 主动关注原则里的「避免追踪感」就是这个：这层的价值是让 TA 不像失忆，
不是让他变成行程播报。

**已知口子**：program 槽在预设配置页**点不开开关**（既有的，所有 program 槽一样，
进去只能看说明）。要让用户能关掉这一层，得先给 program 槽做开关 —— 没做。

真机验过：线上/线下/主动三层都有这一段、私密动态被挡、朋友权限两个方向都对、
出窗口的不进、朋友圈页照常渲染。冒烟新增 1 条断言（`D:/tmp/verify-l15.js`）。

## ⑰ 记忆注入配额重做 + 近景窗口 20→40（v97，已部署）

用户：「固定死六条还是多少的对话记忆其实有点少，一般来说都是固定记住两百条
对话记忆，然后开向量记忆会准一点。」

**先把三件事分清**（当时被说成了一件）：近期原文默认 20（**上限本来就是 200**，
设置页可调）／记忆库注入写死 6 条／存储**完全不裁剪**。

**实测那 6 条，发现比「少」严重** —— 写 3 条边界 + 3 条纠正 + 1 共同经历
+ 1 约定 + 1 偏好：

```
注入条数: 6    共同经历: false    约定: false    事实: false
```

旧的配额是「锚点不限 → boundary 固定 3 → correction 固定 3 → 剩余补到 6」，
**边界 3 + 纠正 3 正好吃满 6 格**。等于给规则类发了固定配额、经历类没有保底 ——
最该被反复看见的先被挤掉，最不需要每轮重复的反而霸屏。`promise` 掉得最伤：
用户不会觉得「它记性差」，会觉得「它根本不在乎」。

**改法**：配额 6 → 12；锚点不吃配额、约定先占座（≤4 条）；**经历类保底一半席位**；
规则类各保底 1 条、上限 3 条；每步按「还剩几格」实时结算。

**近景 20 → 40**，并顺手修了一个**真机才抓到的静默失效**：`api.js` 的默认值改了
根本不生效 —— `store.js` 的 `chatDefaults` 里也抄了一份 `contextMessages: 20`，
它在回落链的第三层、位置更靠后所以赢。现在 `chatDefaults` 只留 `heartbeatAuto`，
生成参数统一认 `api.js` 的 `GEN_DEFAULTS`；老存档由 `migrateChatDefaultsGenerative`
把**正好等于旧默认**的键清掉（用户真改过的值一律留着）。

**顺带统一**：上下文条数的回落规则抽成 `Sleepy.api.contextLimit(chat)`，
真聊天 / 预演页 / 心声三处共用一份（以前各写一遍，改默认值要改三个地方，
漏一个的表现就是「预演里记得的事，真聊天里忘了」）。

详细取舍见 `docs/方案-向量记忆-v1.md` §3.6 与 §4.5。
