## 2. 每个写入路径是否已经经过统一入口

`calEvents` 的实际写点仍是 `calendar.js` 的 `addEvent` / `updateEvent` / `removeEvent` / `clearGenerated` 四处，但**能被外部触发的写入只剩三条路**：

| 路径 | 是否过统一入口 | 锚点 |
|---|---|---|
| UI 新建（私人提醒 / 邀请他） | ✅ 过 `action → requestCreateEvent` | `page-calendar.js:1182 createRequest` → `:1191 runRequest` → `calendar.js:736` |
| 纪念日保存 | ⚠️ **直连 `addEvent`**，未过统一入口 | `calendar.js:647`（`saveAnniversary`） |
| 帷境定史 | ⚠️ **直连 `addEvent`**，未过统一入口 | `wj-canon.js:356` |
| 改期 / 完成 / 取消 / 删除 / 表态 | — 走 `updateEvent` / `cancelEvent` / `removeEvent`；表态走 `respondSharedEvent`（有闸） | `page-calendar.js:975 / :921 / :910 / :934`、`calendar.js:678` |

> 后两条是**本轮刻意没动的**：施工单 §2 只要求「UI 与未来执行器共用」，
> 并明确「不改变纪念日 `saveAnniversary` 的引用保护逻辑」。把 `wj-canon` 和
> `saveAnniversary` 也收进来是下一批的事（纪念日要先解决 `memoryId` 校验、
> 帷境要先解决「审阅台即确认台」怎么映射成 `requestKey`）。**如实列出。**

静态护栏已断言：`action.js` 里不许出现 `.addEvent(`，且必须出现 `requestCreateEvent`
（`scripts/smoke.js` 最后一条）。

- **键**：`actionRequests`（`action.js:41`），已在 `core.js:363` 删房名单、`store.js:225` 默认值。

## 4. requestKey 幂等的实际行为

| 场景 | 行为 | 证据 |
|---|---|---|
| 同 key 第一次 | 建记录 → 执行 → `ok` | smoke「统一入口 + action」 |
| 同 key 再来一次 | `createRequest` 直接命中那条 `ok` 记录，`dup:true`，**不建第二条** | 同上（事件数 = 1） |
| UI 连点两次「记下来」 | 连点保护 `newSubmitted`（`page-calendar.js:1180`）+ 同 key，仍只 1 条 | 无头 Edge B6 |
| 冲突未确认 | **不写入**，记录保持 `failed`（错误码 `conflict`），可带 `allowConflict` 重跑 | 无头 Edge B3/B3b |
| 换一次新建（第二次打开） | `onShow` 重铸新 key（`page-calendar.js:1237`）→ 正常建第二条 | smoke「新建页」+ 无头 Edge B1/B2/B3 连建成功 |

**刻意不用「标题 + 时间」拼弱键** —— 那会把用户确实想建的两条一样的事误合并。

> ⚠️ 这个「第二次打开要重铸钥匙」是**无头 Edge 当场抓出来的真 bug**：
> 钥匙原本在 `render` 里铸，而**页面实例是缓存复用的（render 只跑一次）**，
> 于是第二次新建带着上一次的 key，被当成「已经建过」，**第二条根本建不出来**。
> 已做反向验证：把 `onShow` 改回 `newSubmitKey || mintSubmitKey()`，冒烟立刻变红。

## 5. 成功、失败、重复、取消各自的回执样例

**成功**（`requestCreateEvent` + action 双层）：

```js
// calendar.requestCreateEvent
{ ok:true, eventId:'evmurt…', requestId:'actmurt…', dup:false,
  receipt:{ type:'calendar_event_created', at:1790997520274, ref:'evmurt…' } }
// action record
{ status:'ok', attempt:1, resultRef:'evmurt…', receiptAt:…,
  receipt:{ type:'action_ok', kind:'calendar_event_created', at:…, ref:'evmurt…' } }
```

**失败**（撞车，未写入）：

```js
{ ok:false, requestId:'act…', error:{ code:'conflict', message:'这个时间和别的安排撞了' },
  receipt:{ type:'calendar_event_failed', at:…, errorCode:'conflict' },
  conflict:[{id:'ev…', title:'占坑'}], needConfirm:true }
// action record: status:'failed', error:{code:'conflict'}, receipt:{type:'action_failed'}, resultRef:null
```

其它失败码（每个都会留 `calendar_event_failed` / `action_failed`，**且事件表里不留半成品**）：
`bad-type` `no-title` `no-start` `no-owner` `bad-status` `bad-visibility`
`no-participants` `bad-participants` `bad-createdby`（含 `createdBy.type==='model'`）
`no-sandbox` `write-failed` `no-executor` `no-result`。

**重复**：

```js
{ ok:true, eventId:'ev…（第一次那条）', requestId:'act…', dup:true,
  receipt:{ type:'calendar_event_created', at:…, ref:'ev…', dup:true } }
```

**取消**（用户在冲突框点「取消」或放弃）：

```js
// action.cancelRequest
{ status:'cancelled', receipt:{ type:'action_cancelled', at:…, errorCode:'cancelled' } }
```

## 8. 共同事件角色表态做到哪一步

**做到「玩家明确记录」这一级，没有伪造角色自动接受。**

- **主来源统一为 `participantStates`**（`calendar.js:867` 进 `addEvent`），
  `participants[].state` 降为兼容字段、每次由 `syncParticipantsTo`（`:636`）同步，
  **任何判断都不读它**。注释与测试都固定住了。
- **唯一写入口 `respondSharedEvent(eventId, actorKey, state, via, reason)`**（`:678`）：
  - 状态计算走 `sharedStatusOf`（`:652`）：双方 accepted → **confirmed**；
    任一 declined → **cancelled**（现有值域里没有 `declined`，不擅造新状态）+ 写 `cancelReason`；
    还有 pending → pending。
  - **`via` 必须显式传**，本轮只认 `'user_record'`。传 `'model_said'` 之类一律 `no-source` 拒绝 ——
    **不允许「玩家打开页面 = 角色接受」，也不允许「模型一句话 = 角色接受」**。
  - 挡住的还有：非参与者（`not-a-participant`）、非法状态值（`bad-state`）、
    非共同事件（`not-shared`）、**他看不到的邀请**（`invisible-to-char`）、已取消（`already-cancelled`）。
- **UI**：详情页新增「他的回应」块，显示「你：答应了 / 甲：还没表态」+ 两个按钮
  「记下：他答应了」「记下：他推掉了」，并**明写这是玩家记的、不是他自己说的**。

> **【已跑】confirmed 现在可达**：建 → 记下他答应 → `status:'confirmed'`、
> `participantStates[char]='accepted'`、`participants[].state` 同步为 `'accepted'`、`history` 留痕 1 条。
> 再记他推掉 → `cancelled` + `cancelReason`。
>
> **没做到的**：角色侧自动表态（`'story_candidate'` 来源）**本轮不存在**，
> 函数里留了口子但没有调用方。按施工单「宁可先补齐数据与显示，不要伪造自动接受」执行。
