## 四、§六 审美与身份冲突审计（**待确认清单**）

1. **男性词 daylight 倾向**（`soft dimensional daylight`）：夜景/室内暗光可能被往日光推 → 明确冲突，正式内置分支**未停用**（与实验期同词同态），列为保真适配项待最小决定。
2. **女性 C**：`adult woman` 写死 + 族裔未指定时默认 East Asian + `cinematic photograph/depth of field` 电影感 → 同上三点边界照旧，只服务该底座，不外扩。
3. **年龄无结构化字段**：char/user 记录没有年龄档，程序**无法**按年龄拦截 → 未知年龄不自动标成年做不到结构化，只能如实列为缺口；未成年人保护依赖聊天侧既有门禁，本底座不新增年龄判断。
4. **性别未指定/其他（单人内置）**：**明确报错零请求**（不暗套男女，不发明中性兜底）——这是行为变化：以前 plan 无性别也照画（legacy），现在内置档会拦。custom 档不受影响。
5. **文字身份绑定不是跨图锁脸**：本链路只证明资料正确传入请求。
6. **extras 审计**：正式入口全部不传 extras（`generate({plan})` 调用点核查），提示词库只进「试一张」——无隐藏旧词暗中注入。
