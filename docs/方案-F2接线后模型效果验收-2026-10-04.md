## 一、为什么仍要重跑（结论保留，但理由换了）

**v1 的理由作废**（不能说旧样本「没接线」）。**重跑的真实理由是另外三条**：

### 1.1 旧样本没有任何可用于「效果归因」的判分记录

逐字段检查 10 个样本文件：

| 字段 | 旧样本是否记录 |
|---|---|
| 完整原始输出 | ✅ 有 |
| 解析后 `paras`（含 `type`） | ✅ 有 |
| `raw.len` / `status` / `ms` | ✅ 有 |
| `finish_reason` | ❌ **无** |
| `usage.completion_tokens` | ❌ **无** |
| `reasoning_content` 长度 | ❌ **无** |
| **system 段原文 / 快照** | ❌ **无** |
| **D1–D6 判分** | ❌ **无**（只有 v1 报告里的人工定性观察） |

**关键缺口**：没有 system 段原文 → **无法事后核验「那批到底注进了什么」**；
没有 `finish_reason`/`usage` → **截断原因无从归因**（这正是 8192 争议的症结）。
本轮方案把这三项列为**必落盘字段**（§7.2），就是为了补上这个洞。

### 1.2 旧样本的六项口径落盘值与报告数字不一致（已复核确认）

`复验-8192` 报告写「解析成功 7 / 可用回复 7」，但落盘 JSON 里是
`解析成功数: 10 / 可用角色回复数: 10`，而 `非空内容数: 7`。

**已找到根因**（`scripts/offline-f2-effect-acceptance.js:577-580`）：

```js
if (stage === 'model-returned' && t.已落地 && hasContent && !degraded) {
  口径.解析成功数++;
  口径.可用角色回复数++;   /* ← 同一分支里 ++，两者恒相等 */
}
```
**这两个计数器在实现上就是同一个布尔量**，所以「7 vs 10」不是抄错，
而是「报告按 7 写、落盘按另一个口径算」。**口径本身没有定义清楚** → v2 §6.2 重写。

### 1.3 旧样本的采集器有已确认的误判

`st.n > before && !st.busy` 在**失败收尾时也成立**（busy 被解除），
→ 抓到上一轮残留消息，**3 处超时被误判成「复读」**，报告已撤回该结论。
v2 强制：单一可信判据 = 诊断 `stage`；失败轮不取任何输出；只取本轮新增。

### 1.4 结论

> 旧样本 = **链路探路的历史参照**，可用于 qualitative 前后对比；
> **不能**作为当前版本的效果结论。**但也不能说它「没接线」** —— 它接线在位，
> 只是缺判分记录、缺归因字段、且采集器有误判。

## 二、阶段划分（★ 按你的建议：先单臂小样本，确认链路再决定花钱）

| 阶段 | 内容 | 付费 | 出口判据 |
|---|---|---|---|
| **P0 阶段** | 脚本改造 + 夹具自检 | **0** | 夹具五项自检全过 + `check`/`smoke` 双绿 |
| **P1 试跑** | **新版本单臂 4 轮**（两个独立会话：G4 连续 3 轮 + G7 独立 1 轮） | **≤ 4** | 请求完整回来 + 采集器不拿错 + 判分规则能落地 |
| **P2 决策** | 你看 P1 报告后决定 | 0 | 批准 → 进 P3；否则改脚本重来 |
| **P3 正式** | 单臂 17 轮 或 双臂 34 轮 | 20 / 38 | 出验收报告 |

**P1 是本方案的当前落点。** P1 的 4 轮只验「链路 + 采集 + 判分可用性」，
**不产出任何关于人物效果的结论**（样本量远不足）。

### 2.1 P1 的 4 轮 = **两个独立会话**（★ 已修正矛盾表述）

**P1 共 4 次请求，分布在两个独立会话里**：

| 会话 | 组 | 轮次 | 输入 |
|---|---|---|---|
| **会话 A** | G4 user 主体性 | **连续 3 轮** | 我到了。→ 我坐下了。→ 算了，你看着办。 |
| **会话 B** | G7 复杂输入 | **单轮 1 次** | 复合长输入（追问过去 + 情绪 + 具体请求 + 含糊项 + 明确禁止项） |

⚠️ **为什么必须分成两个会话**：若 G7 接着 G4 的会话跑，G7 会**继承前 3 轮的现场上下文**，
而 G7 要验的正是「复杂输入下五条规则会不会互相打架」——
带着前 3 轮上下文就**污染了判据**。
脚本实现上，每个 `GROUPS` 条目 = 一个独立会话（独立 context + 独立 page）。

**会话 A 的第 3 轮是关键轮**（「算了，你看着办。」最容易诱发「替 user 决定」）；
**会话 B 的两条关键判据**是「明确禁止项有没有被违反」与「含糊项有没有被替 user 定死」。

### 2.2 P1 的结论边界（★ 强制写进报告）

> **P1 只有 4 轮，样本量远不足。**
> **无论这 4 轮人物表现多好，都不得得出任何关于 B/P/L/N/S2 效果���结论。**
> P1 只验三件事：① 请求能否完整回来 ② 采集器会不会拿错消息 ③ 判分规则能否落地。

这一句**由脚本强制输出**到样本落盘文件的 `元信息.结论口径` 字段，
不是靠报告人自觉 —— 见 §7.2。

### 3.1 C2 改为跨轮趋势判据（★ 你的第 3 条批评）

**v1 错在**要求「每轮都出现材料名/尺寸/拆步骤」——
`P` 模块原文恰恰说的是**「不要求每轮展示全部性格」**、
**「选取与处境有关的部分形成言行，其余设定留在背景」**。
逐轮打卡材料名 = 把人物测试变成口头禅检测，**违背 P 的设计意图**。

**修正后的判据（跨轮 2–3 轮看趋势，不逐轮要求）**：

| 档 | 判据 |
|---|---|
| **2** | **整体基调**与资料一致（克制、具体、少形容词）；人设特征**分布在不同轮次**（不要求每轮都有）；无通用体贴人设滑向 |
| **1** | 基调一致但某一轮滑向通用表达（如突然说「别难过」） |
| **0** | 明显 OOC |
| **否决** | 编造旧疤原因 / 把 char 心理写成客观事实陈述 / 无依据读到 user 内心 |

**记分方式**：判「2/1/0」时**必须写出这一轮出现了哪一处人设证据、落在第几轮**，
不许只写档位。

### 3.2 C5 收窄为两条具体禁止（★ 你的第 1 条批评）

**v1 错在**把「角色心理不能写成事实」定得太宽 ——
**有效叙述视角下，写角色自己的念头是完全允许的**（`P` 原文：「文学性的角色念头只在有效视角与输出协议允许的范围内表达」）。

**修正后只禁止两条**：

| # | 禁止项 | 允许（不算违规） |
|---|---|---|
| **F1** | 把**角色对别人的猜测**写成客观事实（「他其实已经决定留下了」——而他没说过） | 角色自己内心的判断、猜测、权衡（「他觉得她今天不太对」） |
| **F2** | 让角色**无依据读到 user 的内心**（「沈砚看出了她在强撑」——user 没写、也无从观察） | 通过 user 的**可观测言行**推断（「她说完就端起杯子，没看他」） |

**判分时必须把命中的原文句子摘出来，并注明触的是 F1 还是 F2。**
分不清是 F1 还是 F2 → 该轮**不判分**，记「证据不足」。

### 3.3 C6 收窄（★ 你的第 2 条批评）

**v1 错在**说「即时动作不许被记住/引用」——**记住 user 明确表达过的计划本身是合规的**。

**修正后的判据**：

| # | 禁止项 | 允许 |
|---|---|---|
| **M1** | 记住 user **明确说过**的计划（「我下周再来」→ 后续轮可记得、可引用） | ✅ |
| **M2** | 禁止把一次动作**推断成频率/常态**（「她每周三都来」——user 只说过一次） | ✅ |
| **M3** | 禁止**宣告未来已发生**（「下周她果然来了」——user 没给那次经历） | ✅ |
| **M4** | 禁止把即时动作**固化成状态字段**（`envUpdate`/长期约定里写死） | ✅ |

**G6 三轮设计**：第 1 轮 user 说「我下周再来」→ 第 2、3 轮看
① 是否记得（**不记得不算违规**，只是没用到这条规则）② 是否推断频率 ③ 是否宣告未来。

## 四、固定夹具（沿用 v1，未变）

虚构角色**沈砚**（材料名/少形容词、不擅长安慰、旧疤不提原因、从不摔门、慢性失眠）；
user `userRef='对方'`，**不设姓名/性别/情绪**；
场景=城西旧书店二楼阁楼/深夜 23:40/雨/NPC 老板娘**在楼下从不上楼**；
固定历史 6 条（开场前动作 + 在场声明 + user 坐下）。

⚠️ **组内多轮时轮次标记绝不写进 user 输入**（第一批写了 `（第二轮）` 被模型看见，污染复读判据）。

**本轮新增**：`P1` 用的 4 轮必须**落在同一条会话**里（G4 三轮连续 + G7 另起一组）。

### 4.1 夹具有效性自检（0 付费，不过就停）

1. `btDecideScene('offline')` → `ok=true` ∧ `modules==['B','P','L','N','S2']`；
2. 真实 system 原文里 **B/P/L/N/S2 五段整块正文各唯一命中一次**（不只查首句）；
3. **反向**：N/S2 不在 `pendingModules` 里；
4. 产物里**不含**旧 shell 卡的 `[角色声音]` 段（该字面量在 `prompt-engine.js:613`）——
   证明确实走共享层、不是回退；
5. 历史真的进了 payload（`hasHistory=true` 且含上表 6 条）。

⚠️ **自检 2/3/4 是「诊断之外的独立证据」** ——
`btNote` 虽然只在调用方把 system 真拼完之后才被调用
（`prompt-engine.js:472-480` 的注释与签名：`必须由调用方在 system 真的拼完之后调用`），
但它仍是**诊断层**；按长期约定，**判据必须落在装配产物上**。
本轮把 system 原文**连同 SHA-256 一起落盘**，P3 之后任何人可重新核验。

### 6.2 统计口径（★ 你的第 4 条批评已采纳，公式重写）

**v1 写错**：`非空内容 = 解析成功 = 可用回复`，且 `可用 + 降级 = 总请求数`。
**实际上三者可以不等**：非空输出**可能**解析失败；解析成功**也可能**没有可用正文；
超时/空输出**未必**产生降级回复（`parseOfflineReply('')` 走 `!text` 分支 →
`paras` 为空 → **既不落地也不提示**）。

**v2 的三条独立判据**：

| 判据 | 定义 | 落点 |
|---|---|---|
| **K1 有返回** | `raw.stage==='ok' && status===200` | 抓 HTTP 事实 |
| **K2 有内容** | `raw.len > 0`（**上游原始长度**） | 抓服务端实际给了字 |
| **K3 可评** | `stage==='model-returned' && 已落地 && K2 && !degraded` | 能进入判分的轮次 |

**只保留这两条恒等式**（都是**定义**，不是经验规律）：

```
K3 ≤ K2 ≤ K1 ≤ 总请求数
K1 - K3 = 解析失败轮 + 空内容轮 + 超时轮 + 网络失败轮
```

**明确不成立的**（v1 写过，全部删掉）：
- ❌ `非空 = 解析成功`（非空但 JSON 坏 → 解析失败）

### 6.4 8192 截断的定性（★ 按你的意见改写）

**v1 写「截断率不是本次要验的东西，记为已知限制即可」——你不同意，我采纳。**

**v2 的定性**：

> **8192 是本轮的目标使用预算**（用户常用线路能给到的档位）。
> **不通过加高额度把问题藏起来。**
> 截断计入「**这条线路 + 这套配置下的可用性问题**」，
> **不判成人设或文笔失败**。

**为什么不能直接断言「中转站硬限制就是 8192」**（v1 也没说清）——
至少有四种可能，本轮**只能测到其中一部分**：

| 可能 | 本轮能否判定 |
|---|---|
| 客户端只申请了 8192，服务端按申请额度结束 | **能**（已知 `max_tokens=8192`） |
| 中转或上游有上限，申请更多也会被限制 | **不能**（本轮不试更高档 → 无对照） |
| 推理与可见回答共享输出预算，推理吃满后正文所剩不多 | **能**（查 `reasoning_content` 长度 + `usage.completion_tokens`） |
| 超时/连接中断/采集错误**看起来**像截断 | **能**（查 `raw.stage` 是否为 `timeout`/`network`） |

**必落盘的归因字段**（v1 漏了，正是旧样本无法归因的原因）：
`finish_reason` / `usage.completion_tokens` / `usage.prompt_tokens` /
`reasoning_content` 长度 / `content` 长度 / `raw.stage` / `ms` / `status`。

**8192 是 token 数**，不是 8192 个汉字，也不等于上下文上限 ——
**输入能读多长与本次最多生成多少是两回事**，本轮不把两者混谈。

**若 P1/P3 出现截断**：
- 1 次 → 记为可用性问题，**不自动重试**（重试会掩盖真实发现且烧钱）；
- 同案例连续 2 次 → 该案例记「本预算下不可评」，如实登记。
