## 二、weEntries 的 kind 兼容方式
- 不加新表，`weEntries` 记录带**可选 `kind`**。写时经 `kindOf()` 归一：白名单（ticket/photo/letter/music/gift/place/other）原样保留，白名单外 / 缺失 / 历史遗留一律落 `'other'`。
- 读时门厅分组、详情显示都走 `Sleepy.weStore.kindOf`（冒烟/真机/页面**同一出口**，无第三份映射），老记录无 kind 字段自动按 `other` 展示。
- 兼容性验证：smoke「老记录无 kind → other」「非法 kind → other」「ticket 原样保留」三断言全绿。

## 三、collection 入口与页面生命周期
- **入口**：We 首页「去收藏馆 →」→ `nav.open('collection')`。收藏馆**不占桌面格**、不新增 ICON、不碰 `LAYOUT_VERSION`；旧 `favorites` 页与入口逻辑原样（冒烟反向断言 `nav.open('favorites')` 已不在 We 首页，且 `favorites` 仍注册）。
- **生命周期**：
  - 门厅 `collection`：`render` 建首屏 + `onShow` 每次进页/切岛重读重画（`ctx.__paint`），保证切岛后不串线、回岛恢复。
  - 详情 `collection-item`：独立页，`params.id` 只读；`nav.back()` 回到门厅。
  - **关键教训（框架坑）**：详情若注册成**同一页** `collection`，`nav.open('collection',{id})` 走的是「栈内已存在 → `applyParams` 重渲染 + `closeTo`」，`nav.back()` 会把整个 collection 弹掉**回到桌面**而非门厅。因此门厅与详情**拆成两个注册页**（对齐 `wj-foyer → wj-work` 惯例）。真机 C3b「返回后仍在门厅」已锁。

## 四、来源复核逻辑（`checkSource`，page-collection.js）
| sourceType | 判据 | 存活 → 文案 | 失效 → 降级文案 |
|---|---|---|---|
| 空 / `manual` | `!sourceType || sourceType==='manual' || !sourceId` | — | **「手动记录」**（不报错） |
| `calendar` | `getEvent(sourceId)` 存在，status 为 scheduled/pending/tentative/confirmed | `来源仍在 · 日历 · <标题>` | — |
| `calendar` | `getEvent` 存在且 **status === 'completed'** | **`done` 态：`来源已完成 · 日历 · <标题>`**（有效历史来源，**不算失效**，不显示「原物已不在」） | — |
| `calendar` | `getEvent` 存在且 **status === 'cancelled'** | — | **「该约定已取消（原物已不在）」** |
| `calendar` | **`getEvent` 返回 null（事件真被删掉）** | — | **「原日历记录已删除（原物已不在）」**（区别于取消） |
| `offline` | `offlineStore.findSession(sourceId)` 存在 | `来源仍在 · 线下 · <标题>` | **「那段线下时光已不在」** |
| `chat` | favorites 里仍能找到该快照 | `来源仍在 · 收藏 · <内容>` | **「原对话已删除」** |
| `photo` | `photos.all()` 仍含该 id | `来源仍在 · 照片` | **「原图已删除」** |
| `moments` | 本版按失效兜底 | — | **「原作品已不在门厅」** |
| `ticket` | `wjTickets` 仍含该 **ticket.id**（票根实体自身 id，见下） | `来源仍在 · 票根` | **「原票根已不在」** |
| 未知 | fail closed | — | **「来源已不在」** |

**ticket 引用口径（唯一，禁止混用）**：
- `weEntries.sourceId`（sourceType='ticket'）引用的是 `wjTickets` 里那张**票根实体自身**的 `id`（`'tk-'` 前缀）；`checkSource` 按 `t.id === sourceId` 查询。
- 票根上的 `workId` 字段指向 `wjWorks` 里的**作品**，是另一层引用 —— 若哪天要做「作品来源」，那是另一种 sourceType 的语义，**不许**拿来当票根实体的 id 查（查不到就 fail closed 显示「原票根已不在」）。
- 本版生产写入路径（`page-we.js` 的 `sourceCandidates`）只产出 calendar/offline 两类候选，不写 ticket 来源；上表口径是对未来写入路径的约束，已在 smoke 里双向断言（ticket.id → live；workId → 拒绝命中）。

- 门厅每张卡在来源角标处**实时调用 `checkSource`**，所以失效来源在门厅卡上就显示降级文案（不只是详情页）。
- 本轮**只复核 + 展示**，不做跨 App 回源跳转，不改聊天/日历/相册/帷境详情页，不加跳转参数。

## 十、修正轮记录（2026-09-27 第二轮：来源状态语义修正）

> 首轮整体通过，提交前修正一处来源状态语义 + 统一 ticket 引用口径。**未提交、未部署**，其余范围不动（不改 weEntries 结构 / favorites / 无跳转 / 无 char 提议等）。

### 修正 1：calendar 来源从「二态」改为「四态」
- 首轮实现把 `status === 'completed'` 也判成失效（「该约定已取消」），语义错误：**已完成的日历事件是有效历史来源**，收藏馆应保留。
- 修正后 `checkSource`（sourceType='calendar'）：
  1. 事件存在，status 为 scheduled/pending/tentative/confirmed → `live`「来源仍在 · 日历 · <标题>」
  2. 事件存在，status === 'completed' → **新 `done` 态**「来源已完成 · 日历 · <标题>」（详情渲染走 live 同款样式，**不显示**「原物已不在」）
  3. 事件存在，status === 'cancelled' → `gone`「该约定已取消」
  4. 事件不存在（真被删掉）→ `gone`「原日历记录已删除」（首轮把这条也显示成「已取消」，已区分）
- 改动位置：`page-collection.js` calendar 分支 + 详情页 `done` 渲染分支；门厅角标 `done` 落「来自 日历」（不标失效），无需改样式。

### 修正 2：ticket 引用口径统一为 ticket.id
- 首轮 `checkSource` 写成 `t.id === id || t.ticketId === id`，`ticketId` 字段根本不存在，且与勘察文档「sourceId=workId」的设想互相打架。
- **最终口径**：`weEntries.sourceId`（sourceType='ticket'）= `wjTickets` 里**票根实体自身**的 `id`（`'tk-'` 前缀）；`workId` 是指向 `wjWorks` 作品的引用，是另一层语义，本版没有「作品来源」类型，不许混用（按 workId 查 fail closed →「原票根已不在」）。
- 真实实现（`page-collection.js`）、文档（本文 §四）、测试（smoke 双向断言：ticket.id → live，workId → 拒绝命中）三处一致。
