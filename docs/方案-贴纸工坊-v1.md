# 方案 · 贴纸工坊 C2 v1（2026-10-02 勘察定稿前案）

> 用户口径：本质是生图；①锁脸三态（char / user / 双人）；②整版切开变多个表情包
> 存入 char 和 user 的表情包库；③归属——单人 char 和双人只属于这个 char 和 user，
> user 单人可选同步到哪些马甲；④套系可选内置（定稿词）或自定义每张的表情。
> 本单只做方案与源码对应，未动运行时代码。

## 一、勘察结论（现有地基，全部实读）

### 1. 表情包库是现成的 —— 「char 能不能发表情包」：**能，机制完整**

| 能力 | 位置 | 说明 |
|---|---|---|
| 数据表 | `page-stickers.js:6` | `stickers: [{id, name, url\|mediaId, group, global, sandboxId, at}]`；name = 解释（给模型匹配用） |
| 可见性 | `page-stickers.js:52 visible()` | `global \|\| sandboxId===本房`；**写纪律：回写必须用 all()**（S4a 坑：拿过滤列表回写会整批抹掉别房表情） |
| user 发 | `page-chat.js:4033 openStickerPanel()` → `type:'sticker'` 消息（:2014 stickerBubble 无气泡贴图） | 群聊同款 `page-group.js:1008-1071` |
| **char 发** | `page-chat.js:495 extractStickers()` | 模型回复写 `[表情:名字]` → 抽标签 → **按 name 匹配表情包** → 落成 assistant 表情消息；上下文注入 `[我发了一个表情：x]`（:662） |
| 推荐条 | `page-chat.js:1385` | 输入文字匹配表情解释名，横滑推荐 |
| 面板入口 | `page-chat.js:4076` / `page-group.js:1069` | foot 有「管理表情包 ›」→ `ctx.open('stickers')` |

> **关键联动**：贴纸的 `name` 就是情绪名（「好耶」「晚安」）——工坊产物入库后，
> char 的 `[表情:好耶]` 自动命中，不用改任何模型侧逻辑。

### 2. 生图基建（B 批遗产）全齐，但差一个口

- 咽喉 `imggen.generate({plan, imageLocks})`（`imggen.js:1858`）：
  - B2 意图解析 `imageRefIntentFor(plan, locks)`（:1721）：按 `plan.subjects` 求交集，
    键 = `refKeyFor` = `'user:'+maskId` / `'char:'+charId`（:1701）；
    本次显式覆盖 > 存档 `faceLockImageOn`（:1732）；
  - 图源：本地图 `faceLockImageMedia` 优先、URL `faceLockImage` 备用（:1735）；
    char / user 两侧字段都齐（`core.js:840-848` 马甲白名单、contact-edit 同套）；
  - 通道：`refChannelSupported(api)`（:1708）—— general 要 `refSupport:'edits'`
    → `requestGeneralEdits`（:1807，multipart 多张）；chat → `requestChat`（:2150）；
    **NAI 明确报错不支持**（:1878）；
  - 落库：`storeBlobResult` → `media.put(blob,{name,kind,w,h})` → `{ok, mediaId, blob}`（:1973）。
- **缺口**：`generateBuilt`（裸词直发，:1962）**不接参考图**；`generate({plan})` 会把词
  交给 `buildFormalPrompt` 分层重组——而贴纸定稿词是**完整词**（实施单 2.1/2.2 三版 +
  负面词，逐字用），不能被分层。
  → **方案：imggen.js 内新增正式导出 `generateStickerSheet(opts)`**，复用内部链
  `imageRefIntentFor → resolveRefData → requestGeneralEdits / requestChat → storeBlobResult`，
  词原样直发；报错口径全按 B2（点名主体、零请求、不静默降级）；NAI 同 B2 明确报错。

### 3. 藏品实贴：槽位与写口都埋好了

- 拍立得 38px 虚线贴纸槽（`page-collection.js` co-pl-slot，占位 toast）；
- `weStore.patch` 白名单已含 `stickers`（page-we.js C1 批）——实贴持久化走它；
- 票根/拍立得详情页现成，抽屉往上一挂即可。

### 4. 没有的：切片器

## 二、数据模型（stickers 向后兼容扩展）

```js
// 现有字段全保留；新增全可选字段（老表情无这些键 → 行为不变）：
{
  id, name,            // name = 情绪名（「好耶」）—— char [表情:名字] 的匹配键
  mediaId,             // 切片 PNG（media.put kind:'sticker'）
  group,               // 默认「贴纸工坊 · <char名 | 我们>」
  sandboxId, global, at,
  /* —— C2 新增 —— */
  kind: 'sticker',           // 区别手写导入
  sheetId: 'shs-…',          // 所属整版（重切/整版删除的把手）
  emotion: 'cheek_pinch',    // 情绪键（自定义时为 'custom'）
  ownerCharId: '…'| null,    // 单人 char / 双人时 = 该 char
  ownerUserId: '…'| null,    // 双人时 = 该 user（单 user 归属见下行）
  ownerMaskIds: ['…'],       // 单人 user：同步给了哪些马甲（多选）
}
```

**可见性过滤点唯一**：`page-stickers.js visible()`（加三条 owner 规则，老条目无字段照旧
全岛可见）——聊天面板、群聊面板都消费 `visible()` 自动继承；char `[表情:名字]` 的
匹配池同用 visible()（发送时过滤，待 C2b 核对匹配调用点取的是哪个池）。

规则：
- **单人 char**：`ownerCharId` 命中当前会话 char 才可见（别的 char 的聊天里不出现）；
- **双人**：`ownerCharId + ownerUserId` 双命中（= 他们俩的私聊）；
- **单人 user**：当前 `activeUserId ∈ ownerMaskIds` 才可见；
- 群聊：默认只显示「user 单人且本人群里身份命中」的（双人/char 单人不进群——群里
  的对方不是那个 char）。⚠️ 待用户拍板，见 §五。

## 三、工坊页（'sticker-workshop' 替换占位）

五步流：
1. **锁脸三态**：`target = 'char' | 'user' | 'both'`；显示双方参考图设置状态
   （`faceLockImageMedia/faceLockImage` 有无），缺图给跳转引导（contact-edit / mask-edit）；
   subjects 组装：char→`[{entityType:'char', entityId}]`，user→`[{entityType:'user', entityId}]`，
   both→两枚（复用 `subjectForChar/subjectForUser`，imggen.js:2271-2272）。
2. **套系**：
   - 内置：both / single_male / single_female 三版定稿词（实施单 2.1 + 修订 2.1 节逐字
     落为 imggen.js 常量，含统一负面词）+ 性别分版规则（char 性别缺失 → 界面让选，
     不猜——实施单「注入要求补充」）；
   - 自定义：6 格情绪槽，每格 = 预设情绪库点选（内置 6 情绪起步）或自由文本
     （一句英文动作描述），拼进模板的 `Sticker N` 段；格子约束词
     （die-cut / 白底 / 无道具）保持模板级不动。
3. **生成**：`Sleepy.imggen.generateStickerSheet({ target, subjects, lines, api, size:'1024x1024' })`
   → `{ok, mediaId, blob}`；进度/报错口径与生图弹层一致（参考图拉取与生成两次请求分别呈现）。
4. **切片预览**：canvas 处理（纯函数化，三条都可单测）：
   - 白底转 alpha：**从四角 flood-fill** 近白像素 → 透底（内部白边不受影响——
     不能全局「近白→透明」，那会把 die-cut 白边一起抠掉）；
   - 连通域标记 → 按面积取前 6 → bbox 外扩 → 逐片 `canvas.toBlob('image/png')`
     → `media.put({kind:'sticker'})`；
   - 手动微调：某片没切准可「重切」（阈值滑杆）/ 单片删除（少于 1 张不许入库）。
5. **归属 + 入库**：命名（默认用情绪名）、group；user 单人勾马甲多选
   （数据源 `core` 本岛 masksOfSandbox）；写 `stickers` 走 all()+save 纪律；
   整版图本身也存 media（kind:'sticker-sheet'）挂在 sheetId 便于重切/整删。

消费口①（表情包库）：入库即生效——聊天面板、群聊面板、char `[表情:名字]` 全自动。
消费口②（藏品实贴）：票根/拍立得槽位点击 → 贴纸抽屉（数据源 = 本岛 + owner 匹配的
工坊贴纸）→ 选中以随机 -6°~+8° 微旋贴在槽位 → `weStore.patch(entry.id, {stickers:[…]})`
持久化（渲染 objectURL 现挂现用）。
聊天侧入口：表情面板 foot「管理表情包 ›」旁加「去贴纸工坊 ›」（page-chat.js:4076、
page-group.js:1071）；收藏馆门厅入口已有。
