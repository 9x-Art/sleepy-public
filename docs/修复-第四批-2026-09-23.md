## ① 「点一个气泡页面就下滑」——真凶是**进多选那一下**，不是点气泡

**量法**（`D:/tmp/probe-select-jump5.js`，停在会话中间，逐步量 + 逐步截图）：

| 步骤 | wrap.top | 参照气泡的屏幕 top | scrollTop |
|---|---|---|---|
| 进页面停中间 | 100 | 109 | 785 |
| 长按（菜单弹出） | 100 | 109 | 785 |
| **点「多选」** | **147** | **156** | 785 |
| 点一个气泡 | 147 | 156 | 785 |

→ 菜单和点气泡都**不动**；**多选条一露面，整段对话往下滑 47px**（正好是条子的高度）。

**根因**：`page-chat.js` 里 `selBar` 是 `body.appendChild(selBar)`，而且是在
`.msg-wrap` **之前** append 的 —— 它在**流里**（不是浮层），露面就把消息区顶下去；
`.msg-wrap` 的顶边跟着移，里面的气泡（内容坐标没变）就整体跟着下移。

**改法**：`renderSelection()` 在**露面前后**各按高度差补一次滚动：

```js
var h0 = msgWrap.clientHeight;
… 切换 selBar 的 display …
if (msgWrap.clientHeight !== h0) msgWrap.scrollTop += (h0 - msgWrap.clientHeight);
```

两处缺一不可：露面那处在函数末尾（所有改高度的事之后），收起那处在 `selecting === false`
的早退分支里。补完的语义：**眼前的内容一动不动**；贴底时会被浏览器夹回新的最大值，
也就是「仍然贴着底」（贴底行为不变）。

**验**：`probe-select-jump4.js` 四种组合 14/14（无键盘/键盘开着 × 停在中间/最底/离底 30px，
每例都断言「点气泡后 |Δ| ≤ 6px」且「选中数真的变了」）；
`probe-select-jump5.js` 复量：气泡 screen top 进多选前后一致。

**护栏**（smoke 静态断言）：补高差的两句必须都在 —— 少一句＝退出多选时又跳一次 47px。

## ② 「算向量失败（返回里没有向量）」——L4 从 v99 起**一条块都没落过库**

**根因一行**：`memory-vec.js` 的 `embedTexts` 读 `r.vectors || r.embeddings`，
而 `api.js` 的 `embed()` 契约字段是 **`vecs`**（v96 起）：

```js
/* api.js */
resolve({ ok: true, ms: ms, vecs: vecs, dim: vecs[0].length … })
```

两个名字都不存在 → **每一次**写入都停在 `返回里没有向量`；而这个失败被
`page-chat.js` 的 `kickSweep` 静默 catch 掉 → 用户只看到「还没有索引」，
不知道该怪接口还是怪 App。写入（sweep 三源 + 素材四源 + `reindexItem`）与
召回（`prefetch`）**走的是同一个 `embedTexts`**，所以整个 L4 是哑的 ——
前一晚「聊了很多轮一条向量都没有」的真根因就是它（那一轮只修了「看不见原因」）。

**改法**：字段名跟着产出方走，`var vecs = r.vecs;`（不再做多名字回落 ——
回落链本身就是「同一个契约两份定义」，正是这次翻车的形态）。
另外把 `embedTexts` 加进 `Sleepy.memoryVec` 导出，**只为冒烟当测试缝**。

**验**（`D:/tmp/probe-vec-sweep.js`，真浏览器 + 真 IndexedDB，embedding 端点用假 fetch 顶掉）：

- `embedTexts(['…'])` → `ok`、1 段 × 8 维
- `sweepIsland()` → `{ ok: true, chats: 1, added: 1, failed: [] }`
- `stats(charId)` → `chat: 1`（块真躺在库里）
- `prefetch(charId, userId, '关东煮')` + `text(...)` → 338 字（召回也通）
- 7 ✓ / 0 ✗

**反向验证**：把字段名改回 `r.vectors` → 冒烟 **W17 立刻红**，报的正是用户那句
「返回里没有向量」。W17 是**真走一遍** `api.embed`（假 fetch 回 OpenAI 形状），
不是查字符串，所以以后哪一边改名字都会当场红。

『现在扫一遍』」（smoke 有静态护栏）。

## 探针踩的坑（下次省时间）

1. **Playwright 的 `.click()` 会自动把元素滚进视野** —— 用它量「点一下会不会跳」，
   量到的位移全是驱动自己滚的假象（第一轮报了个 443px）。要 `page.mouse.click(真实坐标)`。
2. **点头像 ≠ 点气泡**：头像有独立 click（看没说出口的话）+ `stopPropagation`，
   点在头像上永远不切选中。探针必须落在 `.msg-text` 上，并**断言「选中数变了」**，
   否则整份用例是空结果（第一版 4 个用例全废在这儿）。
3. `locator(...).nth(n)` 可能是**屏外元素**（boundingBox 为负）→ 只挑视野内的气泡来点。
4. 「页面下滑」这类投诉**光量 `scrollTop` 量不出来**（内容被推走时 scrollTop 不变）→
   要量气泡的 `getBoundingClientRect().top`，再配逐步截图。
