## 三、核心链路实机验证（重点）

### 1. 聊天全链路 ✅
建岛（默认孤岛存档）→ 建角色林晚（人设写了便利店夜班白月光）→ 开对话 → 发消息 → TA 回复：「有，刚补的汤，萝卜正好煮透了。」——人设埋的关东煮细节都用上了，装配（v238 新管线）正常。

### 2. 向量记忆 · 索引写入 ✅
- 条件判定：`enabled()` 只看两件事——① 没显式关；② 向量 API 已配（baseUrl+model）。两者皆满足，林晚 `byChar` 空=走默认开。
- 阈值注意：`MIN_MSGS=8`（或 600 字）才切块建索引——**对话少于 8 条时 IDB 为空是设计行为，不是 bug**。
- 凑到 8 条消息后 sweep 自动写入 `sleepy-vec`（DB V6）：1 个聊天块，owner=林晚 root，**1024 维**向量，内容含前几轮对话。

### 3. 跨对话召回 ✅
新建林晚对话（无旧上下文），问只存在于向量块、人设里没有的信息：「我叫什么名字？最常点什么？」→ TA 准确答出「沈叙」「萝卜」。新对话没有旧消息上下文，**只能来自向量召回**（compileRecall 进 K03c）。记忆链路（写入+召回）全通。

### 4. 记忆整理 ✅
聊天设置 →「整理聊天记忆」（summaryEngine，回落主 API）→ `sleepy.v1.memories` 落地 **10 条**林晚留痕记忆；留痕页林晚从「还没有记忆」变为「完整记忆 · 最近更新今天」。
- 注：memory 设计上「总结产出的记忆不即时进向量库」，故向量库只有 1 个聊天块、留痕有 10 条——两路并存，符合设计。

### 5. 慢递 ✅
聊天里引导 TA 写慢递信 → TA 自然生成结构化条目落 `sleepy.v1.slowLetters`：`{hours:2, deliverAt(2小时后), opened:false, body:"…你路上慢点…"}`，聊天内出现慢递提示。定时投递链路通。

### 6. 主动消息 ✅（UI 配置完整）
聊天设置页含：主动消息开关「允许他在合适的时候来找你」+ 主动消息安排（免打扰 23:00~08:00 · 每天≤2 次 · 冷却 120 分 · 暂缓 90 分）+ 朋友权限（朋友圈互相都开着 · 日记看不到）。

### 7. 朋友圈 / 日记 / 日历 ✅（UI 渲染正常）
- 朋友圈（chat-app 底部 tab）：空态「这间房里还没有人发过动态」，无报错。
- 日记（聊天详情顶栏「日记」入口）：空态「这一页还空着 · 点右下角的笔」，无报错。
- 日历（林晚的日历）：10 月网格 + 公共日期 + 角色日程 + 留痕纪念日，无报错。

## 五、问题清单（分级）

### P3 · 小问题（建议修，不阻断）
1. **向量记忆 API 配置页**：「恢复默认」那组的副标题，配置好后仍显示「还没配——向量记忆需要它才能开」，看起误导（文案未随配置刷新）。
2. **长按消息菜单 `.msg-menu` 是贴底 action sheet**（微信式 `bottom:0`+顶部圆角），与你 2026-10-11 定的「所有 sheet 一律页面居中不贴底」口径不一致——之前已和你确认待定，这里再记一笔。
3. **预设页**：除「线上普通回复」外，线下/总结/主动消息/群聊都显示「已上锁」。与聊天设置里能正常开关的「主动消息」并存，需确认是设计（预设注入序列未解锁）还是漏接。

### P2 · 观察（非 bug，建议优化）
4. **总结 API 未配** → 记忆整理 / 向量记忆的「记忆整理用的模型」回落主 API（已验证工作，但主 API 比专用总结 API 贵）。建议配一个便宜的总结 API 省钱。
5. **向量记忆 `MIN_MSGS=8` 阈值**：对话 < 8 条 / 600 字不切块，新对话前几轮无向量记忆属正常预期，但用户初次体验容易误判「记忆坏了」。可在 UI 上加一句「攒够若干轮后自动建索引」。

### P0 / P1
**无阻断性 bug。** 所有核心链路（聊天 / 向量记忆 / 召回 / 记忆整理 / 慢递）实机工作正常，全功能 UI 渲染零报错。
