## A. 月历打开、翻月、返回

1. 桌面点「日历」→ 月历出来。
2. 点「‹ ›」翻月，再翻回来。
3. 点某一天看当天列表 → 点左上返回 → 回月历。

**算过**：来回翻不白屏、日期不变形、没有报错；**顶栏右侧是「设置」和一个加号，右下角没有悬浮按钮**。

---

## B. 新建私人提醒（**最关键：连着建两条**）

1. 月历顶栏点**加号** → 选「我的提醒」→ 填标题（`测试A`）、选日期、时间**留空 = 全天**。
2. 点「记下来」→ toast「记下了，只在你这边」→ 自动回月历，那天多一条。
3. **再来一次**：加号 → 标题填 `测试B` → **同一天** → 「记下来」。

**算过**：
- 两条都在；
- **第二次打开时表单是空的**（只保留日期，标题和时间都清空）—— 不用自己清一遍。

---

## C. 跨日冲突文案

> ⚠️ 如果 A、B 是**全天**（时间留空），它们占满整天，下面两条都会跟 A、B、C 一起撞
> （框里会列好几条）。**这是对的**。想只测 C，把 A、B 改成具体时间。

1. 建 `测试C`，日期选今天，时间 `23:00`—`01:00`（结束在第二天）。
2. 建 `测试D`，**同一天**，`00:30`—`01:30`。
3. 建 `测试E`，**同一天**，`23:30`—`23:50`。

**算过**：第 2、3 步都弹「这个时间和别的安排撞了」，且**撞上的那条里有「测试C」**。
> 修之前这两种都**不报**。框里点「还是记下」→ 照样能建；点「取消」→ 不建。

## D. 新建共同事件 + 角色表态入口

1. 加号 → 选「邀请他」→ 标题 `测试F`、`19:00`—`20:00` → 「记下来」。
2. toast 是「发出去了，等他表态 —— 还没到「已确认」」。
3. 点开 `测试F` → 看「他的回应」。

**算过**：
- 显示「你：答应了 / 他：还没表态」；
- 下面有「记下：他答应了」「记下：他推掉了」；
- 有一行小字写着「这里记的是「你记下的他的回应」——不是他自己说的」；
- 顶部状态是「待确认」。

4. 点「记下：他答应了」→ 状态变「已确定」，toast「双方都答应了，这条算定下」。
   （`已确定` 以前永远到不了 —— 角色那一格从来没人写过。）

5. **退出去，再点进 `测试F`**（首轮就是这里没刷新）。

**算过**：显示「你：答应了 / 他：推掉了」（或「已确定」），**不再是「待确认 / 还没表态」**。

6. 再点「记下：他推掉了」→ 状态变「已取消」，**记录还在**（取消 ≠ 删除）。

## 已知会看到的「不像 bug」的现象

| 现象 | 为什么 |
|---|---|
| **全天事件会让当天所有定时事件都撞** | 全天 = 占满整天，这是对的。想避开就别留空时间 |
| 撞车框一次列出好几条 | 它列的是**全部**撞上的，不只最近那条 |
| 共同事件在你手动记之前一直是「待确认」 | **故意的** —— 角色自动表态的来源本轮不存在，不伪造 |
| 加号只有 32×32，比旁边「设置」小一点 | 顶栏图标按钮全项目都是这个尺寸（记忆页的「新增记忆」也一样）。要放大得整站一起改 |
| 详情页「谁能看到」写「只有你看得到」，但他其实排了日程 | 那是他的日程；`ownerCharId` 不等于「谁定的」，看 `createdBy` |
| 撞车框偶尔那条看起来「算得保守」 | 遇到解析不出的旧时间，程序不静默说「没冲突」，会多问一句 |
