# 交接 2026-10-24：校园网封锁 workers.dev 的诊断与 A+B 对策

## 一、诊断结论（当日实测取证）

**现象**：内测一键进门（摇号）在校园 wifi 下必失败，挂 VPN 才通。

**证据链**：
| 探测 | 结果 | 判定 |
|---|---|---|
| `curl sleepy-repo.sleepy-goodluck.workers.dev` | `connect=0.000s`，8–15s 全超时，HTTP 000 | TCP 从未握手 |
| `nslookup` 该域名 | 返回 `2a03:2880:f112:83:face:b00c:0:25de` / `69.171.247.71` | **Facebook IP 段**（face:b00c 是标志性段），DNS 投毒 |
| 同网 `nslookup cloudflare.com` | 正常（2606:4700 / 104.16.x） | 没墙整个 CF |
| IPv6 强制解析 | could not resolve | 投毒只给了假 IPv4/IPv6 |

**结论**：校园网/iOA 零信任对 `*.workers.dev` **按域名清单定向封锁**（DNS 投毒 + TCP 静默丢包），
与「GitHub HTTPS 被掐、SSH 才通」同一类手法。VPN 能通是因为隧道内 DNS 与流量都不经本地网关。
**不是 sleepy 代码缺陷，不分设备**——任何连该网络的终端（含用户真机）都中招；手机流量大概率可直连。

## 二、A+B 对策（v258，已落地，未提交未部署）

### A：多 base 故障转移（repo-core.js）
- `DEFAULT_BASE`（单值）→ `DEFAULT_BASES`（数组，按序故障转移）
  - **主位待填自定义域名**（封锁名单外，校园网可直连）—— 见下方「域名接入三步」
  - workers.dev 降级兜底（VPN 用户 / 自定义域名临时故障）
- `repoBases()`：base 候选唯一出处，**去重**（域名未填时两 base 相同，退化单发不傻等两遍）；
  `repoCfg.base` 覆盖通道升级为**逗号分隔多入口**（作者/自建反代可配多入口，页面不暴露）
- `base()` 改为取主候选（仓库公开功能也自动走新域名）
- `licRequest` 重写：非最后 base **5s 短超时**（`AbortController` 真取消，老浏览器 race 兜底）
  主动切下一个；全失败报统一文案
- 安全性：短超时中止的请求未达服务端，不会重复写库；万一「服务端已处理但响应丢包」，
  `users.qq` 唯一索引兜底不会造双账号（最差 = 用户看到一个 409 重摇提示）

### B：可读失败文案（repo-core.js）
- `LICENSE_NET_HINT`：`连不上授权服务器：当前网络可能屏蔽了 Cloudflare 域名（校园网常见），挂 VPN 或换网络再试`
- 不再把浏览器原始错误（Failed to fetch / Aborted）怼给用户
- 冒烟反向断言：「连不上仓库服务」老文案一个字不许复活

## 三、域名接入三步（用户提供域名后执行）

1. **CF 后台**：Workers → sleepy-repo → 设置 → 触发器/域与路由 → 添加 Custom Domain
   （填用户给的域名，CF 自动签证书，免费）。worker 的 CORS 是 `Access-Control-Allow-Origin: *`，
   **无需改 worker 代码**。
2. **前端改一个字面值**：`repo-core.js` 的 `DEFAULT_BASES` 主位（约第 66 行）：
   ```js
   var DEFAULT_BASES = [
     'https://<用户域名>',        // 主位：自定义域名
     'https://sleepy-repo.sleepy-goodluck.workers.dev'  // 兜底不动
   ];
   ```
3. **部署纪律**（改动只涉及 repo-core.js 一个字面值，但仍是运行时脚本）：
   CACHE 无需再跳（v258 已含此结构，改字面值不改变缓存内容哈希以外的行为 —— 不，
   **要跳**：改了 repo-core.js 内容就必须 CACHE +1 + sw.js 头留说明 + smoke 的
   EXPECTED_SW_CACHE 同步。别省这一步）。
   然后 `node scripts/deploy.sh`（推 master 走 SSH），线上核对带 `?cb=<ts>`。

**新发现（分级量化，当晚补测）**：校园网对两个 CF 域名的封锁**程度不同**——
- `sleepy-repo.sleepy-goodluck.workers.dev`：**0/8 稳定死**（DNS 投毒返回假 IP + TCP 丢包）
- `sleepy-u17.pages.dev`（主站）：**7/8 基本通**，DNS 干净（5/5 真 IP 无投毒），

  电脑多刷两次大概率能开；**pages.dev 基本可用，Pages 换域名是锦上添花不是必须**。
  但 **workers.dev 稳定死，A 方案（worker 换自定义域名）依然是摇号的唯一出路**。
  域名就位时 Pages 项目（`sleepy`）可顺手绑同一个自定义域（CF 后台 Pages → Custom
  domains，免费），图个省心。
