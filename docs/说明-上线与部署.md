# 上线与部署（sleepy）

**一句话**：`bash scripts/deploy.sh` → 生产 `sleepy-u17.pages.dev`。仓库 `git@github.com:9x-Art/sleepy.git`，**推 master**。

---

## 为什么要有脚本（而不是手敲 wrangler）

两件事只有脚本里才做得对：

1. **上线包要剪**。`wrangler pages deploy <目录>` 把目录里**所有**文件原样上传 ——
   `docs/`（45 个设计文档：施工卡、方案、真机验收、bug 核查…）、`_retired/`（归档）、
   `preview/`（字体/开屏预览稿）、`scripts/`（check.js / smoke.js / deploy.sh 自己）、
   `README.md` / `ROADMAP.md` / `serve.js` / `package.json` 全部会变成
   `https://sleepy-u17.pages.dev/docs/…` 这样**公开可访问的 URL**（用户 2026-09-23 问起这件事）。
   脚本用 `tar -x --exclude` 在**提取时就不解出来**，副本从 148 个文件降到 80 个。
2. **提交哈希要带上**。部署副本不是 git 仓库，不带 `--commit-hash` 时 Pages 记录里的
   Source 列是空的，事后追不回「线上到底是哪一版」。

## 用法

```bash
bash scripts/deploy.sh
```

- 脚本先检查工作区是否干净：**`git archive` 只打已提交内容**，有未提交改动会直接拦下（不赌）。
- 提取后先**自查**：`index.html / sw.js / manifest.json / style.css / art/*.webp /
  icons/*.png / vendor/three.module.js` 必须在，`docs/ _retired/ preview/ scripts/ README.md serve.js`
  必须不在 —— 有一条不对就停，不部署。
- 最后 `wrangler pages deploy`，输出预览 URL；`sleepy-u17.pages.dev` 是生产别名。
- 部署前确认 wrangler 登录着：`wrangler whoami`（登录态约一小时过期；**网页登录 Cloudflare ≠
  wrangler CLI 登录**，2026-09-23 在这里卡过半小时）。

## 三个坑（都踩过，别再踩）

1. **`.assetsignore` 对 `pages deploy` 不生效**。那是 Workers 静态资源（`wrangler deploy` + assets）
   的机制。实测：仓库根放一份 `.assetsignore`，跟着 `git archive` 进副本，部署后
   `/docs/DRAFT.md` **照样能读到原文**（用内容比对的，不是看状态码）。所以仓库里没有这个文件 ——
   别再加，加了只会让人以为挡住了。
2. **`rm -rf` 在这台机器上会被安全删除层拦住**（`safe-delete FAIL_CLOSED`，日志里路径会串成
   `D:\projects\sleepy\C:\Users\…\Temp\…`）。所以脚本**不做删除动作**，靠 tar 的 `--exclude`；
   副本目录名带 `$RANDOM`，每跑一次都是新的，不需要清。
3. **线上核对不能只看 HTTP 状态码**。Pages 对找不到的路径会**兜底吐 `index.html`（状态 200）** ——
   于是「文档已经下线」和「文档还在」看起来都是 200。正确做法：取回正文**比内容**
   （例如 `curl … /docs/DRAFT.md | grep -c '<!DOCTYPE html>'`，命中 = 拿到的是 App 外壳 = 已下线）。

## 核对线上是「这一版」

```bash
TS=$(date +%s)
curl -s "https://sleepy-u17.pages.dev/page-chat.js?cb=$TS" -o /tmp/live.js
git show HEAD:page-chat.js > /tmp/head.js
diff --strip-trailing-cr -q /tmp/live.js /tmp/head.js && echo 一致
```

- **必须带 `?cb=`**：边缘会缓存 `index.html`，否则页面正常、新脚本却不存在。
- **必须 `--strip-trailing-cr`**：`git archive` 出来的文件是 CRLF，线上文件比仓库版大的那部分
  正好是行数；不忽略行尾会「明明一样也报不一致」。
- `/index.html?cb=…` 会 **308**（Pages 把 `/index.html` 重定向到 `/`）→ 首页用 `-L` 或直接打 `/`。

## PWA 缓存：老设备什么时候看到新版

`sw.js` 是 **cache-first + stale-while-revalidate**。只要 `sw.js` **自己的字节没变**
（`CACHE` 仍然 `sleepy-v117`），浏览器不会重装 SW、也不清缓存 → **第一次打开还是旧脚本，
第二次打开才换新**（装了 PWA 的手机同理，强刷也行）。只有改了 SW 自身时才需要跳 `CACHE` 版本。

## 文档类改动不用重新部署

`docs/` 本来就不上线 —— 只改文档的提交**不必**再部署一次（线上运行时不变）。
