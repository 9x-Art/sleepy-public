# 发售与授权路线 v1（2026-10-07）

> 背景：sleepy 做了很久、已出成效，一周后进入**对外内测**。本文把「代码防抄 / 账号账密 / App 规划 / 定价 / 渠道」五条线一次定死，供后续施工卡引用。
>
> **本文是决策文档，不是施工卡。** 每条只写「定什么、为什么、代价是什么」，具体实现拆成单独的施工卡。

## 现状底盘（勘察结论，改动成本高，先认清再谈别的）

| 事实 | 数值 / 状态 | 出处 |
|---|---|---|
| 运行时规模 | 94 个顶层 JS、86,150 行、4.7 MB（含 style.css 630 KB） | `ls *.js` / `wc -l` |
| 数据存储 | 全在 localStorage；**图片在 IndexedDB**（`media.js`，因 localStorage 仅 5 MB） | `store.js` / `media.js` |
| 账号体系 | **完全没有** —— grep `register` 全是 `Sleepy.register` 页面注册 | 全库 grep |
| API 模式 | 用户自带 Key（BYO），存在本地 `mainApi.apiKey` | `store.js:108` |
| 部署 | Cloudflare Pages，`wrangler pages deploy`，runtime 剪枝版 | `scripts/deploy.sh` |
| PWA | 已有 `manifest.json` + `sw.js`（CACHE v203） | 仓库根 |
| 导出导入 | **已完整**：`store.exportAll` / `importAll` / `importRollback` 兜底 | `store.js:538/599`、`page-backup.js` |
| 付费痕迹 | 无（`ADMIT ONE · VIP` 是集卡页文案，不是付费系统） | grep |

**这个底盘的真正含义**：「零依赖 + 本地存储 + 用户自带 Key」不是技术选型，它已经决定了商业形态——**你不需要为模型调用付费，所以订阅制在你这里价值不成立，只能是买断。**

## 一、商业形态与定价

### 结论

| 阶段 | 价格 | 理由 |
|---|---|---|
| 内测 | **¥0** | 换的是留存数据，不是钱。承诺「正式版免费获得」以拉高反馈质量 |
| 首发 | **¥12.9 一次性买断** | 对标硬锚点，见下|
| 早鸟 | **¥8.9** | 制造「现在买最划算」，同时验证交付链路 |
| 上架商店后 | **¥19.9** | 商店本身是信任背书，可溢价 |

### 对标（已核实，2026-10-07）

| 产品 | 价格 | 售后 | 备注 |
|---|---|---|---|
| 佳景小手机 | 免费 | 无 | 安卓分发，自带 API 接入 |
| **KOKO小手机** | **约 ¥12** | **有** | **直接对手；用户实测口径** |
| shine 小手机 | 付费 | 有但风评差 | 投诉点集中在「迁移失败 / 超大内容卡」 |
| TA语ai 小手机 | 数块至二十 | — | 本地存数据，和我们同构 |

行业玩家入坑指南原文：付费小手机「**价格大多在几块到二十块之间**」。

### 为什么是 12.9 而不是 19.9

- 唯一同价位（12 元）的 KOKO **有售后**，而它功能不如我们全（无沙盒/ 马甲 / 群声 / 世界书）。
- 定得比它高太多，比价时我们失去优势；**12.9 是「功能更全 + 同价 + 隐私更硬」的正面平价**。
- **要守的不是价格，是售后。** KOKO 12 元能活因为它有售后；shine 付费却风评差，栽在同一个地方。我们多做的事= 内测期把反馈通道做起来。

### 已排除的路线（附理由，避免以后重提）

- ❌ **订阅制** —— 用户自己付 token 费，我们凭什么再收月费？价值不成立。
- ❌ **68–88 元** —— 曾按海外订阅产品（Character.AI $9.99/月、Replika 终身 $299.99）换算，**基数不适用**：那是「代付模型额度」的物种，与我们不同构。
- ❌ **内容包作为主收入** —— 边际成本低但不成主线，**留作后续增值**。

## 二、代码防抄：结论是「基本不做」

### 事实

原生 JS、无混淆无打包，部署到 CF Pages 后任何人 F12 可取全量源码。**APK/IPA 只会更糟** —— JADX/Ghidra 可直接还原，等于主动把代码打包好递给别人。

### 结论

| 动作 | 决定 | 理由 |
|---|---|---|
| 混淆发布版 | ⏸ **稍后做** | 唯一便宜有效项（terser/esbuild minify + 变量改名），1–2 小时可脚本化 |
| 核心逻辑挪后端 | ❌ **不做** | 会破坏本地优先这个核心卖点 |
| 保护源码本身 | ❌ 不可能 | 静态站必须全量下发才能跑 |

### 理由（重要，别以后又纠结）

代码本身**没有防御价值**。8.6 万行里真正值钱的是那些规则沉淀（岛屿隔离、马甲归属、群声身份边界、ta-life 三表消费口径）——抄得走，但抄的人得重踩一遍我们踩过的坑（见 `MEMORY.md` 长期约定，那些坑本身就是护城河）。

**真正要防的伤害是「抄了发到社区引流」→ 伤的是口碑，不是代码。** 应对手段是协议 + 声明，不是混淆。

**保留项**：`scripts/deploy.sh` 的 runtime 剪枝（已排除 docs/ scripts/ _retired/ preview/）必须继续保持——它现在就在做正确的事。

## 三、账号与设备：自建账号层

### 结论

**账号是必需的**（买断凭证 + 设备管控），**但不做传统邮箱/手机注册**。

```
激活码兑换（一码一人，首次注册）
    → 设账密
    → 设备管理（上限 3 台，可踢 + 自助解绑）
```

### 硬性要求

| 项 | 要求 | 理由 |
|---|---|---|
| 密码存储 | 后端**只存哈希**（argon2 / bcrypt），绝不存明文 |硬要求 |
| 登录失败限制 | 次数限制 + 锁定 | 防撞库 |
| 个人信息 | **不收集任何**（无需邮箱/手机） | 合规极轻，且与「数据是用户的」定位一致 |
| 同设备判定 | 浏览器指纹 + 本地安装 id，**重复登录不新增名额** | 否则用户换浏览器就被顶掉 |
| 被踢体验 | 清晰提示 + **自助解绑入口** | 「我明明是自己却登不进」是同类 App 最常见的 1 星评论来源 |
| 离线宽限期 | 7 天 | 断网不能让人打不开 |
| 设备上限 | **3 台** | 用户明确要求 |

### 上限设置的经验判断

设备限制本质是**限制**而非授权。用户换手机、系统重装、清缓存都算新设备 —— 限制过死必然产生误封投诉。3 台 + 同设备不重复计 + 自助解绑，是「能管住」和「不惹人烦」之间的平衡点。

## 四、存储层：三选一，**与账号解耦**

### 结论

```
账号层（必需）：一人一码 + 账密 + 设备管理
    ↓
存储层（可选，三选一）：
  ① GitHub 私有仓   — 给愿意折腾的人，数据落用户自己名下
  ② 官方云存档      — 省事，但要托管数据（以后再说）
  ③ 什么都不配      — 走已有的导出/导入（兜底必须永远能走）
```

### 为什么这样拆（关键设计）

**GitHub 不是登录方式，只是一个「免费的云盘实现」。**

- 没有 GitHub 的用户（大多数人）→ 走导出/导入，**功能一样不缺**
- 有 GitHub 的用户 → 多一份自动备份，且**数据落在他自己名下，服务器看不到**
- 这顺手成了卖点：**隐私上比全托管的同类更硬**

### 实现纪律（后续施工必须遵守）

> **账号和存档必须解耦。** 换存储后端时（GitHub → 官方云），用户的账号、授权、设备列表**全部不受影响**。
>
> **绝不让存储实现渗进账号逻辑。** 也不要把「有没有配存储」变成「能不能登录」的前置条件。

### 云备份的真实能力边界（必须诚实告知用户）

| 想做的 | 网页端现实 |
|---|---|
| 关掉浏览器也自动备份 | ❌ 做不到（JS 不跑即无触发） |
| 后台定时同步 | ⚠️ 仅 Chrome 桌面支持，**iOS Safari 没有** |
| 完全不用管 | ⚠️ 做不到，必须有「打开时」兜底 |

**可行的三层**（合计覆盖约 90% 场景）：

1. **打开 App 时拉一次云端存档**（有更新则提示「发现云端新存档」）
2. **改动后延迟 30 秒静默上传**（合并高频写入，不打扰）
3. **超过 N 天没备份才提醒**（用户诉求里的「多少天提醒一下」，这个最实在）

**真「后台自动备份」只有一条路**：上架原生 App + 后台任务。这是 APK/IPA 的隐藏收益之一，**记进 App 规划的理由里**。

### 第一版云同步的范围限制（重要）

**只同步文字数据。** 图片在 IndexedDB，需额外导出成 Blob 再编码上传，体积和耗时会卡住第一版。**明确告知用户：图片不参与云同步。**

### 为什么不做细粒度双向合并

数据不是扁平表，是一棵作用域树（sandboxes → 房 → 马甲 / 世界书 / 群声 → 消息）：

- 4.7 MB 全量运行时，消息/ 记忆 / 照片占绝大多数，**不适合每次变更都传**
- **「删除」语义无法用 merge 表达**：A 删了的条目 B 还在，该听谁的
- 正确做法是「整包快照 + 时间戳 + 冲突时让用户选」—— **这就是方案 ②，成本小（1–2 周）且不伤架构**

## 五、部署平台：继续 CF，不换

| 平台 | 决定 |
|---|---|
| **Cloudflare Pages** | ✅ 继续（静态托管里最省心的一档） |
| **Cloudflare Workers** | ✅ 需要后端（账号/授权/存档）时**同一家加**，跨供应商成本为零 |
| Vercel | ❌ 比 CF 多一层，无理由换 |
| GitHub Pages | ❌ 国内访问慢 |

**账号/授权后端就放 Workers**，和 Pages 同一家，免费额度足够早期使用。

## 六、渠道：Q群 + 收款码为主

### ⚠️ 硬红线：闲鱼不能卖激活码

已核实闲鱼规则（2026）：

> 「充值平台软件/加款卡」「预售性质的商品**禁止在闲鱼平台出售**」
> 数字商品违规 → **永久封禁，不许申诉**（申诉结果通常为「无法撤销封禁」）
> 「破解软件、**激活码**」在闲鱼是明确列出的**禁售品类**

有真实卖家因此被封，丢失全部交易记录与评价。

### 渠道决定

| 渠道 | 风险 | 决定 |
|---|---|---|
| **Q 群 / 朋友圈 + 收款码** | 低，熟人交易，平台不管 | ✅ **主渠道**，也最符合「找靠谱的人」 |
| 小红书 | 中，不能直接挂码成交 | ⚠️ **只做引流**，导流到私域 |
| **闲鱼** | 高，卖码会被永久封 | ❌ **不用**（除非走数字商品专门类目，需资质） |

内测与首发都用「收款码 + Q 群发货」，**零合规风险**。等真的卖出 100+ 份、验证「有人愿意付」，再考虑上正规数字商品平台（爱发电 / Gumroad 等）。

## 八、App 规划（APK / IPA）

**结论：内测期只发 PWA + 网页**（`manifest.json` + `sw.js` 已就绪，「添加到主屏幕」即 App 体感，零成本）。

上架是**后面所有事里最容易卡三个月的一环**（备案 / 软著 / 审核都不可控），**不是内测的前提**。

### 上架前置（可并行推进，越早越好）

| 项 | 要求 | 备注 |
|---|---|---|
| Android 国内 | **软著证书**（1–2 个月，可自助或代办） | 最耗时的一件 |
| iOS | Apple 开发者账号 **$99/年** | 审核严格：隐私政策页、年龄分级 |
| 国内合规 | **ICP 备案** | 周期不可控 |

### 技术路线

现状是零构建的原生 JS，**最省事的路是套壳**—— Capacitor 或 Tauri 把 `index.html` + 运行时打成 App，**不用改一行业务代码**。这条路成立，因为代码本来就是「浏览器里能跑就能用」的形态。

**云端付费一律不做** —— 涉及内容审核责任，与个人开发者的能力/资源不匹配，也与本地优先的隐私承诺冲突。

### ✅ 已完成：一键导出全部（2026-10-07）

**问题**：原先换设备要**导两个文件、导两次**（文字一份 + 图片一份），漏掉图库就会「聊天里的图全裂」。这个摩擦是换设备焦虑的主要来源。

**做法**：`page-backup.js` 加合包导出，**一个文件带走全部**，导入时按 `app/kind` 标识自动分流。

| 改动 | 说明 |
|---|---|
| `buildAllPack(media)` | 合包结构纯函数，导出/导入共用；`data` 段 = `store.exportUserData()`（**保持 `app:'sleepy'` 不变**，`canImport` 硬判这个） |
| `exportAllInOne()` | 图库不可用（无痕模式）→ **照样出文字文件**，note 如实说明，不因图片卡住整份备份 |
| `importAllInOne(payload)` | 同一入口吃两种形状：合包剥一层取 `payload.data`，老备份传整个 —— `canImport` 认 `app:'sleepy'`（`store.js:588`） |
| UI | 页面最上方新增「换设备 / 一键搬家」组；原有四个分开入口保留（单独导文字更快） |

**冒烟 W11–W13**（已做双向负向验证：改标识→红、搞坏分流→红）：

- W11 合包结构可识别（`app`/`kind` 硬写 `'sleepy-all'`，**不许引常量**）+ 图库段可选
- W12 老备份照样导得进去 + **非备份文件被 canImport 拦下**（负向，证明判据非空转）
- W13 无图库段时安静通过 + **不谎报导入了图片**

**踩过的两个坑**（已登记进 MEMORY 长期约定）：

1. `var downloadText = ui.downloadText` 闭包顶部捕获 → 注入导出面**不生效**，结构断言改读纯函数。
2. **判据里引被测常量导致假绿**：最初写 `pack.app === B.ALL_KIND`，sed 改坏标识后 711 条断言照样全绿。

**验收状态**：`check` 全绿、`smoke` 全绿（711 条）。**真机浏览器验未做** —— 内测前建议实拍：①一键导出提示文案 ②导出后选该文件导入 ③图片是否还原 ④无图库时是否如实提示。

## 十、自助发码流程（2026-10-07 用户设计，已采纳）

用户提出的方案：**小红书/QQ 卖 → 用户登记 QQ 号 → 网页自动生成激活码 → 用户去App 激活设密码 → 换设备用 QQ号+密码登录**，信息存在 Worker。

**结论：采纳。这个设计优于原方案里的「Q群管理手工发码」**，因为它省人力且**可追溯**（能查退款、能限一人一号），还天然约束了二手转卖。

### 完整链路

```
① 付款（小红书 / QQ 群）
    ↓
② 发码页登记 QQ 号        ← Worker 记账
    ↓
③ 当场自动生成激活码       ← 码即账号（不做「码→兑换→账号」两层）
    ↓
④ App 内激活 + 设密码
    ↓
⑤ 换设备：QQ 号 + 密码登录（上限 3 台，可踢 + 自助解绑）
```

### ⚠️ 合规边界（已核实 2026-10-07）

| 渠道 | 结论 |
|---|---|
| **QQ 群 / 好友 + 收款码** | ✅ **主渠道**，平台不管，最适合起步 |
| 小红书 | ⚠️ **只做内容种草**。新规（《交易导流违规管理细则》9-18 生效）把「通过链接/二维码/**QQ号**/微信等引导站外」列为违规，情节特别严重**扣 2 万违约金 + 封号**；监管覆盖笔记/评论/私信/**群聊**/商品信息/售后链路 |
| 闲鱼 | ❌ **禁售激活码**（永久封禁、不可申诉） |

**写法要求**：小红书内容只做功能展示与体验分享，**不写「进群」「加 QQ」**；成交与发码都在站外完成。

### ⚠️ 发码页必须有闸（技术漏洞）

裸着填 QQ 号就出码 = 白送，且必然被脚本薅。**最少要做的一条**：

> **一个 QQ 号只能领一次码**，发过即记。

建议再加：订单号校验（有空时）或人工放行（起步期量小最省事）。

### 技术要求

| 项 | 要求 |
|---|---|
| 密码存储 | **只存哈希**（argon2/bcrypt），Worker 永不存明文 |
| 登录失败 | 次数限制 + 锁定，防撞库 |
| QQ 号定性 | **属个人信息**（可识别自然人）→ 发码页要有一句告知；隐私政策写明用途；提供删除入口（iOS 上架审核硬要求） |
| 分层 | 发码页（Worker 域名，只出码 + 记 QQ）与 App 内激活**分两处**，别混在一个页面 |

### ✅ 已完成：协议 / 隐私页（2026-10-07）

**`legal.js`** —— 内测前第一件，三件事：

| 项 | 说明 |
|---|---|
| 两份正文 | 用户协议 7 节 · 隐私政策 7 节。**每一条都必须是真的** |
| 首启弹窗 | 开屏遮罩摘掉后弹（不盖在开屏动画上）；双标签切换 + 可滚动正文 |
| 两个出口 | 「我已知情，不再提示」记标记；**「先看看」不记标记**（下次还会弹 —— 有意留余地，不做成逼用户勾选）；点遮罩等同「先看看」 |
| 随时可翻 | 设置 → 其他 → 用户协议 / 隐私政策（只在第一次弹是耍流氓） |

**正文措辞红线**：「默认数据全在你自己的设备上」这类承诺可以写，**「永不上传」不可以写** —— 我们有 GitHub 备份这个可选功能（数据在用户自己仓里），写成绝对化表述就是撒谎，扛不住追问。冒烟 L4 用静态护栏拦住了这类词。

**改动文件**：

- `legal.js`（新增）：正文常量 + 同意标记（`legalAgreedAt`，带**版本号**，协议一改就重新提示）+ 弹层
- `store.js`：新增 `DEVICE_LOCAL_KEYS` 判据 —— 同意标记是**设备本地状态**，用户导出 / 内部快照 / 用户导入**三个方向都不带**
- `splash.js`：`finish()` 里遮罩摘掉后触发首启弹窗
- `page-settings.js`：设置页「其他」组加两个入口
- `style.css` / `index.html`：样式与脚本挂载
- `scripts/smoke.js`：L1–L4 四条断言 + 缓存基准 v203 → v204

**⚠️ 冒烟 L3 抓出的真缺陷**（不是测试写错）：同意标记原本会**混进用户存档导出** → 换设备导入后，用户带着上一台设备的「我已知情」直接进桌面，**该弹的协议不弹**。已修：`store.js` 单列设备本地判据，三个方向都拦。

**验收状态**：`check` 全绿、`smoke` 全绿（90 个脚本）。L3 做过负向验证（把 `DEVICE_LOCAL_KEYS` 清空 → 断言报红）。**真机浏览器验未做** —— 内测前建议实拍：①首启弹窗视觉 ②切标签 ③两个按钮的差别 ④勾了之后不再弹 ⑤设置页能再翻出来。
