## 一、必须修正的向量归属边界（审阅 §二，全部经代码核实）

### 1.1 核实到的事实（决定性）

| # | 事实 | 代码证据 |
|---|---|---|
| F1 | **每个向量块都盖 `sandboxId` 章，章值 = 写入那一刻的 `scopeNow()`（当前岛）** | `buildRecs` memory-vec.js:1176 `sandboxId: sid`；sid 由调用方传 `scopeNow()`（1391/1944/2020 等处 `var sid = scopeNow()`；`scopeNow()` = `Sleepy.core.scopeId()`，246-248） |
| F2 | **`ownerKeyFor` 是单池推导**：给 `charId` → `rootOf(root)`；`kind:'moment'` → `islandKeyNow()`（**当前岛**）；`kind:'diary'&&!charId` → `userKey(uid)`；`groupId` → `groupKey(gid)` | memory-vec.js:1712-1727 |
| F3 | **`scanOwner` 有岛过滤**：`var sid = scopeNow(); if ((!sid || b.sandboxId===sid) && ...) out.push(b)` | memory-vec.js:251-264 |
| F4 | **`forget` 吞错 + 单池**：`ownerKeyFor(filter)` 定一个池 → `scanOwner` → `forgetHit` 过滤 → `removeBlocks`；`['catch'](()=>0)` | memory-vec.js:913-921 |
| F5 | **userMasks 按岛隔离**：真马甲 `upsertUser` 盖 `sandboxId` 章（648），跨岛配置台可显式给 `sandboxId`（645-648）；唯一不打章的是 `ensureDefaultUser` 兜底「我」（606-609，**故意跨岛共享**） | core.js:613-670、595-611 |
| F6 | **主表一律按 `sandboxId` 章隔离**：`tagScope` 盖当前岛章、`scoped` 按章过滤 | core.js:63-77 |
| F7 | **char 有 `parentId`**：皮套/NPC 挂在 `parentId=大号` 名下；`rootOf(id)` 顺着 parentId 归到大号 | core.js:480-490 |

### 1.2 由 F1-F4 推出的硬结论

- **现有 `forget` 不能用于 purge 级删除**，两个结构性缺陷：
  1. **单池**：删岛要跨 `island:` + 各角色 `rootOf` + 各马甲 `user:` + 各群 `group:` 四类 ownerKey，`forget` 一次只能扫一个池；
  2. **scopeNow 岛过滤（F3）**：删岛 / 删别岛角色 / 删别岛皮套时，当前岛往往已切走 → `scanOwner` 会把目标岛的块全滤掉 → **漏扫向量**。这不是边缘情况，是删岛最典型的场景。
  3. **吞错（F4）**：失败返回 0，调用方误以为「删干净了」。

- **由 F5 推出**：马甲 `user:<uid>` 池里，同一 uid 在不同岛可能各有日记（uid 相同、sandboxId 不同）→ **删马甲不能清整个 `user:<uid>` 池**，必须按 `userId===uid && sandboxId===目标岛`。

### 1.3 向量过滤条件 = 主表/派生删除集合（审阅 §二.4 一致性红线）

**铁律：向量的 `charId/fromCharId/userId/sandboxId` 过滤条件，必须和 localStorage 主表/派生数据「被删对象集合」完全一致。** 主表按岛清（`scoped` 按章），向量就必须按 `sandboxId` 清；主表删一个 root 及其皮套，向量就必须按 `charId===root && sandboxId===岛` 清（**不得** `charId===root` 不带岛、更不得 `fromCharId` 模糊）。下面 §三 的删除矩阵逐项对上。

## 二、API 职责分离（审阅 §三）

**杜绝 `forgetSandbox` 兼任所有删除语义。** 确认数据模型后，`ownerKeyFor` 单池 + 块上四类章（charId/fromCharId/userId/sandboxId/groupId）足以支撑一个**统一的底层「按章全库过滤」游标**，但**core 层必须暴露语义明确的包装函数，UI 禁止直接传任意过滤器物理删**。

向量层新增 **4 个不吞错语义出口 + 1 个内部私有底层游标**（出口全部复用底层 `scanAll(filter)` 全库游标，命中 `forgetHit` 的扩展版）：

| 向量层出口 | 过滤条件 | 用途 | 覆盖的池 |
|---|---|---|---|
| `forgetSandbox({sandboxId})` | `b.sandboxId === sandboxId` | 拆岛 | 全库（跨 island:/rootOf/user:/group:） |
| `forgetCharSet({charIds, sandboxId})` | `b.fromCharId ∈ charIds && b.sandboxId === sandboxId` | 删大号 / NPC / 皮套（**统一出口**） | 按 `fromCharId`（产出方）集合精确命中 |
| `forgetUser({userId, sandboxId})` | `b.userId === userId && b.sandboxId === sandboxId` | 删马甲 | `user:<uid>` 池里该岛的块 |
| `scanAll(filter)`（**内部私有，不导出**） | 底层全库游标 | 各出口共用 | 全库 |

**设计要点**：
- **`scanAll(filter)` 是 memory-vec.js 内部私有底层函数，不导出给 core 或 UI，不得成为生产删除 API。** 生产对外**只暴露**三个语义明确的出口：`forgetSandbox({sandboxId})` / `forgetCharSet({charIds, sandboxId})` / `forgetUser({userId,sandboxId})`。
- **scanAll 实现**：不依赖 ownerKey、不依赖 scopeNow，`open()` 后全库 `openCursor` 遍历，用扩展版 `forgetHit`（加 `fromCharIds`/`userId`/`sandboxId` 维）过滤。**唯一**的「按任意章组合全库扫」实现，各出口都复用它。
- **三个出口统一契约**：
  - **缺少必要字段时拒绝执行**（直接 reject，不依赖调用方自觉）：`forgetSandbox` 缺 `sandboxId`、`forgetCharSet` 缺非空 `charIds`/`sandboxId`、`forgetUser` 缺 `userId`/`sandboxId` → reject。
  - 成功 resolve 删除数量；空结果 resolve 0；IndexedDB 失败 reject。
  - **不依赖当前岛**（不读 `scopeNow` 过滤）；**不吞错**。
- **核心不变量**：每个出口的 `sandboxId` 都是**必传** —— 因为 F1 已证明块按岛盖档，不按岛删就会误删别岛。**禁止无 sandboxId 删除角色/皮套/马甲向量。**
- **删除角色一律按 `fromCharId`（产出方）精确命中**：`forgetCharSet` 的 `charIds` 是**产出方集合**（非 `charId=rootOf`），由 core 的 `doomedCharIds`（递归角色树）算好传入。块上 `charId=rootOf(产出方)`、`fromCharId=产出方`；一张 NPC 挂大号名下时 `rootOf(NPC)=大号`，若按 `charId=rootOf` 删会把同 root 大号+全部皮套+全部 NPC 的目标岛块一锅端（红线），按 `fromCharId∈集合` 删才能让「主表 doomed = 向量命中」一一对应。
- **现有 6 个 `forget` 调用方不动**（幂等清理语义保留），只是新增 purge 级出口。

## 三、四类删除对象 · 逐项删除矩阵

> 约定：`rootOf(c)=R`（大号）；`sub` = 皮套；`npc` = NPC。所有向量出口 `sandboxId` 必传目标岛。

| 删除对象 | 主表集合（localStorage，`scoped` 按章） | 派生键集合 | 向量 ownerKey | 向量字段过滤 | 说明 |
|---|---|---|---|---|---|
| **岛** `purgeSandbox(sbId)` | `sandboxes` 删该房；`scoped` 28 键按 `r.sandboxId===sbId` 删（chats/memories/links/photos/diaries/todos/favorites/userMasks/characters/moments/wallet/stickers/offlineSessions/groups/groupMembers/groupMessages/offlineHandoffs/groupOfflineSessions + phone 十条表）；动态键 `charRel:<sbId>` 整键删；`appearance.desktop.islands[sbId]` / `desktop.islands[sbId]` / `desktopRemoved` / `charAppearance.byChar` 悬空引用 | 见「向量」列 | `island:<sbId>` + 岛上每角色 `rootOf` + 每马甲 `user:` + 每群 `group:` | `b.sandboxId === sbId`（`forgetSandbox`） | 跨岛引用守卫见 §四；`activeSandboxId===sbId` 才清 active（现有语义保留） |
| **角色大号** `purgeChar(mainId, sbId)` | `characters` 删该 main + 其全部皮套 + 其下 NPC（doomed 集合，按 `parentId` 归并）；对应 `chats`（`characterId∈doomed`）/`links`（`charId∈doomed`）/`memories`（`rootId∉doomed && fromCharId∉doomed`） | 同上 | `rootOf(mainId)` | `b.fromCharId∈doomed && b.sandboxId===sbId`（`forgetCharSet`，charIds=doomed） | **不得** `charId===root` 不带岛（会误删别岛该 root 的块）。主表 doomed 集合 = 该 root 宇宙（main+皮套+NPC），向量 = 该 root 池该岛块 —— 两者一致（都归 root + 该岛） |
| **NPC** `purgeChar(npcId, sbId)` | `characters` 删该 npc（doomed={npcId}）；chats/links/memories 按 doomed 清 | 同上 | `rootOf(npcId)` | `b.fromCharId∈{npcId} && b.sandboxId===sbId`（`forgetCharSet`，charIds={npcId}） | NPC 无皮套，向量=该 root 池该岛块 |
| **皮套** `purgeFace(subId, sbId)` | `characters` 删该 sub + 其下 NPC；chats/links/memories 按 doomed 清 | 同上 | `rootOf(subId)` | `b.fromCharId∈doomed && b.sandboxId===sbId`（`forgetCharSet`，charIds=doomed={subId+其子NPC}） | **按 fromCharId 精确**：同 root 别的皮套、别岛的块**必须保留**（审阅 §二.2 硬性要求）。主表 doomed = 该皮套+其 NPC，向量 = 该皮套一张脸的块 —— 一致 |
| **user马甲** `purgeUser(uid, sbId)` | `userMasks` 删该行 + 大号顶替（`isDefault` 继承，现有逻辑保留）；**按岛**：只删 `u.sandboxId===sbId` 那件（若同 uid 跨岛有两件，只删本岛那件） | 它建的 `chats`（`userId===uid && sandboxId===sbId`）/`links`/朋友圈（`maskId===uid && sandboxId===sbId`）/线下会话 —— **补齐历史遗留「对话留下来但找不到马甲」** | `user:<uid>` | `b.userId===uid && b.sandboxId===sbId`（`forgetUser`） | **马甲按岛隔离（F5）**：`user:<uid>` 池同 uid 不同岛各有日记，**不得**清整个 `user:<uid>` 池。仅当确认 uid 全局唯一且不跨岛复用，才允许 `forgetUser({userId:uid})` 不带岛 —— 见 §三注 |

### §三注 · userId 是否按岛隔离（审阅 §二.3 / 回交必答项）

**结论：按岛隔离。** `upsertUser` 给真马甲盖 `sandboxId` 章（core.js:648、655），`scoped`/`masksOfSandbox` 都按章取本岛马甲。唯一全局共享的是 `ensureDefaultUser` 兜底「我」（不打章、跨岛复用）——**兜底件不允许被删**（`removeUser` 现在 `list.length<=1` 就拒删，正是防它）。因此：
- 默认 `purgeUser(uid, sbId)` **必须带岛**，清 `user:<uid>` 池里该岛的块；
- 兜底「我」不纳入 purge（它是「连马甲都没有时的最后兜底」，删它会破坏跨岛兜底）。

## 四、跨岛引用守卫（审阅 §四）

**执行顺序：任何向量清理或主表清理之前。**

```
purgeSandbox(sbId):
 ① findSandbox(sbId)，不存在 → { ok:false, message }
 ② 计算将被连坐清掉的集合：
     doomedChars = characters 里 sandboxId===sbId 的全部（大号+皮套+NPC）
     doomedUsers = userMasks 里 sandboxId===sbId 的全部
 ③ 扫描其他所有 sandbox（id≠sbId）：
     for each other in sandboxes:
        other.charIds ∩ doomedChars 非空  → 记入 refs.chars[charId] = [other.id,...]
        other.maskIds ∩ doomedUsers 非空  → 记入 refs.users[uid] = [other.id,...]
 ④ 若 refs 非空 → 返回 { ok:false, why:'still-referenced', by:[{type,id,refedBy:岛名列表},...] }
     —— 失败时【不删向量、不删主表、不删派生】，UI 不显示成功 toast
 ⑤ refs 空 → 才进入向量门禁（判 IDB → forgetSandbox → 清派生 → 清主表）
```

- **依据**：char/userMasks 的 `sandboxId` 章 + 每岛 `charIds/maskIds` 数组（core.js:147-148、357-378）可精确判「被删身份是否仍被别岛引用」。`validateSandboxChars` 不校验跨岛（core.js:119-132），所以这个守卫是防幽灵的**必要兜底**。
- **兜底安全网（既有）**：即便有残留引用，`activeCharOnIsland`/`activeUserOnIsland`（core.js:744/759）保证当前身份必须是本岛名册成员，否则 null —— 幽灵不会写到错误角色。purge 施工后加冒烟守它。

## 五、每个 purge 的失败与重试语义（审阅 §五必答项）

统一事务门禁（对齐项目3 `purgeGroup`）：

| 阶段 | 判定 | 返回 | 副作用 |
|---|---|---|---|
| ① 存在性 | `find` 无目标 | `{ok:false, message}` | 无 |
| ② 默认「我」保护（仅 `purgeUser`） | 目标是 `ensureDefaultUser` 产生的跨岛共享默认用户 | `{ok:false, why:'default-user-protected'}` | **无**（不调用向量删除、不改主表派生） |
| ③ 跨岛守卫 | 仍被别岛引用 | `{ok:false, why:'still-referenced', by:[...]}` | **无**（向量/主表/派生都不动） |
| ④ 能力判定 | `!global.indexedDB` | 直接 cleanup → `{ok:true}` | 主表是唯一真相，无向量可清 |
| ⑤ 能力判定 | 有 IDB 但 `memoryVec` 缺失 / 未初始化 / 出口 API 缺失 | `{ok:false, why:'memory-vector-unavailable/api-missing'}` | **主表保留**，可重试 |
| ⑥ 向量清理 | 对应出口 reject | `{ok:false, why:'memory-vector-failed', error}` | **主表保留**，可重试 |
| ⑦ 向量清理 | resolve（含 0） | 清派生 → 清主表 → `{ok:true}` | 全部落 |

- **默认「我」保护（`purgeUser` 特有，core 层显式）**：只有真正的岛内 userMask（`sandboxId===目标岛`）才进入跨岛守卫和向量门禁；`ensureDefaultUser` 产生的跨岛共享默认用户被 `why:'default-user-protected'` 挡住，**该分支不得调用向量删除、不得修改主表和派生数据**。`forgetUser` 的参数校验拒绝缺少 `userId` 或 `sandboxId`，不依赖调用方自觉传参。
- **可重试**：失败阶段⑥ 主表一行没动，重试会重新走①-⑥，幂等。
- **空结果也算合法成功**（resolve 0 → 继续清主表）。
- **UI**：⑤失败/④不可用 → **不显示成功 toast**，弹失败原因（沿用项目3 的失败可见样式）。
