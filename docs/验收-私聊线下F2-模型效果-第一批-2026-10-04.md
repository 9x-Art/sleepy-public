## 二、问题分类（**这是本批的交付物**）

### P0 · 协议降级：3/10 轮的原始 JSON 直接进了正文

组 3 轮 1、组 3 轮 2、组 4 轮 1 —— 气泡里出现的是这样的东西：

```
{"paras":[{"type":"prose","text":"沈砚看了你一眼…"},{"type":"dialogue","text":"外套得拧一下…
```

**这不是渲染 bug，是模型吐的 JSON 本身语法就是坏的**：
- 组 3 轮 1：`{"type":"prose":"沈砚看了你一眼…"}` —— **缺冒号**（`"prose":` 写成 `"prose":` 后直接跟值）
- 组 3 轮 2：`{"type":"prose":"他重新坐下…"}` —— 同样缺冒号，且**整段被截断**（末尾是 `{"type":"prose":"`）
- 组 4 轮 1：JSON 前后**混进了「修正版：」和两段分隔线**，模型自己产出了 v1 + 修正版两份

`parseOfflineReply` 的行为是**正确的**：`JSON.parse` 抛异常 → 降级成整段原文当 prose。
它没有崩溃、没有丢数据、没有伪称解析成功。**降级策略本身没问题。**

⚠️ 但**用户体验上这是失败的**：正文里出现裸 JSON。
本批**不修**（协议与解析器在冻结范围内），只如实登记。

> 这一条**必须在进入六套文风之前定夺**：
> 现在的降级是「原文照显」，读起来像程序崩了。
> 可选方向（**都需要改协议或解析器，属于解冻范围，等你拍板**）：
> ① 解析失败时给一句人话提示 + 保留原文进「原文」折叠区；
> ② 提示模型重试一次；
> ③ 收紧输出协议（更严格的 schema + 少样本示例）。
> **我倾向 ①** —— 最省事、不改协议、不动模型行为。

### P0 · 端点稳定性：1/10 轮真实超时

组 2 轮 3：`stage: timeout, ms: 120003`（**真的挂了 120 秒**）。

对照实测：同一端点 5 次裸 curl 延迟为
`8.0s / 5.4s / 6.5s / 8.1s / **25.6s**` —— **抖动极大**。
所以这一次是端点侧的极端慢，不是代码问题（超时下限 60s，实际给到 120s）。

**这条要记在 F2 修复的功劳上**：诊断把它标成 `request-failed-unknown`
（「请求失败（无法确认服务端是否收到）」）——
**没有**误标成「服务端已收到并拒绝」。这正是本次 F2 改掉的错误结论。
按 v1 的旧逻辑，这里会被写成「服务端拒绝」，误导排查方向。

⚠️ **同一批共 3 次超时**（全部-带原始 组2轮3、探路 组4轮2、补跑23 组2轮3），
全部被我的采集器误判成「已落地」→ **这 3 轮都不该有输出**。

### P1 · 组 4 轮 1：模型输出「修正版」双份

模型先给了一份 JSON，然后输出「修正版：」又给一份。
解析器取的是 `indexOf('{')` 到 `lastIndexOf('}')` 的**整段**，
所以两份都进了正文。这是 P0 那条的**加重形态**。

### P2 · 「我没事」「随便啦」的解读：本次**未观察到**问题

组 3 两轮的真实输出（降级前从 JSON 里能看到内容）：

轮 1「我没事」→ 模型写
> 他说完又觉得自己这话挺多余的。**你说没事，他就该信。**

✅ **这是正确的** —— 模型明确把「我没事」当作字面接受，没有写
「你其实很难受吧」「逞强」「嘴硬」「不用在我面前装」。

轮 2「随便啦」→ 模型写他**没接这个话茬**，直接起身去拧外套。

✅ **也是正确的** —— 没有把「随便啦」当成默许信号、没有借机推进关系。

**但这两个判断的证据强度弱**：因为这两轮恰好都降级成了裸 JSON，
内容能读到但**没有进解析器**（`suggests` / `envUpdate` 都没生效）。
**不能据此宣布「模型不擅自解读」** —— 需要在 JSON 正常输出的条件下重跑才能定性。

### P2 · NPC 主体性：本次**表现良好**（样本量不足）

## 四、明确不能下的结论

1. **不能说「F2 效果达标」** —— 只有 1 个模型、10 轮、1 组角色设定。
   用户要求里「同角色同关系同场景」是做到了，但**跨模型差异完全未测**。
2. **不能说「复读是模型问题」** —— 原证据已撤回（见勘误）。
   重跑后只找到 1 例真复读（`补跑4` 组4 两轮），**样本量不足**。
   ⚠️ 另一个新问题：重跑组 2 的 3 轮里有 **2 轮模型返回 HTTP 200 空内容**，
   组 3 轮 1 同理 —— 这类轮次**没有可评估输出**，不能算「模型没擅自解读」。
3. **不能说「不擅自解读」已解决** —— 关键两轮恰好降级，证据强度不足。
4. **不能说「协议没问题」** —— **3/10 轮裸 JSON 进正文**，这是本批最硬的发现。

## 五、验收脚本本身的两个缺陷（如实登记）

1. **会话隔离**：初版所有样本组共用一个页面，
   而**页面实例是缓存复用的** —— 上一组若有未收尾请求，
   busy 状态会跟着 DOM 复用进下一组，导致第 2 组起 send 一直 disabled、样本全废。
   已改为**每组全新 context + 全新 page**。
2. **轮询超时**：初版 40×600ms=24s，把「模型还在想」误判成「没落地」。
   已放宽到 120s，并区分「在途」与「真失败」。

这两个都是**验收脚本的缺陷，不是产品缺陷**。第一次跑出来的「7 个红」和「后续组全废」
都不能作为产品结论。
