## 〇、统一出口与 R7 修复覆盖范围

人设编译唯一实现：`prompt-engine.js:1555 compileCharacter` + `prompt-engine.js:1527 charMetaLines`。

R7（2026-10-13 已落地到工作副本）把 `compileCharacter` 改成：

- kind≠'sub'：`[CHARACTER]` 包裹 `content` + 短字段（charMetaLines）。
- kind==='sub'：**root 本体 content 在前**，sub 的 `content` 作为「【当前账号对外补充】」在后并标注性质；短字段逐项处理（speech 账号优先、gender/nationality 本体优先、**neverDo 红线并集**）；父映射断裂时只用 sub 自己的资料。

**只有调用 `PE.compileCharacter(charId)` 的功能，才能自动吃到这套分层 + 红线并集。** 其余手写 `[CHARACTER]` 包裹 / 裸 `ch.content` 的地方，全部绕过了它。

## 二、绕过统一出口（手写包裹 / 裸 content）—— 不会吃到 R7 修复 ⚠️

### 2.1 群聊 `page-group-ai.js`
`entityKnowledge`（`page-group-ai.js:128-164`）注入每个 `[ENTITY]` 块的人设：

```js
// page-group-ai.js:135-140
var persona = String(rec.content || '').trim();          // rec = core.findChar(ownerId)
if (persona) {
  lines.push('人设：' + (persona.length > 1200 ? persona.slice(0, 1200) + '…' : persona));
}
// page-group-ai.js:144-146
var meta = (Sleepy.promptEngine && Sleepy.promptEngine.charMetaLines)
  ? Sleepy.promptEngine.charMetaLines(rec) : [];
meta.forEach(function (t) { lines.push(t); });
```

问题：
- 走的是 `rec.content`（裸本体内容），**不是** `compileCharacter`。
- `rec = core.findChar(ownerId)`：当 owner 是 **sub** 时，`rec` 就是 sub 本身 → `rec.content` 只含 sub 的「对外补充」，**缺 root 本体人格**；`charMetaLines(rec)` 也只读 sub 的 speech/gender/nationality/neverDo，**缺 root 本体的红线与身份信息**（见 `charMetaLines` 实现 1527-1539，它对传入对象直接取字段，不做 root 回退）。
- 对 sub 角色 = 本体人格 + 本体红线**整段缺失**，群聊人设严重失真。
- 截断到 1200 字。

## 三、真实缺口 / 非缺口确认（用户复核后重分类）

> 用户指出：以身入局、ta 本应吃人设、现在没注入是缺口而非设计选择。经源码复核，结论如下。

### 3.1 以身入局 `book-core.js:474-570`（`buildBookMessages`）—— **真实缺口（P1）**
叙事者 system 提示只注入：席位/身份、世界状态、在场人物档案（NPC name/stance/fact/voice）、委托、前情、判定格式。**全程不注入当前 char 的角色卡人设**。`run.charName` 仅在 line 565 作为名字引用（"推进 {charName} 的行动与心理"）。
- 主模式（user 出面，line 561-563）：叙事者写「世界反应」、不替 char 决定言行 —— 此处不吃人设尚可接受。
- **但无输入分支（line 564-565）**：user 在局外观测、不出面时，叙事者要"推进 {charName} 的行动与心理"——也就是**由模型代写 char 的心理与行动**，却没有任何 char 人设可依，结果是泛化的、非角色保真的描写。这是实打实的缺口。
→ 修复：在无输入推进分支注入 `PE.compileCharacter(charId)`，让 char 的心理/行动有据可依。

### 3.2 We 收藏馆 `page-we.js:459-465` —— **非缺口（低风险，P3 待定）**
「共同记录」草稿生成是中立事实摘要器：system 只给"替一对关系写收藏卡"的规则，素材走 `chatLines`（最近聊天）+ `LF.text`（生活动态），不注入 char 角色卡。
→ 它抽取的是"真实发生过/说定过的事"，不需要角色以自己声音说话，中立摘要合理，**不构成缺口**。若未来要卡面文案带角色口吻，才是可选增强（P3，非阻塞）。

### 3.3 ta —— 分两半看（用户心智模型需校正）
- **关系网 `ta-network.js` —— 非缺口（只读、本就不吃人设）**：文件顶部明写"0 模型 0 网络 0 写入"，关系网是从 `findLink` / `getPairRel` / NPC 数据算出的**只读投影**，根本不调模型，所以"ta 根据人设生成关系网"不成立 —— 关系网这条线不吃人设、也不该吃。
- **生活提案 `ta-model.js:149-166`（`buildAdvance` / `buildReview` / `buildCandidates`）—— 真实缺口（P1）**：三模式 system 走 `FORMAT_RULES`、user 端 JSON 喂的是 ta-life 结构化关系/生活数据（`confirmedNpcs` 喂的是 **NPC 的** `content` 片段、不是 char 自身角色卡；items/follows/promises/events）。**全程不注入 `ch.content`**。即 ta 的"自主生活推进/复核/候选"生成不带角色自身的性格与口吻，是实打实的缺口。
→ 修复：在 `buildAdvance` 等三处补 `PE.compileCharacter(charId)`（以 system 附块形式），让生活提案带角色保真。

## 四、问题分级（先不改，仅登记）

### P0 · 人设被静默截断 / 缺失，角色保真直接受损
- 查手机 `caughtReaction`：`slice(0, 800)` 截断人设（page-phone-ai.js:354）
- 朋友圈：`slice(0, 600)` 截断（moments-ai.js:137）
- 日历日程：`slice(0, 1200)` 截断（schedule-gen.js:60）
- 群聊 sub 角色：本体人格 + 本体红线整段缺失（page-group-ai.js:135 / 144）

### P1 · 缺 sub 分层 / 红线并集 + 角色卡正文缺失（非 sub 用户无感，sub 用户失真）
- 群聊、查手机、日记、朋友圈、线上整理、离线总结、查岗、日历日程 —— 全部手写 `[CHARACTER]` / 裸 content，**没有走 `compileCharacter`**，因此吃不到 R7 的分层与红线并集。
- 另：**以身入局**（无输入推进分支，`book-core.js:564-565`）、**ta 生活提案**（`ta-model.js` advance/review/candidates）—— 同样不调 `compileCharacter`、缺 char 角色卡正文，角色保真受损（见 §3.1、§3.3）。

### P2 · 设计性不注入（非缺口，仅登记）
- We 收藏馆「共同记录」草稿：中立事实摘要器，不吃人设属合理（§3.2，P3 待定，不阻塞）。

## 五、统一修复建议（待批准后实施）
所有「需要角色以自己身份说话/行动/被描写」的 AI 链路，应**改调 `PE.compileCharacter(charId)`**（已含 sub 分层 + 红线并集），废弃手写 `[CHARACTER]` 包裹与 `slice()` 截断。具体替换点即第二节 2.1–2.8。
- 群聊：把 `entityKnowledge` 的 `rec.content` + `charMetaLines(rec)` 换成 `compileCharacter(ownerId)`（sub 自动分层）。
- 查手机 / 日记 / 朋友圈 / 线上整理 / 离线总结 / 查岗 / 日历：把裸 `ch.content`/`char.content` 换成 `compileCharacter(charId)`，删掉 `slice()`。
- 三级截断（800/600/1200）一律取消——`compileCharacter` 不截断。
