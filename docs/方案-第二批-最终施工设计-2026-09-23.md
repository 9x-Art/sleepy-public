## 1. 项目 1｜清空 / 导入（先做）

### 1.1 `wipeAll()` 三态（不许把三种混成一类）

```
wipeAll(): Promise<{ status:'cleared'|'not-applicable'|'failed', removed?:number, why?:string }>

cleared        真实清空，且 **await total() === 0** 通过
not-applicable 环境**明确不支持 IDB**（`indexedDB` 不存在 → 本来就没有块）
failed         blocked / open 失败 / transaction 失败 / clear 失败 / 清完 total() !== 0
               → why 带上具体原因（'blocked' / 'open' / 'txn' / 'verify'）
```

- 旧设想（"无 IDB 返回成功"）**作废**：`noidb` 归 `not-applicable`（不是"清干净了"的证据，只是"本来没有"）。
- `blocked`（别的标签页占着 DB）归 **failed**，不是 not-applicable。

### 1.2 导入七步 + 独立恢复区

```
1. 完整解析并校验备份文件 —— 不写入
2. 把当前 localStorage 快照写进**独立恢复区**（见下）
3. 开启 wiping gate
4. wipeAll()
5. wipe 成功（cleared / not-applicable）才 store.importAll()；failed → 停，报错，恢复
6. importAll 失败 → 用恢复区还原 localStorage
7. 全部成功 → **立即删除恢复区** → 解除 gate → reload
```

**独立恢复区（按你的第四条）**：
- 用**独立前缀**，不复用 `sleepy.v1.`：`sleepy.rb.<txn> = { at, kind:'import'|'clear', data:{…} }`。
- 依据：`store.clearAll()` 只删 `sleepy.v1.` 前缀（`store.js:472-487`）、`exportAll` 只扫该前缀（`:406-420`）
  → 独立前缀**天然不被清空覆盖、也不会被导出**（不会把"回滚快照"当用户数据带走）。
- 规定：**成功后立即删除**；失败保留（供回滚），并在 UI 提示"有未完成操作"。

### 1.3 清空：非原子 → 逐项报告

```
1. 快照进独立恢复区（kind:'clear'）
2. 开 wiping gate
3. wipeAll()
4. store.clearAll()
5. await Sleepy.media.clear()
6. memoryVec.clearCache() 等内存缓存
7. 汇总 { ok:[…], failed:[{item, why}] } → **逐项列出**（例：localStorage ✅ / 图库 ❌ / 向量库 ❌）
   —— 不许只写"重试"
8. 全 ok → 删恢复区 → 提示完成 + reload
   有 failed → **删恢复区**（清空语义优先，不留长期快照，见下）→ 列出失败项 + 提供「重试未完成项」
```

**清空的临时快照不得长期保留**（你的原话）：清空走完（无论成败）**都必须删掉** `kind:'clear'` 的恢复区，
否则违反"清空"语义。失败时靠"逐项报告 + 重试"补救，不靠留快照。

### 2.4 条目级冲突规则（按你的第一条重写）

**胜者**：保留**原 ID** 与**最终状态**。
**败者**：改**新 ID**，状态**统一标 `superseded`**，`supersededBy` 指向**真实存在的胜者 id**；
原状态写进 **`migrationOriginalStatus`**（仅供审计）；**败者不得进入注入与向量库**。

| 场景 | 胜者 | 败者处理 |
|---|---|---|
| 完整字段全同（C1） | — | **两条视为同一条 → 跳过**（幂等基石） |
| 同级（active×active 等）内容不同 | `updatedAt` 较新者（缺则回落 `createdAt`；都缺视为最旧） | 改新 id、`status='superseded'`、`supersededBy=胜者id`、`migrationOriginalStatus=原状态` |
| 跨级（如 active + invalid） | **优先级高者**：`invalid > superseded > active > pending` | 同上（失效优先，作废的不复活） |
| pending × active | active | 同上（`migrationOriginalStatus='pending'`） |

- **自动满足"败者不进注入与向量库"**：注入只取 `status==='active'`（`page-memory.js:383`），
  `sweepMem` 只切 `status==='active'`（`memory-vec.js:1100-1105`）→ 败者恒 `superseded` 天然被排除；
  **仍要补测试断言**（不许只靠"按理说"）。
- **`isAnchor` 只参与字段合并**（同级合并时取 OR），**不得改变失效状态**（结果是 invalid/superseded 时，锚也不改状态）。
- **`understandings`**：不合并；源键 `understandings` 非空 → **整键不迁不删**、隔离计数（schema 无写入方，无法核实）。
- **`fromCharId`**：源键是脸 → 该脸 id；源键是 root → 自身 id；推不出 → `null`。
- **孤儿键**：无可靠 parent/root 映射 → 隔离 + 计数，不猜、不合并、不删。
- **时间口径**：ISO `localeCompare`（`page-memory.js:68`）。

### 2.5 迁移锁与崩溃恢复（按你的第二条）

**持久化事务状态**（不再只用内存标记）：

```
charMemMigrationState = {
  txn: '<id>', phase: 'snapshot'|'merged'|'verified'|'srcDeleted'|'done'|'failed',
  backupKey: 'charMemBackup:<ts>', affectedRoots: [rootId…], startedAt, updatedAt
}
```

**启动时发现未完成事务（phase ≠ done）→ 三分支**：

| 状态 | 动作 |
|---|---|
| 未校验（`snapshot` / `merged`） | **从 `backupKey` 完整快照恢复**（源键 + 目标键都还原）→ 清事务标记 → 下次重跑 |
| 已校验但未删源（`verified`） | **继续完成**（删源键 → 落日志 → 清标记） |
| `srcDeleted` / `done` | 只清标记 |
| `failed` | 同上"未校验"分支 |

- 写入锁（`isMigrating`）**仍然要有**（内存快，用于挡写入），但**不再是唯一保障**：崩溃靠 `charMemMigrationState`。
- 迁移结束（含失败）**必须清 `charMemMigrationState`**（`finally` + 启动恢复双保险）。

### 2.6 向量块的 `fromCharId`（按你的第五条）

**问题**：归一后块的 `charId` = root，同岛多张脸共用一个 root + 一个 sandboxId
→ `forget({charId: root, sandboxId})` 会**误删同 root 同岛的其他脸**的块。

**定稿**：
1. 块上**新增 `fromCharId`**（产生这条块的那张脸）：
   - chat/offline：sweep 传入的**原 charId**（脸）
   - mem：条目自身的 `fromCharId`
   - phone：`phones.charId`
   - diary（char 写的）/ moments（角色发的）：该脸 id
   - 岛池/账号池/群池：`null`
2. `forget(filter)` 支持组合过滤：**`{charId, fromCharId, sandboxId}`**（三者都给了就必须全中）。
3. **`DB_VER 5 → 6`**，并把游标前缀从 `vecCursor3:` → **`vecCursor4:`**
   （依据 `memory-vec.js:746-749`：DB 升级必须配套作废游标，否则以为写过了、索引永远空）。
   → 老块丢弃重建（沿用"索引本来就可以重建"的既有取舍）。
4. 删皮套：`forget({ charId: root, fromCharId: 该脸, sandboxId: 本岛 })`
   移出岛：`forget({ charId: root, fromCharId: 该脸, sandboxId: 本岛 })`
   —— 两者都**不再**只按 root+sandbox。

### 2.7 备份与保留期

- 备份 = **源键 + 目标 root 键**双份完整快照 → `charMemBackup:<ts>`；
- 失败**整份恢复**（不是按 id 删）；
- **保留最近 3 份**，更早在"迁移成功且校验通过"后清理；
- 备份键含记忆原文 → **纳入清空清单**（§1.4）→ 这也是把项目 1 排在前面的原因。

### 2.8 迁移流水线（终版）

```
1. 写 charMemMigrationState(phase='snapshot') + 上内存锁
2. 读源键（A 组 + charSettings 字段级）+ 前缀兜底捡孤儿键
3. 备份：源键 + 目标键完整快照 → charMemBackup:<ts>；更新 state.backupKey/affectedRoots
4. 合并并写目标（§2.4 规则）→ phase='merged'
5. 校验（数量 / ID 集合 / status / updatedAt / fromCharId / 去重）→ phase='verified'
   不通过 → 用备份整份恢复 → phase='failed' → 清锁 → **不删任何源键**
6. 删源键（含子 map 的键）→ phase='srcDeleted'
7. 落日志 → 清 state（phase='done' → 删键）→ 清过期备份（保留 3）→ 清锁
```

## 4. 项目 3｜解散群（第四个做）

- **`purgeGroup(groupId)` 是唯一公开入口**；页面不得再直接调只清三表的 `removeGroup`

- **顺序（先派生/向量，最后主表）**：

```
1. tombstone：groupOfflineSessions 里该群的行 → status='ended'
2. 清派生：remove('groupPending:'+gid)、remove('groupInner:'+gid)、remove('sumCursor:g:'+gid)

### 5.4 `removeUser`：不转移、不改署名（按第七条定稿）

**本批规则（唯一结论）**：**只解绑"名册归属"，不动任何历史数据的署名，不做转移。**

| 数据 | 处理 | 理由 |
|---|---|---|
| `chats.userId` / `offlineSessions.userId` | **保留原值** | 不改写历史作者；该会话对新 identity 不可见 = 归档 |
| `links.userId` | **保留原条目**（`cognition`/`barrier`/feed 四开关**一字不改**） | 删除动作**不改变任何已有权限**（不放宽、不扩大） |
| `memories.toUserId` | **保留原值** | 记忆可见性不得扩大 |
| `moments.maskId` / `diaries.userId`（user 写） | **保留原值** | 不悄悄改写历史作者 |
| 显示层 | 解析不到的马甲 → 显示「**已删除身份**」 | 不新增字段（若你要显式 `formerMaskId`，说一声） |
| `sandbox.maskIds` | 摘掉该件 | 名册归属必须更新 |
| 保护 | **本岛至少留一件马甲**，否则**禁止删除**（新增；现有全局判断 `core.js:675` 不够） | 保证每岛有"我" |

**若将来要启用"转移"**（本批**不启用**，规则先定好备查）：
- `chats`：default 与其角色**无** chat 才转；**有则不合并**（不无规则拼接历史）；
- `links`：权限取**更严格**值 —— `barrier=true` 优先、`cognition` 取 `unaware`、feed 四开关注"关"优先；
- `moments` / `diaries`：**不改署名**；
- `memories`：仅在"目标马甲不比原马甲更宽松"时才转 `toUserId`。

   charState/openLoops/attentionInbox/diaryAuto/diaryPeek/charSettings **保留**
```
