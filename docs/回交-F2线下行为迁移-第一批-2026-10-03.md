### 1.1 prompt-engine.js

**新增 `btOfflineDecision()`**（`:235-341`），与线上 `btOnlineDecision` 同构但三处刻意不同：

```js
var BT_SCENE_OFFLINE = 'offline';
```

任一不过 → 两个正文一律 `null` + 固定原因码。

### 1.2 page-offline.js

**诊断四阶段**（闭集，不可互相顶替）：

| 阶段 | 含义 |
|---|---|
| `assemble-failed` | 装配就抛了 / 没产出 messages —— **没有出站请求** |
| `at-call-boundary` | 已装配完成、正要交给 `callModel` |
| `model-returned` | 模型这一轮有返回（ok 与 fail 都算到达过服务端） |
| `no-connection` | `callModel` 因无可用连接直接失败 —— **没有出网** |

**`go()` 的真实异步链**（`:1212` 起，与实际调用一一对应）：

```js
var built = null; var seq = 0;
try { built = E.assembleOffline({...}); }
catch (e) { pending = null; setBusy(false);
  diagRecord(DIAG_STAGE.ASSEMBLE_FAILED, null, { modelOk: null }); ...; return; }
if (!built || !Array.isArray(built.messages) || !built.messages.length) { ...同上... }

var behavior = built.behavior || null;          /* ★ 只从这一份 built 取 */
if (userInput == null) built.messages.push({ role: 'user', content: '（开场…）' });

pending = true;
var cand = candForSession(session);
seq = diagRecord(DIAG_STAGE.AT_CALL_BOUNDARY, behavior, { modelOk: null }).seq;
if (!cand) diagRecordIfCurrent(seq, DIAG_STAGE.NO_CONNECTION, behavior, { modelOk: false });

callModel(cand, built.messages).then(function (r) {
  if (diagSeq !== seq) return;                  /* seq 守卫：迟到结果直接丢弃 */
  pending = null; setBusy(false);
  if (!r.ok) { diagRecord(DIAG_STAGE.MODEL_RETURNED, behavior, { modelOk: false }); ... return; }
  diagRecord(DIAG_STAGE.MODEL_RETURNED, behavior, { modelOk: true });
  var parsed = E.parseOfflineReply(r.text);    /* ← 以下原样，未动 */
  ...
});
```

**为什么必须有 `no-connection` 这一档**：`callModel` 在 `!cand` 时是
`return Promise.resolve({ ok:false, error:'还没有可用的模型连接…' })` ——
**直接失败、不出网**。若只记「已到达调用边界」，会把「准备调用」说成「已经调用」。

**并发守卫**：`diagSeq` 单调自增，`diagRecordIfCurrent` 与 `then` 头部各比对一次
—— **比 seq，不比时间**（同一毫秒内两次请求时间不可分）。

**查看入口**：设置 sheet 第三个页签「请求诊断」，`<details class="off-diag-fold">` **默认折叠**，
标题「展开查看」，区块标题「最近一次线下请求」。
**刻意不在沉浸正文常驻技术状态行** —— 只放设置里。

**对外只读口** `Sleepy.offlineDiag`：`snapshot()` / `stageLabel()` + `__` 前缀测试钩子。
**不提供任何外部写入或清库接口**；记录只由本文件内部调用链产生。

### 1.3 诊断字段（白名单，九个）

```js
{ seq, at, stage, behaviorUsed, reason, touched, version, modules, modelOk }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | number | 本地请求序号，单调自增，刷新归零 |
| `at` | string | ISO 时间 |
| `stage` | string | 四阶段闭集 |
| `behaviorUsed` | boolean | **本次装配是否真的采用了新正文** |
| `reason` | string | 固定原因码，成功时为空串 |
| `touched` | boolean | 是否因用户 override 回退 |
| `version` | string | 受校验的版本锚 |
| `modules` | string[] | **实际使用**的模块 id；**回退时为空数组** |
| `modelOk` | boolean\|null | null = 本轮未到返回 |

**不记录**：prompt 正文、聊天内容、角色名称、用户 override 内容、异常全文、API 配置（baseUrl / model / key）。
**不入库、不上传、不写聊天记录。** 刷新即失。

**脱敏样例**（夹具跑出来的真实形状，无任何真实数据）：

```json
{
  "seq": 3,
  "at": "2026-10-03T14:52:07.481Z",
  "stage": "model-returned",
  "behaviorUsed": true,
  "reason": "",
  "touched": false,
  "version": "sleepy-behavior-v1-review-01",
  "modules": ["B", "P", "L", "N", "S2"],
  "modelOk": true
}
```

回退时（**关键：候选可用不冒充已使用**）：

```json
{
  "seq": 4,

  "stage": "model-returned",
  "behaviorUsed": false,
  "reason": "user-override",
  "touched": true,
  "version": "sleepy-behavior-v1-review-01",
  "modules": [],

}
```
