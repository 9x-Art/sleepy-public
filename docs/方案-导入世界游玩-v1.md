# 方案 · 导入世界入世游玩 v1.1（2026-10-10 晚，按用户纠正修订）

> v1 的「锚点校验=改剧情记异常」**作废**——用户纠正：进局本身就是为了
> 改原书，改变是玩法本体，不是异常。真问题有两个：
> ①改动之后，世界/NPC 如何合理接续；②委托不一定合理/不一定最优，
> 「做得比委托更好」要被承认。

## 一、不变的部分

- 穿书口径 = 外来占位（旅/帮/查，不占书中人）；
- 预读建剧情地图（nodes/npc/places），不每轮喂大段原文；
- 一轮 = 一次调用（叙事+判定同往返）；卷宗重放管接续；
- 出口：委托达成 / 异常度 ≥60（爆表仍封存——但异常度只来自**规则违规**
  与**玩家自己的危险行为**，不再来自「改了剧情」）；暂停存档 / 手动封禁；
- 能量点下下批。

## 二、核心机制一：改动账本（divergence ledger）——NPC 接续的根据

**世界有两层事实：**

1. **书的原事实**（map.nodes + 各 NPC 的 `fact`，预读时登记）——只读底稿；
2. **已发生的改动**（run.divergences）：判定块每轮可以带
   `worldChanges: [{about:"陈婆", change:"知道了邮包里是那封信", at:"第X章"}]`，
   程序校验（字段齐、长度限）后落进账本，**永久累积**。

**NPC 接续的注入规则（每轮 system）：**

- 每个 NPC 档案 = 「原事实 + 与 TA 有关的改动（按人过滤）+ 当前态」；
- 提示词规则写明：**世界角色不知道「原剧情」**——他们只知道自己经历过
  的事（原事实 + 被波及的改动），行为从此出发往后推；
- 判定块同时要求 `npcReactions`：本轮哪些 NPC 因为改动更新了态度/认知，
  程序写回 NPC 的「当前态」（同 ta-life / wj 反应的落库路数）。

→ 接续合理性不靠模型记性好，靠**每轮都看得见「书的事实 + 改动清单 +
NPC 当前态」**；改动越滚越多，NPC 的反应就越有迹可循。

## 三、核心机制二：委托是「愿望」不是「验收标准」

**委托者站在局外**（用户定案：相当于未来的 A 委托我们回过去改变过去的事）：

- 委托在开局前定死，**局中不改口、不追加、不干预**——委托者不参与世界，
  只在结算时「收卷」；
- 世界里如果恰好有委托者的对应人物，那只是**原世界的一部分**：不知道
  原剧情、不知道委托存在，按普通 NPC 的账本规则走（§二）；
- 结算不只看「委托完成了没」，评四样：
  **委托者满意度**（局外的 TA 拿着结果评——真愿望满足程度，可能比表面
  委托做得更深/更好）、**世界受益**（改动对这个世界是好是坏）、
  **char 满意度**、**完成度**；
- 「做得比委托更好」在结算里是**加分项**（超出委托的价值），不是违规；
- 需求清单原话保留：「穿书局评价高，不代表 char 一定满意；char 满意，
  也不代表任务一定符合穿书局规则」——四样分开评，不揉成一个分。

## 四、异常度的新含义

只来自：对世界角色暴露「局」的存在、玩法规则违规（协议卡定义）、
玩家自己选择的危险行动的后果。**改动剧情本身不涨异常度。**

## 五、施工顺序

①委托建议卡（suggest 渲染 + 可改可换人）→ ②预读升级出地图（含 NPC fact）
→ ③ yr-play 接导入世界（四件套注入：席位 / 原事实+改动账本+NPC 当前态 /
当前章原文节选 / 前情）→ ④改动账本落库与 NPC 状态写回 → ⑤四样结算与
出口接线。check+smoke 双绿后真机验收。
