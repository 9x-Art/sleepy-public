# 验收 · 假期表述按「节 ≠ 节假日」分层 + 给全事实 · 2026-10-03

## 一、用户反馈

> 设置是中国大陆，中国传统节日和国际常见节日，时区上海，结果他说今天是国庆第一天

**换了几个 api 也一样，上次中秋也有这个问题。**

## 二、根因：不是措辞不精确，是**事实错了**

`CN_OFFICIAL` 的 `name` 指的是**整段连休的名**（国庆 = 10-01~10-07），
而旧句式 `今天是<名字>` 连着 7 天都说「今天是国庆节」—— **7 天里 6 天是假的**。

模型同时读到两条互相打架的信息：

```
你的现在：2026年10月3日 星期六 19:36（上海 · Asia/Shanghai）
公共日期（中国大陆）：今天是国庆节（假期期间的周末）。
```

一条说今天是 10 月 3 日，一条说今天是国庆节（通常＝10 月 1 日）。
模型调和这两条的最省力方式就是**采信节日名、忽略日期** → 说「国庆第一天」。

**它不是算错了，是我们逼它二选一。** 换几个 API 都一样，正说明是原文的结构性误导。

同病案例（都实测过）：

| 案例 | 表现 |
|---|---|
| 中秋 2026-09-26/27 | 两天都自称「今天是中秋节」 |
| 清明 2026-04-04~06 | 假期 04-04~06 但**清明当天是 04-05** → 前后各一天都自称「今天是清明节」 |
| 春节 2026-02-15 | 那天是腊月二十八，也自称「今天是春节」 |

## 三、方案：用户 2026-10-03 拍板

> 感觉 B 好一点，就是包括日历上也可以是写明"国庆假期"而不是"国庆节"，节和节假日是有区别的

**「节 ≠ 节假日」这句话直接点了病根** —— 病根正是这两个概念被混用了。

### 1. 数据层：假期名与节日名分层

`calendar-data.js` 的 `name` 改成**假期名**：

```
2026: 国庆假期 / 中秋节假期 / 清明节假期 / 春节假期 / 劳动节假期 / 端午节假期 / 元旦假期
2025: 国庆中秋假期（那一年是合并连休）/ 元旦（单日，不加后缀）
```

- **单日的块不加「假期」后缀** —— 没有区间就没有歧义。
- **规则型区域（JP/US/UK/KR）一个字都没动** —— 它们全是 `MM-DD` 单日，
  `name` 就是当天名（`成人の日`/`Thanksgiving`），本来就是对的。

### 2. 计算层：记下区间与第几天

`buildYear` 每条记录带上 `from` / `to` / `span`，多日连休另带 `day` / `total`。

⚠️ **踩过的坑**：`daysBetween` 本身**已含首尾**（`from~to = span`），
我在算 `day` 时又 `+1`，结果 10-01 变成「第 2 天」、7 天的假期说成 8 天。
护栏里专门有一条逐日递增断言卡这个。

### 3. 文案层：新增 `calendar.publicDayLine` —— **那一行的唯一出口**

以前 `timeFacts`（喂模型）和 `page-calendar` 日列表（给人看）**各拼一次**，
所以同一个错在界面上会重现一次。现在两边共用同一个出口。

```
公共日期（中国大陆）：国庆假期（10月1日—10月7日，共 7 天）· 今天是 10月3日，是这段假期的第 3 天。
```

三件**不需要模型推理**的事实一次给全：区间、今天、第几天。
单日假日仍走 `今天是成人の日（法定放假日）`（没有区间就没有歧义）。
调休上班日、补班日、2027 降级（无内置数据）三条分支各自保持原口径。

日历页日列表同步：多日连休标题变成 `国庆假期 第 3/7 天`，描述里带区间。


### 两条护栏自己踩的坑（第一版假绿 / 误报）

- **③ 第一版没抓到**：正则里的 `\s` 经 python 写入变成了字面双反斜杠
  `\\s`，匹配的是字面「\s」。**写正则断言必须用 Edit 工具落，不要经 shell 转义。**
- **真机清明断言第一版误报**：文案是 `今天是：清明节。`（**冒号在**），
  我断言写成 `今天是清明节。` → `indexOf` 永远 -1，看着像功能坏了。
  已把该前缀提成一个具名常量 `FEST_PREFIX` 并写明原因。
