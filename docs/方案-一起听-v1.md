## 二、红线（施工时不许破）

1. **不破「双击就能开」**：曲源必须浏览器直连。项目第一条约束（`app.js:7` 的 D9、
   README 第一句「本地优先」、`page-tts.js:1054` 的「没有服务端代收凭据」）——
   为网易云加后端代理**不划算**，详见第三节。
2. **成功判据不能只看 HTTP 状态**：Jamendo 失败时也是 `HTTP 200`，真判据在
   body 的 `headers.status`（`success`/`failed`）与 `headers.code`。这条跟 MiniMax
   （`base_resp`）是同一个坑。
3. **三层边界**（照 TTS 的三层文本边界）：
   - **曲目数据**（服务商返回的真字段：id / name / artist / audio url / duration）
   - **共听叙事**（角色说的话，是我们自己的业务数据）
   - **播放状态**（本地运行时，不进存档或只进最小字段）
   服务商字段**不许漏进业务数据**（比如别把 `audioformat=mp32` 拼出来的 URL 存进存档 ——
   它是会过期的临时直链）。
4. **不伪造成功**：连接测试、试听、播放一律不许假成功（TTS 那轮的反面教材已经吃过一次）。
5. **播放/共听挂了不影响聊天**：音乐是加分项，不许拖垮主链路。
6. **许可（2026-09-23 查官方 ToS 后补全，原文引在 §三.4）**：
   - **免费 API 只许非商业用途**；商业（含广告 / 内购 / 联盟推广收入）必须找
     `licensing@jamendo.com` 谈授权 —— **这决定本功能能不能进商业项目**。
   - ⚠️ **条款明文禁止「专门为缓存内容或提供离线访问而设计」** —— 这条**跟 sleepy 的
     「本地优先 / 双击就能开」正面冲突**：音频**只能在线流播**（`<audio src>` 用现取的 URL），
     **不许存进 IndexedDB 长期离线听**，SW 也不许缓存音频。
   - **强制署名**：要标「创作者（Jamendo 会员）」+「JAMENDO 提供内容」，且**每首曲目要有
     一条直链回到它在 Jamendo 平台上的页面**。
   - **不许**用 `jamendo` 或近似元素当 App 名 / 商标 / 域名 / logo / 配色
     （我们定名「一起听」，正好避开 —— 这条也是当初不叫「网易云」的正确性佐证）。
   - `audiodownload_allowed=false` 的作品**不许提供下载**（`audiodownload` 会是空串）。
   - **single（单曲）的 `album_image` 是空串**，必须处理，否则封面裂图。
   - 免费额度 **35,000 次/月**；超 50 万 hits 要联系 `api@jamendo.com`；他们保留将来
     收费或在 API 里插广告的权利。

## 三、真实探测结论（都是刚跑出来的，不是猜）

### 1. 网易云：直连走不通，三条死因

| 探针 | 结果 |
| --- | --- |
| `OPTIONS music.163.com/api/search/get/web` | `200`，但响应头**无 `Access-Control-Allow-Origin`** |
| `GET` 同接口 | **服务端有真数据**（返回真 JSON），但同样无 ACAO → 浏览器必被拦 |
| `GET music.163.com/song/media/outer/url?id=186016.mp3` | `302 → http://music.163.com/404`，版权歌取不到 |
| 登录 / 歌单 | 走 weapi（AES+RSA 签名）+ OAuth 回调域名，纯静态无服务器做不到 |

**结论**：加 Cloudflare Pages Functions 代理**能通**，但代价是「双击就能开」作废 + 用户的
登录 cookie 要经过我们的服务器（与「数据不出门」正面冲突）+ 版权歌直链照样 404。
**放弃网易云，选 Jamendo。**

### 2. Jamendo：CORS 放行，但必须 client_id

| 探针 | 结果 |
| --- | --- |
| `OPTIONS api.jamendo.com/v3.0/tracks` | `200`，**`access-control-allow-origin: *`** ✅ |
| 不带 `client_id` | `code 5`「credential is not authorized」 |
| `client_id=test` | 同上 `code 5` |
| 官方文档里那个老 demo key | `code 11`「application has been suspended」（已停用） |

**结论**：浏览器直连成立，但**必须有有效的 `client_id`**（注册地址官方文档明确写了
`devportal.jamendo.com`）。**这是最后一公里，只有用户能走完。**

### 3. 还没验的那一段（诚实记账）

- 真实 `client_id` 下的**字段实测**（`audio` 直链能不能直接喂 `<audio>`、返回的
  CDN 域名是什么）—— 没有 Key 拿不到真实响应，只能等。
- 用**故意错的 Key 发真请求**验跨域与错误归一化 —— 这条**不需要真 Key 就能做**
  （skill §5.1 的标准手法），开工第一批就做。

### 4. Jamendo 许可条款 —— 决定「能不能商用」（查官方 ToS）

原文：`devportal.jamendo.com/api_terms_of_use` §3.3 Restrictions：

> including but not limited to commercial uses please contact our sales team at
> licensing@jamendo.com … **Commercial use shall be understood as any use that is
> intended for or directed toward commercial advantage or any monetary compensation,
> including any revenue arising from affiliation programs or advertising.**

- **免费 API 只给非商业**；商业要联系 `licensing@jamendo.com`（Jamendo 本来就有
  Pro / royalty-free 授权业务）。devportal 首页也把免费档直接叫 **"Non-Commercial Apps"**。
- 「商业」的定义**很宽**：广告收入、联盟推广、内购、卖钱 —— 只要指向商业利益或金钱补偿都算。
- §4.1 强制署名（创作者 + JAMENDO + 每首曲目直链回 Jamendo）；
  §4.2 **不许**用 `jamendo` 或近似元素当 App 名 / 商标 / 域名 / logo / 配色；

## 四、官方规格（对着文档抄的，不是转述）

来源：`developer.jamendo.com/v3.0/tracks`。

- **必需**：`client_id`。**可选**：`format=json`、`limit`（默认 10，**最大 200**）、`offset`。
- **搜索维度**（对「角色点歌」极有用）：
  `search`（自由文本，含曲名/专辑/艺人/标签）、`tags`/`fuzzytags`（布尔/模糊）、
  `vocalinstrumental`（vocal/instrumental）、`acousticelectric`、`speed`（verylow…veryhigh）、
  `gender`、`lang`、`durationbetween`、`featured=1`（Jamendo 官方精选）。
- **排序**：`order`（默认 `relevance`）、`boost`（在搜索里加权，不破坏相关性）。
- **音频格式**：`audioformat` = `mp31`（96kbps，默认）/ `mp32`（VBR 好音质）/ `ogg` / `flac`。
  → 我们取 **`mp32`**。
- **封面尺寸**：`imagesize` 枚举（60/100/200/300/…）→ 我们取 **200**。
- **返回**：`audio`（**流地址**）、`audiodownload`（可下载空串）、`audiodownload_allowed`、
  `id` / `name` / `artist_name` / `duration` / `album_name` / `album_id` / `image` / `album_image`。
- **错误体**：`{headers:{status:'failed',code:N,error_message:'…'},results:[]}`。

## 七、共听机制：角色怎么「点歌」（本方案的核心）

**不能**让模型直接编歌名（编出来搜不到，或搜到一首不相干的，破戏）。
做法与生图的「导演请求」同构：**模型只出意图，程序去执行**。

```
角色当前情境（人设 + 近期聊天 + 现实时间 + 我上一首在听什么）
        ↓  directorAsk（复用 page-chat.js:2980，一次非流式）
{ mood: '安静', why: '深夜了', speed: 'low', vocal: 'instrumental', tags: ['piano'] }
        ↓  纯函数 buildSearch(intent) —— 把意图映射成 Jamendo 查询参数（闭集白名单）
        ↓  music.js 的 search()（唯一发送函数，可注入 transport）
真曲目（id/name/artist/audio/duration）
        ↓  落一张 assistant 的 music-share 卡 + 它的一句话
```

**红线**：`buildSearch` 的映射是**闭集白名单**（文档里出现过的字段值才进映射表），
映射不到就**退回默认查询**，不许拼一个可能 400 的参数（这条是 TTS 标签白名单的同一条）。

### 会话状态机（照 `wj-coread.js`）

- session：`{id, charId, status:'invited|active|paused|ended', currentTrack, transcript[], memorySaved, ...}`
- 状态流转 `invited → active/paused ↔ → ended`。
- **结束时只产出一条记忆候选**（`candidateFor()` 那种），写进 memoryStore 的 `pending`，
  由用户确认 —— 铁律复述一遍：**「一起听了歌」是真事件，「听了之后聊了什么」是叙事**。

## 十一、给用户的收尾路径（最后一公里）

1. 去 `devportal.jamendo.com` 注册，拿一个 **Client ID**（免费）。
2. 打开「一起听 → 设置」，填进去，点「测试连接」。
3. 搜一首、点播放。
4. 回聊天点「一起听」分享给 TA，看 TA 怎么回应。

> 在拿到真 Key 之前，第 1–8 项都能做，第 2 项就能验掉「直连成不成立」，
> 第 9 项用假 transport 验完整个链路。**唯一没验的就是真实曲库那一段**。
