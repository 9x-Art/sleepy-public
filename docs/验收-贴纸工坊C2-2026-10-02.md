## 一、按施工单顺序的落点（文件 × 关键函数）

### P2 数据模型与可见性（page-stickers.js）
- `isC2(s)`：存在任一 owner 字段或 `kind==='sticker'` 即按 owner 规则（老数据 legacy 不混判）。
- `legacyVisible(s)` / `c2OwnerVisible(s, ctx)`：**新旧分流，不是一个布尔表达式**；
  `global` 对 C2 专属贴纸**永不生效**（禁止 `global || ownerMatched`）。
- `getVisibleStickers(ctx)`：统一读取出口，ctx = `{scope:'chat'|'group'|'collection', charId, maskId, groupId}`；
  缺省字段用当前身份补；无 scope 的调用**不放行 C2 专属**（宁严勿泄）；岛隔离仍适用。
- 身份映射（施工单允许的映射声明）：本产品「user」= 一件马甲（userMasks 表），
  `context.maskId = core.activeUserOnIsland()`；`ownerUserId` 记**创建时那件马甲的 id**；
  私聊会话的 maskId = `chat.userId`（跟人走的会话绑定）。
- 写口：`addSheetStickers(records)`（all() 读全量 + tagScope 盖房章 + 一次整批 save）、
  `removeSheet(sheetId)`（只删整版条目 + 回收切片媒体）。
- `match(query, limit, ctx)` / `replySpec(ctx)`：推荐条与 char 说明书都按会话上下文过滤；
  管理页列表换 `getVisibleStickers({scope:'collection'})`。

### P3 生成（imggen.js）
- 定稿词常量 `STICKER_PROMPTS`（VERSION='c2-v1'）：both / single_male / single_female
  三版 + both/single 两份负面词**逐字落库**（实施单原文），`composeBoth/composeMale/composeFemale`
  + `customSlices(lines)`（自定义只换六段，base/负面/模板级约束不动）。
- `generateStickerSheet({target, subjects, imageLocks, prompt, negativePrompt, api, size})`：
  词**原样直发**（不进 buildFormalPrompt）；复用 `imageRefIntentFor → resolveRefData →
  requestGeneralEdits / requestChat → storeBlobResult` 内部链；
  锁脸全主体必须带图（locks 缺省全 true，缺图逐个点名）；
  NAI → `NAI_UNSUPPORTED`、refSupport 不符 → `UNSUPPORTED_REF`、缺图 → `MISSING_REFERENCE`
  （stage 'resolve-ref'，全部**前置失败零生成请求**）；
  图库落库失败（mediaId 空）→ `STORE_FAILED`；日志区分参考图拉取与生成两次请求。
  `storeBlobResult` 加 meta 参（整版存 `kind:'sticker-sheet'`）。

### P4 切片器（新文件 sticker-cut.js，index.html defer 引入，sw warmShell 自动预缓存）
- 纯函数：`removeOuterBackground`（**四条边种子** flood-fill，只清连通背景）、
  `splitStickerSheet3x2`（固定 3×2 网格逐格处理，非全局连通域）、
  `trimStickerCell`（alpha bbox + 可配置外扩/最小面积）。
- 浏览器包装：`cutSheet3x2(blob, {threshold})` → 6 格 `{sliceIndex, blob, width, height, empty, bbox}`；
  空格/全透明/面积过小 → `empty`，绝不静默产出空贴纸；重切只改临时结果。

### P5 工坊页（page-collection.js，替换占位）
- 五步流 `paintSkTarget/Style/Generate/Preview/Save`（模块态 `skState`，身份变了自动重开）：
  ① 三态卡 + 缺图引导（`ctx.open('contact-edit'/'mask-edit', {id, sandboxId})`，不猜性别）；
  ② 内置（单人按性别分版，资料缺在页内明选）/ 自定义 6 槽（预设 12 情绪下拉 + 80 字
  单行英文输入二选一）；
  ③ 生成（错误面板照搬生图口径）；
  ④ 预览（空格标红 / 阈值滑杆重切 / 单片删除 / <1 张有效禁入库）；
  ⑤ 命名（情绪中文名）+ 归属（user 单人马甲多选，`[]`=不可见 明示）+ 入库
  （先媒体后 stickers；失败报 sheetMediaId 可重试）。

### P6 聊天/群聊/char 匹配（page-chat.js / page-group.js）
- 私聊 `stickerCtx()`（chatId → charId，chat.userId → maskId）：面板池、推荐条 match、
  说明书 replySpec 全走统一出口。
- `charSendSticker`：**matchKey 优先 → name 唯一 → 模糊唯一**，0 个或多个候选**都不发**
  （同名不跨角色猜测，施工单 §七）。
- 群聊 `stickerPool`：`{scope:'group'}` —— 只放 user 单人（char 单人/双人不进群，
  `allowInGroups` 本批恒 false，施工单 §一.1）。

### P7 藏品实贴（page-collection.js）
- 拍立得槽位 → `openStickerDrawer`（页面内 absolute，we-drawer 范式；
  数据源 `getVisibleStickers({scope:'collection'})` 只列 C2 切片）。
- 贴入 `pasteSticker`：**媒体快照复制**（media.get → media.put 新 id）→ 随机 -6°~+8°
  （0.1° 精度）→ `weStore.patch(en.id, {stickers:[…]})`。
- 渲染：`.co-pl-pasted` img 挂在相纸上（旋转角存数据）；**藏品存自己的 mediaId 快照**，
  表情包条目被删 / 整版清理不影响已贴藏品（施工单 §八）。

## 三、坑与取舍（施工时的真实发现）

1. **smoke 岛类型坑**：测试里用 `'isle'` 塞两个角色被「孤岛只能 1 个角色」校验静默拒
   → 名册空、身份指针失效；换 `'archipelago'`。
2. **ImageData 实例**：纯函数区返回裸 `{data,width,height}`，`putImageData` 只认真
   ImageData —— 导出前 `new ImageData(...)` 重建。
3. **edits 端点响应格式**：OpenAI 风格 JSON `{data:[{b64_json}]}`，不是裸 PNG。
4. **die-cut 白边保留的原理**：贴纸轮廓线（深色）把圈内白底与背景白隔开，
   flood-fill 穿不过轮廓 → 圈内白自动保留；全局近白→透明会毁掉它（施工单禁止项）。
5. smoke 连续两次背靠背启动有收尾竞态偶发 exit 1，单跑为准。

- **扫描结论**：`page-collection.js:1491` 存的是 `st.user.id` = 创建时 `activeUserOnIsland()`

  （user 侧归属凭据）」，双人可见性改为 **ownerCharId 匹配 + 本岛隔离**——

  user 单人仍精确按 ownerMaskIds（未勾选马甲不可见）✓。

## 2. 旧 stickers 数据 kind 扫描（无污染，isC2 不改）

  六条写路径（addBatch / add / update / setGlobal / setGroupGlobal / move / remove）
