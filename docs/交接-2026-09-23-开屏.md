## v117 补的两件事（2026-09-23 晚）

上一版有一个明显的收尾问题，用户给的指令是「点进去网址就开始我们的动画，最后 sleepy
呆一下之后就自动进入桌面」—— 后两句正好是缺的：

### 1. 播完自动进桌面（原来是"只能点一下"）

上一版 `finish()` 的唯一调用点是 `pointerdown`：动画停在 sleepy 上**再也不动**，
用户只看到名字停在那儿、以为卡死。

现在：logo 浮现完 → 停 `CFG.logoHold:850` → `finish(CFG.outFade:420)` 自己摘遮罩。
**点击仍然只是"提前结束"，不是唯一出口。**
`finish(fade)` 因此多了个时长参数：点击跳过用 220ms（要跟手），自动收尾用 420ms
（要柔 —— 夜色得**化开**，不能切）。**注意别把 `finish` 直接当监听器传**：
`pointerdown` 的实参是事件对象，会被当成 fade。

### 2. 预遮罩 `#splash-pre`（原来是"先闪一下桌面"）

splash.js 排在所有脚本**最后**（这个顺序不能动，见下文第 1 点），所以在它执行前，
浏览器画的**已经是桌面**。探针实测（headed + 截图驱动）：

| 时刻 | 事件 |
|---|---|
| 937ms | `#splash-pre` 被升级成 `#splash` |
| 1003ms | 桌面渲染完成（bootHome） |
| 1026ms | first-paint / FCP |

改之前的同一支探针：**桌面 742ms 渲染完、遮罩 881ms 才插进来** —— 中间那 139ms
就是「一进网址先闪一下主页」。现在 `index.html` 的 `#phone` 里先写死一层夜色空壳，
**第一帧就是夜色**（截图 `f001` 实测），splash.js 执行时把它升级成 `#splash`。

⚠️ 三条早退路径（`?splash=0` / 没有 `#phone` / 减少动效）**都必须 `bail()` 掉它**，
漏一条就是「减少动效」的用户冷启动**永久黑屏**。style.css 另加
`#splash-pre{animation:sp-bail 0s linear 7s forwards}` 兜底（splash.js 万一报错，
7 秒后自己退开）。smoke 三条断言分别锁这三件事。

## 它是什么

冷启动时，`#phone` 里盖一层全屏遮罩（`z-index:300`，连状态栏一起盖），播一段约 **9.5 秒**的动画：

```
纯夜色 → 十六句古今中外的诗句散落浮出 → 一起退去 → 「爱」
      → 天亮 → sleepy 浮现 → 停住 0.85s → 淡出 → 桌面
```

- **播完自己进桌面**（不用点）；**点任意处只是提前结束**（淡出 0.22s 摘掉）
- **「减少动效」或系统 `prefers-reduced-motion` 时整段不播**，直接进桌面
- 调试：`?splash=0` 关掉、`?splash=1` 强制播放

## 七个「以后很容易被好心改回去」的点

### 1. 脚本必须排在 index.html 最后

`page-chat-settings.js` 末尾才调 `Sleepy.bootHome()`（`app.js:745`），
**在那之前桌面是空的**。splash 排在最后，是为了保证遮罩下面**早就渲染好了** ——
摘掉遮罩那一下才不会白屏。

> **代价**：正因为它排在最后，在它执行之前浏览器画的已经是桌面 —— 所以
> `index.html` 里必须有那层 `#splash-pre`（见下第 6 点）。
> 「排最后」和「预遮罩」是**一对**，动一个就要想另一个。

### 2. 「减少动效」是 splash.js 自己拦的，**不能靠 CSS**

`style.css:6761` 那条

```css
#phone[data-motion="off"] *{ transition:none !important; animation:none !important; }
```

**只杀 CSS 动画，杀不到 WAAPI**（`el.animate()` 不受 `animation` 属性管辖）。
splash 用的正是 WAAPI，所以必须自己判断 `data-motion` 与 `prefers-reduced-motion`。

> ⚠️ **这条是通用坑**：项目里以后任何用 WAAPI 写的新动画，都得自己补这一条。
> 一刀切保护不到它。

### 3. sleepy 的字体必须 base64 内嵌，不能外链

`@font-face` 指向本地 `.woff2` 在 `file://` 下会被 Chrome 的 CORS 拦掉，
而**「双击 index.html 就能开」是不能破的底线**。所以做成 data URI。

字体只子集化了 `s l e p y` 五个字形（1.88 KB）——
Google Fonts 的 `&text=` 参数原生支持，不需要 fonttools。换字体重跑脚本即可（见文末）。

### 4. 颜色不写死，跟着主题走

`getComputedStyle(phone)` 取 `--g-base` / `--g-accent`：
天亮亮到**当前主题底色**、sleepy 用**当前主题强调色**。
所以青提玻璃 / 海盐 / 蜜桃 / 夜灯主题下都不会跳色。

### 5. 不写任何「已播过」标记

页面加载＝冷启动（站内切页走 `.page` 栈，**永远不会重载**），天然不会重播。
加 `sessionStorage` 只会带来一个副作用：**刷新不播**，调试时看不到第二遍。

### 6. 预遮罩 `#splash-pre` 的三条早退**缺一不可**

`index.html` 里那层夜色空壳是「第一帧就是夜色」的唯一保证（原因见第 1 点）。
它只在**一条**路径上被正常升级：动画真的播。另外三条早退路径
（`?splash=0` / 没有 `#phone` / 减少动效）**必须显式 `bail()` 掉它** ——
漏一条，「减少动效」的用户冷启动就是**永久黑屏**（他被锁在夜色里，什么也点不了）。
smoke 用 `(splash.match(/bail\(\);/g) || []).length >= 3` 锁这个数量。

### 7. `finish()` 的时长参数不是装饰

`finish(fade)` 两个入口两个值：点击跳过 220ms、自动收尾 420ms。
**别把 `finish` 直接挂成监听器**（`el.addEventListener('pointerdown', finish)`）——
`pointerdown` 的实参是事件对象，会被 `typeof fade === 'number'` 判掉并回落 220ms，
**看起来是对的、实际是靠运气**。现在是包一层显式调用。

## 时长为什么是 8.2 秒（以及不要再动它）

用户先嫌「太快」（当时间隔 160ms），调成 270ms 后又嫌「太长」（12 秒）。
**所以这次不能靠缩间隔省时间** —— 那会直接回到被否掉的版本。

用的两个办法：

1. **句子间隔递减**：`gapStart 290 → gapEnd 105`。
   开头**比原来还慢**（290 > 270），后段快起来，平均间隔降到约 197ms。
   副作用是好的：后段句子互相重叠入场，从「一句一句来」变成「潮水涌上来」。
2. **sleepy 提前 150ms 开始**（`CFG.logoLead`）：让「天亮」和「名字浮现」咬在一起。

时间表：

| 时刻 | 事件 |
|---|---|
| 0.40s | 第一句浮出 |
| 3.36s | 最后一句出现 |
| 5.04s | 「爱」出现 |
| 6.97s | 天亮 |
| 8.24s | sleepy **落定** |
| 9.09s | 停住 0.85s 后开始淡出（`logoHold`） |
| **9.51s** | **进桌面**（+ 0.42s 淡出 `outFade`） |

**动画本身仍是 8.24s 落定，用户感知总长约 9.5 秒。**
**要再短只能减句子**（16→14 约省 400ms）。**不要再动间隔。**

## 时序安全（这里踩过坑，改参数必须重核）

初版「爱」入场动画的 `duration` 是 1300ms，但淡出的调度时间是 `420ms` ——
**入场只播了 32% 就被后创建的淡出动画打断**，而且淡出第一帧写死了 `opacity:1`，
于是「爱」被从半透明硬拽到全透明再变暗，看起来就是**闪了一下**。

> **通用规则**：`setTimeout` 的延迟若要排在一个 `animate()` 之后，
> **必须 ≥ 那个 animate 的 duration**。否则新动画会打断旧动画，硬编码的首帧会造成跳变。

当前四拍之间都留了安全间隙（句子退场 4.40→4.82s；“爱”入场 5.04→5.82s；不重叠）。
**唯一有意的重叠**是天亮（6.97→7.55s）与 sleepy（7.40→8.24s）—— 但两者作用于不同元素，安全。

## 探针（自动验证用，2026-09-23 晚记）

`D:/tmp/probe2.cjs`（playwright-core + 系统 Edge）能回答「第一帧画的是什么」。

**踩过的三个坑，下次别再来一遍**：

1. **无头模式下这个页面的定时器会被冻住** —— 200ms 的心跳 14 秒只跑 4 次，
   整条动画时间线测不出来（`splash.js` 全部同步代码都执行了，但 `setTimeout` 队列不动）。
   加 `--disable-background-timer-throttling` / `Emulation.setFocusEmulationEnabled` /
   `Page.setWebLifecycleState('active')` **都不够**。
2. **必须用「截图来驱动」**：`page.screenshot()` 会强制渲染一帧、顺手把定时器队列推起来。
   纯 `sleep` 等不到动画，纯 `evaluate` 轮询也等不到。
3. **`addInitScript` 里 `document.documentElement` 可能是 null** ——
   这时 `MutationObserver.observe(null, …)` 直接抛 TypeError，
   **后面所有打点全没了**（看起来像"功能没跑"，实际是被自己的探针吞了）。
   要先用 `setTimeout` 轮询等它出现。

判断「首帧是不是夜色」不看 rAF（它的第一次回调 ≠ 第一帧绘制），
看 **CDP screencast 的第一帧图像**（第一帧就是浏览器画的第一眼）。
