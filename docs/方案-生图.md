## 0. 一句话定位

查岗是**单向偷偷看**（TA 不知情 + 40% 察觉）；生图是**明面上的图片互动**——
我发一张给 TA，或者 TA 发一张给我。两者共用同一条生图管线
（imggen.js：接口配置 → 拼提示词 → 生成 → IndexedDB 图库 → mediaId）。

## 1. 两种显式模式

### A. 我发一张（user → char）
- user 写一句中文画面描述，AI 起稿转成 tag（复用查岗的「导演」请求），
  预览后发送。
- 消息类型沿用 `type:'photo'`（mediaId + name），上下文以
  「[我发了一张照片：xxx]」出现——零新机制。

### B. 让 TA 发一张（char → user）
- user 输入意图（可留空 = TA 自己决定发什么）。
- **导演请求**（主 API，一次）：角色卡 + 近期聊天 + 意图 + 现实时间 →
  `{ subject（英文 tag）, caption（TA 发图时配的一句话）,
  refuse（TA 可以拒绝：不爱发自拍/在忙/不想给，给一句拒绝的话）}`。
- **拒绝也是结果**：refuse 时只落一条纯文字回复，不生图——
  比百依百顺像活人，也是防滥用的天然闸门。
- 生图（`faceText: char.faceLock` 锁脸）→ `role:'assistant'` 的图片消息 +
  caption；attachText 输出「[你发了一张照片：{caption}]」，
  TA 记得自己发过什么。

## 2. 图片理解：user 发图，char 当轮读图（多模态）

大部分接口都是多模态的，所以 **user 发的照片不再只是文字占位**：

- `type:'photo'` 的消息进 buildMessages 时，从图库（media blob）取 data URL，
  组成多模态 content 数组（`[{type:'text'},{type:'image_url'}]`），
  char 在回复的那一轮**直接看到图**。
- 回落：接口不支持多模态（请求报错含 image 相关字样）时，
  自动降级为现有的「[我发了一张照片：xxx.jpg]」文字占位并提示一次。
- 只对 user 发的真实图片生效；表情包继续走文字解释（那是另一套语义）。

## 3. 日常对话里 TA 主动发图（★ 要做）

主动消息带图后置，但**普通聊天中 TA 要有主动生图发图的能力**：

- 机制照抄表情包：模型在回复正文里写 **`[生图:一句话描述]`**，
  程序抽出标签 → imggen 生成（锁脸自动带上）→ 文字气泡后面跟一张
  assistant 图片消息。
- 说明卡（c05 或单独小卡）教三件事：什么时候值得发图（分享生活/展示了
  什么东西/对方想看）、不要每轮都发、发图要配 caption。
- 消息落库带 `subject`，TA 记得自己发过什么图、说了什么。

## 4. reroll 图片

- 不做局部重绘，但**图片消息支持 reroll**：同 `subject`（消息上存着）
  重新生成一张替换 mediaId，caption 不变。
- 入口：assistant 图片消息的 meta 行挂「重画」（沿用 reroll 按钮的位置）。

## 5. 提示词拼装：男 / 女 / 静态怎么办

拆成**两个正交的维度**，谁的数据谁负责，不复制两份全局预设：

### 维度一：人物差异 → 角色侧数据（K 层）
- **角色档案加「性别」字段**（女 / 男 / 其他）：
  生图时自动拼基础 tag `1girl / 1boy`（其他性别手填 tag），加上
  该性别惯用的画面词（如女性向的 delicate face、男性向的 handsome 等
  少量差异词，放内置映射，不进用户预设）。
- **锁脸分组**：`faceLock.base`（必填：发色/瞳色/年龄感等身份特征）+
  可选场景组（`selfie` 自拍近景 / `fullbody` 全身 / `scene` 在场景中）。
  导演/发图时按画面类型选组，base 永远带上——近景和全身才不会两张脸。
- 男角色、女角色各自的差异全部落在**角色数据**里（锁脸 + 性别 tag），
  全局预设只写一份。

### 维度二：画面差异 → 预设侧档位（P 层）
- 内置预设分两档：**人物向**（现行的质量词，保证脸和手不崩）和
  **场景向**（去掉人物质量词，换 `scenery, no humans, detailed background`
  等静态场景词）。
- 选档规则：subject 里含 `1girl/1boy/人物 tag` → 人物向；没有 → 场景向。
  「静态」（空景/物件/风景）自动落到场景向，不用人管。
- 用户自定义预设照旧可改（newApi 拷出厂值），档位只是出厂起手式。

### 拼装顺序（buildPrompt 扩展，向后兼容）
```
预设基底（人物向/场景向，含 {p}）
  ← 性别基础 tag（1boy/1girl，来自角色档案）
  ← 锁脸组（base + 按画面类型选的组）
  ← 动态段（subject）
  ← 用户自定义词条
```
现有 `char.faceLock`（字符串）向下兼容：有分组的用分组，只有字符串的
当作 base 用。
