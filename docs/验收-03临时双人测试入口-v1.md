## 2. 拼接层序（本轮永久生效在这条实验路上）

```
positive = General qualityPositive
         + TWO_SUBJECT_STRUCTURE（人数/身份归属/不编关系，原文见 imggen.js:881）
         + 'Person A（人物A）: ' + A原文
         + 'Person B（人物B）: ' + B原文
         + 'Scene（画面描述）: ' + 共同描述原文
         + 自定义视觉词（空则为无） + extras（勾选词条）
negative = SLEEPY_VISUAL_STYLE.general.qualityNegative（仅此一份）
```

- 画面描述**只出现一次**（在 Scene 块里），不重复再拼一遍。
- 人物块各自一层；词级去重沿用既有 `joinLayers`/`dedupeTerms`，不做整块合并。
- 负面不沿用单人的 `negativeStructural`（含 extra person），也不取 legacy 整表
  —— 人数与身份约束放在**正向**，避免「负面支持未知」变成「完全没有人数要求」。
- 系统手部附加段**恒空**；不恢复 `handsPositive` / `handsStructure` / `SLEEPY_HANDS_UNIFIED`；
  不拼男女单人底座。用户描述与 custom 里的手部内容照常保留。

## 3. 三组取证（虚拟夹具，无真实身份）

### A 并肩 —— custom 为空 vs 非空对照

**输入**（人物A / 人物B / 想画什么 / 自定义视觉词）：

```
人物A：30 岁成年人，黑色短发，深蓝色外套，面部轮廓清晰
人物B：成年人，栗色肩长发，米色上衣，圆脸
想画什么：两人在安静的海边并肩站在一起看镜头，肩膀靠得很近但没有任何身体接触，身后是平静的海面和黄昏的光
自定义视觉词：（空）
```

**实际请求（`prompt` / `negative_prompt`，浏览器拦截实测，逐个字段抄录）**：

```
positive: masterpiece, best quality, highly detailed, Exactly two people are present in the image: Person A and Person B. Keep each person's described appearance and clothing associated with that person. Follow the scene description for their positions, expressions, gaze, actions, and any physical contact. Do not add other people or invent a relationship or physical contact that is not described., Person A（人物A）: 30 岁成年人，黑色短发，深蓝色外套，面部轮廓清晰, Person B（人物B）: 成年人，栗色肩长发，米色上衣，圆脸, Scene（画面描述）: 两人在安静的海边并肩站在一起看镜头，肩膀靠得很近但没有任何身体接触，身后是平静的海面和黄昏的光
negative_prompt: lowres, worst quality, low quality, jpeg artifacts, blurry
model: two-fixture   size: 1024x1024（取自接口表单，测试接口故意指向不可达端口）
```

custom 非空（同一套人物与场景，只加 `flat graphic illustration, limited 6-color palette, thick clean outlines, soft matte texture`）→ 该串**恰好一份**，且整份 prompt **以空值那份为正前缀**（前后层一个字没动）。

**断言过的负向**：没有 `solo` / `exactly one person`、没有 `1girl`/`1boy` 单人性别标签、
没有 male v2 / female C / 旧默认 look、没有系统手部词、负面无 `old`/`elderly`/`wrinkle`
与 `extra person`。

### B 递物（动作归属）

```
想画什么：人物A 的右手握住一只透明饮料瓶的瓶身下半部，人物B 的左手接住瓶身的上半部，两人看向对方；其余手臂自然放下或被身体挡住。站在海边，黄昏，两人肩膀没有接触。
```
结果：两条手部文本都进请求、各一份；系统没追加任何手部词、也没改写用户原文。
**这只证明文本被保留，不判断图像解剖是否正确**（见 §7 第 3 类）。

### C 非爱情（女儿 / 母亲）

```
人物A：30 岁成年女性，女儿，黑色短发扎成马尾，浅灰色针织开衫
人物B：60 岁成年女性，母亲，花白短发，深咖啡色围裙，手掌粗糙有皱纹
想画什么：母女两人在家里的餐桌边聊天，母亲（人物B）坐在左侧看向女儿（人物A），女儿（人物A）坐在右侧抬头微笑回应；桌上是两杯茶和一碟水果，没有拥抱也没有牵手。
```
结果：年龄、亲属关系、左右与视线都保留；全份 prompt 里 `kiss / embrac / hand in hand /
couple / romantic` **零命中**；负面仍只有那一条 qualityNegative（不压 60 岁主体）。
参照施工单的纠正口径：这里**没有**已证实的文字冲突（上一轮报告里说的 `old/elderly/wrinkle`
压年长主体，本轮在双人路径上**不取用**，但 legacy 表本身没删）。

**照做路径（手机同 Wi-Fi）**：

1. 打开 `http://172.24.16.192:5174/`（本轮实测可达；下次需要时本机跑 `node serve.js --lan`，
