## 0. 先给结论

1. 这不是「加一个写小说功能」。它是 Sleepy 的**第四种时间观**，落地时
   要新增的不是页面而是**一套权限模型 + 一个段落级锚点系统**。
2. 8 张 Demo 里，**真正的地基只有一处**：段落 `anchorId`。阅读、批注、
   共读挂靠、分享段落、局部重写、正史候选来源，六件事全钉在它身上。
3. Demo 是**产品关系的证词**，不是工程结构。它们的 state 全部用
   `window.PolarisRoom`（Demo 平台的持久化桥）——正式版一律换 `Sleepy.store`。
4. 这份包**没有覆盖**三块正式实现必须有的东西：**生成状态机**（排队/暂停/
   取消/失败/重试/幂等）、**成稿检查与局部重写**、**分支树与版本比较**。
   第 6 节把它们补进梯队。
5. 最大的**未解冲突是视觉**：Sleepy 是纯白底 + 焦糖（`--g-base:#FFFFFF`
   / `--g-accent:#B08A5E`），帷境 Demo 是深夜蓝 `#0d1424` + 月光纸本
   `#eee8dc`。这两套不能直接叠——见第 8 节问题一。

## 1. 我的理解

### 1.1 一句话

帷境是一个**默认私密、默认非正史、默认人物不知情**的私人叙事空间：
以剧院语法做入口仪式（帷境/门厅/开帷/同席/谢幕/票根），
以文学语法做作品本体（剧本/章节/出场人物/本篇身份/故事分支/创作手记/文风/批注）。

它的存在理由是一句产品级的许可：

> **允许故事成立，同时不强迫故事立刻成为现实。**

### 1.2 它是 Sleepy 的第四种时间观

这是我认为最该先想清楚的一层。Sleepy 现有三个模块各自锁死了一种时间：

| 模块 | 时间 | 人物知情 | 结果归属 |
|---|---|---|---|
| 聊天 / 主动消息 | 现在进行时 | 天然知情 | 现实事件 |
| 线下场景 | 现在进行时（共同在场） | 在场者知情 | 现实事件 |
| 留痕 / 时间线 / 日历 | 过去完成时 | 已承认 | 现实事实 |
| **帷境** | **假设语气（未定过去 / 平行世界）** | **默认不知情** | **纸面，除非逐条定史** |

所以帷境的核心数据结构**不是 message**，是
`作品本体 + 权限矩阵 + 段落锚点`。凡是照着聊天那套做（一串气泡、
一个长回复、角色自动评论），产品就退化成「长回复模式」，这是总纲 §2.2
明令禁止的六种退化里的第一、二、六条。

### 1.3 三层权限不是三个字段，是三个「动作对」

总纲 §4 说得很清楚，我把它翻译成工程语言：

| 层 | 回答 | 读/写 | 谁来判断 | 绝不能合并到哪 |
|---|---|---|---|---|
| **创作取材权限** | 模型能看到什么 | 读 | 创建时授权 + 本篇临时设定 | 不等于「人物知情」 |
| **作品真实性** | 这篇在世界里算什么 | 声明 | 创建时定 + 谢幕后改 | 不等于「写入现实」 |
| **人物知情权限** | 谁知道这篇存在、看过哪部分 | 写 | 分享 / 共读 / 论坛 / 定史 | 不等于「他经历过」 |

三条几乎处处被误当成一条，所以要有一句随身口诀：

- 取材了 ≠ 他知道这篇作品；
- 他读过 ≠ 他经历过；
- 他觉得「写得像我」≠ 他同意它成为正史；
- 作品公开 ≠ 所有出场人物知情；
- **共读事件可以是真的，共读的故事仍然是假的。**

### 1.4 最硬的一条工程论断：anchorId 是全身的骨

总纲 §7.3 有一句容易被当细节放过的话，我认为它是全案最关键的技术决定：

> 每个正文段落需要稳定 `anchorId`。共读反应、批注、分享和局部重写
> 均应挂靠锚点，不能依赖容易变化的全文字符串匹配。

往下推：

- 共读的 `annotation`（Demo 已见到 `挂靠 p_004`）挂在段上；
- 一个 prompt「局部重写本段」要在原地改字，**id 不能变**，否则所有挂靠全断；
- 分享段落 = 分享一个 anchorId；正史候选的 `来源章节与锚点` 也是一个 anchorId；
- 生成中的状态（排队/失败/重试）也是**按段落**的，不是按全文的。

推论（Demo 都没做到，正式版必须做）：

- 段落 id 必须是**不可变 id**（建议 `p_<章节序号>_<8位随机>`），
  而 `p_001` 这种「展示用序号」单独算、可以重排；
- 段落表 = 作品的骨，章节 = 段落的切片 + 顺序；正文文本存在段落对象里，
  生成状态、批注、重写历史也都挂在同一个对象上。

### 1.5 最容易做错的三件事（我会重点盯）

1. **把共读做成「边滚动边自动评论」**。总纲 §10.1 明确禁止。
   共读是独立回应模块，`stay_silent` / `defer` / `leave` 都是**合法输出**。
   它记录的记忆候选只能是「我们共同读过这篇作品」这一条现实事件，
   绝不能把剧情写成人物亲历。
2. **把谢幕五路并成一个「发布」**。收藏 / 分享 / 共读 / 公开 / 定史
   是五种不同的副作用（Demo 的 `route em` 已经给了五个准确标签：
   收藏纪念 / 改变知情 / 创建邀请 / 改变公开范围 / 可能改变现实）。
   合并了就再也拆不回来，而且其中「可能改变现实」是唯一有现实杀伤力的一路。
3. **把文风做成四根滑杆**。四根滑杆只是用户看得见的控制台，发动机在
   雷区规则 + 五层八股拦截 + 局部重写 + 人物声音/跨章漂移检查。
   而且 §9.5 要求这些规则**必须原创**，不复用旧卡片或外部作者提示词的措辞。

## 2. 八张 Demo 逐张解剖

### #1 开帷创建流程 v1 · `card-1789823421135-s3fm3l`

**结构**：`.top`(退出=存为未开帷) + `.progress`(5 段) + 5 个 `.step[data-step]` + 固定 `.nav`。

**state 字段**（正好就是 work 的创建参数）：
`step / source / scopes[] / actors[] / userPos / mode / time / memory / style / wish`

**五步**：
1. 取景 `source: island|archipelago`；群岛才出现第二座岛（`.arch-only`）；
   开关不许全关（`至少保留一座来源岛`）。
2. 选角：`.actor` 点选切换，`.role-pill` 显示 主角/配角/未出场；
   下方 `user 位置` 三档（作为人物出场 / 只在幕外旁观 / 在故事中完全隐去），
   带一句 notice：「隐去后系统不会把故事强行绕回 user」。
   拦截：`state.actors.length` 为空不许下一步。
3. 现实：`mode: story|past` 两张 `.select-card` + 时间落点四档
   （已知过去之前 / 认识 user 以前 / 两段经历之间 / 平行时间线）。
4. 取材：`memory` 四档（不读取 / 只读关系与性格底色 / 选择性读取 /
   读取当前世界资料）+ `.boundary` 固定边界条 + 故事愿望 textarea + chips。
5. 试读：6 个 `.style-btn`，切换即换 `.preview` 试读纸的三句话 + 元信息行；
   下方 `.summary` 纸本是**开帷前的确认单**（六行汇总 + `未定故事·角色不知情·不自动写回`）。

**必须修正**：演员→**出场人物**；舞台身份→**本篇身份**；试演片段→**试读片段**
（`content:"试演片段"` / nav 的「下一步·安排演员」/ summary 里的字样全要改）。

**Demo 缺口**：临时 NPC 只 toast 不真建；「选择性读取」的逐条选择器没做
（只 toast，正式版要接留痕/时间线）；离开没真存草稿。

### #2 门厅与剧本详情 v1 · `card-1789825529641-ilnwuw`

`.shelf` 卡片墙）+ `#detailView`（`.detail-hero` 书封 + `.facts` 四格 +
`.tabs` 四页）+ 邀请 sheet。品牌文案随视图切换（`帷境 · 门厅` / `帷境 · 剧本详情`）。

**work 假数据字段**：`title / status(unfinished|completed|draft) / statusText /
desc / cast[] / progress / reality / user / time / material / cover(night|paper|fog) / chapters[[标题,状态]]`

**两个必须保留的设计**：
- `.facts` 四格 = 当前进度 / **作品性质** / **user 位置** / 最近修改；
- `概览` 页的 `.boundary` 三卡 = **创作取材 / 人物知情 / 现实写回**，
  每张都配了一句「它不等于什么」。这是三层权限在 UI 上的第二处落点，

**缺口**：`新建故事` / `继续阅读` / 查找 / 作品档案 全是 toast；
分支页与版本页写死；书架筛选按 status 过滤没问题但**缺「草稿续建」入口**。

### #3 阅读舞台 → **剧本阅读页** v1 · `card-1789823125128-v47pqm`

**结构**：`.foyer`（左右幕布 `transform:translateX(-94%)` 拉开 1.05s + 节目单
`.invitation`）→ `.reader`（`.stage-light` 光柱 + `.manuscript` 月光纸本 +
底部 `.reader-tools` 4 按钮 + 右侧 1px 进度轨）。

**正文语义段落**（要继承）：普通 `p` / `.dialogue`（台词）/ `.memory`

**交互**：点纸面任意处 toggle 工具条；`.choice` 三分支 → `#resultText`。

**必须修正**：卡名与前台用词 →「帷境剧本阅读页」；试演 → 试读。
`#resetBtn`（从开场重新试演）语义危险，正式版要改成「重读本章」之类。

另：`.drawer` 的导演参数（pace/camera/emotion）与文风设置台的四参数
（distance/density/pace/dialogue）**不是同一套**，要分清

**第二处权限 UI**：`.sheet#boundarySheet` 三行
`允许读取 / 角色知情 / 写入正史`——三层权限的又一个落点，保留。

### #4 同席共读 v2 · `card-1789825841554-uo2qne`（只能用 v2）

**三视图**：`setup`(邀请票) → `waiting`(等回应) → `reader`(共读现场)。

- **setup**：开放范围三档（start/chapter/current）+ 陪读方式三档
  （quiet/occasional/free）+ boundary + 「查看对方将获得的权限」。
- **waiting**：四种回应 `accept / later / share / refuse`，
  **只有 accept 才显示「进入同席」并创建 session**。文案要照抄这个分寸：
  拒绝是「今天不太适合读这个。不是不想看，改天再说。」
- **reader**：`.sessionbar` 状态胶囊（`林渡正在同席 · 安静陪读 · 读至 p_001`）
  + `.para[data-anchor]` + `.current` 高亮 + `.anchor` 角标
  + `.annotation`（`林渡 · 挂靠 p_004`）+ `.whisper` 此刻反应浮条
  + tools 五按钮（继续阅读 / 此刻反应 / 重要节点 / 暂停讨论 / 结束同席）。

**模式真的改变行为**（关键，别退化成三个装饰按钮）：
`quiet` → 暂停讨论 disabled、重要节点隐藏、此刻反应改叫「询问反应」；
`occasional` → 到候选节点才提示判断回应或沉默；
`free` → user 发言触发回应判断。

**灵魂 UI = `.ledger` 两张并置的卡**：
`real 共读事件`（可成为现实事实：谁邀请、读到哪个 anchor、说了什么、何时离席）
vs `story 剧本内容`（不会自动成为现实）。加上 `#memoryCandidate` 在结束时
才出现，文案是「候选：user 与林渡共同读过《潮声以北》，结束于 p_00x」。

**Demo 缺口**：异步只做了 waiting 一屏（`invited/active/paused/ended`
状态机不完整）；回应没有「稍后阅读→稍后真的挂靠到某 anchor」的回收路径。

### #5 谢幕与作品去向 v1 · `card-1789826610027-1nxy0v`

**结构**：ending 头 + `.ticket` 票根（`:before/:after` 两个半圆缺口做票根形）
+ `.routes` 五张 route 卡（`history` 通栏满宽、酒红描边）+ warning。

**五路 + 五个副作用标签**（原样进正式版）：

| route | 标签 em | 副作用 |
|---|---|---|
| ticket | 收藏纪念 | 进收藏馆，不复制正文、不改权限 |
| share | 改变知情 | 聊天收作品卡，可读后回应，**不创建共读** |
| coread | 创建邀请 | 需要回应，接受后才创建 session |
| forum | 改变公开范围 | 账号/板块/可见范围 |
| history | **可能改变现实** | 只提取候选事实，进独立审阅 |

**state 用四个独立布尔**（`ticketSaved / shared / coreadInvited / forumPublished`）
—— 正说明五路彼此独立。每路一个 sheet，sheet 里都带**实物预览**
（收藏馆里的票根长什么样 / 对方在聊天里收到的卡长什么样）。

**Demo 缺口**：没有幂等保护（连点会重复创建）；完成后只改 `em` 文字。

### #6 三种卡片实物样张 v1 · `card-1789827745112-tmd3je`

纯静态三张：`.ticket`（收藏馆票根）/ `.share`（聊天作品卡：书封 + 标题 +
字数 + blockquote 附言）/ `.invite`（聊天同席邀请卡：深色 + meta 两格 +
**四个回答按钮**）。

**结论**：跨 App 要新增两种消息类型（`wj-share` / `wj-invite`），
不是同一张链接卡换文案。invite 卡带回答按钮 = 聊天里的交互卡。
底注红线原样保留：**收藏不等于分享；分享不等于共读；共读不等于定史。**

### #7 正史审阅 v1 · `card-1789827375650-3xgi2h`

**四步**：候选事实 → 冲突确认 → 人物认知 → 最终写入。

- 候选 `{id, kind, text, note, conflict}`，kind 四类：
  时间与地点 / 共同事件 / 人物关系 / 片段记忆；
- 决定三档 `keep / hold / reject`，另有 `fixed`（冲突是否已处理）；
- **认知按二维键存** `knowledge['林渡-event'] = '清晰记忆'`，
  六档：清晰记忆 / 片段记忆 / 情绪残留 / 角色隐瞒 / 本人未知 / 完全不知情；
- 硬闸门：冲突没处理（`!state.fixed`）不许进下一步；
- 写入页文案：「只写入批准且冲突已处理的结构化历史」+ 一句 seal：
  「小说仍保留原文与所有文学加工」。

**Demo 缺口**：候选事实从哪来（模型提取）没做；写入落到哪个存储没定义。

### #8 文风设置台 v1

**左栏**：6 个 preset + 4 个 range（distance/density/pace/dialogue）
+ 雷区 tabs（全局 / 本篇）+ rule 行（text + strength select + 删除）
+ 「加入候选」（`confirmed:false`，alert 说「正式生效前仍需你的确认」）。
**右栏 sticky**：动态试读纸（滑杆一动，三句话实时改写）+ 生效边界。
**雷区强度四档**：永久禁止 / 尽量避免 / 限制频率 / 特定场景允许。
**六套 preset 自带四参数**：
静水{62,30,34,28} 近火{24,58,42,46} 行旅{48,44,68,40}
群像{82,55,60,57} 冷镜{74,25,52,32} 夜谈{38,38,45,78}。

**缺口**（用户已列 + 我强调）：圈选一句指出问题 / 区分词语·句式·语气·
人物行为·频率 / 五层八股检查结果 / 只重写问题段 / 人物声音差异 /
跨章文风漂移。**四根滑杆只是控制台，发动机在后面。**

## 6. 梯队计划 T1–T7

> 原则（总纲 §19.2）：**先让剧本自身活起来，再逐条连外部**。
> 每梯队独立可验收、无头桩 + 真机各过一遍。

### T1 · 地基与门厅壳

- **做**：`wjWorks` 数据层（work/chapter/para/anchorId 生成器）+ `wj-foyer`
  门厅（最近阅读 / 四档筛选 / 书架 / 空态）+ `wj-work` 详情
  （书封 / facts 四格 / 四 tab / **三层权限三卡**）+ 桌面入口格 +
  `LAYOUT_VERSION:15→16` + 迁移实跑。
- **不做**：真实生成；先用一条手写的示例 work 打底。
- **验收**：桌面新格子能进门厅；详情里三层权限三卡文案齐全；
  老存档升级不丢坐标；`pnpm check` + `pnpm smoke` 绿。

### T2 · 开帷创建流程

- **做**：五步向导（取景 / 出场人物 / 现实 / 取材 / 试读确认）+
  逐步保存与恢复 + 存为未开帷草稿 + 术语修正（出场人物 / 本篇身份 / 试读）。
- **验收**：中途退出再进**恢复到最后一步**；不选出场人物拦住；
  群岛切换正确显示第二座岛；草稿态在门厅「未开帷草稿」里出现。

### T3 · 生成链与剧本阅读页（最重的一梯）

- **做**：`wj-prompt.js` 独立槽位装配（故事规划 / 正文生成 / 局部重写三支）+
  段落级生成 + 状态机（排队/生成中/暂停/取消/失败/重试，**幂等**）+
  阅读页（月光纸本 + 幕布入场 + 语义段落 + 章节导航 + 已读位置 +
  版本信息 + 段落工具条）+ 分支选择 + 创作手记。
- **验收**：断网/改错 key 时**已生成正文不丢**；重试不产生重复章节；
  段落 id 在局部重写后不变，挂靠不失效。

### T4 · 文风设置台 + 雷区 + 检查

- **做**：六底座 + 四参数 + 全局/本篇雷区（候选确认后才生效）+
  动态试读 + **五层八股检查结果面板** + **只重写问题段** +
  人物声音差异 / 跨章漂移提醒。
- **验收**：滑杆变化真的改变试读文本结构（不只是形容词）；
  拒绝一条候选规则不会进全局；重写只动目标段且不破坏后文。

### T5 · 同席共读 v2

- **做**：邀请四回应 + session 状态机 + 三模式触发策略 + 段落锚点挂靠
  （annotation / whisper）+ 认知与记忆边界台账 + 异步状态
  （已送达 / 稍后阅读 / 正在读 / 回应挂靠 / 暂停恢复）+ 结束时只产出
  「共同读过」这一条候选。
- **验收**：quiet 模式滚动**不触发任何模型调用**；
  `stay_silent` 是合法输出；session 结束后现实候选只有共读事件、没有剧情。

### T6 · 谢幕五路 + 三种卡片

- **做**：谢幕页（票根 + 五 route + 五标签）+ 五路各自 sheet 与实物预览 +
  `wj-share` / `wj-invite` 两种聊天卡片（**invite 带四个回答按钮**）+
  票根进收藏馆（`favorites` 扩 kind）+ 邀请卡接受后创建 session +
  幂等保护 + 论坛先做「仅自己可见」占位。
- **验收**：连点两次「保存票根」只产生一张；分享**不**创建 session；
  拒绝邀请不产生 session 但作品仍可见（若选择只收作品）。

### T7 · 正史审阅与写入（最高风险，最后做）

- **做**：候选事实提取（模型独立职责）+ 冲突检查（只给证据与风险）+
  逐条批准/暂缓/拒绝 + 多主体认知分配 + 最终写入
  （落到 `memoryStore` / calendar，按 char 所在岛 scoped）。
- **验收**：拒绝一条不删小说；批准一条不让所有人物自动知情；
  冲突未处理不能进下一步；重复确认不重复写入。

## 7. 红线清单（防退化，验收时逐条对）

1. 剧院意象只承担空间与仪式，「剧本」正文读起来是**小说**，不是台本。
2. user 可以完全不出场；char-only 故事不许被强行绕回 user。
3. **三层权限在数据、UI、写入三处都必须分开**，任何合并视为架构错误。
4. 取材 ≠ 知情；读过 ≠ 经历；公开 ≠ 全员知情；共读事件真 ≠ 故事真。
5. 分享 / 共读 / 公开 / 定史是**四条独立链路**，不许并成一个按钮。
6. 定史只能逐条批准结构化事实，**绝不写整篇正文**。
7. 共读不许边滚动边自动评论；沉默是合法输出；有频率上限与冷却。
8. 段落 `anchorId` 稳定不可变；局部重写不换 id。
9. 生成失败、暂停、取消、重试、版本回退都是**一等状态**，不是异常分支。
10. 有副作用的动作（定史 / 分享 / 发布 / 票根）必须幂等。
11. 文风服务于人物与事实；同一人物跨文风仍是同一个人，不同人物不共用声音。
12. 不暴露内部完整 Prompt；不导入其他来源的提示词原文。
13. 时间只走 `Sleepy.calendar.timeFacts`，帷境不许自己手写日期字符串。
14. 页面实例缓存复用 → 凡「按岛/按作品切换」的绘制都要比对 id，
    不比对就串档（无头桩测不出，只有真机能抓）。

## 8. 需要你拍板的八个问题

**问题一（最重要）· 视觉怎么落地？**
Sleepy 现在是纯白底 + 焦糖，帷境 Demo 是深夜蓝 + 月光纸本。三选一：

- **A 独立世界**：帷境 App 内部整体走深夜蓝（进 App 像走进另一个空间），
  与桌面/其它 App 形成反差。最贴 Demo，也最符合「进入感」。
  代价：与「不要蓝」「要亮」的既有定调正面冲突。
- **B 双态映射**：帷境自己也跟随全局主题——浅色主题用**暖白 + 焦糖细边**
  的门厅，夜间/夜灯主题才用深夜蓝。「门厅深、纸本亮」的对比保留在夜景态。
  代价：要做两套材质，但保住项目视觉一致性。
- **C 折中（我推荐）**：**空间深、纸本亮**两层分开处理——
  正文/票根/审阅纸本永远是**月光纸本**（`#eee8dc`，这个不冲突，反而和
  现有米白只出现在设置页的规矩同源）；而门厅/设置层的深色**降级为
  「夜景态」**：浅色主题下门厅走暖白 + 极淡冷灰细边，夜灯主题下才转深夜蓝。
  深夜蓝只在它真该出现的时候出现。

**问题二 · 桌面入口放哪？**
主屏第 6 行现在还空着（`p1-mode` 占 3-4 列，第 6 行全空）。
建议：主屏第 6 行做**一张通栏入口卡**（4×1），形态是「幕布一角/半张票」，
而不是普通 App 图标——因为它要承担「进入另一个世界」的仪式感。
备选：普通 1×1 图标格放第 3 屏（第 5 行已满，需替换占位 App）。

**问题三 · `wjWorks` 是全局还是按岛？**
我建议**全局**（理由见 5.1），写回现实时才按 char 的岛 scoped。要确认。

**问题四 · 论坛这一轮做不做？**
Sleepy 里**没有论坛**。谢幕五路里的「发布到论坛」要么本轮只做
「仅自己可见」占位（route 卡在、点了只记状态），要么整路后置。建议前者。

**问题五 · 文风六底座用哪一套名字？**（见 4.2c，建议废弃「月下私语」那套）

**问题六 · 第一轮做到哪？**
建议 **T1 + T2 一轮跑通**（门厅壳 + 创建流程，纯本地数据不打模型），
确认视觉与信息架构后再进 T3 生成链。T3 是重活，单独一轮。

**问题七 · 定史的写入目标？**
三个候选：(a) 直接写 `memoryStore` 的 CharMemoryFile；
(b) 写新的 `canonFacts` 键，再由用户确认同步到 memory；
(c) 写 calendar 事件（时间锚点）。
我建议 **(b) 为主 + 按需同步到 (a)/(c)**——原因是 `memoryStore` 里的条目
语义是「user 亲自确认的记忆」，直接混入定史事实会让两种来源不可分辨。
要确认。

**问题八 · 共读回应的模型成本闸门？**
三模式里「偶尔回应」需要程序先识别重要节点。是全本地规则识别
（0 API，安全但粗糙），还是用小模型做一次节点预筛（准但多一次调用）？
建议**先全本地规则**（段落长度突变 / 对话段落 / 章末 / 用户停留时长），
跑起来不够再升级。
