## 2. 共用设计：三个受控迁移检查（#1–#4）

### 2.1 形状一律照抄 `rebuildOnline`（:753）与 `strictGroupOnlineCase`（:860）

已在本仓验证过的两个正确范式：
- `rebuildOnline`（:753–773）：**从 v1 深拷贝 → 只替换批准字段 → 期望 tokens 由 `estimateText` 公式重算 → 整条 `diffPaths` 比对**。
  期望值来自**冻结模块 + 生产常量源码**，注释明写「测试里不自造」。
- `strictGroupOnlineCase`（:860–935）：**按偏移量移除新增块 → 剩余与 v1 逐字一致 + 长度守恒**。

**沿用 `rebuildOnline` 的关键纪律**（缺一不可）：
1. 期望正文 = `PROBE.S.behaviorText.module(id)` 按契约 `join('\n\n')`，**取自生产模块**；
2. 期望 tokens = `estimateText(期望正文)`（复刻生产 `estimate()`，:157），**不是从当前 capture 读**；
3. **底稿口径自检**：替换前先断言 v1 侧对应字段是 `on + required + !hidden`（`rebuildOnline:762` 已示范）；
4. 整条比对用 `eq(diffPaths(rebuild(key), CAPS[key]), [], …)`。

## 5. #3 CACHE 断言（:691–696）—— 不改成 161

**修改前（原文）**
```js
t('sw.js CACHE 已按现有规则递增（v151 → v152）', function () {
  var sw = fs.readFileSync(path.join(ROOT, 'sw.js'), 'utf8');
  var m = /var CACHE = 'sleepy-v(\d+)'/.exec(sw);
  assert(m, '找不到 CACHE 定义');
  eq(Number(m[1]), 152, 'CACHE 版本号：');
});
```

**问题**：`152` 是一次性常量，与 `smoke.js` 的**独立手写基准**（:12901
`EXPECTED_SW_CACHE = 'sleepy-v161'`）**各说各话**。改成 `161` 只是把同一个
「手写常量」推到下一个版本，下次递增又红一遍 —— 而且**两处常量会漂移**。

**修改后（拟）** —— 复用 `smoke.js` 的独立基准，**不自造第二份**：
```js
t('sw.js CACHE 与 smoke.js 的独立基准一致（缓存递增的唯一对照点）', function () {
  var sw = fs.readFileSync(path.join(ROOT, 'sw.js'), 'utf8');
  var m = /var CACHE = 'sleepy-v(\d+)'/.exec(sw);
  assert(m, '找不到 CACHE 定义');
  /* ★ 基准**从 smoke.js 源码读出**，不在这里再写一个数字。
     smoke.js 的 EXPECTED_SW_CACHE 是**手写常量**（smoke.js:12901），
     它自己就断言 sw.js 等于它 —— 那条才是「本批跳位」的守门人。
     这里做的是**两文件一致性**交叉检查：防止有人只改 sw.js 忘了改基准，
     或只改基准忘了跳位。任一单边改动都会红。 */
  var smokeSrc = fs.readFileSync(path.join(ROOT, 'scripts', 'smoke.js'), 'utf8');
  var sm = /const EXPECTED_SW_CACHE = 'sleepy-v(\d+)'/.exec(smokeSrc);
  assert(sm, 'smoke.js 里找不到 EXPECTED_SW_CACHE 独立基准');
  eq(Number(m[1]), Number(sm[1]),
    'CACHE 与 smoke.js 独立基准不一致：sw.js=v' + m[1] + ' / smoke.js=v' + sm[1] +
    '（改了运行时脚本必须两处同跳）');

  /* 下界护栏：版本号不得倒退（防「为了消红把 CACHE 改小」） */
  assert(Number(m[1]) >= 161, 'CACHE 不得低于已发布的 v161：实得 v' + m[1]);

  /* 跳位必须在 sw.js 文件头留下说明（与 smoke.js 的同类护栏配对） */
  assert(sw.indexOf('v' + m[1] + '（2026-') >= 0,
    'CACHE 已到 v' + m[1] + '，但 sw.js 文件头缺少 v' + m[1] + ' 的变更说明');
});
```

**为什么这套能在下次递增时正确失败**：
- 有人改 `sw.js` 到 `v162` 忘记改 `smoke.js` 基准 → `eq` 红（不一致）。
- 有人只改 `smoke.js` 基准忘记跳 `sw.js` → `eq` 红。
- 有人把两处都改成同一个**错**号（如手滑 `v160`）→ **下界护栏** `>= 161` 红。
- 有人把 `CACHE` 改小 → **下界护栏**红。
- 有人跳位但没写文件头说明 → **说明护栏**红。

**明确不做**：不把 `152` 机械改成 `161`（那只是把同一个坑推到下个版本）；
不新建 `expectedCache.json` 之类的**第二套基准**（`smoke.js` 已是唯一对照点，
再建一份就是第 8 条明令禁止的「第二套漂移基线」）。

**负向注入与预期失败点**

| 注入 | 预期红点 |
|---|---|
| N3-a 只把 `sw.js` 的 `CACHE` 改 `v162` | `CACHE 与 smoke.js 独立基准不一致：sw.js=v162 / smoke.js=v161` |
| N3-b 只把 `smoke.js` 基准改 `v162` | 同上（反向） |
| N3-c 两处都改 `v160` | `CACHE 不得低于已发布的 v161` |
| N3-d 两处都改 `v162` 但删掉 sw.js 文件头 v162 说明 | `sw.js 文件头缺少 v162 的变更说明` |
