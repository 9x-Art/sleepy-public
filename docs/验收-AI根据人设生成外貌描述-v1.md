## 一、功能形态（§1 定案）

角色编辑与 user 马甲编辑的「生图外貌」字段旁各有一个**手动按钮「AI 根据人设生成」**：
点开面板 → 预览/修改「本次分析材料」（整段展示待发送范围）→ 显示将使用的副 API 与费用提示 →
点「AI 根据人设生成」发**恰好一次**分析请求 → 可编辑草稿 + 缺项/冲突提示 →
「采用草稿」回填表单字段（原字段值非空时二次确认替换）→ **页面原「保存」才写档案**。

生图链路**零改动**：正式生图继续只读已保存的 faceLockText 字段，不在任何时点自动调用分析
（B9 实测：刷新/打开各页零分析请求）。本功能不修改内置/自定义视觉层设置（§8.7）。

失败分支（网络失败/超时/畸形 JSON/空 appearanceText）：同一条代码路径统一处理——
「分析失败（原因）。原字段没动；可以再点一次手动重试」，不自动重试、不回落主 API、
不暗中换模型；取消/失败不清空用户正在编辑的内容（B7/B8 + 代码路径核查）。
过期保护**两层**（`page-idcard.js:109-120` 注释、`:156-166` 快照、`:196-216` staleReasons）：
①面板被移出 DOM（切身份/关页/重开）→ 迟到响应按 `panel.isConnected` 丢弃；
②面板还在但**外貌字段 / 人设内容 / 分析材料**任一在等待期间被改（请求时快照 vs 采用时
现值比较）→ 草稿实时标旧横幅，采用必须过「仍要采用」确认，不静默覆盖新编辑。
草稿面板出来后字段再被改也会实时亮横幅（`getFieldInput` 的 input 监听）。

## 四、内容边界与多形态（§4）

- 提示词层落实：只提炼明确视觉事实；性别/年龄/族裔仅在材料明确时转写，未知不补；
  不加审美/摄影/镜头/关系词；不从「清冷」等性格词编五官；冲突列 conflicts 不裁决；
  多形态分别标明适用条件（如「鳞片（人鱼特征，当前为人形）」），不融合肢体、不擅自选形态。
- 仓库无结构化形态字段（审计过 char/mask 记录）→ 按施工单最小方案：**分段保存在既有
  faceLockText 文本字段内**（草稿文本自带「当前为人形」等条件标注）；当前链路消费方式 =
  整段进身份块（identitySegmentFor），**没有**自动形态选择——如实申报，未「保存即宣称完成」。
- 未知性别不阻止生成草稿、不触发判别；正式生图沿返修 v2 的中性底座路径，无需为此填性别。

## 五、费用与能力边界（§7，界面/报告如实口径）

- 每次点「生成草稿」= 一次副 API 分析调用，可能产生费用（面板明示）；首次与再次手动生成都要调；
  省&quot;的是重复整理人设，不是生图免费——保存的外貌描述仍会进生图请求占文本用量。
- 识图→文字 ≠ 生图携带原图 ≠ 视觉锁脸：本功能只产出文字草稿；现有生图通道无图片输入能力
  （返修 v2 报告 §五审计），界面无任何「已看图/已锁脸」表述。
- 参考图选择：第一阶段未实现（无既有图片输入通道与授权机制可复用）——按 §6 列为未实现，
  不伪造通过；不阻塞文本辅助填写交付。
