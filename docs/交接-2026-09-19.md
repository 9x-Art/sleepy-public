## 三、踩坑（新会话必读）

- `ui.h()` 第三参字符串是**纯文本**——塞 SVG 必须 `el.innerHTML = ...`（日记波浪线翻过车）。
- `char.faceLock` 字段不存在，角色卡存的是 `faceLockText`——取锁脸一律走
  `Sleepy.imggen.faceTextFor(ch, shot)`（查岗曾因取错字段导致锁脸从未生效）。
- 场景向预设取 `.positive`（BUILTIN_SCENE[kind] 是对象不是字符串，smoke 抓过）。
- 壁纸要铺在 **section 级**（ctx.el = .page）而非内容层——顶栏透明后露出来的才是同一张纸；
  换壁纸要在 onShow→rebuild 里重刷（页面实例缓存，render 只跑一次）。
- schedule 的延迟单位是**秒**（later 决策传分钟要 ×60，注释里有实测记录）。
- smoke 沙盒隔离段（~1605 行）clearAll 之后 m1/m2 已死，后面的测试自带角色。
- `store.get` 返回深拷贝，改完必须 set 回去；diaries 写回必须用 writableDiaries() 全量。
- 无头桩没有 `Node` 全局，别用 instanceof Node，用 nodeType。
- button 记得显式 `border:0`；顶栏 title 不用 italic（用户明确避过斜体，正文阅读优先）。

# 追加交接（六）· 线下 = 一篇长文（23:10–23:35）

> 开新对话框时先贴**这一节**（比第五节更晚，涉及篇幅与写法）。

## 一、用户这次的定调

> 「我不是很懂 prose 和 dialogue 两类是什么意思欸，因为我以为是他输出一个长文，
> 里面有对话有描写有心理，要是没有想说的就不说，就只有描写和心理这样，

**结论：线下是一篇连续的叙事，「段落类型」只是给程序排版的标记。**
分类型的唯一理由是机器要两样东西：**译文得挂到具体那句话上**、
**多人时得知道谁在说**。所以不能真的只吐一整块文字 ——
但那篇文章读起来必须是一整篇，不是一条条一句话的短段。

## 二、改了什么

1. **篇幅档位上移**（`prompt-engine` 的 `LENGTH_LABELS`）：
   简短 150~250 / **适中 300~450** / 详尽 500~800（旧值 150~300 写出来像分镜）。
   私聊线下的字数行注明「一条回复合计，不是每句对话的字数」。
2. **群线下按在场人数放大**（`lengthHintOf(n, people)`）：
   适中 = `350 + 190×(在场人数-1)`（单人 350 / 三人 730），
   且提示里写明**这是全场总字数** —— 不写的话模型会按人翻倍。（只影响群线下。）
3. **写法（[WRITING]）重写**，中心句是「你写的是一篇连续的叙事」：
   · 描写与心理是主体，同一段要成段（两三句），不要一句一段；
   · **有想说的才写 dialogue 段** —— 没人开口就整轮只有叙述；
   · 场面要具体的物与动静；没开口的人写在叙述里（值得突出时用 silent）；
   · 位置关系要立得住。
   ⚠️ **把上一轮那句「叙述与台词大致各半」删掉了** —— 它会逼模型硬凑对话，
   跟「没有想说的就不说」正好相反。
4. **心理**：`- 描写 Char 内心：开（心理活动写在叙述段里）`，关掉时才只写外部言行。
5. **整轮没人开口 → 一个头像块都不出现**：`blockFor` 里先算 `hasDialogue`，
   没有 dialogue 的消息整条按叙述渲染（prose → 段落，aside / silent 保留形式）。
6. `parasText()` **三处**（prompt-engine / page-offline / page-group-offline）
   改成用 `\n` 拼（原来直接粘成一行），渲染端 `.gof-prose` / `.off-char-p` /
   `.gof-aside p` 加 `white-space:pre-line` —— 模型自己分的自然段要留住。

## 二、这轮定稿的语义（改之前先读）

1. **一章一次调用**，非流式；`chapter.status`：planned→generating→ready/failed。
   失败只标这一章并记 `chapter.error`，**别章正文分毫不动**。
2. **幂等 = token**：`running[chapterId]` 里存 token；取消删表 → 迟到的响应
   按 stale 丢弃，绝不落库、不重复建章。取消后 generating 回 planned。
3. **岔路**：模型在协议里给 `choices`（≤3），渲染成选择卡；选了记进
   `work.branches`（挂靠章末锚点）+ `work.nextBranch`，**下一章生成时消费一次**。
4. **手记按章生效**：`chapter.directorNote` 只进**这一章**的续写/重写提示词，
   不串到下一章（真机断言钉住了）。
5. **手记/重写/目录的弹层关掉必须 `sh.close()` 再 `paint`** —— mask 挂在
   `.page` 上，不拆会一直拦点击（真机抓到的，桩测永远测不出）。
6. **scene_break 空 text 要保留**：`parseChapter` 对它单独放行
   （协议要求它 text 为空，一刀切 `trim()` 会把场景转换全丢掉）。
7. **点击「写下本章/重试」要立即 `paint`** —— 不然「生成中/先停一下」
   要等请求返回才出现，用户没有取消入口。
8. 字数档：每章 短篇 900~1400 / 中篇 1600~2400 / 长篇 2400~3600（总章口径）。
9. 引擎测试注入 transport 时**必须用按调用注入**（`{transport}`）——
   共享 `_transport` 会被并发异步断言互相覆盖（冒烟踩过）。
