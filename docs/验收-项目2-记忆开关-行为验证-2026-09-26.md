## 一、M新1 · 重开重扫去重 —— 抓到并修复 Bug1（核心）

**修复前原生实测**（构造 chat 20→30→40 条，setCfg + invalidate + sweep 四轮）：

| 轮次 | 块数 | embedding 增量 | 重复段指纹 |
|---|---|---|---|
| 开1 | 2 | 2 | — |
| 关 | 2 | 0 | — |
| 开2 | **4** | **2** | `chatR\|R_0\|R_7` |
| 开3 | **6** | **2** | `chatR\|R_8\|R_15` |

→ **相同源内容随开关次数线性增副本，确认 Bug1**。

**根因**：`nextBlock` 确定性（同源同段同 fromId/toId），但 `buildRecs` 每次 `newId()`、
`putBlock` 无条件 `os.put` → 无指纹去重；rootEpoch 失配后 `readCursor` 返回 0 → `from=0`
**从头重扫**，绕过了游标防重机制。

**最小修复**（`memory-vec.js` `sweepSource` ~1344–1394）：入库前 `buildFingerprint(src.ownerKey)`
建 `{sourceId|fromId|toId:1}` 集合，跳过已存在段且**不占 SWEEP_MAX 配额**：

```js
while (fresh.length < SWEEP_MAX) {
  var blk = (src.blocker || nextBlock)(msgs, fromNow, src.lineOf);
  if (!blk) break;
  if (blk.skipTo != null) { fromNow = blk.skipTo; continue; }
  var fp = (src.sourceId || '') + '|' + (blk.fromId || '') + '|' + (blk.toId || '');
  fromNow = blk.end;
  if (done[fp]) continue;        // 跳过，不占配额
  done[fp] = 1; fresh.push(blk);
}
```

**修复后实测**：块数 2→2→**3→5**、embedding 增量 2→0→**1→2**、重复段 **0** —— 重扫只算真正新增。

**为什么必须从头重扫（如实，非增量补建）**：`readCursor` 失配返回 0 是最朴素的作废语义；
游标只记 `lastId/index`，**无法从关闭时刻做增量恢复**（游标位置 ≠ 新内容起点）。
**未用全库 wipeAll** —— 作废只打 `vecEpoch4:<root>` 单 root，其余 root 不受影响。

**如实费用说明（2026-09-26 实测修正）**：重开记忆会**从头遍历历史源**（含关闭前内容），
但**已有段在指纹去重时跳过、不重新 embedding、不收费**。原生实测 M新7（旧块→关→开、无新增消息）：
重扫 `added=0`、embedding 增量 `0`、块数不变。**仅新增/未命中段才 embedding（$）**。
「定向扫描」≠「不会重复建块」—— 已靠指纹去重避免**重复建块**；历史段**不重算**。
**区分遍历与重算**：遍历整个源（O(块数)，免费）≠ 重算每段 embedding（收费，仅新增/未命中段发生）。

## 二、M新2 · 关闭立即生效与旁路覆盖 —— 抓到并修复 Bug2

**实测现象**：开启时预热召回 → 关闭（不刷新）→ 下一次请求，`compileRecall→text→lastOf`
**仍读开启时热过的旧私有块缓存**并注入 —— 关闭未立即生效，确认 Bug2（消费旁路）。

**根因**：`text→lastOf` 读 `lastRecall` 缓存不判 `charMemOff(charId)`。

**最小修复（`memory-vec.js` `lastOf` ~2056 + `prefetchInto`）**：`prefetchInto` 的 items 补带 `ownerKey`
（块归属池的钥匙），`lastOf` 关闭分支**只滤当前 root 私有块、保留岛/账号池**：

```js
if (charMemOff(charId)) {
  var root = rootOf(charId);
  return r.items.filter(function (it) { return it.ownerKey !== root; });
}
```

> 不能整体 `return []`：私聊召回池是 [root, island:*, user:*]（`poolsFor`），旧缓存里混着岛/账号块，
> 一刀切会把它们一起毙掉。**只滤 root 私有块**后，关闭立即生效、共享内容照常（原生 Edge M新5 验证，
> 见 §四）。

关闭后缓存即使还热也不给消费。原生实测：关闭后 `text` 不带旧私有记忆，通过。

**全入口核对**：

| 入口 | 关闭期间行为 | 结果 |
|---|---|---|
| prefetch / lastOf / text / 缓存链 | 私有源 **embedding 计数 = 0**；lastOf 只滤 root 私有块 | ✅ |
| sweep / sweepOffline / sweepMem / sweepPhone | 走 `sweepSource`，已有 memoff 短路（不建块不 embedding） | ✅ |
| **reindexItem / refreshMem / refreshPhone** | **本轮补 memoff 短路**（私有池裸键返回 memoff，不删块不 embedding 不写块；带前缀的岛/账号/群池不误伤） | ✅ |
| 旧异步结果 | 写入前判 memoff，不会重新进可消费缓存 | ✅ |
| 共享池 `group:<id>` / 岛 `island:` / 账号 `user:` | 仍正常建块 + 消费（charMemOff 查不到前缀 key → false） | ✅ |

## 三、M新3 · 群注入边界 —— 定论「段级消费软隔离」，非硬隔离

线上群 `page-group-ai.js`（`entLines` @208-227）与群线下 `page-group-offline.js`
（`presentParts` @213-230）在**同一次装配调用**里，对每个实体/参与者调 `groupTextFor(groupId, ownerId)`
逐成员注入：

- A（关）→ `groupTextFor` 返回 `''`，该成员段/行**不含群池摘要**；
- B（开）→ 有内容；
- **这是段级消费软隔离**（隔离单位是**段/行**：同一模型上下文里 A 段没有群池，但 B 段有），**不是模型上下文硬隔离**。
- 若需硬隔离（关 A 的段根本不进模型上下文），需**拆请求**或**全员关闭**策略 —— **本项目不拆请求、不改全员关闭**（只补证）。

### M新5（lastOf 池过滤）实测数据

`prefetch` 缓存 ownerKey 组成（M新5 原生 Edge）：

| 阶段 | ownerKeys |
|---|---|
| r1 开启时 | `["island:sb1","user:u1","r1"]`（三池混合） |
| r1 关闭后 | `["island:sb1","user:u1"]`（**r1 私有块被滤，岛/账号保留**） |
| r2（不受 r1 关闭影响） | `["user:u2","r2","island:sb1"]`（r2 私有 + 共享全在） |

> 结论：`lastOf` 不再整体 `return []`（那会误杀岛/账号池），改为按 `ownerKey` 只滤当前 root 私有块。
> 块在 `prefetchInto` 里带上了 `ownerKey`，`lastOf` 关闭分支 `items.filter(it => it.ownerKey !== root)`。

### M新6（refresh/reindex 旁路）实测数据

| 入口 | 关闭 r1 时 | embedding 增量 | 是否写私有块 |
|---|---|---|---|
| refreshMem（私有 mem） | `why='memoff'` | 0 | 否 |
| refreshPhone（私有 phone） | `why='memoff'` | 0 | 否 |
| refreshDiary user 分支（共享 user:u1） | `ok=true` | 1 | 是（user 块 +1） |

> 结论：`reindexItem` 补了 `charMemOff(key)` 短路（私有池裸键关时返回 memoff；带前缀的岛/账号/群池查不到配置→不误伤），
> 关闭时私有素材入口不重建、不调 embedding；共享账号池照常。

### M新7（指纹跳过在 embedding 之前）实测数据

「旧块→关→开、**无新增消息**」四步原生 Edge：

| 步骤 | added | embedding 增量 | 块数 |
|---|---|---|---|
| 开1 首建块 | 2 | 2 | 2 |
| 关闭 sweep | `memoff` | 0 | 2 |
| 重扫（无新增） | **0** | **0** | **2** |

> 结论：`sweepSource` 里 `buildFingerprint` 去重（1357 `if (done[fp]) continue`）**先于** `embedTexts`（1367）——
> 重扫时 nextBlock 切出的段指纹全部命中库内已有块 → `fresh.length=0` → 走 `if (!fresh.length) return {added:0}`，
> **一次 embedding 都不调**。历史段**不重算、不收费**；**仅新增/未命中段才 embedding**。
> 原文档「历史段会重新计算并收费」已修正为「从头遍历历史源，已有段跳过，仅新增/未命中段计算」。

### M新8（同指纹正文编辑）实测数据

同 `sourceId='mem'`、`fromId=toId='it1'`，正文从「版本A」改为「版本B」，两次 `reindexItem`：

| 步骤 | ok | added | embedding 增量 | 该指纹块数 | 库内文本 |
|---|---|---|---|---|---|
| reindex（版本A） | true | 1 | 1 | 1 | 版本A |
| reindex（版本B，同指纹） | true | 1 | 1 | 1 | 版本B（含A=false） |

> 结论：定向重建路径 `reindexItem` 先 `forget` 精确删旧块（1906），再用相同 `sourceId|fromId|toId`
> 重建新正文（fromId=toId=item.id）→ **替换旧块 + 重新 embedding**，块数不重复累加。
> **这是期望行为，非缺陷**；该路径不经 `buildFingerprint`，不被指纹去重挡住，所以编辑后重扫
> 指纹命中跳过的是**新正文**块，不会被旧内容覆盖。**未为此清空向量库**。
