## 二、参考图的三条送达路径（按接口 kind）

| 通道 | 机制 | 能力边界（如实） |
|---|---|---|
| **general** | 改打 `{base}/images/edits`（multipart FormData：`image[]`＝blob、`prompt`、`model`、`n`、`size`）——OpenAI 兼容系参考图的标准位（gpt-image-1 支持多张 `image[]`） | 取决于中转/模型是否支持 edits；不支持时**报错原文照旧交用户**。无参考图时**一律照旧打 generations**（反向断言保证现有行为不变） |
| **chat** | 参考图作为 `image_url` content part 附在 user 消息里（复用 `page-chat.js:739` 形态），文字提示词照旧 | 中转生图模型普遍吃 vision 输入；URL 源可直接给远程地址（由接口方拉取，**绕开本地 CORS**） |
| **NAI** | 仅 img2img（`action:'img2img'` + `image` + `strength`/`noise`）或 vibe（`reference_*`）——**两者都不是「只锁脸」**：img2img 是整图重绘参考（姿势构图会一起进来），vibe 官方定位是风格迁移 | **建议第一批不接 NAI 参考图**（见 §五.3），等真图拍板 |

**URL 源的关键差别**（两种来源不对称，必须写清）：
- 本地图：已在图库（IndexedDB blob）→ 任何通道都能转 dataURL/formData 发送；
- URL 源：chat 通道直接把 URL 交给接口方（推荐）；general edits 需要**本地先
  fetch URL 转 blob**——跨域会被 CORS 拦，失败时明确报错并提示「改用本地图」，
  不静默降级。

## 四、发送语义（回答「给的图占第一？」）

建议**分层优先级**，不是整图占第一：

| 内容 | 优先级 |
|---|---|
| **脸与外貌特征**（脸型/五官/发型发色/肤色/体貌） | **图 > 文字**——文字描述与参考图冲突时以图为准 |
| **姿势 / 表情 / 动作 / 构图** | **永远文字（描述）为准**，参考图一律忽略 |
| **画面风格 / 渲染方式** | **当前视觉层（builtin/custom）为准**，不取参考图风格——参考图只是身份证，不是调色板 |

落点：有参考图时在 positive 前**插一段约束句**（每主体一份，不跨层去重）：
"Use the attached reference image only for this character's facial identity and
physical features; where the text and the reference conflict about appearance,
follow the reference. Ignore the reference image for pose, expression, clothing,
background and rendering style — follow the text description."
→ 写进 debug（`referencePolicy: 'face-only'`），UI 参数回显「图片锁脸：开」。
⚠️ 这段是**文本引导不是检测器**：模型是否真只取脸，只有真图能验证——
不宣称已解决风格/姿势污染。

「图占第一」的反对意见也如实给：若整图占第一（img2img 强约束），
姿势/表情/风格会被一起锁死，与你的核心需求（只锁脸）直接冲突——
所以建议「长相上图说了算，其余文字说了算」。

## 五、注意事项清单（你问「还有其他要注意的吗」）

1. **风格不一致是真实风险且各通道不同**：chat/edits 通道靠 §四 的约束句 +
   模型能力；**NAI 的 vibe transfer 本身就是风格迁移**，和「只锁脸」方向相反
   ——这是建议 NAI 暂缓的最大原因。
2. **大小与费用**：参考图随请求出网，768 jpg 约 100–200KB/张；多人合影多人
   参考图叠加，请求体变大、部分中转按图片张数计费——UI 提示知情即可。
3. **NAI 暂缓**（建议）：无契约、无「只锁脸」机制；若一定要接，只有
   「img2img 整图参考」降级模式可选（明确标注会连姿势一起参考），等真图拍板。
4. **CORS**：URL 源走 general edits 时本地拉图可能被拦——明确报错指路本地图，
   不静默。
5. **失效引用**：mediaId 被清图库/换设备后不存在 → 锁脸留空 + console.warn +
   toast 明告（沿用 B1 群线下空号口径，绝不静默换图）。
6. **隐私知情**：锁脸图 = 用户真实照片的可能（选本地图）——UI 一行说明
   「这张图会随每次带锁脸的生图请求上传」，给「移除」入口。
7. **反向兼容**：无参考图时请求与现在逐字节同形（不打 edits、不加约束句），
   六套既有拦截测试必须零回归。
8. **红线不碰**：锁脸图不进提示词文本、不进记忆/向量、不写进导出快照的
   base64（只记 mediaId/URL 引用）。
