# 方案卡 · 账密系统 v2（对齐《方案-发售与授权路线-v1》）

> 2026-10-21。v1（御膳房用户名+密码）与已定路线不符，**作废**；本版以发售规划第三/十节的决策为准：
> **激活码即账号（QQ号+密码）+ 设备管理（3 台）**，为买断凭证服务。v1 里「御膳房作者身份绑定」降为后续可选项，不混进这期。

---

## 已定路线复述（出处：方案-发售与授权路线-v1 三/十节，不再重议）

```
① 付款（Q群 / 朋友圈 收款码；小红书只种草；闲鱼禁售激活码）
② 发码页登记 QQ 号 → 当场自动生成激活码   ← Worker 记账；一个 QQ 号只能领一次
③ App 内激活：输激活码 → 设密码            ← 码即账号，不做「码→兑换→账号」两层
④ 换设备：QQ号 + 密码登录                   ← 上限 3 台；同设备不重复计；可踢 + 自助解绑
```

## P0 · Worker 侧（账号层，挂现有 sleepy-repo worker 同一实例）

### 数据（D1 新表，ensureSchema 幂等建）

```
codes    code PK, qq, issued_at, used_by, status        ← 发码页记账 + 闸（qq 唯一索引）
users    id PK, qq UNIQUE, salt, hash, created_at, status
devices  id PK, user_id, install_id, ua, name, created_at, last_seen, status(0=已解绑)
         UNIQUE(user_id, install_id)                    ← 同设备不重复计
sessions token PK, user_id, device_id, created_at, last_seen, status
```

- 密码哈希：**PBKDF2-SHA256 / 10 万迭代 / 16B salt**（WebCrypto 原生；doc 写 argon2/bcrypt，Workers 无原生 argon2，PBKDF2 是零依赖可审计的合格替代——10 万迭代 + 服务端限速补位）。
- 登录失败限制：KV 计数 per「IP+QQ」，15 分钟 5 次 → 429 锁定。
- install_id：复用 `repo-core.deviceId()`（本机随机 id，已存在）+ UA 存档做展示名。

### 端点

| 端点 | 说明 |
|---|---|
| GET /issue（发码页，独立静态页从 worker 域名出） | 表单：QQ 号 → 校验没领过 → 生成激活码当场显示 + 记账。附 QQ 号用途告知一句 |
| POST /account/activate | {code, qq, pass, installId, ua} → 码有效且未用 → 建 users + devices + session。一码一人，用过即废 |
| POST /account/login | {qq, pass, installId, ua} → 设备数 <3 自动登记；=3 且本机不在列 → 403 带设备清单（触发踢/解绑 UI） |
| GET /account/me | token → {qq, devices, lastVerifiedAt}（App 存 lastVerifiedAt 供 7 天宽限） |
| GET /account/devices | 设备列表（登录态） |
| POST /account/devices/:id/revoke | 自助解绑/踢（登录态；踢自己之外设备即时作废其 sessions） |
| POST /account/password | 登录态内改密（老哈希校验） |
| POST /account/forget-devices | 「删除我的 QQ 号」合规出口：注销设备+会话（QQ 号删除入口，iOS 审核硬要求；users 行保留哈希与码的账目，qq 字段置空脱敏） |

### 发码页（独立小页，worker 出 HTML）

- 一屏：QQ 号输入 + 一句用途告知 + 「领取激活码」→ 当场显示码（只显示一次）。
- 闸：qq 唯一索引 + 插入冲突即拒绝；再加 KV 限速（per IP，10 次/时）。
- 不与 App 内激活混页。

## P0 · App 侧（page-license.js 新页面 + repo-core 出口）

- **repo-core.js 加 `license` 段**（账号层唯一取数出口，账号与存储解耦纪律：不含任何备份逻辑）。
- **激活/登录页**：设置入口「我的授权」；未激活 → 激活（码+设密码，二次确认）或登录（QQ+密码）；已激活 → 状态卡（QQ 尾号、设备数、最近校验时间）+ 设备管理（列表/踢/解绑）+ 改密 + 注销。
- **设备判定**：`installId = deviceId()`；换浏览器 = 新设备（doc 已预判，靠自助解绑化解）。
- **7 天离线宽限**：本地存 `license.lastVerifiedAt`；登录/激活成功即刷；**内测期不设强制闸**（宽限只是为将来强闸预埋字段），发码/激活链路先真跑起来。
- **语义红线**：激活数据是**账目**不是游玩数据；`DEVICE_LOCAL_KEYS` 口径外新键（token/lastVerifiedAt）要登记清楚——token 不进 exportAll（换设备本来就要重登）。

## P1（下批）

- 强制闸（内测转首发时开）：无有效授权 → 宽限期内可用，超 7 天锁 App。
- 评论/点赞按账号去重（御膳房）；作者身份并账（v1 方案的 bind-author 降级到这里）。
- 订单号校验（发码页可选）。

## 不做（本批红线）

- ❌ 不做邮箱/手机注册（doc 定死：不收集个人信息，QQ 号是唯一例外且有告知/删除出口）
- ❌ 不做云存储挂进账号（解耦纪律）
- ❌ 不动御膳房游客路径

## 验收

- 发码页：同 QQ 二领被拒。
- check + smoke 双绿；真机验激活页 + 发码页（worker deploy 后 `?cb=<ts>` 核对）。
