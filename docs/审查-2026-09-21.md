## 4. 三、世界书导入 —— ✅ 确认，「格式未知」是设计上就没暴露

**证据** `page-worldbook.js:451` 只收 `.txt/.md/.markdown`（**file picker 的 accept 里根本没有 .json 和 .docx**），`ui.js:277-293` 只做 `readAsText`。

三个问题的根：

1. **json 被主动拒收** —— `:285-291` 的 `isTavernJson` 判断「扩展名是 .json」或「正文以 `{`/`[` 开头且能 parse」→ `:452-455` 直接拦掉并提示。所以你看到的其实是「酒馆格式不兼容」，不是「没内容」。
2. **docx 是 zip，按文本读出来是 `PK...` 乱码**，落到 `parseEntries`（`:205-228`）时找不到 `===== 条目：` 标记 → 整包塞进一本无名书，`entries = []` → `:457-463` 用 `p.entries.length || p.name` 判空 → toast「这个文件里没有内容」。**docx 解析全仓不存在。**
3. **纯 txt 散文也一样被判空** —— 没有 `===== 世界书：xxx =====` 头部标记的散文，同样 `entries = []` → 报「没有内容」。**这就是「合法文件也报空」的真相。**

**你到底需要什么格式**（从 `bookToText` `:167-175` 反推）：

```
===== 世界书：夜航船 =====
范围：个人
挂角色：林渡

===== 条目：码头规矩 | 关键词：码头，卸货，船
深夜的装卸单从不写全，缺的那几行要用眼睛补。

===== 条目：老周的烟 | 关键词：老周，烟
他只抽一种烟，牌子换过三次。
```

**修改方案**（三件事）：
1. 导入弹窗里**直接给出上面这个可复制的模板和一句格式说明**（现在用户只能靠猜 —— 这是本次审查里最典型的「UI 在、说明不在」）。
2. 判空要**分因报错**：二进制文件 → 「这是 Word/PDF，需要先导出成 txt」；有 `{`/`[` → 「这是酒馆世界书，暂不直接兼容」；无标记散文 → 「没找到 `===== 条目：` 标记，点这里看格式示例」。别再用一句「没有内容」盖住三种情况。
3. 想收 docx 就正经做：`DecompressionStream('deflate-raw')` 解 `word/document.xml` → 抽段落文本（浏览器原生，零依赖，约 40 行）。
