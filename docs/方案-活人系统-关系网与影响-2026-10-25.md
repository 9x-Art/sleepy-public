# 方案 · 活人系统移植：关系网生长 + 对 char 的影响 v1

2026-10-25 · 自 SullyOS「活人系统」（`relationshipAccounts / relationshipFeed / relationshipChat / todayStateBlock / negativeMoodLedger`，共 ~2000 行）移植到 sleepy。

## 一、现状对照（为什么值得搬）

| SullyOS 活人系统 | sleepy 现状 | 缺口 |
|---|---|---|
| L1 关系人账户表（TA 认识的第三人：name/relation/bond/note/learned/currentState/openThreads） | **无**——ta-network 只有只读关系图（岛内节点+有依据的边，0 写入不生长） | ✅ 要搬：账户表 + 生长 |
| 近况推进（currentState 隔几天养一格 / openThread 悬置话题开合 / lastMentioned 防复读） | 无 | ✅ 要搬 |
| L2 今日状态块（今天的他：mood/occupation/towardYou/smallThing，一天一次、挂 prompt 最前） | 无（有 calendar.timeFacts 时间事实，但没有「状态块」） | ✅ 要搬 |
| 对 char 的影响（ta-impact 已有对应：K03d 已成立的影响，三道闸） | **已有**（ta-impact + K03d） | ❌ 不重复搬，只做素材对接 |
| 承诺/生活支线（promiseEngine/lifeThreads） | **已有**（ta-life 三表：taPromises/taItems，纪律更严） | ❌ 不重复搬 |

结论：搬「关系人账户 + 生长 + 今日块」三块，其余复用 sleepy 已有的 ta 基建。

## 二、sleepy 侧的落地口径（不是照抄）

1. **挂表口径**：新 store 键 `taRelations`（账户表）+ `taToday`（今日块），记录带 `sandboxId`（岛章）+ `refCharId`（**归 root**，皮套与大号共享同一段关系网——与 ta-life/charState 同口径）。
   ⚠️ 两个键都必须登记 store.js DEFAULTS **并** core.js cleanupSandbox 删房名单（ta-life.js 头注释原文规矩：漏了拆岛不清）。
2. **生长走提案制**（sleepy 红线：数据层 0 模型；模型产出走待校验提案）：
   - SullyOS 的 relationshipFeed 是 LLM 直接写 currentState —— sleepy 改成：LLM 生成 → 落 `taProposals` 待校验提案 → 用户确认才生效（与 ta-life 的提案通道同构）。
   - **例外**：`lastMentioned`（对话提及检测）是本地事实，自动更新不走提案。
3. **数据哲学三条铁律照抄**（SullyOS 原文，和 sleepy 的 ta 纪律同味）：
   - `note` 用户手写确立事实，系统推进**永不覆盖**；
   - `learned` 是「印象」，注入时强制「未必属实」措辞，只有「亲历」才可升级为事实；
   - 生命周期铁律：进了表的人持久存在，系统只许更新 currentState / 开关 openThread，**严禁默默换人**。
   - openThread 只在「确实有支线卡壳/对话里真的闹掰」时打开，绝不凭空制造。
4. **L2 今日块生成走直接落库**（同 schedule-gen.js 先例：系统状态非事实写入）：一天一次 LLM 生成 mood/occupation/towardYou/smallThing，素材**只从账本读**（taRelations/ta-life 三表/taImpact），空材料合法、生成失败静默降级不阻塞主链路。
5. **注入**：照 K03e 的抄法在 prompt-engine 新增 program 槽 `K03g 今天的他`（today 块贴最前）+ 关系网摘要并入 K03e 或同槽；learned 措辞强制「未必属实」。
6. **与 ta-network 的关系**：ta-network 继续当「玩家显示层」唯一出口；账户表是「TA 认知层」新数据源。ta-network 红线「fail 方向和注入侧刻意相反」不动。

## 三、分期

- **P0**：`ta-relations.js` 数据层（账户 CRUD / 提案生长落库 / buildAccountsSummary / buildLifeThreadsSummary 对接 ta-life）+ 键登记 + cleanupSandbox + Node 单测。
- **P1**：提及检测（回复里出现关系人名 → lastMentioned 自动 + learned/currentState 走提案）+ 主聊流每次回复后 fire-and-forget 推进（节流：同关系人 3 天内不重复喂）。
- **P2**：`ta-today.js` L2 今日块（一天一次生成 + 本地日历日判定 + 跨时段恢复回拉）+ prompt-engine K03g 槽接线。
- **P3**：ta 首页 UI（关系人列表/编辑骨架/提案确认卡片）+ negativeMoodLedger 负面账本（mood 素材源）。

## 四、风险

- 第三人名字与岛内角色重名 → 提及检测按账户表全名精确匹配（不做模糊），歧义时跳过。
- 提案堆积：同账户待校验提案 > 3 条时旧提案自动标记 superseded（防确认疲劳）。
- today 块生成一次/天/角色，API 没配则静默跳过——绝不空转刷请求。
