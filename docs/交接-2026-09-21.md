## 二、这一轮新增的自检层（重要，别再退回）

**`scripts/smoke.js` 末尾加了「全页渲染冒烟」**：把注册表里 69 个页面挨个真的 `nav.open()` 一遍，拦截 `console.error` 里 `[Sleepy]` 前缀的行（app.js 的 `logError` 打的就是这个前缀），谁触发错误边界谁上报。

**为什么必须有这一层**：`check.js` 只验语法，而 `app.js:244-253` 的错误边界会把 `render()` 抛的异常**吞掉**、把整页换成「这一页出错了」—— 语法全绿照样整页崩。**P0-1 当时就是这么溜过去的，check + smoke 双绿。**

我已经验过它真的有效：把 `var charId = ...` 临时注释掉 → 它精确报出
`chat-settings → ReferenceError: charId is not defined at page-chat-settings.js:642`；恢复后全绿。

**同时补了 3 个 DOM 桩缺陷**（不补的话这层会误报，然后就会被人关掉）：
1. 元素缺 `parentNode` / `firstChild` / `lastChild` / `nextSibling` 等 → `x.parentNode.removeChild(x)`、`box.lastChild.appendChild(...)` 这类常见写法全变成 TypeError。
2. `appendChild` **没实现「移动」语义**（真实 DOM 会把节点从原父节点摘下来）→ `while (a.firstChild) b.appendChild(a.firstChild)` 这种搬家循环变成死循环，最后以 `RangeError: Invalid array length` 收场（`page-group.js` 的 `paintHero` 就是这么写的）。
3. `document.getElementById` 返回的节点没有父节点 → 同样误报。

> 教训：**桩越假，测试越没用。** 以后往桩里加东西，标准是「真实 DOM 里一定成立的性质，桩也必须成立」。

## 六、PWA 那条：已定位、已修、已实测

你给的截图是 `ERR_FAILED` + URL 显示 `/index.html`。查下来**真机实测**抓到三个问题，都修了（`sw.js`）：

| # | 问题 | 为什么会这样 |
|---|---|---|
| 1 | 离线兜底可能 resolve 成 `undefined` | `caches.match('./index.html')` 未命中时返回 `undefined`，而 **`respondWith(undefined)` 在 Chromium 里就是 ERR_FAILED** —— 页面一片空白，我们这边毫无报错，极难定位。改成三级兜底：`index.html` → `'./'` → 自带的 `offlineShell()` 提示页 |
| 2 | `install` 用 `caches.addAll` 是「全部成功才算成功」 | 弱网下挂掉任意一个文件，整个 install 就 reject → SW 停在 redundant → **这台设备根本没有可用的离线壳**。改成逐个 `add`、单个失败不拦安装 |
| 3 | **离线可用以前要等到第二次打开才成立** | 首次访问时 SW 还没控制页面，页面自己发的那些 `<script src="page-*.js">` 请求**根本不经过 fetch 处理函数**，一个都缓存不上。断网重载只有 `index.html` 能出来 →「有壳没 app」（顶部时间、底栏在，界面全空）。加 `warmShell()`：install 期读 `index.html` 的文本、正则出全部本地资源主动灌缓存（**仍然不写死清单**，脚本列表继续长也不会漏） |

> 第 3 条是**只有真机 + 断网才看得见**的，文件头原来那句「装完第一次打开之后整个 App 就能离线跑」是假的。

### 3. 顺手记下的两个真实缺陷（用户没报，我没动）

- **群头像把 base64 塞进 localStorage**：`page-group.js` 本地上传走 `media.shrink` → `blobDataURL` → `avatar`（data URL）→ 进 `group` 记录。而 `media.js`（IndexedDB）就在手边，正确做法是存 `mediaId` + 渲染时取 objectURL。**这是全项目唯一一处还在往 localStorage 塞图片二进制的代码**，也正是那句「容易爆 5M」本来的出处。改它要动群头像在列表/详情/头部的几处渲染，建议单独一批。

### C. 流式输出 O(n²) → 增量（page-chat.js onDelta）

- 以前每个 delta 都 `renderMessages()`：`innerHTML=''` 把全部消息重画一遍。
- 现在：is-pending 气泡第一帧画好（类名/停止键都在它身上），之后只更新
  它那一个 `.msg-text` 的 textContent + 滚到底；正文还没吐出来（在发心声）时
  保持打字点不动；**多段气泡的 reroll（querySelector 命中多个）回落全量**，免得几段不同步。
- `pendingVisible()` 每帧仍要重解析 raw（字符串级），不是热点；DOM 全量重建才是。

### D. 密码叙事化（phone.js / prompt-engine.js / page-chat-settings.js）

- `[手机]` delta 通道新增 **`{"app":"lock","op":"set","payload":{enabled, pin, note}}`**：
  char 在剧情里自己设锁 / 改密码 / 去掉锁（拍板口径：pin 是他会在意的日子，
  MMDD 4 位；「在一起之后」随剧情换；改了旧密码就作废）。
- 校验：enabled 布尔必带；pin 选传，传了必须 `/^\d{4}$/`；不传沿用现有 pin。
- `applyLock`：换码时旧 pin 进 `lock.pinHistory`（留 5 条内，含当时的 note）——
  「旧密码作废了」本身可玩；去锁不清 pin（再开时现成，避免「有锁没密码」死路）；
  `lock.pinNote / changedAt / narrative` 记录剧情事实。
- prompt-engine `compilePhoneDelta` 加一条指令线（只在剧情真走到才用，别硬凑）。
- 设置页「锁屏密码」开关保留为 OOC 兜底（两路写同一个 `lock.enabled`），
  note 补「剧情里他也可能自己设」；新增只读行「剧情里他自己设的」展示
  pinNote + 换过几次（**pin 不明文出现**，保住「猜密码」玩法）。
- smoke +1：「设锁换码 + 坏 pin 拒 + 旧密码进 pinHistory + 去锁不清 pin + [手机] 全链路」。
