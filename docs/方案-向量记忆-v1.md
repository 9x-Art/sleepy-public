# 方案 · 向量记忆 v1（讨论稿 · 2026-09-22）

> 用户：「向量记忆 api 应该简单一点，只是我们要讨论哪些进入向量记忆对不对，
> 我记得之前有记忆系统设计，那个可以读一读，以及做了这些功能以后宝宝觉得
> 有什么补充或者调整」。
>
> 底稿：`Sleepy-整体记忆与主动陪伴系统-v5-·-详细设计.md`（Downloads）§3 / §8 / §9。
> 本文只回答三件事：**现在到哪了 / 哪些进向量 / 最小怎么做**。

---

## 0. 先给结论

**向量记忆要做的事只有一件**：现在角色「想不起来」的东西，靠语义能找到。

现在的记忆注入（`page-memory.js:342 getMemoryInjection`）是**规则挑**：
锚点 → 边界 → 纠正 → 最近的，凑够 6 条。它挑得出「你讨厌什么」，
挑不出「上次聊到海的时候说的那句话」—— 因为后者没有任何标签能命中。

所以 v1 就做**一个检索层**，不做 v5 那套完整的多路召回 + 七路重排。
一句话概括取舍：

> **进向量的只有「原话与事件」；规则与状态（禁区/身份/承诺/授权）继续固定注入，
> 永远不走向量。**（v5 §9.5 那条红线，照抄）

| L1 近期原文窗口 | 线上按条数截、线下按 20 条 | ✅ 有 |

写记忆的入口现在有四个：总结引擎（线上/线下）、朋友圈 `rememberMoment`、

**已经有料，缺的是「按语义找回来」这一步。**

另外两处已经预留好的口子：
- 设置页有「**向量记忆 API**」的灰行占位（`page-settings.js:196`，编号 2.13，写的是
  「填 embedding 模型，不是对话模型」）—— 这次就是把它点亮。

## 2. 哪些进向量库（这一节是重点）

### 进：原始文本块（v5 §8.2 的源料）

| 源 | 切块建议（v5 原值） | 备注 |
|---|---|---|
| 线上聊天 | 4～6 轮 或 600～1000 字，相邻块少量重叠 | 主料 |
| 线下场景 | 2～4 轮 或 1000～1600 字，**优先在动作/小情节结束处切** | 线下是长文，切点比长度重要 |
| 朋友圈动态 | 按**动态事件包**（动态 + 互动 + 图一起算一个包） | v5 §6.1 已设计过 |
| 日记 | 按篇 | 它是「TA 代笔写的」，天然是记忆素材 |
| 记忆库里的档案条目 | 每条一个向量（`memories[]` 里 active 的） | 档案是提炼过的事实，比原文更该被找到 |

### 不进：确定性信息（固定注入，绝不走向量）

照抄 v5 §9.5：

- user 明确禁区 / 边界
- 当前身份与关系定义（大小号、认知模式 —— 这些走 I01，本来就不进记忆）
- 最近明确纠正
- 尚未兑现的重要承诺
- 当前线下续接状态
- 当前已生效的 App 授权（查手机、朋友圈权限）

理由很直白：**向量是「可能相关」，这些是「每轮都必须在」**。
放进向量就会出现「今天要跟他说的事，因为语义分数低没被召回」这种事故。

### 灰色地带，我的判断（要你拍）

| 东西 | 我的建议 | 理由 |
|---|---|---|
| **帷境的剧本正文** | **绝对不进** | 它是虚构作品。v5 那条「共读的故事仍然是假的」如果被向量打破，角色就会拿剧本里的事当亲历讲出来 —— 这是帷境红线（收藏≠分享≠共读≠定史）的地基。**共读事件**（谁和谁一起读过什么）可以进，那是真发生过的事。 |
| 帷境定史写回的事实 | **进** | 它是用户逐条批过的结构化事实，是「最真」的那一档。 |
| 角色的内心/心声（`heartbeats`） | **不进** | 那是状态不是记忆；而且它已经是「没说出口的话」，被召回进对话会很怪。 |
| 群聊消息 | v1 **先进**，但不单独开一路 | 群里的话也是 TA 看见过的，但它有「谁能看见」的可见性问题，比私聊复杂。先当普通文本块进，可见性那层以后再说。 |
| 查手机翻到的东西 | **不进**（除非 TA 本来就有权看） | 那是「你偷看的」，进向量就等于 TA 记住了他本不该知道的事。 |

## 3. 最小方案（比 v5 简在哪）

v5 的 §9 有七路候选 + 六个权重的重排 + 邻块扩展 + 去重。**v1 砍到两路 + 一条硬规则**：

```
查询 = 最近 1～2 轮原文 + 当前场景/人名（本地规则抽，不调模型）  ← v5 §9.1 照做
      ↓
候选 = ① 向量语义 top-N（N≈12）
       ② 现有本地规则（锚点 / 最近 active / 世界书关键词命中）   ← 已经在跑，不另写
      ↓
重排 = 硬过滤（角色权限、岛、状态 active、非错误身份）→ 向量分 + 时间近的微调
      ↓
注入 = 3～6 条，拼成一段【相关的过去】，和现有 getMemoryInjection 的输出并列
```

**砍掉的**：七个权重表（改成「向量分 + 时间」）、邻块扩展（v1 不做，看效果再说）、
事件簇。

**调用时机**（v5 §8.3，照抄但可以再懒一点）：
- 线上：累计 12～20 轮，或旧块快离开近期窗口
- 线下：6～10 轮
- App：批次满 / 退到后台时
- 失败保留本地队列重试，**绝不阻塞聊天**

**存在哪**（这条 v5 没写，但必须定）：**IndexedDB，不是 localStorage**。
1536 维 float32 一条就 6KB，本地存档那点配额几百条就爆。
项目里 `media.js` 已经走 IndexedDB 了，照它那套用即可。
向量库里只存 `{ blockId, vec, meta }`，原文仍在存档里 —— 向量是索引，不是副本。

**成本**：embedding 是便宜模型，但**块数会很多**。建议一开始就带上限
（比如最多保留 N 条/角色）+ 一个「向量记忆：开 / 关」的开关在设置里。

## 4. 要你拍板的

1. **「进 / 不进」两张表认不认**（尤其：帷境正文不进、查手机翻到的不进）
2. **v1 砍到两路候选 + 时间微调**，够不够？（还是你想要 v5 那套完整重排）
3. **切块参数照抄 v5 吗**（线上 4～6 轮 / 线下 2～4 轮）
4. **注入位置**：和现在的「关于对方的记忆」并列一段，还是并进同一段？
5. 设置里那个「向量记忆 API」行，**要不要顺便把「总结 API」也一起点亮**
   （两个都是便宜模型，现在都跑在主 API 上）

## 5. 顺手看到的几处补充（跟向量无关，但都是真缺口）

1. **总结还在用主 API** —— `page-summary.js` 文件头自己写着「MVP 跟随主 API」。
   总结是**批量、长文本、要质量但不要个性**的活，用主 API 跑很浪费。
   设置页那行「总结 API」也灰着。这个比向量更早该接。
2. **L1.5「近期生活动态」是空的** —— 也就是角色**不知道你昨天发了什么朋友圈**
   （除非总结已经跑过）。朋友圈发完 → `rememberMoment` 写的是**长期记忆**，
   缺「近期视野」这一层。用户能感觉到的现象是「我刚发的动态，TA 聊天时完全不提」。
   这一层比向量更便宜（不用 embedding，就是取最近的几条 App 事件）。
3. **记忆没有「事件时间」** —— 每条记忆只有 `createdAt/updatedAt`（**写入时间**），
   没有「这件事是什么时候发生的」。所以「三年前那个夏天」这类召回天生做不了，
   角色也说不清「那是很久以前还是上个月」。v5 §13.2 只要求绑来源，
   但要做时间感，就得在写入时让总结多输出一个 `when`。
4. **S2 关系罗盘是空的** —— v5 里它管「角色现在想不想推进、能推进到哪一步」。
   现在主动消息只有心绪（charState）+ 关注队列，**没有「推进意图」这一层**。
   表现是：TA 会主动找你，但不会「一步步把关系往前带」。
5. **`getMemoryInjection` 的 6 条上限在长对话里会「失忆」** ——
   聊了半年之后，早期那些没被打锚的记忆永远挤不进前 6 条。
   这其实就是第 4 条 L4 要解决的，但值得单独记：**向量上线前，
   把上限做成可调的**（现在写死 6）。
