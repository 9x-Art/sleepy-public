## 3. 判定口径里最容易误读的三处（实测钉死）

1. **块 0 ≠ 增量断了**：对话块真正门槛是「自基线起满 8 条有效消息行」，不足就挂起等，游标不动。
2. **试召回永远给「最像的 8 段」**：屏障生效的证据是「目标块本身不出现」（剩弱相似块），不是「什么都不显示」。
3. **试召回里没有皮套行**：块按**大脑**归池（`ownerKey=rootOf`），皮套的话就归在大号的池里——这本身就是要验的设计。

## 4. 验收过程中抓到并修复的问题（全部双绿后进入下一步）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 重建会把升级→点重建之间**增量建的块复制一份**（双份内容 + 双倍 embedding 钱） | 块 id 是新随机数，重扫不覆盖旧块 | **重建首轮 = 先清库再从头扫**（`wipeAll({quiet:true})`；失败重试不清、断点续扫）；桩测试新增 H 组钉死 |
| 2 | 切块「8 条**且** 600 字」对实际聊天太苛刻 | 实现与方案原文「**或**」不符 | 改回「或」：满 8 条就切，或不满 8 条但满 600 字也切；smoke 加两断言 |
| 3 | 换会话**顶栏名字不换**（列表「皮套5号」、进去显示「验收员」） | chat-detail 页面实例复用，顶栏在 body 外共享，名字槽被旧会话占住 | 名字槽记 `data-hb-chat`，会话变了摘掉重挂 |
| 4 | 流式回复**整条挤一个气泡**、落库才拆段 | 原设计取舍 | 流式**渐进拆段**：段数不变只改文本，变了才重排 |
| 5 | 空发送后几乎每轮开场「我继续说的话…」 | 空发送提示只说「主动开口」，没禁请示式开场白 | 提示改写「直接说内容 + 禁请示」；C05 输出协议同步加禁令 |
| 6 | 8-B 首测：占住连接时小手机**白屏**一次 | 桌面端复现**不白屏**（挂起只影响向量 open），定为 Android boot 期异常且无控制台 | ① bootHome 点火失败每 250ms 幂等重试（≤10s）；② boot 期错误**画成屏幕红条**（20s 窗口）——复测未再白屏，成因存疑但已有观测手段 |

另：种子页「先删旧库…」卡死（其他标签页占库 + Android Edge `onblocked` 不触发）→ delDB 加 3s 超时 + 明确指引。

## 5. 遗留（如实记录，均不阻塞部署）

1. **三维 forget 无生产 UI 入口**：`forget` 的按脸/按岛维度（fromCharId/sandboxId）逻辑已由桩 F 组 + 原生测试覆盖，但「删皮套/移出岛」还没接线到它——换皮套、移岛后旧块暂不会按脸精确清。
2. **提示词不注入农历/节日**：模型只知公历日期，user 提月亮/月饼就幻觉「今天是八月十五」。提案：把 CN_FESTIVALS 显式表里「今天/昨天/明天命中」的节日注进时间槽（一句话根治），**待拍板**。
3. **索引行「清掉」误触代价大**：左滑菜单里一键清整池，且故意不重置游标（忘掉的不再爬回来）。建议加后果说明或挪位。
4. **8-B 首次白屏成因未定**：bootHome 重试已兜住「点火丢失」类；复测未再现。
5. **PWA 模式复验**：本轮全部为浏览器模式（LAN http 无 SW）。部署后需在真 PWA 上抽验**升级路径 + B4-b**。
