## 改了什么（按批，细节进对应验收存档）

### B0 · 生图统一意图管线
- **核心思想**：「谁发的图」和「画面里有谁」分家。`imggen.js` 新增 `ImagePlan`：`{sender, contentType:'scene|object|person|mixed', description, shot:'auto|selfie|portrait|full|candid|group|scene', subjects:[{entityType, entityId, name, gender, faceText}]}`，全字段白名单收口（`normalizePlan`）。
- `buildPrompt` 带 `opts.plan` → `buildPromptForPlan`：**hasPeople 只看 subjects.length**；只有「无人 且 contentType 是 scene/object」才允许 `BUILTIN_SCENE`（排人负面词）。身份段（性别+锁脸，多主体带 `名字 (tags)` 绑定）整段拼入**永不合并去重**——去重只扫 description+extras。
- 无 plan → legacy fallback（`isSceneSubject`/PERSON_RE 原样保留）：只剩生图页「试一张」和 AI 解析失败兜底在用。
- **AI 入口结构化**：`directorAsk`（查岗/charPhoto/userTag）、朋友圈 `[图]`、日记 `[图]` 都改吐 `{description, contentType, shot, subjects}`；解析失败 `legacyFallback:true` 回退旧路不报错。`page-chat` 新增 `planFromDirector` 把 'char'/'user' 字符串映射真实实体；**plan 存进消息**（`msg.plan`），重画按快照重画。
- 线下两入口显式传 plan：私聊三键（scene/person/mixed）+ 群线下（subjects=present&&!away 参与者+user 按 `userIdentityAccountId`）。
- `replySpec` 教 `[生图:{...}]` 可选 JSON。

### sender 补验 + 查岗居中卡
- 查岗 = **user 偷看 char**（＋面板「查岗」），消息 `role:'user' type:'checkin'`，sender='user' 与归属一致（smoke 有正则契约断言锁死）。
- 查岗渲染改**居中系统镜头卡**：`bubbleFor` 对 checkin 早期返回 `.msg-checkin-row`（对齐 msg-pat 先例），长按菜单照旧、左滑引用不挂；存储/noticed 隔离闸门（60% 从 char 上下文过滤）全不动。注意：查岗重画**没有 UI 入口**（`redrawBtn` 只挂 assistant photo），`as:'checkin'` 是预留路径。

### B1 · user 马甲外貌与文字锁脸
- `core.upsertUser` 新建分支补 `gender/faceLockText/faceLockSelfie/faceLockFull` 默认空串（更新分支原样透传）；mask-edit 新增「生图外貌」分组（性别 select 与 char 同选项、三个 textArea，不预填不猜测）。
- `subjectForUser(u, shot)` 读马甲**自己**的资料，分档与 char 同（selfie/portrait→自拍组）；名字空兜「我」；绝不读 char、不回落别的马甲。
- 群线下 user 三路解析：id 命中→真实马甲；挂空号→保留身份+空锁脸+console.warn+toast；没记 id→岛卫兵兜底。
- 顺手修 B0 真 bug：`buildPromptForPlan` 预设兜底链把 `BUILTIN_PRESET.general`（对象）当字符串，无接口时 `.indexOf` 崩——改为取 `.positive`。

### E1 · 视觉层本地实验（未接入任何正式入口）
- 独立实验字段：`sleepy_img_visual_exp_mode`（legacy/sleepy-default/custom）+ `sleepy_img_visual_exp_custom`，只走 localStorage，不进接口配置不进导出。
- `SLEEPY_VISUAL_STYLE`（general/nai 各：质量层正负 + sceneObject 正向 + 无人结构 + 结构负面 + 审美负面；**实验草案**，与 `BUILTIN_SCENE` 完全独立）。
- `buildSceneObjectExperimentPrompt`：positive = 质量层→无人结构→description→视觉层→extras（层内去重不跨层、不走 {p}）；negative = 必要负面+结构负面（+审美负面仅 sleepy-default）；legacy 或 subjects 非空 → null 走旧路。
- UI：**试一张在接口编辑/添加页（settings-imggen-add/edit），不在一级页**——浏览器测试别开错页。生成按钮分流：legacy→原 generate 分毫不动；新模式→`generateBuilt`（prompt 已拼好直进请求）。

### 文字通道生图（用户报告：很多中转生图走 /chat）

## 关键技术事实（一眼看不出、踩过坑的）

- `PERSON_RE` 只认英文 tag；中文 subject 误判场景是 B0 前最大 bug，现在只剩「试一张」+ AI 兜底在用（合法）。
- `{p}` 只替换第一处；缺省则 core 追加预设尾；多个 `{p}` 残留字面量。subject 截 400（directorAsk）。
- `promptLib` 零内置词条（store.js 默认 []），extras 唯一消费点=试一张。
- **textarea 的值不在 textContent 里**——浏览器测试断言表单回显必须读 `.value`。
- 真机浏览器验收骨架：`scripts/browser-{b1-mask,e1-visual,collection}-test.js`（playwright-core 在 managed node workspace、系统 Edge、serve.js 起本地站）。
- E1 三模式 UI 截图：`preview/phone-test/e1-mode-{legacy,sleepy,custom}.png`；B1 截图 `b1-mask-edit.png`。
