## 一、共享决策层

### 1.1 抽取方式

`btDecide(spec)` 是**五场景唯一实现**，十步校验与原先两份逐字同构。
两个旧函数改成**薄包装**，**返回字段逐字不变**：

| 旧函数 | 返回字段（未变） |
|---|---|
| `btOnlineDecision()` | `ok / reason / shellText / f1Text / c05Text / VERSION / modules / touched` |
| `btOfflineDecision()` | `ok / reason / shellText / f2Text / VERSION / modules / touched` |

保留旧函数名是**必须的**：`behavior-offline-migration-test.js` 的 67 条断言
逐条锚在它们身上，改名或删除会破断言，而本批不允许改测试迁就重构。
**实测：重构后 67/0 全绿，一条断言未改。**

**同批清掉的死代码**（各自只剩一份定义，正是抽共享层的起因）：
`BT_SCENE` / `BT_SLOT_CONTRACT` / `BT_SLOT_CONTRACT_OFFLINE` /
`btCardsTouched()` / `btOfflineCardsTouched()`

### 1.2 spec 护栏（G1–G8，第 0 步，失败即 throw）

| 护栏 | 内容 |
|---|---|
| G1 | 场景必须属于 `BT_SCENES` 五者之一 |
| G2 | `contract.shell` 逐项等于 `['B','P','L']` |
| G3 | `contract.shell.concat(contract.scene)` 逐项等于 `planOf(scene)`（**拿到真 plan 之后**才判） |
| **G4** | scene 契约的**形状**校验：元素必须是已知模块、不得含 B/P/L、不得重复 |
| G5 | `protocolText` 只能 string 或 null |
| G6 | `touchedCards` 必须是字符串数组 |
| G7 | `injectShell`/`injectScene` 必须是**布尔** |
| G8 | `skipSceneIfOverridden` 若给出必须是字符串数组 |

**G4 按批准修正**：上一版写成「scene 只能是媒介段 E/N」是**错的** ——
媒介段在剩余序列的**首位**、场景专属段 S\* 在其后，且 S1/S3/S4 是消息向、S2/S5 是现场向。
只认 E/N 会把 `E/S1`、`E/S3`、`E/S4` 三种合法契约全判非法。
现只做形状校验（允许 S1–S5），「是否真等于该场景 PLANS 的剩余序列」交给 G3。

**模块可用性检查不被抢先**：`btSpecGuard` 只做**纯本地**校验，不碰
`Sleepy.behaviorText`；模块可用性由 `btDecide` 内部在正确位置自己判。
`BT_SCENES` 也是本地闭集，**不从 `planOf` 反推** —— 否则模块缺失时
连「场景名认不认识」都判不了。

**不向页面泄漏未捕获异常**：`btDecide` 的 throw 由 `btDecideScene` 接住，
转成一次正常的整条回退（`reason = module-missing`），不 console 抛栈。
实测全程零未捕获异常。

### 1.3 诊断口径

```js
Sleepy.promptEngine.btDecideScene(sceneKey, overrides?)  // 跑决策，不宣称「实际使用」
Sleepy.promptEngine.btNote(sceneKey, dec, usedShell, usedScene, shellCard?)  // 装配后记账
Sleepy.promptEngine.btScenes                            // ['online','offline','proactive','groupOnline','groupOffline']
```

| 字段 | 含义 |
|---|---|
| `modules` | **实际产出正文的那几段**（三个维度都看：`wantShell` / `wantScene` / 全部） |
| `pendingModules` | 已知但本次没进 system 的模块 |
| `partial` | `pendingModules.length > 0` |
| `sceneSkippedByOverride` | scene 位是**被 override 跳过**（区别于「本批没接通」） |
| `sceneMismatch` | 接线与 spec 脱节的信号（正常路径恒 false） |
| `shellCard` | `'behavior'` / `'card'` / 其它 |

**fallback 时 `modules = []`**，不报任何模块。

**工厂不提前宣称**：`btDecide` 只产出「按 spec 能拿到什么」，
「用没用到」由调用方在 **system 拼完之后**回报（`btNote`）。
接线漏了 push，诊断就如实记 false —— 这由第 11b 节的端到端判据锁死。

## 二、主动消息（完整接线）

**装配顺序**（固定，作为快照；**不宣称顺序本身能解决规则冲突**）：

```
shell(B/P/L) → proactive 协议卡 → E/S3 → K01 → I01 → life → recall
```

`proactive` 卡**保留在原位**，它自带 `【调用任务】/【候选判断】/【输出结构】`
与 `{"decision":"send|skip|defer|blocked"}`；E/S3 管「人物为什么想主动、怎么措辞」。

### override 三分支（分别测过）

| 情形 | 结果 |
|---|---|
| 默认 | `modules = ['B','P','L','E','S3']`、`partial = false` |
| **proactive 卡被 override** | **保留 B/P/L、跳过 E/S3**（`skipSceneIfOverridden`）→ `modules = ['B','P','L']`、`pendingModules = ['E','S3']`、`partial = true`、`sceneSkippedByOverride = true` |
| **shell 被 override** | **整条回退** → `modules = []`、`reason = user-override`、`behaviorUsed = false` |

`skipSceneIfOverridden` 的理由：proactive 卡与 E/S3 是**并列互补**的两块，
用户改卡只说明他不接受默认那张卡，不代表 B/P/L 的行为纪律也要一起丢。
