## 二、四源分开回交（权限等级与隔离机制各不相同）

### ① 群线上世界书（K04）

- **实现**：`compileWorldbookGroup` 复用私聊 `compileWorldbook` 的书/条目/关键词闸（`wbEntryHit` 同一套判据），但按**知情范围**在编译层分流，不靠模型自觉：
  - **全局书**（scope `'global'`）＝世界级设定 ⇒ 进 `shared` 共享块（文案明写「群里的大家都可能知道」），格式与私聊一致；
  - **个人书**（scope `'personal'`）＝只有挂靠者知道 ⇒ 进 `perEntity[挂靠本体]`，块头「【仅TA知道的世界设定】…别的成员不一定知道…不会当成人人都懂的事在群里直接说破」，与 innerText / I01 / 群池同级的**软隔离**；
  - **挂群外角色的个人书：整本不注入**（knownBy 语义 = 个人书只归挂靠者知道；映射含 root/皮套归并——书挂在任何一张脸上都归它 root 的本体）。
- **关键词闸**：群场景匹配文本 = 最近 30 条群消息 content（夹具实测「青岚镇」「胶片」命中、无关条目不进）。
- **「按当前世界过滤」本批不另做**：worldbooks 存档本来就不分岛（page-worldbook 写入不盖 sandboxId 章，私聊线上同样不分），群场景单独加岛过滤只会造成两场景口径分叉。要分岛需先给世界书写入补 tagScope，属独立批次。
- 容量：共享 ≤10 条、每本体 ≤10 条（扫描上限 20，与私聊同）。

### ② 群线上语言信息（I03）

- **实现**：`compileLangGroup(charId)` —— 复用 `langOfChar`（常驻地区唯一出处 calendar.langOf），只产出「【说话方式】你平时说X语（原文）。在群里也照常用X说…」一行，**逐本体进各自 [ENTITY] 块**。
- **没有语言资料时静默**：说中文（`lang.same`）/ 日历缺位 → 空串，槽位自动不上，不占块内篇幅。
- **不搬私聊协议**：`[译]…[/译]` 行是私聊线上气泡协议（splitBubblesT 消费），线下 `dialogue.trans` 是另一场景的——群线上输出是 JSON messages，两套塞进去都会污染输出结构，所以群版只说「说什么语言」，没有译文协议。smoke 有反向断言（`[译]` / `trans 字段` / `dialogue 段` 不得出现）。
- 注意：语言与翻译开关（`translateOn`）是 user 侧偏好，群场景**不消费**它。

### ③ 群线上自定义卡（K/S）

- **实现**：`composeRound` 在编号禁令之后逐张接卡，**唯一准入条件 = 卡上显式 `group: true`**；正文非空 + `cardEnabled`（用户停用闸）双闸。
- **默认关闭、宁缺勿错**：没有标记的卡一律视为私聊专属（可能写着某角色的私密设定），绝不广播——旧卡（无 group 字段）天然全部不进群。
- **私聊线上不受影响**：`assembleOnline` 的 custom 分支没动，仍注入全部卡（私聊场景本来就没有广播问题）。
- UI：预设页 `preset-custom-edit` 加「群聊可用」开关，hint 写明「开着 = 全群可见」。
- smoke 覆盖三态：标记 → 进群；未标记 → 不进；停用 / 去标记（不留 `group:false` 尸体）→ 立即退出。

### ④ 群线上近期生活动态（K03b / L1.5）

- **实现**：`composeRound` 逐本体调 `Sleepy.lifeFeed.text(e.ownerId, userMaskId)`，进各自 [ENTITY] 块。
- **为什么可以接**：lifeFeed 本身已按角色过滤——朋友圈走 `canCharSee`（自己发的 + 我的，权限/可见范围三道闸）、日历走 `charViewOf`（visibility 四档 + createdBy）、日记走 author + `lifeShare` 授权。所以「A 的近况给 B 看见」在数据层就不成立，逐本体注入安全（实测：甲的动态只进甲的块，乙/NPC 块干净）。
- 开头自带的「不必逐条回应 / 聊过别再提」边界句随块进入，无追踪感。
- 无动态的角色整块静默。
