# 第 1 步 · 开关入口与默认态（主角开 / NPC 关）

> **前置**：种子页点「布置全新库 · 对照」（干净隔离存档），手机打开小手机首页，等开屏摘掉。
> 本步不涉及向量请求，只确认**三个开关入口都在、都汇聚同一 setter、默认态正确**。

## 1-A 对话设置页「角色记忆」开关

1. 进一个角色（如「验收员」）的聊天 → 右上 **设置 → 角色记忆**（开关项）
2. 应显示**开**（主角默认开），note 是「自动整理聊天中值得留下的内容」
3. 随手**关一下再开回来**（验证入口可写；写的就是 `setCharConfig(root,{enabled})`）

## 1-B 记忆岛页 角色行 + NPC 行 开关

1. 进 **设置 → 记忆（留痕/记忆岛）** 页：主角「验收员」那行右侧有记忆开关，默认 **开**
2. 若岛上有 NPC 角色（或先建一个 NPC），NPC 那行右侧开关应默认 **关**（NPC 默认关、不误开）
3. 顺手开/关一次 NPC 行的开关（写入口= `updateMemoryConfig(n.id,…)` → `setCharConfig`）

## 1-C 报告页确认落库

1. 种子页报告：主角的 `memoryIsland.byChar[root].enabled` 在开关操作后是你要的布尔值；
   NPC 默认 `false`（没动过的 NPC 不带 enabled 或为 false 都算默认关）

**判定**
- **通过** = 三个 UI 入口都能写、主角默认开、NPC 默认关、报告页落库对得上
- **失败 A** = 某个入口不存在 / 点了没反应
- **失败 B** = 主角显示关 / NPC 显示开（默认态反了）
- **失败 C** = 报告页红字 / app 报错

**回交要点**：1-A 开关截图、1-B 主角行 + NPC 行开关截图、1-C 报告页截图。

# 第 2 步 · 关闭停建（私有池一个 embedding 不调）

> **前置**：第 1 步通过，主角记忆默认开。本步核心 = 关了之后聊新消息，**私有池不建块、不调 embedding**；
> 共享池（群 / 岛 / 我的日记）**照常建块**。先配好两个 API（对话生成 + 向量记忆 embedding，测试连接都过）。

## 2-A 关掉主角记忆

1. 对话设置页 → **角色记忆 → 关**
2. 报告页：主角 `enabled = false`

## 2-B 聊新消息（私有源应停建）

1. 回「验收员」聊天，**发 5 轮（≥8 条）**，每条 ≥20 字、带「新话」标记
   （对话块满 8 条有效消息行就切一块；不足就先挂着，块数 0 属预期不是断了）
2. 角色回复全部完成、等 30 秒 → 种子页报告，应看到：
   - **私有对话块数 = 0**（或停在关之前的值，不新增）
   - 若无 vecFail 红字、且（若工具页能挂 embedding 计数）embedding 计数不增 = **停建生效**

## 2-C 共享池对照（应照常建）

1. 写一条**我自己的日记**（共享账号池 `user:*`）；或群里聊两句（群池 `group:*`）
2. 报告页：**共享池块数新增**（island / user / group 前缀的块在长）
   —— 关闭只影响角色私有池，共享池照常 = 判据核心

**判定**
- **通过** = 关闭后私有对话块不新增、共享池照常建、无 vecFail、embedding（若可计）私有侧为 0
- **失败 A** = 关闭后私有对话块还在涨（停建没生效 / 判据用错池）
- **失败 B** = 共享池也停了（误伤 —— 关闭范围过宽）
- **失败 C** = 报告页红字 / vecFail 出现（embedding 挂了，先查是不是 API 没配对）

**回交要点**：2-A 开关关态截图、2-B 报告页块数、2-C 共享池块数截图；embedding 计数（若看得到）顺手记。

# 第 3 步 · 关闭停消费（私聊不再召回私有块，共享块照常）

> **前置**：第 2 步通过（关闭中、私有对话块停、共享池照常）。本步验**消费侧**：关闭时私聊召回
> 不再出私有块；但私聊召回池是 [root, island, user]（`poolsFor`），**岛/账号共享块仍应能召回**
> （这是 `lastOf` 按 ownerKey 只滤 root 私有块、不整体 return [] 的真机证据）。

## 3-A 先让私有块存在（切回开，造一块，再关）

1. 对话设置页 → **角色记忆 → 开**（回到开）
2. 回聊天**再发 ≥8 条**带「旧话」标记 → 等建块（报告页应出现含「旧话」的私有对话块）
3. 对话设置页 → **角色记忆 → 关**（重新关闭；本步开始是「关闭消费」场景）
4. 报告页：`enabled=false`、私有对话块**还在库里**（关闭不清块不删库）

## 3-B 试试召回（私聊消费侧）

1. 进 **设置 → 其他能力 → 向量记忆 API → 试试召回**，目标选**验收员**
2. 查询「旧话」里的一句整话（**用整句当查询**，单字信号太弱）：
   - **关闭后**：不应召回私有「旧话」块（`ownerKey=root` 的被滤）
   - 但若库里同时有岛/账号共享块，查询共享话题应**仍能召回**（共享块保留）
3. 报告页交叉核对：召回命中的块 ownerKey —— root 私有块不在、岛/账号块在

**判定**
- **通过** = 关闭后私有块不被召回、岛/账号共享块仍可召回（只滤 root、不误杀共享）
- **失败 A** = 关闭后私有块还能召回（消费旁路：lastOf 没判 memoff）
- **失败 B** = 关闭后连共享块也全召不回（过滤范围过宽：整体 return [] 误杀共享）
- **失败 C** = 报告页红字

**回交要点**：3-A 开关两次切换 + 报告页块数、3-B 两次试召回结果截图（含命中的 ownerKey）。

# 第 4 步 · 群注入 A 关 / B 开（段级消费软隔离）

> **前置**：第 3 步通过。本步验**群聊 / 群线下装配**的逐成员隔离：同一次请求里，关闭成员
> 的群池段/行为空，开着成员的段/行有群池摘要。**定论是「段级消费软隔离」（隔离单位=段/行），
> 不是模型上下文硬隔离** —— 验收时以「关 A 的段/行不含群池摘要、开 B 的段/行照常有」为判据，
> 不做「A 的段根本不进上下文」的硬隔离断言。
> 前置要求：群池里**先有内容**（群里聊过、建了群池块）才看得出隔离。

## 4-A 造群池内容 + 一关一开

1. 建一个群，拉「验收员」+ 另一个开着记忆的角色（如「阿乙」）+ 你自己
2. 群里聊 ≥8 条（带「群话」标记）→ 报告页：**群池 `group:*` 块建成**（added>0）
3. 给「验收员」关记忆（`enabled=false`）；「阿乙」保持开

## 4-B 线上群聊装配

1. 群里以「阿乙」（开）的视角聊一轮；以「验收员」（关）的视角聊一轮
2. 报告页：群池块仍存在（共享池本体继续建块、关闭不误伤群池建块）
3. （若工具页能看装配段）抽查「验收员」实体的 `[ENTITY]` 段不含群池摘要、「阿乙」的含

## 4-C 群线下装配

1. 走一次**群线下**（离线群聊 / 群聊的线下模式）
2. 报告页：群池块不变；关闭成员那一行无群池回忆、开着的成员行有

**判定**
- **通过** = 同一次请求里关成员空、开成员有（段级软隔离）；群池共享本体照常建块；`groupText`
  共享路径已删（护栏，行为验证 M5c 已钉，真机只抽查装配结果）
- **失败 A** = 关了之后群池摘要还全局注入（A 关了还有）—— 隔离没生效
- **失败 B** = 关 A 把 B 的群池摘要也掐了 —— 逐成员判据写反
- **失败 C** = 报告页红字

**回交要点**：4-A 群池块建成截图、4-B/4-C 装配结果（能看到的段/行差异）、4-B 报告页。

# 第 5 步 · 重开定向补扫（false→true → rootEpoch +1 → 私有池从头定向重扫）

> **前置**：第 4 步通过（当前主角记忆=关、库里已有旧私有对话块「旧话」+ 群池块）。
> 本步核心 = **重开那一瞬间的 false→true 边沿**：`setCharConfig` 只在这条边沿调
> `invalidateCursorsFor(root)` → `vecEpoch4:<root>` +1 → 该 root 私有池游标 epoch 失配 →
> **从头定向重扫私有池**；**已有段被指纹跳过、不重新 embedding、不收费**（行为验证 M新7 已钉），
> **仅新增/未命中段才 embedding**；**其他 root / 共享池游标不动**。

## 5-A 先记录重开前状态

1. 报告页记录：`vecEpoch4:<root>` 当前值（应为 0，若之前有开→关→开则可能 >0）、
   私有对话块数、群池块数

## 5-B 重开 + 补聊新内容

1. 对话设置页 → **角色记忆 → 开**（false→true 触发）
2. **立刻**报告页：`vecEpoch4:<root>` 应 **+1**（边沿只加一次，不是连续加）
3. 回聊天补发 ≥8 条带「新开话」标记 → 等角色回完、等 30 秒
4. 报告页：
   - 私有对话块：**旧「旧话」块还在**（重扫不是清库）+ **新增「新开话」块**（新增段才 embedding）
   - **旧段没有重复建块**（若工具页能看 embedding 计数：重扫只对新增段计数）
   - 群池 / 岛 / 账号共享块数**不变**（重开不碰共享池）
   - 其他角色的 root 游标不动（若库里有别的 root 角色，其块数不变）

**判定**
- **通过** = 重开后 rootEpoch +1、旧私有块保留不重复、新增块出现、共享池与其他 root 不动
- **失败 A** = rootEpoch 没 +1（边沿没触发：false→true 没调 invalidate）
- **失败 B** = 旧私有块重复建了一份（指纹去重没生效 → 重开会重复 embedding 花钱）
- **失败 C** = 重开把群池/别的 root 也重扫了（定向失败，变全局）
- **失败 D** = 报告页红字 / vecFail

**回交要点**：5-B 重开前后报告页两次截图（rootEpoch / 块数 / ownerKey）、embedding 计数（若可计）。

# 第 6 步 · 边沿三态（true→true 不重扫 / true→false 不清游标不删块）

> **前置**：第 5 步通过（当前记忆=开，rootEpoch 已 +1 过一次）。本步钉**剩下两条边沿**：
> 重复开（true→true）**不**再 +1、不再重扫；关闭（true→false）**不清游标、不删块**（关的只是继续建/消费）。

## 6-A true→true（重复开）

1. 记忆当前=开，再点一次「开」（或开→关→开里，重开后**再点一次开**）
2. 报告页：`vecEpoch4:<root>` **不变**（没再 +1）→ 不触发重扫
3. 会话页无「正在重建索引」动静

## 6-B true→false（关闭不清库）

1. 对话设置页 → **角色记忆 → 关**
2. 报告页：
   - `enabled=false`；私有对话块**数不变**（关闭不清块）
   - `vecEpoch4:<root>` **不变**（关闭不 +1、不清游标）
   - 游标 `vecCursor4:*` 仍在（游标没被删）
3. 试试召回「旧话」→ 关闭后不再召回（消费停）—— 但**块还在库里**（只是不消费）

**判定**
- **通过** = 重复开 rootEpoch 不变 / 关闭块数、游标、rootEpoch 全不动 / 消费停但块还在
- **失败 A** = 重复开又 +1 又重扫（true→true 误触发）
- **失败 B** = 关闭把块/游标清了（关闭越界到删除）
- **失败 C** = 报告页红字

**回交要点**：6-A、6-B 报告页截图（rootEpoch / 块数 / 游标）、6-B 试召回结果。

# 第 7 步 · reindex / refresh 旁路（关闭时编辑素材不建块，共享账号池照常）

> **前置**：第 6 步通过。本步验**素材侧写旁路**：关闭记忆时，编辑**角色私有素材**
> （档案记忆、查手机条目）不得调 embedding、不得写私有块（`reindexItem` 的 charMemOff 短路）；
> 但**共享账号池**（我写的日记 `user:*`）refreshDiary **照常**（带前缀池查不到配置、不误伤）。

## 7-A 关闭时编辑私有素材

1. 确认当前记忆=关
2. 编辑/新增**验收员的记忆档案**（记忆岛页给角色加一条记忆），保存
3. 编辑/新增**查手机**里的一张照片条目（若可达）
4. 报告页：
   - 私有记忆块（`ownerKey=root`、kind=mem）+ 手机条目块（kind=phone）**数不变**
   - （若可计）embedding 计数不增

## 7-B 共享账号池对照

1. 编辑/新增一条**我自己的日记**（共享账号池 `user:*`）

**判定**

- **失败 A** = 关闭时编辑档案/手机还建私有块（reindex 旁路没短路）
