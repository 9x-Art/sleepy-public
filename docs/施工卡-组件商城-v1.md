## 三、自定义组件规格（批4 核心）

1. **模板 = HTML/CSS + `{{变量}}`**；只做变量替换，**不执行脚本**（安全边界）。
   CSS 限组件内作用域（群聊美化 `apCustomStyle` 的隔离思路复用）。
2. **变量白名单**（第一批）：`{{time}} {{date}} {{solarTerm}} {{weather}} {{weatherCity}}`
   `{{photo}} {{countdown:目标日}} {{lampNote}} {{charName}} {{todoCount}} {{weekday}}`。
   提供方各回各源：realworld / calendar.timeFacts / lampNotes / photos / todos；
   取不到就回空串（组件显示留白，不报错）。
3. **形状大小自由**：`customWidgets` 记录 `{id, sandboxId, name, w, h, html, css, createdAt}`，
   w/h 是用户调的格数（不锁 1×1）；圆角、边框、背景全由模板 CSS 说了算——
   想做圆的、透明的、全屏横条都行。
4. **编辑器**：商城「自制」入口 → 左模板右实时预览；可从内置模板起步改。
5. **分享**：导出/导入 JSON（组件包），导入走白名单校验（只收 HTML/CSS/变量名，
   拒绝 script/事件属性——`<script`、`on*=` 一律剥掉再入库）。
6. 刷新时机：进桌面 / 数据变更事件（灯牌留言、天气缓存到期）。

## 四、验收口径

- 每批 `pnpm check` + `pnpm smoke` 双绿；运行时脚本动了就 CACHE +1 + 头留说明 +
  smoke 的 `EXPECTED_SW_CACHE` 手动同步（每次人工确认，护栏会红）。
- 组件白名单加进 smoke 静态护栏（新 RENDER 类型必须登记，防止冒名壳）。
- 玻璃一致性走查：新组件在浅色主题下不出现写死深底。
- 涉及决策层的批 5：照 ta 提案通道口径（候选→确认→落库，不静默生效）。
