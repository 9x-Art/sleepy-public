## 2. 数据对象

两张表，**都 scoped 到 `sandboxId`，且都按 `charId` 分开**（总纲 §0.4）。

```js
/* calConfigs —— 每个 char 一份，缺省不写盘 */
{ id, sandboxId, charId,
  region:'CN',                // CN/JP/KR/US/UK/NONE
  cultures:['cn','intl'],     // 多选
  timezone:'Asia/Shanghai',
  scheduleOn:false,           // 「生成角色日程」——§6.4 默认**关闭**
  anniversaryPerm:'ask',      // off | ask | auto，默认「保存前询问」
  remindOn:true }

/* calEvents —— 字段照总纲 §11 */
{ id, sandboxId, ownerCharId, eventType, title, desc,
  startAt, endAt, timezone, allDay, status, tentative,
  createdBy:{type,id}, participants:[{type,id,state}], participantStates:{},
  visibility, deviceProtection, sourceType, sourceIds,
  memoryId, meaningType, repeatRule, cancelReason, history[],
  createdAt, updatedAt }
```

`eventType`：`public_holiday` / `cultural_day` / `char_schedule` / `user_reminder` /
`shared_event` / `anniversary`（公共两层**不进事件表**，由数据包现算 —— 它们是客观背景，char 改不了）。

## 3. 三条硬约定（改之前先读）

### 3.1 离线数据必须是 `.js`
项目第一条约束是「双击 index.html 就能开」（file://），而 `fetch('xxx.json')`
在 file:// 下会被 CORS 直接拦死。所以节假日表挂全局，不引 fetch。
`serve.js` 虽然已带 `.json` MIME，但那只解决 http 那一侧。

### 3.2 中国大陆的「班」不许当「周末」算
`dayInfo()` 里**补班日优先级最高**：`2026-02-28` 是周六却要上班，
不特判就会被算成 `isDayOff=true`。冒烟桩当场抓到过一次（总纲 §5.3 红线）。
三类必须分得开：`legal_off`（法定放假日）/ `weekend`（普通周末，可能是假期里的自然周末）/
`workday_adjustment`（周末补班日）。

数据来源只认官方（国务院办公厅通知），2025 = 国办发明电〔2024〕12 号、
2026 = 2025 年 11 月那份，都经多源互证。**2027 及以后没公布就如实降级，不猜**
（总纲 §19.1：普通公历照常显示 + 一句「该年度未内置法定节假日数据」）。

### 3.3 农历节日走「显式年份表」
项目没有可靠农历库，所以除夕/春节/元宵/端午/七夕/中秋/重阳在
`CN_FESTIVALS` 里按年**逐条列出**（现在只有 2025/2026）。
`repeatRule:'yearly_lunar'` 只存不展开 —— 宁可只留原始那天，也不硬转一个错日期（总纲 §10.5/§10.6）。

## 4. 语义定稿（验收时逐条对）

1. **孤岛直达**：孤岛打开日历 = 当前 char 的月历，**不出选人页**（§2.1）。
2. **群岛先选人**：点日历 → 选人页 → 个人月历；返回**先回选人页**再离开（§2.2，走 `def.onBack` 拦）。
3. **换岛要重置视图**：页面实例是缓存复用的，`viewSyncSandbox()` 比对 `sandboxId`
   —— 不比对的话新岛的日历上写的还是上一个 char 的名字（真机抓到过）。
4. **关闭「生成角色日程」不删数据**，也不影响纪念日（§6.2/§6.3）。
   关掉后 `char_schedule` 不再显示、不再注入，但**一条记录都没动**。
5. **「清除 AI 日程」是单独操作**，只清 `char_schedule`；user 提醒、共同事件、
   纪念日、公共日期一概不碰。
6. **删除 ≠ 取消**（§7.3）：已成立的共同事件、绑了留痕的纪念日，`removeEvent` 直接拒绝。
7. **共同事件先 pending**：user 邀请只写一条 `shared_event` + `participantStates`，
   双方都答应才 `confirmed`（§8.4）。user 不能替 char 表态。
8. **user 改不了 char 的私人日程**：详情页只给一句「去聊天里问他」，不给编辑入口（§8.2）。
9. **纪念日必须绑来源**：候选只从 `memoryStore` 里 `isAnchor` 的留痕来，
   写入时建 `calendarEventId ↔ memoryId` 双向引用；`meaningType='char_subjective'`
   —— 私人纪念日不自动升格成双方关系事实（§10.2/§11.2）。
10. **我的提醒不进他的上下文**：`visibility:'private'`，§12.3。
11. **冲突检测是程序的活**（§12.6）：时间重叠即报，**取消的不占时间**，
    撞了不自动覆盖旧日程、也不拦死 —— 弹一句「撞上了，还是记下吗」。

## 7. 追加 · 常驻地点 × 时间事实（2026-09-19 第二轮，用户当场提的）

用户原话：「选择那边的 char，时间喂给 char 的也要是那样才对，
或者我们加一个字段是目前常驻地点什么的？」

### 7.1 定稿：字段挂在 char 身上，不放进日历

`char.city` / `char.region` / `char.timezone` 三个字段 = **他的常驻地点**。
- **编辑处**：浮岛 → 角色档案（`contact-edit`，新的一组「常驻地点」）；
  `city` 本来就有（旧 hint 还写着「用在桌面的双城时间」，那个组件早撤了），这轮扶正。
- **显示处**：浮岛角色页 hero 加一行「常驻 · 东京 · 日本 · Asia/Tokyo」。
- **读取处**：`Sleepy.calendar.cfgOf()` 的**第一层默认值**。

为什么不放进日历设置：它描述的是「这个人现在在哪儿」，不只是日历的配置。
放进日历就会变成日历配一份、聊天配一份、以后语言再配一份 —— 三份早晚打架。

**两层来源，优先级固定**：常驻地点（天然默认）→ 日历里的显式覆盖。
所以用户在日历里手动改过之后，会看到「这里已经手动改过了」+ 一条
**「恢复跟随他的常驻地点」**（`resetToPlace`：把 region/timezone 两个键从记录里摘掉，
记录空了就整条删，不留空壳）。

### 7.2 时间事实（I02）

**线上普通回复以前完全没有时间** —— char 在聊天里不知道今天几号、也不知道自己那边几点；
只有线下注入了「现实时间」，而且还是按 **user 机器的本地时间**算的。
这轮两边统一到一个来源：`Sleepy.calendar.timeFacts(charId)`，
prompt 槽位 `I02`（排在 I01 之后、C 系之前），线下 `sceneText` 也改走 `calendar.tzNow()`。

注入内容（实测 140 tokens）：

```
【时间事实】现在的真实时间以这里为准；不要自己编日期，也不要把它当台词念出来。
你的现在：2026年9月19日 星期六 22:51（东京 · Asia/Tokyo）
user 那边：21:51
公共日期（日本）：今天是普通周末。它只描述客观环境，不代表你一定休息。
```

规则（总纲 §14 的落地）：
- **只给「现在」+ 今天的状态**，不注入整月（冒烟有一条断言守着不许出现别的月份节日）；
- **关着「生成角色日程」就不注入他的安排**，开了才带一句「你近期的安排」（§14.2）；
- 纪念日只在 **±3 天内**才说，且注明「他自己赋予的意义 / 你们确认过的」；
- 时差只在真的不同的时候占一行（同一天同一时刻就不写）；
- 时区用 `Intl`（准）；拿不到 `Intl` 就退回 `TZ_OFFSET_MIN` 近似表并在文本里标一个「约」字，
  **绝不假装精确**。

### 7.3 这一节留下的坑

- `scripts/smoke.js` 的 vm 沙箱白名单里补了 `Intl` —— 不补的话时区断言只能测到降级那条路。
- 以后加语言 / 翻译档，**仍然从这三个字段推**，不要再开第四个设置项。

## 8. 追加 · 翻译（2026-09-19 第三轮，用户拍板）

用户原话：「做翻译！但是我感觉要用下 skill，看看怎么样放翻译好看一点，
如果只是放在同一个气泡 you are beautiful（你很漂亮）这样我觉得很丑omo，
翻译开关放在加号面板吧！」

### 8.1 语言不是新设置项 —— 从常驻地点推

`calendar.langOf(charId)`：CN→中文（`same:true`，即「不用翻译」）、JP→日语、
KR→韩语、US/UK→英语。**没有第四个设置项**（承接 §7 那条规矩）。

### 8.2 说什么语言 ≠ 要不要翻译（两件独立的事）

prompt 槽 **I03「语言与翻译」**（排在 I02 之后）：
- 常驻地在外国的角色才注入「你平时说日语…」；
- 翻译开关**只决定后半句在不在** —— 关掉开关，他**照样说日语**，只是不附译文。
- 说中文的角色这一槽整块不注入（`lang.same`）。

### 8.3 输出协议：`[译]中文译文[/译]`

- 与 `||` 分段**按索引配对**；`parseReply` 返回 `trans[]`，且 `visible`
  已经是**剔掉标签的干净正文** —— 带标签落库的话下一轮会把 `[译]` 当原文喂回去
  （冒烟桩当场抓到过这条）。
- 半截标签（只有 `[译]` 没有 `[/译]`）也收；某一句话没译文就是 `null`。
- 译文**不进 msg.content**，单独存 `msg.trans`；回给模型的上下文只有原文。

### 8.4 怎么摆好看（走 finesse-ui 的组件级路线）

组件 `msg-trans`（stamp 写在 style.css 里）。用户否掉的括号并排，问题在于
**两段不同语言的正文抢同一行基线**，读者来回横跳。所以做成气泡里的**第二层**：
极淡分隔线 → 一行标头（「译」标 + 语言标签 + 可转的箭头）→ 译文。
- 分隔线是**上方一条水平细线**，不是侧边色条（侧边色条是廉价卡标志）；
- 点标头就地收起/展开，`grid-template-rows 0fr↔1fr`（长译文不会被截断）；
- 收起状态**不落盘** —— 它是「这一眼想不想看」，不是数据；
- 触控命中区用 `::after` 撑到 44px，视觉上仍是一小行；
- 夜灯主题走 `--g-*`，自动翻色。

### 8.5 加号面板里的开关

`PLUS_ITEMS` 新增 `{ id:'translate', toggle:true, naCheck }`：
点它**不关面板**（想接着点别的很正常）；右上角挂「开/关」字标、开着时整块换焦糖底。
**他说中文时这一项灰掉**（`.is-na`），点一下给一句「他跟你说的是一种语言，用不上翻译」——
灰掉而不是藏掉，因为面板条目数量应该稳定，少一个会让别的方块跳位。

### 8.6 这一轮**没做**（明确划出去）

- **群聊**（`page-group-ai` 有自己的输出校验器）与**线下**（`parseReplyOffline`）——
  解析层是共用的，接上去各需一轮；
- 朋友圈 / 日记 / 查手机里的消息镜像；
- 双向翻译（user 说中文 → 自动译成他的语言发出去）。
