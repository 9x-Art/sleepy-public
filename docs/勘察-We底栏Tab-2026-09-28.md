# 勘察 · We 首页底栏 Tab 缺失（2026-09-28）

> 触发：用户反馈「We 已完成 P2，但首页底部没有 Tab 选择」。本轮只读勘察，未改生产代码、未提交、未部署。结论除特别标注外均来自静态源码检索，**本轮未跑 dev/smoke、未真机渲染**。

## 1. 根因与证据

**根因归类：未渲染（从未实现）。** We 页从挂载到渲染全程没有任何底栏/Tab 代码；Demo v1 的 `.tabbar` 只停留在设计稿，从未移植进实现。排除其余三类：

- **非条件隐藏**：不存在路由分支 / 功能开关 / 空数据分支控制导航——根本没有这段代码可被隐藏。
- **非布局问题**：没有元素就谈不上被裁切 / 覆盖 / 滚出屏。We 页内容（`.we-page-paper`）在 `.app-body` 内自然滚动，滚到底也不会出现底栏。
- **非版本问题**：源码里本就没有；`sw.js:189` `CACHE='sleepy-v123'`，不是「部署没带上新代码」。

### 证据

1. **We 页注册与渲染（page-we.js:716-735）**——`render` 只做 setTitle / setActions / paint；`paint`（373-535）只建 `.we-page-paper` 及编号区块，全文件检索 `tabbar|tab|nav` 仅有一处 `nav.open('collection')`（:504）。

```js
Sleepy.register('we', {
  title: 'We',
  render: function (ctx) {

```

2. **全项目唯一挂 `.tab-bar` 的地方是聊天 App 壳（page-app.js:194-218 `mount()`）**，只服务 `chat-list / moments / me` 三个入口（:281-300）；`'we'` 不在 `ENTRY` 表里，不走它。

3. **样式侧（style.css）**：`.tab-bar / .tab-btn` 只有 5704-5766 一段，段注释明写「聊天 App 容器（page-app.js）：微信式底栏 + 四个 Tab」；We 样式段（12580 起，`we-` 前缀）无任何 tabbar/nav 类。`.page.has-tabbar` 布局机制（5716-5742）是通用容器 CSS，可复用但 We 没用。

4. **立项时就没打算挂**：`docs/勘察-We前置仓库-2026-09-27.md:76` 明确「不推荐复用 page-app —— We 是独立关系空间首页，硬塞会污染聊天页的 4 Tab 心智」。P1/P2 交付范围只有首页闭环 + 收藏提议链路。

5. **测试也没要求它存在**：`scripts/smoke.js` 对 We 的断言（8518 起）只覆盖 weStore 落盘 / scoped 隔离 / kind 兼容 / checkSource / 提议链路，无底栏断言。

## 3. 最小改动清单（建议，未实施，待拍板）

方向：**We 页内挂自有底栏，复用 `.page.has-tabbar` 既有布局机制，条目只放真实目标。** 视觉按原稿：纸色底、顶部 1px 细线、深色文字、选中项短下划线（下划线色取 `--g-accent-deep`——We 现有「砖红」竖线引文用的就是它，style.css:12677）。

### 改动 1 · page-we.js `render`（:720-728）

```js
render: function (ctx) {
  ctx.setTitle('We');
  ctx.setActions([ /* 记一条，原样保留 */ ]);
  ctx.el.classList.add('has-tabbar');   /* 新增：启用通用容器布局 */
  mountWeBar(ctx);                      /* 新增：底栏（render 建一次） */
  paint(ctx);
}
```

`mountWeBar`（新增函数）：建 `div.we-tabbar`，`appendChild` 到 `ctx.el.querySelector('.page-inner')`（`.app-body` 之后、文档流 flex:none，**非 fixed**，不碰 `#phone`）。条目：

- **首页**：`is-on`；点击即本页（可顺手 `paint(ctx)` 轻刷）。
- **收藏馆**：`Sleepy.nav.open('collection')` —— 与正文入口**同一实现、同一路由**，满足「不产生两套路由或状态」。
- **＋（待拍板）**：若确认语义就是「记一条共同记录」，接 `openAddDrawer(ctx)`（同一动作换入口，非新页面）。
- **时光：本期不上条**——没有实现就放一个无响应占位＝冒充完成（红线）。列为范围缺口交回。

为何不整体复用 `page-app.js` 的 `mount()`：它绑死聊天 `TABS` 四项，`paint()` 里含 `is-moments` 白底、`setTitle` 抑制、`__backGuard` 返回切回消息 tab 等聊天专属逻辑；且 We 前置勘察已点名不复用该壳。只借它的 **CSS 布局机制**（`.page.has-tabbar`：滚动交给 `.app-body`、底栏 flex:none 常驻），不借 JS。

### 改动 2 · style.css 末尾 we- 段追加

- `.we-tabbar`：纸底（`var(--we-paper, var(--g-accent-pale))`，与 `.we-page-paper` 同源）、`border-top:1px solid` 细线、深色文字、`padding-bottom: calc(env(safe-area-inset-bottom) + …)` 自带安全区；选中项短下划线（`::after` 短横线，色 `--g-accent-deep`）。不复用 `.tab-btn`（图标+双行的聊天风，与原稿文字+下划线不符）。
- 防双份安全区：`.we-page-paper` 自带 `padding-bottom: calc(env(safe-area-inset-bottom) + 30px)`（:12598），底栏又自带一份 → 补一条 `.page.has-tabbar .we-page-paper{padding-bottom:30px}`（同 style.css:5726 的既有纪律）。

### 改动 3 · sw.js:189

`CACHE` `'sleepy-v123'` → **+1**（改运行时脚本必须跳位，老用户缓存才会换新代码）。

### 不动的东西

- `paint()` / `onShow` 现有逻辑原样：底栏在 `render` 建一次，`paint` 只清 `ctx.body`，不会把条删掉；切岛重画（`onShow→paint`）不串线，指针卫兵照旧。
- P2 收藏提议 / pending / 确认 / 来源校验 / 隔离链路（page-we-proposal.js、page-collection.js）零改动。

## 4. 范围缺口（交回决定，未擅自补）

1. **「时光」tab**：无实现、无设计细节（全量视图怎么排、lifeFeed 聚合哪些源）——需要单独立项，本期只做「有真实目标的条目」。
