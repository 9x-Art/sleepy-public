## 2. 导入失败时采用方案 A 还是方案 B

**方案 A：把向量库也纳入导入失败回滚。**（你推荐的那个）

导入前建快照，**快照含四样**：

| 内容 | 存在哪 |
|---|---|
| localStorage 完整快照（`store.exportAll()`） | `sleepy.rb.pending` 的 `local` 字段 |
| **旧 sleepy-vec 数据块**（全部块，含原文与向量） | 独立 IDB 库 `sleepy-vec-snap`（块几十 MB，localStorage 装不下） |
| `vecCursor*` + `vecFail:*` + `vecEpoch` | `sleepy.rb.pending` 的 `index` 字段 |
| 块数（验证用） | `sleepy.rb.pending` 的 `vecBlocks` |

**失败回滚顺序**（按你给的 8 步）：暂停召回门 → 恢复 localStorage → 恢复旧向量块 →
恢复游标/失败记录/索引版本 → **验证**（块数对得上）→ 验证成功才删快照 →
释放召回门 → **不 reload**，显示失败原因。

**不声称「完整回滚」的边界**：块本体在独立 IDB 库里。恢复它需要 `indexedDB` 可用；
如果恢复时 IDB 也挂了，回滚会**失败**并保留快照（不会假装恢复完成）。

## 3. 恢复区在三种情况下的去留

| 情况 | `sleepy.rb.pending` | 向量快照库 | 召回门 | 结果标记 |
|---|---|---|---|---|
| **导入成功** | **删** | **清空**（`snapDrop`） | 释放 | `restored:'none'`, `reload:true` |
| **导入失败 + 回滚成功**（且验证通过） | **删** | **清空** | 释放 | `restored:'ok'`, 不 reload |
| **导入失败 + 回滚失败/验证不过** | **保留**（`status:'restore-failed'` + `failReason`） | **保留** | 释放 | `restored:'failed'`, 不 reload，UI 提示「恢复未完成，恢复快照仍保留」 |

恢复区结构：
```js
{ v:1, at:<ts>, status:'pending'|'restore-failed',
  local:<store.exportAll() 的结果>,
  index:{ cursors:{...}, fails:{...}, epoch:n },
  vecBlocks:<块数>,
  failedAt?:<ts>, failReason?:'...' }
```
「下次启动能发现并继续」：进入「设置 → 数据与备份」，页面顶部出现一组
**「上次导入未完成」→ 继续恢复**（`:616`），点了就走 `resumeRestore()`（成功后删快照、刷新）。
