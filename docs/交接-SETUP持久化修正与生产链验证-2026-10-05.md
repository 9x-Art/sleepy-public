所以场景名**只能**走 `createSession` 的 `form`。这一点已写成测试用例（§三 的负向对照第 4 条）。

### 改法

```js

/* 冗余但有意：再走 updateEnv 显式 reaffirm 四个 env 值 */
```

## 六、要求 5 · 三条「不许静默」红线

| 红线 | 实现 | 测试 |
|---|---|---|
| ① **请求记录写入失败 → 不得静默续发** | `__SEND.push` 抛错 ⇒ **不调 `origFetch`**，直接 `Promise.reject` | 断言 **底层 fetch 调用次数 = 0**（真的没发出去）+ `onRecordError` 收到原因 |
| ② **请求拒绝/超时 → 仍要留下请求侧记录** | fetch 自己 reject 时**只补** `fetchError`/`fetchErrorName`，**不删**已有记录 | 网络失败与 `AbortError` 两条；端到端验生产 `stage='timeout'` 时旁路记录仍在 |
| ③ **已有响应时，记录异常不得把成功改成失败** | 副本读失败 / `clone()` 抛 / 响应记录写不进 ⇒ **一律 `return r`**（原对象） | 断言 `r === real`（同一引用）、`r.ok === true`；`clone()` 抛错与响应记录写失败各一条 |

### 与停机调度的接线代码

```js
/* 旁路只如实报告；「要不要停整跑」是调度层的决定 —— 不混进旁路 */
function stopKindForSend(send) {
  if (!send) return null;
  if (send.记录写入失败) return 'link';            // 证据永久缺失 → 硬停
  if (send.fetchErrorName === 'AbortError') return 'net';
  return null;
}
```

```js
/* acceptance 侧：hardStopKind 里显式接线，且**顺序在 network 之前** */
function hardStopKind(t) {
  if (!t || t.未跑) return null;
  if (t.未发出) return null;
  if (t.发送瞬间请求体 && t.发送瞬间请求体.记录写入失败) return 'link';
  if (t.发送记录错误 && t.发送记录错误.length) return 'link';
  var raw = t.原始请求结果 || {};
  if (raw.status === 403 || /403/.test(String(raw.error || ''))) return 'perm';
  if (raw.stage === 'network' || raw.stage === 'timeout') return 'net';
  if (!t.诊断 || (t.已落地 && t.诊断.requestId === undefined)) return 'link';
  return null;
}
```

⚠️ **顺序是关键**：记录写入失败时生产会因 reject 得到 `stage='network'`，
若不显式判，会被 `network` 抢走，停机原因就写成「网络故障」而真实原因是「证据没留下」。
已写成测试：同时具备两者时必须判 `link`。

轮记录新增字段：`发送瞬间请求体` / `发送记录错误` / `发送停机建议`；
页内新增 `window.__SEND_ERRORS` 收集记录失败（`onRecordError` 回调），每轮取走不清空。

## 七、要求 6 · 脱敏修正

### 从两条腿补到四条腿

| 腿 | 覆盖 | 说明 |
|---|---|---|
| ① **已知凭据精确匹配** | `opts.knownSecrets` | **最可靠的一条**。测试/验收用的固定串（`stub-trace-key-not-real`）**未必**长得像 `sk-…`/JWT —— 实测不传 knownSecrets 时**脱敏改动数 = 0**（漏） |
| ② **键名** | `api_key`/`authorization`/`token`/… | 整值替换 |
| ③ **取值形状** | `sk-…`/`Bearer …`/JWT | 键名无辜也打掉 |
| ④ **URL** | `?key=`/`?access_token=` + URL 里的已知凭据 | **本轮新增**。URL 也会进记录，不脱敏就是漏 |
| ⑤ **错误文本** | `bodyCaptureError` / `parseError` / `fetchError` | **本轮新增**。错误文本会带上原始串片段 |

**结构化 content** 走深脱敏：键名、**键名以 url 结尾的值走 URL 脱敏**、字符串内凭据三条腿，
且**仍是内容本身**，不退化成长度或摘要。

### 统一记账，不靠字段名推断

```js
out.脱敏改动数 = led.计数;      // 数字
out.脱敏改动 = led.改动;       // 数组：[{位置, 原因, 命中}]
out.已脱敏 = led.计数 > 0;     // 布尔（派生）
```

`位置` 精确到 `messages[0].content` / `messages[0].content[1].image_url.url` / `url`。
**没有发生改动时账本是空数组** —— 空数组本身就是「没改过」的证据。
配套测试：给一个真不含凭据的 body，账本必须**空**（防「见谁都脱敏」）；

## 八、本轮踩到的坑（都是老家族的新实例）

1. **静态护栏扫源码没剥注释 → 假红**（第 N 次犯，这次是我自己写的判据）
   「SETUP 不该再有 `s2.sceneName =`」这条断言直接扫原文，命中了 SETUP 里
   **那段说明旧写法如何失效的注释**。修法：判据先剥注释与字符串字面量，
   并给剥注释器**加阳性对照**（注释/字符串里的写法被剥掉、真代码里的保留）。
2. **断言字段名跟着实现改**：`脱敏处数` → `脱敏改动数`（统一记账后改名），3 处旧断言红。
3. **沙箱缺 `AbortController` 导致 `assert signal 存在` 假红**
   —— harness 的 D5 沙箱刻意最小化，缺 AbortController 时生产走 `ctrl = null` 分支。
   那条红**不是生产没设 signal，是沙箱没有**。补上宿主真实的 `AbortController` 后，
   生产中止分支才真的被走到。
4. **判据过时**：`/r\.clone\(\)\.text\(\)/` 匹配不到重写后的
   `cloned = r.clone()` + `return cloned.text()`。改成两条更准的判据，
   并补一条反向断言（没有退回 `return r.text()` 直接读生产响应体）。
5. **Edit 插入吞掉了下一个注释块的开头** → 语法错。插完必须 `node -c` 过一遍。
6. ⚠️ **流程缺陷（再次）**：动文件前没先存一份上一轮副本，
   而这些脚本又都不在 git HEAD 里 ⇒ **逐行 diff 无法事后重建**。
   本轮只能给哈希 + 完整代码。长期约定里早有这条，又犯了一次。
