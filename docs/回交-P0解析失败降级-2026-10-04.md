### 核心实现要点

**① 原始返回放模块级内存 Map，绝不挂消息对象**

```js
var rawReturnMap = {};
var rawReturnOrder = [];
var RAW_RETURN_MAX = 8;   // 内存不该无限长
```

⚠️ **为什么不能挂 `msg`**：`appendMessage → mutateSession → saveAll(list)`
会把挂在 `msg` 上的任何字段写进 `store` → `localStorage`。
挂上去等于把模型原始返回**落库**。这不是推测 —— 负向注入 A 真的验到了：

```
✗ localStorage 里出现了 UNIQ-BAD（说明落库了）：sleepy.v1.offlineSessions
```

**② 降级消息的 `paras` 只有一句中性标记**

```js
var PARSE_FAIL_MARK = '这一轮的回复格式出了点问题。';
```

⚠️ 措辞里**刻意没有**「JSON」「格式错误」「模型」这类词 ——
历史装配会把它当场景文本回灌给模型，
否则下一轮会读到「上一轮出了个 JSON 错」这种莫名其妙的话。

**③ 消费方分叉，解析器不动**

```js
var parsed = E.parseOfflineReply(r.text);
if (parsed.ok === false) {
  /* 坏 JSON 与空串统一走这里 */
  var failMsg = appendMessage(id, {
    role: 'char',
    paras: [{ type: 'prose', text: PARSE_FAIL_MARK, trans: null }],
    parseFailed: true
  });
  rememberRawReturn(failMsg && failMsg.id, r.text);
  /* …重绘… */
  return;                      // ← 这一轮没有可用内容，不进向量库
}
/* 成功路径：paras / trans / suggests / envUpdate / scene 全部照旧 */
```

**④ 渲染用原生 `<details>`**（不给 `open`）→ 默认折叠、零 JS，
与诊断面板 `off-diag-fold` 同一个既有模式，不发明新写法。
`blockFor` 里 `if (m.parseFailed) return parseFailedBlock(m)` 放在**最前**
（降级消息 `role` 也是 `'char'`，走 char 分支会被当正常台词渲染成气泡）。

### 负向注入（三条，全部精确抓到）

| 注入 | 结果 |
|---|---|
| **A** `rawReturn` 挂上消息对象 | ✅ 抓到 2 处：字段断言 + **localStorage 真的出现了 UNIQ-BAD** |

⚠️ **注入 B 最值得看**：降级块**照常出现**、UI 看起来完全正常，
但数据已经进了历史装配、下一轮上下文和落库。
**这正是「UI 没显示 ≠ 数据没进入上下文」的反面** ——
「UI 看起来对」同样不等于「数据没进去」。两条判据（装配层 + payload）才抓到它。

### 我自己写错的三个判据（都已修正，如实登记）

1. **正文纯净**：原来直接判 `textContent`，而 `textContent` **不区分 `<details>` 收没收起**
   → 把折叠区里的原始返回算成正文，误报。改成先克隆 DOM、把 `.off-parsefail-raw` 替换掉再判。
2. **上下文标记**：原来靠「拦 `requestOnce` 抓 payload」，但那一轮 payload 是**发送前**装配的，
   里面还没有刚降级的那条消息 → 抓到的是上一轮。改成直接调 `assembleOffline` 看装配结果，
   再单独用**透传观察器**（记下 payload 后原样调用原实现）验真实出站。
3. **译文可见性**：断言「正文应显示译文」是错的 —— 译文由 `msgTrans` 组件挂载，
   受「全局译文开关 + 海外角色」两道闸门管，夹具角色没开海外，**不显示才是正确行为**。

另有两个 fixture 缺陷：`createSession` 默认 `openingBy: 'char'` → 进页 350ms 自动开场，
抢在模型通道桩装好之前发一轮；以及 stub 里引用 Node 侧常量（页内取不到 → ReferenceError）。
都已修。
