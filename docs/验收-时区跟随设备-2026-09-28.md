## fallback 最终调用链
```
cfgOf(charId) ──> runtimeTzOf(charId)          ← 唯一出口（calendar.js:174）
  ① rec(calConfigs).timezone 非空 → level:'calendar'
  ② char.timezone 非空           → level:'char'
  ③ deviceTimezone()             → level:'device'   （Intl resolvedOptions，只读不落盘）
  ④ 兜底 'UTC'                   → level:'fallback' （TZ_OFFSET_MIN.UTC=0 兜近似表）
tzNow(tz) ── Intl formatToParts（准）→ 近似偏移表（标「约」）→ null
timeFacts()：mine 为 null 再退 localNow（设备本地）＝第 5 层
```
消费方（全部自动受益，无需各自解析）：prompt-engine `compileTimeFacts`（线上）、`sceneText`（线下）、wj-prompt、page-we `relationFacts`（We 此刻）、page-calendar、page-desktop 两块钟。

# v2 补验（第二轮，终版）

## 代码增量（相对第一轮）
1. **calendar.js `tzUsable(tz)`**（runtimeTzOf 同区）：显式时区值先过有效性校验（显式 timeZone 的 Intl formatter 试构造，带记忆）；无效值**跳级**落到下一级（角色坏值→设备，全坏→UTC），不再直接采用。⚠️ 旧版本自动写入的 `'Asia/Shanghai'` **不做批量清洗** —— 无法区分「自动默认」与「用户主动选上海」；旧角色要跟设备，在设置里明确选一次「跟随角色（未设置则跟随设备）」即可（真机断言：坏值 `Mars/Olympus` 原样保存在 char 资料里、运行时按设备显示）。
2. **page-calendar.js 空值选项文案**：「跟随设备」→「跟随角色（未设置则跟随设备）」，组说明同步改 —— 空值的语义是摘掉日历覆盖，先跟角色档案，角色没设才跟设备。角色侧（idcard）空值文案仍为「跟随设备」，两级文案各自如实。

## 设置语义核对（TZ8 真机断言）
- **idcard 保存**：`timezone: tzSel.value || ''` —— 「跟随设备」存空串，不写解析出的设备时区；改无关字段（如微信名）不会碰 timezone 键。
- **日历设置保存**：各字段只写自己的键（`saveCfg(ch.id, {scheduleOn/cultures/…})`），不附带 timezone；时区 select 只在自己的 change 事件里写。
- **原值与有效值分离**：`cfgOf().timezone` 是**运行时有效值**（含设备级解析），只用于显示/计算；落盘的只有用户显式选择（char.timezone / calConfigs.timezone）。真机断言：对无时区角色 `saveCfg({scheduleOn:true})` 后 `calConfigs` 记录里**没有 timezone 键**，runtimeTzOf 仍 level=device。
- 已知显示瑕疵（既有行为，本轮未改，不扩大范围）：timeFacts 的地点名取 `char.city` 优先，日历覆盖时区与城市不同时文案可能混搭（如「东京 · Europe/Paris」）；事件存档字段 `event.timezone` 记录创建时的运行时有效值，属事件自身的出处元数据。

## 双口径声明（有意保留，不宣称处处同时区）
- **We 时光日期分组**：按**设备本地日期**（user 浏览自己经历的视角；同一时刻 LA=「9月27日 · 周日」、上海=「9月28日 · 周一」，TZ6/TZ6b 双 context 实证）。
- **We 此刻**：按**当前角色的运行时时区**（无配置=设备，显式 Tokyo=东京 14:00，TZ5a/TZ5b 实证）。
- 两者口径不同是设计使然：时光是「我的记录按我的日历翻」，此刻是「他在他那边现在」。
