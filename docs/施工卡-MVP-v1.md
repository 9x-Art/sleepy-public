### 计划外已完成（原件里没写，但必须做）

这些是原件写完之后才发现的坑，不修的话上面的卡都过不了验收。

- **`page-chat.js` / `page-settings.js` 语法错误** —— 补丁式插入导致整页报废，已重排（`2ba708e`）
- **`store.set()` 单段路径套娃** —— `set('chats', arr)` 实存成 `{chats: arr}`，聊天记录永远读写不到（`2ba708e`）
- **`.send-btn{` 没闭合** —— 把后面约 460 行 CSS 吞成后代选择器，加号面板 / 导航栏 / 文件气泡全部失效（`2ba708e`）
- **三个页面文件从未被 `index.html` 加载** —— 心声 / 手账本 / 拼贴墙永远是占位页（`597b001`）
- **连点返回会把整个页面带出 App** —— `history.back()` 重入，退过基线记录（`597b001`）
- **`.msg-assistant` 文字隐身** —— `color:var(--text)` 和气泡底色是同一个色值（`2ba708e`）
- **首页「字条」入口是死的** —— `data-app="chat"` 但只注册了 `chat-list`（`2ba708e`）
- **`savePresets()` 漏了 `return`** —— 数据其实存进去了，但调用方拿到 undefined 走失败分支：
  保存后不关页面 + 弹「保存失败」（`b7ea5c3`）
- **页面缓存不重渲染** —— app.js 把页面实例缓存复用，但同一个 id 带不同参数再次打开时
  不重渲染，闭包里还捏着上一次的参数。后果是「点开 B 预设/对话，看到并保存的是 A 的内容」。
  已改成参数变了就重渲染（`b7ea5c3`）
- 底栏调整：加号移到左侧、发送键换成小猫爪（`36d3918`）

- [x] **A2 主 API 配置**（URL/Key/模型/温度/上下文/流式/超时）+ 测试连接按钮
  验收：填入真实API信息后点"测试连接"，能返回成功/失败的明确提示；配置保存后刷新页面不丢失
  → 已实测：保存后刷新仍在，测试连接会区分 超时 / 网络 / HTTP / 解析 四类失败原因。
- [x] **A3 本地存储机制**（刷新不丢）
  验收：所有设置项、聊天记录，刷新浏览器/重启App后仍存在
  → 已实测。修掉了 `set()` 套娃（否则聊天记录根本存不下），并给旧存档加了自动解包。
- [x] **A4 清除数据**（二次确认）
  验收：点击清除后必须弹出二次确认弹窗，确认后数据才真正清空，不能一键误删
  → 做成了「再点一次确认清除」+ 4 秒自动撤销，比弹窗更难误触。
- [x] **A5 人设预设库**（增删改 + 导入导出 txt/md，禁 json）
  验收：能新建一个预设、编辑保存、删除；导出的txt/md文件能再导入回来且内容一致
  → 已实测。文件格式是纯文本 + 「===== 预设：名字 =====」分隔头；
  同一份导出再导入后逐字比对 `roundTripExact: true`（正文里的空行、句尾空格都没丢）；
  json 文件会被明确拒收。同名再次导入＝覆盖而不是新增（重复导入幂等）。
  **新建/编辑/删除都验证过。**
- [x] **A6 聊天默认参数**（温度/流式开关）
  验收：改动这里的参数，实际发消息时会带上这个参数（可通过网络请求或行为差异验证）
  → 已实测：改温度 1.6 + 关流式后，抓到的请求体是 `temperature=1.6, stream=false`；
  上下文条数改成 2 后，请求里真的只带 2 条。
  **附带修正**：`mainApi` 里的温度/上限/上下文条数默认改成 `null`（＝跟随这里），
  否则接口自己那套值会一直压过 A6，变成「改了没反应」。

  验收：正常输入文字能发送并收到AI回复；清空输入框直接点发送按钮，AI会主动说一句话
  → 已实测。没有可用接口时会明确提示「还没有可用的模型连接」，不会发空气泡。
- [x] **D2 消息气泡长按菜单**（引用回复、多选、收藏单条、编辑、复制、删除）
  验收：长按任意气泡弹出菜单，六个操作逐一点击验证
  → 六项全做了（底部动作表）。引用后输入框上方出现引用条；
  多选可批量删除；收藏后能在右上角 ★ 收藏夹里查到；编辑/复制/删除都实测过。
- [x] **D3 基础 reroll**（可选带说明）
  验收：点reroll能重新生成一条回复；带说明的reroll，AI的新回复能体现出这条说明的要求
  → 已实测：说明会以指令形式进请求，回复原地替换那一条（不会多出一条）。
- [x] **D4 加号面板基础项**（先做发照片、发文件）
  验收：点"+"弹出面板，能选择发一张图片或一个文件，对方能"看到"
  → 已实测。附件**只存文件名/大小/类型，不存二进制** —— localStorage 只有 5MB，
  存两张原图就会爆配额。上下文里以「[我发了一张照片：xxx.jpg]」出现。
  真要存图得先上 IndexedDB。

## 模块 E：心声（依赖 D 的头像组件存在）

- [x] **E1 头像"未读心声"状态位 + 呼吸光点动画**
  验收：当有新心声时，char头像边缘出现呼吸光点动画；心声被查看后光点消失
  → 已实测。光点挂在**顶部头像**（气泡头像会随消息滚走，看不见）；
  打开面板即已读，光点消失。动效只动 transform/opacity，带 reduced-motion 降级。
- [x] **E2 心声内容独立渲染层**（点头像弹出，不与普通消息气泡共用组件）
  验收：点击有呼吸光点的头像，弹出的心声内容展示层与普通聊天气泡在视觉上明显区分
  → 已实测。面板在**页面正中**（原本做成底部抽屉，用户要求改居中 —— 抽屉和长按菜单、
  加号面板是同一种姿势，放一起会混）。纸条：无尾巴、无大圆角、左边缘一道竖线、衬线字体。
  面板分两页：默认只显示**最新一条**（放大），点「看前面的 N 条」翻到历史列表，
  历史页点「回到最新」翻回来。

> **E 的实现方式**：心声不再是「回复落地后再发一次请求」，而是往消息数组最前面
> 加一条 system 指令，要求模型把心声用 `<心声>…</心声>` 包在正文末尾，前端在流式过程中
> 切出来。**一轮交互只发 1 个请求**（实测过），**一轮永远只有一条**心声。
> 代价：依赖模型听话；不写标签就只是没有新心声，不影响正文。
> **F 模块做提示词引擎时应该把这条格式指令收进去统一管理。**
