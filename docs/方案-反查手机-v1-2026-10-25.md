## 一、qs 是怎么做的（勘察结论）

| 模块 | 职责 | 可借鉴点 |
|---|---|---|
| `reverseTrigger` | 概率主动触发（按角色倾向 high/medium/low/none → 5%~20% 每轮）+ 20 分钟冷却 + 最少 3 轮 + 用户意图正则（"你查一下我手机"）+ 倾向决定同意/拒绝 + 本地拒绝文案 | 触发闸全套照搬思路 |
| `reversePermissions` | 每个 App 一个开关（localStorage），设置 App **硬禁止**，缺省全开 | 权限面照搬 |
| `reverseTakeover` | 接管状态机：浏览计划（固定顺序 or **AI 个性化计划**：LLM 按角色心态挑 3~6 个 App 排序）→ 逐步骤推进 → 120s 超时熔断 | 计划/超时思想 |
| `reverseSampler` | **真实数据采样**：按当前步骤真读该 App 数据 → `detail`（看到了什么）+ `learned`（知道了什么，只提炼用户主动表达的关键内容）。私聊「**滑到谁读谁**」——计划每步聚焦一个联系人，只读那个人的 | 采样/防越界的核心 |
| `reverseThought` | LLM 对真实内容生成一句内心想法，弹幕气泡飘过；prompt 明确「这是真实数据不是演出」 | 想法层 |
| `reverseLogs` | 反查记录落档（看了什么/知道了什么） | 记录层 |
| `reverseReply` | 「替用户回消息」：以 role:'user' 写入目标对话，metadata.source='reverse_reply' 标记 | ⚠️ 危险，见下 |

qs 的精髓一句话：**看的是真数据（采样），知道的是提炼（learned），走的是权限，扮的是机主**。

## 二、sleepy 侧的落地差异（不是照抄）

1. **岛章红线是第一约束**。TA 只能看**本岛**的数据：
   - 孤岛（isle）：只有这一个角色 → 可看的是与你自己的聊天、朋友圈、相册、日记、收藏，**没有"你和别人的私聊"**（房间里没别人）；
   - 群岛（archipelago）：才有「滑到谁读谁」——TA 可以翻你和岛上其他角色的私聊，每步聚焦一个 targetChar，没滑到的不知道。
   - 跨岛数据**绝对不进采样**（所有读取走 `core.scoped` 同一口径）。
2. **执行形态（v1.1 定稿：接管覆盖层是主形态）**：
   - **主形态 = 真·接管覆盖层**：全屏蒙层盖在手机上，TA 的手指（指针动画）真的逐屏滑动——每一步真实打开对应的 sleepy 页面数据视图：TA 滑到私聊列表就渲染私聊列表、点开谁就渲染谁的消息、滑到朋友圈/相册/日记/群声/「我」的资料页就渲染什么，**滑到哪显示到哪**。TA 的内心想法（LLM 生成）以弹幕气泡飘过当前屏。数据层与采样层共用：屏幕上渲染的内容 = sampler 读到的同一份真数据（不是另演一套）。
   - **兜底形态（轻量）**：覆盖层开不出来（无头/极端环境）时，降级成后台采样 + 「系统镜头」卡（`type:'revcheck'`，复用查岗卡位）在聊天流里播报 + eventNote 注入。数据管线完全相同，只是没了演出层。
   - TA 看完 → `learned` 走查岗同款 **eventNote 注入下一轮** + 落 TA 侧记忆（commitMemory，标注来源）。
3. **已知的不对称**：sleepy 的查岗是 user→TA（`noticed` 闸门控制 TA 知不知道）。反查是 TA→user，产出天然是「TA 知道了」，所以不需要 noticed 闸——但需要一个「**你事后知不知道 TA 看了**」的可选玩法（TA 可以偷偷看不留卡），v1 先做成必留卡（你能看见），隐藏模式留做后续开关。
4. **qs 的「替用户回消息」不建议 v1 做**：以 user 身份写消息会污染 userMask 语义（sleepy 的 user 消息绑 activeUserOnIsland 身份，且直接进 TA 上下文当真实用户发言）。真要做，放 P3 单独评审。
5. **入口**：聊天加号面板（和查岗并排）+ TA 主动触发两个方向，与 qs 对齐。

## 三、数据与存储

- `revcheckPermissions`（map，默认 chats/moments/photos/diaries/favorites 全开，设置类硬禁）——设备本地口径。
- `revcheckLast`（每岛一条：{sandboxId, charId, at}）——冷却 20 分钟 + 最少 3 轮聊天。
- 角色倾向 v1.1 保留 qs 的**自动推导**：按 systemPrompt 关键词推导 high/medium/low/none（如占有欲/好奇心/八卦类词 → high；尊重隐私类 → low），推导结果可在聊天设置页看与手动改档（自动为默认，手动可覆盖）。
- 采样上限对齐 qs：聊天 MAX_MSG=6 / 每屏 MAX_ITEMS=4，`learned` 只提炼用户主动表达（不回读原文）。

## 四、分期

- **P0**：`revcheck-core.js` 纯逻辑（触发闸/冷却/意图正则/权限/倾向自动推导/采样计划构建），Node 单测。零 DOM 零 store——采样函数由 page-chat 注入读取器（保持可测）。
- **P1**：page-chat 接线：手动入口 + 主动触发挂进 reply 轮次；采样跑真数据（scoped）；**接管覆盖层主形态**（蒙层 + 指针逐屏滑动 + 真数据视图渲染 + 内心想法弹幕）+ eventNote 注入 + 记忆落库；兜底镜头卡。
- **P2**：权限开关 UI（聊天设置页一块，含微信账号/群声两项）+ 倾向档位展示/覆盖 + 反查记录页（列表：何时/看了什么/知道了什么）。
- **P3（可选）**：「替回消息」单独评审（伪装 user 身份，风险项）。

## 五、风险清单

- 采样读到查岗卡/心声等隐私层 → 采样必须过滤 `type:'checkin'`、心声、hypnotic 类内部消息。
- 群岛 TA 翻到「你和其他角色的暧昧」→ 这正是功能价值，但 learned 提炼时只摘事实，不加戏（对齐 qs 的 userSays 口径）。
- 群线上版（page-group-ai）v1 不做，先私聊。
- 冷却/权限存键必须带岛章或按 chat 存，防串岛。
