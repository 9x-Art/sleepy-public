## 一、八个问题逐条回答

### Q1. compileWorldbook 接入了哪些场景？

| 场景 | 接入 | 证据 | 闸 |
|---|---|---|---|
| 私聊线上 | ✅ K04 槽 | `prompt-engine.js` `case 'worldbook'`（近 4000 字历史做匹配文本） | 关键词命中 + 常驻条目 |

| 群线上 | ❌ | `page-group-ai.js` 无 | — |
| 群线下 | ❌ | `page-group-offline.js` 无 | — |

**实测**：关键词命中 → 条目整块进 system；无关输入 → 不注入（双向验证通过）。
注意：compileWorldbook 是**关键词闸**不是按参与者闸 —— 群场景若接入，NPC 条目的
`knownBy` 闸必须在条目级生效（现在私聊场景天然单主体，闸是隐式成立的）。

### Q5. 群线上能否按参与者注入各自不同的信息？

**结构性结论：不能做真隔离。** 群线上一次请求 = 一条共享 system 产出全场发言，
[ENTITY_KNOWLEDGE] 的「逐本体块」只是**排版归属**，模型全部可见。当前的信息隔离
全部靠**软机制**：

1. groupRound 卡知识边界纪律：「本体只知道 TA 看得见的群消息和 [ENTITY_KNOWLEDGE] 里
   **TA 自己的内容**；别人的私聊、别的账号背后的归属、TA 没看见的事，一概不知、不提、不暗示」；
2. `forbiddenDisclosures` 字段（plans 里每本体声明不可泄露项）；
3. 编号禁令（[ENTITY id=…] 不进消息正文）。

要真隔离只有 **per-entity 多请求**（每个本体一次调用，成本 ×N，且失去「全场连续」）——
不建议。**施工方向应是收紧软隔离**：接入任何 per-entity 信息前先确认该信息
「被其它本体看见」是否可接受；不可接受的（ta 影响、世界书 NPC 条目）要么不进群、
要么在编译层做「仅对该本体知情才写入其块」的过滤（knownBy 闸已有先例）。

### Q7. 零网络 messages 是否真的包含这些动态片段？

**实测 14/14**（`probe-dyn-chain2.js`，harness 沙箱，造真实形状数据走生产装配）：

| 验证 | 结果 |
|---|---|
| 世界书命中 → 整块进线上/线下 system | ✓ |
| 世界书无关输入 → 不注入 | ✓ |
| ta 已确认影响 + 相关输入 → 进线上 system（[TA_IMPACT] 块） | ✓ |
| ta 无关输入 → 不注入（relevance 闸） | ✓ |
| 知情闸 fail closed（knownCharId 不符不注入） | ✓ |
| 群线下 NPC 本体块进 system | ✓ |
| 群线下不含 ta 影响（未接 = 不广播） | ✓ |
| life/recall/worldbook/phone/drop/taimpact 无数据时全静默 | ✓ |

（探针调试过程中两次红均为夹具问题：① `eventsInScope` 无当前岛 fail closed → 夹具需
造岛；② relevance bigram 阈值 → 夹具 query 需真相关。生产链无缺陷。）

### Q8. 广播风险：私密数据 / 未确认提案 / 其他角色信息会不会被广播？

按数据源分级（**当前全部受控**，但机制不同）：

| 数据 | 隔离机制 | 等级 |
|---|---|---|
| ta 提案（pending，未确认） | **零进入任何场景**（全库消费点仅 ta app 内） | 🟢 结构隔离 |
| ta 影响的知情闸 | `knownCharId` fail closed（单聊语义） | 🟢 结构隔离（**群场景未接入，接入时必须扩展为按本体过滤**） |
| 朋友圈生活动态 | lifeFeed 只聚合 char 有权看见的内容（canCharSee + 日历 visibility 四档） | 🟢 结构隔离 |
| 日记 | author:'char' 天然可见、author:'user' 默认关 | 🟢 结构隔离 |
| 群场景 per-entity 块（NPC knownBy、innerText 等） | **软隔离**：groupRound 卡纪律 + forbiddenDisclosures + 编号禁令；整条 system 模型全可见 | 🟡 软隔离（靠模型遵守） |
| 群线下 away 成员 | 文字声明「听不见也看不见」 | 🟡 软隔离 |
| **未验证的高危点** | 群线上**未接** ta 影响与世界书 —— 一旦接入，现有软隔离**不足以**承载「仅某本体知情」的数据：ta 影响的 knownCharId 闸是**单 root 语义**，群场景每个本体 root 不同，直接整块注入 = 把 A 的私事广播给 B 的发言 | 🔴 接入前必须解决 |

**结论**：现状安全；**最大的未来风险是「把单聊语义的知情数据（ta 影响、世界书 NPC 条目）
原样接进群场景」** —— 接入施工单必须包含「按参与者过滤」设计，否则宁可不接。
