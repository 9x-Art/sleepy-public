## 零、先说一个比报告更严重的问题（v156 那版是**不可用状态**）

`page-offline.js` **模块顶层求值就抛异常**，整个文件的导出全部丢失：

```
Sleepy.offlineDiag   → undefined
Sleepy.offlineStore  → undefined
Sleepy.offlineUI     → undefined
PAGEERROR: Cannot read properties of undefined (reading 'NO_CONNECTION')
```

**根因（两个，都在这一处）**：

也就是说：**v156 那版一进线下场景就是坏的**，不是「诊断不准」而是「线下不可用」。
本次把它一起修了。修法：诊断常量块整体上移到所有使用点之前；导出面删到只剩只读。

## 一、F1 请求身份与诊断阶段混用

| 项 | 修前 | 修后 |
|---|---|---|
| 请求身份 | 拿 `diagSeq`（诊断记录序号）当身份 | `requestSeq`，每次新请求只分配一次 |
| 诊断序号 | 与身份混用 | `diagSeq` 独立，只给面板按写入顺序看 |
| 分配时机 | `go()` 内部分配 | **`requestTurn()` 入口**分配（预取阶段就占位） |
| 业务守卫 | `if (diagSeq !== seq) return;` → **整段丢弃业务回调** | `isLatest = (reqId === requestSeq)`，**只判断要不要动共享 UI 状态** |
| 收尾 | 旧请求会误关新请求的忙碌态 | `finishTurn(ownId)` 带身份核对 |

**为什么必须这么改**：`diagRecord` 每写一条就自增 `diagSeq`。「已到达调用边界」写一次、
「无连接」再写一次 → 序号变了 → 回调里 `if (diagSeq !== seq) return;` 命中 →
pending 永久占位、按钮不解禁、无错误提示。守卫只能管「这条诊断要不要写」，
**绝不能管业务回调要不要跑**。

**异步边界（不只 diagRecord 两个函数）**：

- **预取阶段**：`pending` 原来在 `go()` 里才置位，召回那 1.5s 内能连点两次发两个请求。
  改到 `requestTurn` 入口占位。
- **预取回来**：新增 `afterPrefetch()`，先核对「页面还在 / 会话还在」，
  否则记 `canceled` + `finishTurn(reqId)` 后不再往下走。
- **页面切换**：修了一个 v2 遗留的真 bug ——
  `onHide` 去改 `Sleepy.__offlineSceneCtx`，**那个全局从未被赋值**，
  于是 `ctx.__alive` 一个标记都没真清掉。
- **再进入**：`ctx.__alive` 只在 `renderScene` 入口置 true，但**页面实例是缓存复用的**，
  再进入走 `onShow` 不重跑 render → `__alive` 永远停在 false →
  离开一次之后该场景所有请求都被当成「页面已离开」而作废。**已在 `onShow` 重新置位。**
  （这条是测试第 6 节抓出来的，不是我预判到的。）

## 二、F2 失败语义与异常收尾

读了真实的 `candForSession` / `callModel`，阶段严格分级：

| 情况 | 判定 | 诊断阶段 |
|---|---|---|
| 没有可用连接 | `cand === null`，**本地判定，没出网** | `no-connection` |
| HTTP 错误 | 服务端**确实收到了**并拒绝 | `request-rejected` |
| 响应无法解析 | 服务端**确实返回了** | `request-rejected` |
| 网络失败 / 超时 | **无法确认**服务端是否收到 | `request-failed-unknown` |
| `callModel` 同步抛 | 请求可能根本没发出去 | `request-failed-unknown` |
| 页面离开 / 被取代 | 本轮被放弃 | `canceled` |

- **已删除**「ok 与 fail 都算到达服务端」「失败一定是服务端拒绝」两个错误结论，
  面板说明文案同步重写。
- 同步 `throw`、`Promise reject`、非 thenable 三条路径**都收尾**，
  不再永久忙碌、不再沿用上次成功状态。
- 诊断**不写异常全文**；`requestOk` 三态（`true`/`false`/`null`=尚无结论）。
- 协议、解析器、正常回复业务语义**一行未动**。
