## 0. 摘要与三个必须先说的结论

盘点覆盖 **28 个信息源（S01–S28）**，其中已闭环送达模型请求 **14 个**，仅存储未送达 **8 个**，仅 UI **3 个**，未实现/未找到 **3 个**。

**结论一 · 纠正一处口径**（承接前两轮）：线下文风在代码里是 **3 套 + 自定义**，不是"六套"。
`prompt-engine.js:1227 STYLE_LABELS` / `:1233 STYLE_HINTS` 三套；群线下 `page-group-offline.js:173-179 styleHintOf` **另三句、另一份实现**。
两侧 UI 各有独立选项，合计六段提示词正文，但**分属两套互不同步的系统**（详见 S24）。

**结论二 · `relation.confirmedChange` 产出即丢弃**（S09）。提示词卡 `:477` 要求总结模型输出关系变化，但 `page-summary.js` 全文件无 `relation` 字样 —— 不校验、不落库、无读取点。

**结论三 · 关系变化与人格变化有真实入口**（S10–S12），我前一轮"无支撑"的偏严判定在此更正：它们由 `relationship_fact` / `habit` 两类记忆条目与 `taEvents[].impacts[]` 承载，且真进模型请求。未证实的是**独立持久化与状态级送达闭环**，不是"完全没有依据"。

### S01 角色设定原文 ｜已接

1. **内容**：角色卡 `content` 全文。
2. **生产**：用户录入 → `core.upsertChar`。

## 5. 专项核对结论

### 5.1 charState（专项四）

- **rootId 生命周期**：`core.rootIdOf`（`core.js:593-596`）→ `rootOf(id)`。键 `charState:<rootId>`，**不含 sandboxId**。
- **跨岛/拆岛语义**：**[已确认] 读、写两端均无岛校验**。定性为"缺闸"成立；定性为"已泄漏"**不成立**，需运行验证。
- **全部读取点过滤**：`page-proactive.js:246`（注入，无过滤）、`page-proactive.js:98`（候选，只取 unspoken）、`page-ta.js:547`（UI）。**三处均无时效过滤**。

### 5.2 人物变化（专项四）

- **关系事件** → `shared_event`/`promise` 记忆条目。
- **关系变化** → `relationship_fact` 记忆条目（自由文本）。
- **人格/习惯变化** → `habit` 记忆条目 **+** `taEvents[].impacts[]`（结构化、带有效期）。
- **不能仅因无专用字段就断言没有依据** —— 上一轮我给的"无支撑"判定偏严，此处更正。
- **未证实的是**：独立的状态级持久化载体，以及它到聊天请求的送达闭环。

### 5.3 六套文风 vs 三项 STYLE_HINTS（专项四）

- **实际资产**：私聊线下 3 套（`prompt-engine.js:1233`）+ 群线下 3 句（`page-group-offline.js:173-179`）= **六段提示词正文，分属两套系统**。
- **选择入口**：两侧 UI 各自独立（`page-offline.js:1666-1670`、`page-group-offline.js:1897 起`），都含"自定义"。
- **装配路径**：私聊经 `narrativeText:1260-1262`；群线下经 `styleHintOf` → `[PRESENCE RULES]`（`:275-276`），**用户 `styleWords` 优先**。
- **关系**：**互不同步的两份实现**。改私聊不影响群线下，反之亦然。
- **未修改、未复制任何旧提示词原文。**

### 5.4 多层持有同一事件（专项四）

| 重叠组 | 权威源 | 确认字段 | 显式去重 |
|---|---|---|---|
| 记忆 ↔ ta 承诺 | **[已确认] 未定义** | 两套闭集**不映射**（记忆五态 `page-memory.js:53-56` vs ta 四态 `ta-life.js:48`） | **无跨表去重**；ta 内部 `findBySource` `ta-life.js:198-207` |
| 日历 ↔ 记忆（**仅纪念日**） | 日历 `KEY_EVT` | `ev.status` + `memoryId`↔`calendarEventId` | **有**：`requestCreateEvent` `calendar.js:838-851`；`saveAnniversary:1157/1172`；拒删 `:975/978` |
| 日历 ↔ ta | 日历 | `ev.status` | **无**（`grep taLife calendar.js` = 0） |
| We ↔ 日历/记忆 | **源系统**（`checkSource` 四态复核 `page-collection.js:68-134`，**fail closed** `:130`） | `createdBy`/`confirmedBy` | **无跨库**；We 内部 `dedupeKey` `page-we-proposal.js:89` |
| 帷境 ↔ 记忆 | 帷境（`status:'active'`） | `source:'other_app'` + `sourceRef` | **有**：`write` `wj-canon.js:343-359` |
| 帷境 ↔ 日历 | 帷境 | `historical` + `authorizedVia` | **有**：`requestKey` `wj-canon.js:315` |

**总体**：只有「日历↔记忆（纪念日）」与「帷境→记忆/日历」两处有真跨层绑定 + 幂等键。**记忆↔ta、日历↔ta、We↔任何库三组纯各管各的。**

### 5.5 能力说明 vs 执行回执

- **能做什么 ≠ 已经做了什么**：`[手机]`/`[生图]`/`[表情]`/`[收藏提议]` 四类标签的说明书**只讲"可以写这个标签"**。

- **[已确认] 缺口**：`[AVAILABLE_ACTIONS]` 在 proactive 卡里出现，但**程序侧零输出** —— 卡上写着「只申请 `[AVAILABLE_ACTIONS]` 中允许的动作」，而程序从未提供该清单。
