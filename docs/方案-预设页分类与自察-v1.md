# 方案卡 · 预设页完善 v1（分类上锁 / 自定义排序 / 条目自察）

> 2026-10-21 · 用户三点需求：① 内容分类上锁不加解释；② 自定义预设条目可调注入顺序并真实应用；③ 帮助 user 判断世界书/预设条目有没有起作用（思维链自察）。

---

## 现状勘定（先说清楚地里有什么）

- **装配顺序的真话**：`cfg().custom` 数组顺序**就是**注入顺序——线上 `assembleOnline`（prompt-engine.js:2093）和线下（:2492）都是 forEach 数组序逐张 push。所以「调顺序并真实应用」= 数组重排 + UI，装配层零改动。
- **上锁现状**：内置卡 `CARD_DEFAULTS[id].locked:true` 已经大部分锁了（f1/c05/shell 等 15 张），但页面仍分「调用类型 / 注入序列·线上 / 注入序列·线下 / 自定义注入」四段，每行带 slot 名、token 数、note 解释，locked 行还能看到结构。
- **世界书命中**：`compileWorldbook` 装配时**完全知道**哪些条目命中（常驻 or 关键词），但这些信息只进了 prompt 正文，没暴露给用户。
- **输出协议**：c05 规定 `[WHISPER]…[/WHISPER]`，`parseReply` 已有「抽标签→不进气泡→不回喂」的成熟模式（[WHISPER]、[译] 都是这么处理的），自察块可以完全照抄这条路。

## A · 分类上锁（P0）

预设页重组为分类分组，非开发者模式下**内置行全部只显示名字，不可点开、不带 note/slot/token 解释**（"不加解释"落到字面）：

| 分类 | 内容 | 可操作 |
|---|---|---|
| 调用类型 | 线上普通回复 / 线下 / 总结 / 主动消息 / 群聊 | 只读（名字） |
| 线上提示词 | 共享外壳 / F1 线上规则 / 输出协议 / 关系与记忆 / 世界书 / 召回 等 K 层槽 | 只读（名字） |
| 角色功能 | 拍一拍 / 撤回 / 灯牌 / 慢递 / 表情包 / 发图 / 小游戏 / 手机 / 收藏提议 / 记一笔 / 群声 | 开关保留（见问题2） |
| 线下与后台 | f2 / 总结卡 / 主动消息卡 / 群聊编排 | 只读（名字） |
| 自定义注入 | 用户自己的卡 | 编辑 + 排序 + 开关 |

- 开发者模式：保持现状全可见可编辑（隐蔽开关不动）。
- 归类实现：给 `ONLINE_SLOTS` 每行加 `cat` 字段（'prompt' | 'feature'），页面按 cat 分组渲染； program 槽（realworld/lang/drop/history 等纯程序生成）归进「线上提示词」，不单列。
- 不动装配层——纯 UI 重排，冒烟照跑。

## B · 自定义注入排序（P0）

- **数据**：`prompt-engine.js` 加 `moveCustomCard(id, dir)`（-1/+1 交换数组相邻项，`saveCfg` 落库）。
- **UI**：自定义注入列表每行右侧加 ↑↓ 两个小钮（首行禁↑、末行禁↓），点击即落库重渲染。
- **真实应用**：线上/线下装配都按数组序，天然生效。
- **回归**：冒烟加一条——三张自定义卡乱序存放，move 两次后断言装配产物（system 拼接串）里的相对顺序 = 新顺序。判据落在装配产物上，期望值硬写。

## C · 条目作用判断（P0 半 + P1 半）

### C1 · 命中报告（P0，零成本、可靠）

**思路**：模型自述「我用了哪条设定」是自我报告，可能编；但**哪条世界书条目命中了、为什么命中（常驻 / 关键词「X」），装配时是确定的**——这才是可验证的"有没有作用"。

- 调试预览（preset-preview）加「本轮命中」段：世界书条目逐条列 `条目名（常驻 / 命中关键词：X）`，外加命中的自定义卡、召回块。
- 实现：`compileWorldbook` 已经在算 hit，让它在装配结果里带一份结构化命中清单（只进预览数据，不进 prompt、不加调用）。

### C2 · 模型自察（P1，默认关）

宝宝说的思维链方案，可行，且工程上有现成轨道：

- 新增**自察开关**（预设页，默认关）：开着时装配在 c05 前注入一段自察指令，并**附上本轮命中条目的编号清单**（C1 的数据顺手就用上了——不给清单，模型只能瞎编条目名）。
- 协议：回复最前面输出 `[自察]…[/自察]`，内容三问：本轮适配了哪些设定条目 / 有没有哪个条目要求特别注意 / 它把本来要说的话改成了什么。
- 解析：`parseReply` 增加 `[自察]` 剥离（照 [WHISPER]/[译] 同一套：不进气泡、不落 content、**不回喂下一轮**——喂回去会变成永久噪音），存 `msg.inspect`。
- 查看：长按消息菜单加一项「TA 的自察」（没有就灰）。
- 成本：每轮多几十 token 输出；默认关，想查记忆链路时再开。

## 分阶段

- **P0**：A 分类上锁 + B 自定义排序 + C1 命中报告。全是 UI/数据层，装配语义零变化。
- **P1**：C2 模型自察（装配 + 解析 + 长按查看 + 冒烟）。
- 每阶段 `pnpm check` + `pnpm smoke` 双绿再交。
