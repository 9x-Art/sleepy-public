## 二、§1 修复：组末失败漏停

### 症状（实测复现）

```js
// 单轮组 + 超时
runGroupSchedule({ id:'S1', turns:['只有一轮'], send: 失败轮, … })
// → 停机原因: null · 停止整跑: false · 登记: {"组":"S1","正常跑完":true}
```

**末轮失败被记成「正常跑完」** —— 因为停机检查只在循环内做，
最后一轮之后就跳出循环，**没有任何人再检查它**。

### 修法

在 `runGroupSchedule` 里，**每轮持久化之后立刻**做失败与停机判定
（含最后一轮、单轮组）：

```js
      /* ---- ★ 失败与停机检查：**每轮之后立即做**，含最后一轮、单轮组 ---- */
      var reason = null;
      var sk = stopKind(rec);
      if (sk === 'perm') reason = '权限不可用(403)';
      else if (sk === 'net') reason = '网络/超时：' + …;
      else if (sk === 'link') reason = '采集关联异常（…）';
      else if (rec.未发出) reason = '未发出：' + …;
      else if (!trust(rec).ok) reason = '本轮未产出可信回复（' + trust(rec).why + '）';
      if (reason) {
        state.停机原因 = reason;  state.停止整跑 = true;  state.终态 = reason;
        /* ★ 剩余轮补记未跑，**不依赖进入下一轮** */
        if (ti + 1 < turns.length) {
          await markRestUnrun(ti + 1, '前一轮失败（' + reason + '），依赖轮不自动重试');
        }
        registerGroup({ 组: spec.id, 停机: reason, 停机轮: ti + 1 });
        await persistPhase('终态');
        return state;
      }
```

**两道防线都保留**：
- 防线①（原有）：每轮**发出前**查 `trust(上一轮)` —— 不发依赖轮；
- 防线②（本轮新增）：每轮**持久化后**查失败/停机 —— 抓末轮 + 单轮组。

### 顺带修正的语义（上一轮改错了）

上一轮我把 `timeout`/`network` 从 `hardStopKind` 移除，理由是「让依赖检查有机会跑」。
**那是错的** —— 移除后调度器在当轮就 `return`，依赖检查根本没机会跑。

你已明确：**网络/超时继续停止整跑**。现已恢复：

| 条件 | 归属 |
|---|---|
| **403** | 硬停止 |

## 四、§3 发送计数校正

### 三个计数，含义不同、不可混用

| 计数 | 定义 |
|---|---|
| **调度次数** | 循环走到第几轮（含未发出/未跑） |
| **确认发送数** | **真的交给了请求出口**的次数 —— **未发出不算** |
| **未知状态数** | 已到出口但采集异常（诊断缺失）—— **不记为零请求** |

调度器内：
```js
      if (rec.未发出) {
        state.确认发送数 += 0;          /* ★ 未发出绝不能加 */
      } else {
        state.确认发送数++;
        if (rec.采集异常) state.未知状态数++;
      }
```

正式落盘（`meta.请求计数`）：
```js
    return { 确认发送数: sent, 未知状态数: unknown, 未发出数: notSent, 未跑轮数: unrun,
             口径说明: '确认发送数=到达请求出口；未知状态数=已到达但采集异常（不记为零请求）；未发出数=明确没发出' };
```
`meta.实际HTTP请求数` 保留为**兼容字段**，现等于 `确认发送数`。

⚠️ **旧口径的错**：用「有原始请求结果」判定 → 会把「已发出但采集异常」误算成没发。

**测试验证**：
```
§4 ✓ ★ 未发出不计入确认发送数（确认发送数 = 0，调度次数 = 1）
§5 ✓ ★ 采集异常仍算「已发出」（确认发送数 ≥ 1，停机原因=采集关联异常）
```

## 五、§4 持久化与终态统一

### 计数含当前写入

`persistPhase(phase)` 是**唯一**写入口：
```js
  async function persistPhase(phase) {
    state.当前写入阶段 = phase;
    await persist(state, phase);
    state.持久化次数++;
  }
```

| 时机 | 阶段 | 次数 |
|---|---|---|
| 每轮发送后 | `'轮次'` | n |
| 依赖拦截 / 硬停止 / 正常跑完 | `'终态'` | +1 |

⇒ **n 轮 → n+1 次写入**（末尾多一次终态）。
⚠️ **不再以「n 轮只能写 n 次」为通过条件** —— 那正是末轮失败被漏掉的原因。

### 终态必须被保存

`makeSnapshotWriter` 现在写入：
- `阶段`：`'终态快照（该组已结束）'` / `'逐轮快照（运行中，尚未收尾）'`
- `写入阶段`、`确认发送数`、`未知状态数`、`调度次数`
- `终态`、`停机原因`、`持久化错误`

**验证**：读回落盘 JSON 确认终态快照里有停机原因。

### 写入失败 → 停轮 + 停组 + 保留错误上下文

```js
      } catch (e) {
        state.停机原因 = '持久化失败：' + String(e && e.message);
        state.停止整跑 = true; state.持久化失败 = true; state.终态 = '持久化失败';
        state.持久化错误 = { message: …, code: e && e.code, 轮: ti + 1, 已发送数: state.确认发送数 };
```
