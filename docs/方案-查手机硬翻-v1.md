## 二、硬翻掷骰（核心玩法，✅ 已按此实现）

**入口**：有锁且屏幕已暗的锁屏上，「趁他不注意，硬翻」按钮（danger 色）。

**掷骰**：点下那一刻定结果（本地 `Math.random()`，不调 API）。

```
p = 基础档位（OOC 全局，三档可调：温和 20 / 标准 30 默认 / 刺激 40）
  + 15%   他刚放下手机（lastExitedAt < 10 分钟）
  + 10%   他设了密码（有防备的人警觉）
  + 10%   存在未消化的 pin_fail 痕迹（他可能已经起疑）
  封顶 85%
```

**入口与设置**：档位入口在**锁屏右上角的小齿轮**（点开浮层：seg 三档 +
实时概率文案「现在硬翻：约 N% 会被发现（含当前情境）」）——
调它的人就是正盯着锁屏犹豫的那个人，不放进全局设置 app（安乐 2026-09-21 拍的）。

**确认弹窗（硬要求）**：按硬翻先弹确认，正文写明「**有被 TA 发现的风险 ——
被发现会当场中断，TA 会知道你翻过**」+ 当前概率。不做确认直接掷 = 验收不过。

**结果分两路**：

- **没被发现** → 进入会话（`unlockMethod:'force'`），**必留轻痕迹**
  （type:'recent'）。他之后凭痕迹察觉 —— 走已有的察觉机制，不当场抓包。
- **被发现** → 会话当场 `caughtOnScene` + 收束；重痕迹（type:'read'）当场
  `detectedAt`；「被发现了」画面上由 **char 即时反应**接管：
  调一次模型（`phoneAI.caughtReaction`，卡片 `prompt-engine: phoneCaught`），
  提示词即拍板口径——「你发现 user 在翻你的手机，这时你会说什么做什么」，
  生气/冷脸/试探/装没看见由 char 的性格和关系决定，**连手机怎么处置也交给剧情**。
  没配 API / 生成失败就老实显示兜底文案，不编假台词（六.1 教训）。
