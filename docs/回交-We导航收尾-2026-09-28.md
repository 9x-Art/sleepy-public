## 1. 时光条目跳转：补齐「具体记录定位」+ 失效反馈

**原先**：moments/diary 条目只 `nav.open('moments'/'diary')` —— 就是打开来源 App 首页，按指令判为缺口，已修。

**现在**（page-we.js:966 `jumpToSource` + :1006 `revealInPage`）：

- **点击先预检**（删除 / 失效 / 无权都在这里拦）：
  - moments：`momentsTab.byId(id)` 取不到、`status==='deleted'`、`sandboxId` 不是当前房、`canSee(m, user.id,'user')` 不过 → toast「这条动态已经不在了」，**停在原地不跳页**；
  - diary：`diary.list()`（scoped 实时读）里找不到 → toast「这一篇已经撕掉了」；
  - we：`collectionStore.findInScope(id)` 找不到（跨岛/已拆）→ toast「这件记录已经不在馆里」。
- **预检过了才跳转并定位到那条记录**（不只是开 App）：
  - 表现层挂钩：`page-moments.js:959` momentCard 加 `card.setAttribute('data-id', m.id)`；`page-diary.js:457` 日记条目加 `item.dataset.id = d.id`（一行/处，无新路由无新页面）。
  - `page-app.js:293`：聊天 App 壳 render 支持 `params.tab` —— 跳朋友圈带 `{ tab:'moments', jump:id }`，保证落进朋友圈那一屏，不会停在用户上次离开的 tab。
  - `revealInPage`：找到 `[data-id]` 条目后，**手动算滚动容器内偏移**（工作记忆红线：不用 scrollIntoView，避免整页被搬走），滚动到位 + `we-jump-flash` 短高亮（style.css 末尾，1.6s 动画自动摘）。
- **说明**：日记没有「单篇详情页」——`diary-edit` 是**写/补写编辑器**（TA 已写完的日记进编辑器 = 让 user 改 TA 的话，不是现有流程），日记页本身就是浏览界面，所以日记的「具体定位」= 打开日记页滚到那一篇并高亮，这是现有页面上的最小定位能力，没有复制页面。
- **测试**：browser-we-test **W21**（朋友圈/日记各跳一次：目标页 data-id 元素存在 + we-jump-flash 挂上 + top 正确）、**W20**（删除来源后聚合消失；DOM 残留条目点击 → 预检 toast「这条动态已经不在了」且 top 仍是 we-time 不跳页；TA `privacy:'self'` 动态与缺 userId 旧日记不出现）。均为真实执行通过。

## 3. weStore.list() 的类型与时间字段规则

- **纳入时光的类型**：`weStore.list()`（page-we.js:157 `weList` = `core.scoped(store.get('weEntries'))`）全部入列。weEntries 只有两种 createdBy：`'user'`（手动/抽屉）与 `'char'`（P2 提议经 user 确认，page-we-proposal.js:264）；**P2 的 pending/declined 提议在独立的 `weProposals` 表**（page-we-proposal.js:209-234），`weProposals.accept` 之前不会出现在 weStore.list() —— 未确认内容不可能冒充经历。
- **时间字段规则**：`at` 是「原始发生时间」：
  - 手动记录：抽屉里用户填的日期，留空 = 今天（page-we.js:322-330）；
  - P2 入馆：`page-we-proposal.js:218` 提议创建时 `at: ev.startAt`（**取真实事件的开始时间，模型自报值不采信**），:257 `accept` 落表 `at: p.at` —— **继承原始发生时间，不是 proposedAt / confirmedAt（入馆时间）**；`createdAt/confirmedAt` 另存，只作档案字段，展示层不用。
  - 时光排序用 `atNum(en.at)`（page-we.js:830，number 直用 / 日期字符串解析 / 失败当 0 排最后显示「时间不详」）——**不会用入馆时间替代原始发生时间**。P2 回归输出里可见实证：accepted entry `"at":"2026-10-03 16:00"`（事件时间）而 `confirmedAt:1790600685876`（确认时刻），两者分离。
- **不会重复成为经历**：weEntries 的来源类型全集 = `manual` / `calendar`（手动候选 page-we.js:141-150 + P2 提议）/ `offline`（page-we.js:153-166）——**时光的另两个源是 moments 和 diary，与 calendar/offline 无交集**，所以「来源记录与其馆藏引用共存」在当前数据模型下天然不重复；再加防御性 `type+id` 去重（page-we.js:857 `seen` 键）。`sourceCandidates` 目前**没有** moments/diary 选项，若未来放开，需要把去重键升级为跨源比对（如 weEntry.sourceType==='moments' 时压掉 moments 源同 id 条目）——已在代码注释与本回交中标注，不凭空扩建。
