## 2. 提案表与事件表

- `taProposals`：kind 六类（item_update/follow_update/promise_review/npc_event/impact_review/contact_candidate）、operation 四类、status 五态（pending/accepted/rejected/expired/failed）、targetRef + **baseVersion**、summary/reason、**extra 白名单**（只收 eventText/basis/targetStatus 等 16 个固定键）、dependsOn、requestId + **modelMeta**（模型名/label/promptVer/时间）、fp 内容指纹、history；
- `taEvents`：已成立 NPC 事件（提案接受后写入），knowledge[] / impacts[] 各自绑定依据；
- 四件套齐：DEFAULTS + 删房名单（真跑拆岛零孤儿）+ tagScope 盖岛章 + scoped/findInScope；refCharId 归 root。

## 3. 模型调用入口、装配与解析

- **入口白名单**（§1）：幕后「生成一轮生活提案」（advance）、「复核现有事实」（review）、「提名 NPC 候选」（candidates）、详情页「复核或推进」（review，ta-item/ta-follow 各一个按钮）。**页面打开 / 切页 / 切岛 / 聊天每轮零调用**（门禁在 runMode，不在模型）；
- 装配：`FORMAT_RULES` 系统规则（只吐 JSON / 空 proposals 合法 / 高影响禁令 / 不准代替 user）+ JSON 数据段（世界简报 + 目标对象摘要含 updatedAt 作 baseVersion + 已成立事件）；
- 调用：`Sleepy.api.requestOnce(cand, messages)`，cand = 主 API（store 'mainApi'，总结引擎同款回落，**本轮未新增 ta 专用模型设置**——如实记录）；
- 解析：剥 code fence → JSON.parse，失败如实报错不落表；
- **NPC 候选（A 模块）不走提案表**——直接落 taNpcDrafts（status=draft、**sourceType:'model_proposal'**、sourceRef 带模型标识），≤3 条、同名同角色不重建（§3.A 原文「模型候选只进入草稿区」；§8「先进 taProposals」针对 B/C 生活提案——两类分流的理由见报告附注）。

## 4. 程序校验与审核（证据）

- 白名单收口：非法 kind / 无 target / 无依据 → failed 丢弃（smoke：5 条输入 1 收 2 拒 1 重）；
- **版本过期**：baseVersion ≠ target.updatedAt → expired；acceptProposal 落库前**双保险再验一次**（审核期间目标又变 → 拒绝，不覆盖新状态）；
- **高影响**：关键词（死/重伤/结婚/离婚/怀孕/分手/前任…）→ extra.highImpact=1 → 接受必须 `confirmHighImpact:true`（UI 单独确认），未确认返回 needConfirm（smoke 双向验证）；
- **承诺红线**：promise_review 只更新 pendingWhy/evidence，status 永不被提案改（smoke：接受后承诺仍「待核实」）；
- **关注没有完成态**：follow_update 忽略 targetStatus；
- **requestId+fp 幂等**：同输入重放 duplicate，不重复落（smoke：两轮后 pending 数不变）；
- **未审核零变化**：pending 期间 taItems/taFollows 本岛快照逐字节比对不变（smoke）；
- **contact_candidate**：接受 → 只追加进 attentionInbox 候选队列（≤4 截断、带提案号来源），**不发送**；
- **自主开关**：键 `taAutoLife:<rootId>`（enabled + updatedAt + scope）；关闭 → runMode('advance') 直接 `gate:'auto_off'` 且 **transport 零调用**（smoke 计数 0）；review / candidates 不受影响；不倒灌、不影响聊天链路；
- **npc_event → impact**：事件接受落 taEvents；impact_review 必须 eventRef 存在 + knownCharId + basis（知情依据），缺一拒；重放同 fp 不叠加（impacts 恒 1 条）。

## 5. 真实模型调用（如实记录）

**本轮未执行真实网络调用**：本地验收环境的 store 没有主 API 配置，而冒烟按项目惯例用**注入 transport**（不打真网络）完成了装配→解析→校验→落表→审核→落库的**全链路**验证。真机步骤：设置 → 主 API 配好模型 → ta 幕后 → 打开「自主生活更新」→ 点「生成一轮生活提案」→ 幕后「待审核提案」区审核。调用记录会写在每条提案的 modelMeta（模型名/promptVer/时间/requestId）里，控制台无相应日志不显示成功。

## 6. F1 / F2 / 主动消息接线（如实记录）

- **F1/F2：未接线**（施工单 §7 允许项）——不注入任何 ta 内容、不注入 pending proposal；已接受的影响摘要目前存于 `taEvents.impacts`，仅 ta 内部可读，留给后续批次设计注入协议；
- **主动消息：半接**——accepted 的 contact_candidate 会进 `attentionInbox:<rootId>`（主动消息引擎的既有候选队列，符合「只读已成立触发候选」），发送仍走既有权限/频率/确认规则；
- 提案生成失败不影响聊天链路（ta-model 独立于 prompt-engine）。
