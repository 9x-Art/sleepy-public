## 一、目标（3 件事）

> 角色可以独立开关自己的记忆消费；关了之后：**自己大脑的块不再建、不再被消费**，
> 但**共享池（群/岛/我的日记）照常**；重开后**定向补扫**（不全局重扫）。

| 场景 | 关闭后 | 判据 |
|---|---|---|
| 角色私有池建块（sweep / sweepOffline / sweepMem / sweepPhone） | **停建**，一个 embedding 不调 | `charMemOff(root)` |
| 私聊 L4 召回（角色池部分） | **空** | `blocksOf` 跳过角色池 |
| 群聊注入（群池 L4） | 该成员实体段**不含群池** | `groupTextFor` 逐成员判 |
| 群线下注入 | 同左 | 逐参与者判 |
| 重开后补扫 | **定向作废该 root 的私有池游标** | `invalidateCursorsFor(root)` |
| 共享池（群 / 岛 / 账号） | **照常** | 不判 |

## 四、`invalidateCursorsFor(root)` 设计（勘察后定稿：定向 rootEpoch）

> 源设计 §3.3 原是「按 chatId/sessionId **逐个删键**作废」—— 但游标值走 store（带**内存缓存**，
> `resetCursors` 注释已明示：绕过缓存直接删键，读的时候还会命中缓存里的老游标，真机翻过车）。
> → 勘察后改为**定向 rootEpoch 世代号**（与全局 `vecEpoch` 同哲学、无缓存陷阱）。

```js
rootEpochKey(root)   = 'vecEpoch4:' + root
rootEpochNow(root)   = store.get(key) || 0
invalidateCursorsFor(root) = store.set(key, rootEpochNow(root) + 1)  // 定向递增

// writeCursor 游标值加 rootEpoch: root ? rootEpochNow(root) : null（共享池 null）
// readCursor  私有池检查 (cur.rootEpoch||0) === rootEpochNow(root)，不匹配返回 0 → 从头重扫该 root
// sweepSource 传 root = src.charId ? rootOf(src.charId) : null
```

- 重开时调 `invalidateCursorsFor(root)` → 该 root 私有池游标 epoch 失配 → **私有池从源头定向重扫**。
- 全局 `resetCursors` 与定向互不干扰（两套维度叠加）。
- 共享池 src 无 charId → root = null → 行为不变。
- `invalidateCursorsFor` **不是数学意义上的幂等函数**，而是**可重复安全执行**（重复调用只会 +1）；
  但实际**只有** `setCharConfig` 的 false→true 会调它一次，true→true / true→false 均不调用。

### rootEpoch 全链路审计（勘察证据）

- **游标键不含 root**：`chat.id` / `off:<sessionId>` / `phone:<sub>:<phoneId>`，游标值当前也不存 root。
- `readCursor` @1224 被 `sweepSource` @1287 调 1 次；`writeCursor` @1242 被调 3 次（1294 / 1312 / 1325）。
- `resetCursors` @1259 只 set 全局 `vecEpoch`，**不清 rootEpoch**（两套维度天然叠加）。
- 老游标无 `rootEpoch` 字段时 `(cur.rootEpoch||0) === rootEpochNow(root)`：若 rootEpoch 从未递增过，
  `rootEpochNow(root)=0` 与老游标 `(cur.rootEpoch||0)=0` **兼容** → 存量用户升级后不用重扫。
- **关闭期间不推进私有池游标**：`sweepSource` @1277 命中 `memoff` 直接 return，**不碰 writeCursor**
  → 关闭期间私有池游标停在该 root 最后一次推进的位置；重开后 rootEpoch 失配，**私有池从源头定向重扫**
  （含关闭期间关闭前的内容都**重新遍历**），不承诺"只计算关闭期间新增内容"。已有段被指纹跳过、不重算
  embedding（见 §十，2026-09-26 实测重扫无新增时 embedding=0）。

### sweep 全源 charId 归一（勘察证据：谁带 charId、谁是 rootOf）

| 源 | charId 值 | 位置 |
|---|---|---|
| `sweep` 线上私聊 | `rootOf(charId)` | @1345 |
| `sweepOffline` 线下私聊 | `rootOf(charId)` | @1359 |
| `sweepMem` 查档案 | `rootOf(charId)` | @1557 |
| `sweepPhone` 查手机 | `rootOf(charId)` | @1626 |
| `sweepDiary`（char 分支） | `rootOf(charId)` | @1515 |
| `sweepGroup` 群池 | 无 charId | @1377 |
| `sweepMoments` 岛池 | 无 charId | @1470 |
| `sweepDiary`（user 分支） | 无 charId | @1506 |

→ `sweepSource` @1277 判 `src.charId && charMemOff(src.charId)` 时，所有私有池源传的都是 rootOf → 判据正确。

### 池类型契约（勘察结论，需测试钉死）

- **角色私有池 = 裸 charId**（无前缀，`ownerKey: rootOf(charId)`）。
- **共享池带前缀**：`group:<id>` / `island:<sbId>` / `user:<userId>`。
- `k === rootOf(charId)` 只匹配**裸键**，与带前缀共享池**互不重叠** → `blocksOf` @402 的跳过判断安全。
- 契约测试：M3b 断言 `rootOf('chX')` 不含 `group:`/`island:`/`user:` 前缀，共享池键含前缀。

## 六、群线下：逐参与者内联（施工前收口正式定稿）

线上群聊是**逐实体的独立 `[ENTITY id=…]` 段**（page-group-ai.js:208-222），群池 L4 挪进逐本体循环即可隔离。

**群线下不同**：`[PARTICIPANTS]` 是**合并段**（page-group-offline.js:211-225，所有参与者在一个块里），
没有线上那种独立实体段。逐参与者塞独立段落会破坏段落结构、且 token 膨胀严重。

**→ 正式定稿：不拆段，在 `[PARTICIPANTS]` 里逐参与者内联**（不采用"全员全开才注入共享段"方案）：

- 在 `presentParts(s).forEach` @213-224 循环体内，对该参与者的 `ownerId` 调
  `groupTextFor(s.groupId, ownerId)`，非空时**内联进该参与者那一行**（`m.name：<人设摘要> + 群池回忆`）。
- **每个参与者单独调 `groupTextFor`** → 关闭成员自己的群池摘要为空，其他成员不受影响。
- **共享池本体仍继续建块**（`sweepGroup` 不判 charMemOff，照常 embedding 建块）—— 关的只是"消费/注入"。
- 代价（已接受）：同一段召回文本按"开着记忆的成员数"重复 → token 增量（施工报告量化）。
- ⚠️ 内联摘要若偏长，退化为：紧跟在 `[PARTICIPANTS]` 块后追加「<名字> 的回忆」独立小段，**不入共享 sys**、仍逐参与者隔离。

> 与"共享段按在场全员全开才注入"的取舍：内联方案与线上逐实体隔离语义一致、不留共享路径
> （任何共享路径都会被 M5c 反向锁死），故正式采用内联。

## 七、边沿行为（施工前收口正式定稿）

**rootEpoch 三态边沿**（与 `setCharConfig` 判断一致，消除旧"每次+1但重复开不作废"的矛盾表述）：

| 转换 | rootEpoch | 是否调 `invalidateCursorsFor` |
|---|---|---|
| false → true | **+1（一次）** | 是 → 定向重扫该 root 私有池 |
| true → true | **不变** | 否（不调用） |
| true → false | **不变** | 否（不调用，不清游标、不删块） |

实现位置：`page-memory.js setCharConfig` @112 内，`before = charConfig(charId).enabled`，
仅当 `patch` 含 `enabled` 且 `before===false && after===true` 才调 `invalidateCursorsFor(root)`。

| # | 场景 | 预期 |
|---|---|---|
| E1 | false→true | rootEpoch +1 一次，只作废该 root 私有池游标；readCursor 失配 → **该 root 私有池从头定向重扫** |
| E2 | true→true（重复开） | rootEpoch 不变，不调用 invalidate，不重扫 |
| E3 | true→false（关闭） | rootEpoch 不变，不清游标、不删块（关的是"继续消费/建块"） |
| E4 | 关闭期间 | **不推进私有池游标**（sweepSource @1277 直接 return）；重开后该 root 的 rootEpoch 失配 → **私有池从源头定向重扫**（含关闭前内容，不承诺只算关闭期间新增）；**共享池与其他 root 游标不动** |
| E5 | 环境无 memoryStore | `charMemOff` 返回 false（默认开），不误关（判据已覆盖） |
| E6 | NPC 角色 | `charConfig` 默认关 → 视为 off（判据已覆盖） |

### 发现并修复的真 bug / 缺陷（非静态护栏可替代）

**① 重开重扫去重（核心）**
- 现象：重开记忆 → `readCursor` 失配返回 0 → **from=0 从头重扫**。旧段（同 sourceId/fromId/toId）
  与已入库块完全同指纹，却被当成新内容重新 embedding + 建块。
- 原生实测（修复前）：块数 2→2→**4→6**、embedding 增量 2→0→**2→2** —— 相同源内容随开关次数**线性增副本**。
- 最小修复（memory-vec.js `sweepSource`）：入库前按 `sourceId|fromId|toId` 指纹去重，
  **已存在的段跳过、不建块不 embedding；跳过的旧段不占 SWEEP_MAX 配额**（否则重扫被旧段占满、新增永远切不到）。
  修复后实测：块数 2→2→**3→5**、embedding 增量 2→0→**1→2**、重复段 0 —— 重扫只算真正新增，旧段不重算。
  **未用全库 wipeAll**。
- **从头重扫是否确有必要**：是。rootEpoch 失配后 `readCursor` 返回 0 是最朴素的作废语义——
  游标只记「切到第几条」（lastId/index），无法只从关闭时刻增量恢复（关闭期间游标停在原地，
  游标位置 ≠ 新内容起点，见 §七 E4）。不用 wipeAll，靠指纹去重让重扫只花新增段的费用。
  **代价如实说明（2026-09-26 实测修正）**：重开记忆会**从头遍历历史源**（含关闭前内容），
  但**已有段在指纹去重时跳过、不重新 embedding、不重复收费**（原生实测：旧块→关→开、无新增消息，
  重扫 `added=0`、embedding 增量 `0`，块数不变）。**只有新增/未命中段才 embedding**。
  「定向扫描」≠「不会重复建块」—— 已靠指纹去重避免重复建块；历史段**不重算**。
  注意区分：**遍历**整个源（O(块数)，免费）≠ **重算**每段的 embedding（收费，仅新增/未命中段才发生）。

**② 关闭消费旁路（lastOf 过滤范围过宽）**
- 现象：关闭记忆后，**不重新 prefetch** 时，装配端 `compileRecall` → `text` → `lastOf` 仍读到
  **开启时预热的旧私有块缓存** → 关闭未立即生效。
- 最小修复（memory-vec.js `lastOf` + `prefetchInto`）：`prefetchInto` items 补带 `ownerKey`，
  `lastOf` 关闭分支**只滤当前 root 私有块**（`items.filter(it => it.ownerKey !== root)`）。
- ⚠️ **不能整体 `return []`**：私聊召回池是 [root, island:*, user:*]，旧缓存里混着岛/账号块，
  一刀切会把共享内容一起毙掉（原生 Edge M新5 点出「过滤范围过宽」）。
  原生实测：关闭后 `text` 不再带旧私有记忆，岛/账号池仍可消费，通过。

**③ refresh/reindex 写旁路**
- 现象：`refreshMem` / `refreshPhone` / `refreshMoment` / `refreshDiary` 都汇聚到 `reindexItem`，
  但 `reindexItem` **没有 charMemOff 判断** → 角色关闭时编辑档案/手机条目仍会调 embedding + 写新私有块。
- 最小修复（memory-vec.js `reindexItem`）：算得 ownerKey 后加 `if (charMemOff(key)) return {why:'memoff'}`。
  私有池裸键关时短路（不删旧块、不 embedding、不写块）；带前缀的岛/账号/群池查不到配置 → 不误伤。
  原生实测 M新6：关闭时 refreshMem/refreshPhone 返回 memoff、embedding 0、私有块数 0；共享账号池照常。
