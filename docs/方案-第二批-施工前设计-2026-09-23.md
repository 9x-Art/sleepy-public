#### 1.4-2 条目级规则（按你的六条重写）

**C1 · 完整字段比较（不是只比 content/status/updatedAt）**
把条目做**规范化序列化**（全部字段、键排序、忽略 `updatedAt` 之外的时间噪声）→ 完全相等才判"同一条"并跳过。

**C2 · 状态矩阵（invalid / superseded / active / pending 分开定义）**
状态优先级：**invalid > superseded > active > pending**（越"死"越优先，与 C3 失效优先同源）。

| 组合 | 结果 |
|---|---|
| 同级（如 active + active） | 内容同 → 跳过；内容不同 → `updatedAt` 较新者**原样保留**；较旧者**改新 id**、`status` 保持自身、`supersededBy = 胜者 id` |
| 跨级（如 active + invalid） | **高优先级条目原样保留**；低优先级那条**改新 id**、`status` 保持自身、`supersededBy = 胜者 id`（= 失效优先，作废的不复活） |
| pending + active | active 胜；pending 那条改新 id 保留 pending（不丢"待确认"这件事） |
| invalid + invalid | 内容同 → 跳过；不同 → `updatedAt` 较新者胜，另一条改新 id |

**C3 · `isAnchor` 只合并字段，不改失效状态**
仅在"同级合并"时取 `isAnchor = A.isAnchor || B.isAnchor`；
**若结果是 invalid / superseded，即使一方是锚也不改成 active**。

**C4 · `understandings` 未核实 schema 前不合并**
审计结论：`understandings` **没有任何创建方**（全仓只有读：`page-memory.js:141/284/325/384/433/689/791/923`；
总结写的是 `memories`，`page-summary.js:137`）→ schema 无法核实。
→ 规则：**不合并** `understandings`；且**只要源键的 `understandings` 非空，就整键不迁移、不删除、隔离并计数**
（宁可留一份可疑数据，也不猜着合并）。空数组则与"无该字段"等价，正常迁移。

**C5 · 时间可比性**：ISO 字符串 `localeCompare`（`page-memory.js:68`）；缺 `updatedAt` 回落 `createdAt`；都缺视为最旧。

**C6 · `fromCharId` 的取值**：源键是皮套 → `fromCharId = 该皮套 id`；源键本身是 root → `fromCharId = 自身 id`；
**推不出来 → `null`**（不猜）。

**C7 · 孤儿键**：无可靠 parent/root 映射 → **隔离并计数**（`orphans`），**不猜、不合并、不删除**。

#### 1.4-3 迁移写入锁（新增）

迁移期间**暂停三类写入**，避免"边迁边写"产生既不在源也不在目标的条目：

| 暂停对象 | 位置 |
|---|---|
| 总结引擎 | `page-summary.js` 的 `onChatTurn` / `runNow` / `ingest` |
| 手工记忆写入 | `page-memory.js` 的 `addMemoryItem` / `writeMemoryItems` / `updateMemoryItem` / `deleteMemoryItem` / `confirmMemoryItem(s)` / `invalidateMemoryItem` / `toggleAnchor` |
| 向量档案写入 | `memory-vec.js` 的 `sweepMem` |

做法：`memoryStore` 暴露 `isMigrating()`；上述入口第一步判它 → 直接返回
`{ok:false, why:'migrating'}`（**不排队、不缓存**：总结有游标不推进、手工操作可由用户重试，
语义上都安全）。迁移结束（含失败）**必须解锁**（`finally`）。

#### 1.4-4 备份与恢复（修订）

- 备份内容 = **所有将被合并/删除的源键** + **目标 root 键的迁移前完整快照**（两者都要）。
- 形态：`charMemBackup:<ts> = { at, ver, src:{key→原文}, dst:{key→原文} }`。
- **失败时整份恢复**：按 `dst` 把目标键**还原成迁移前原文**、按 `src` 把源键写回
  —— **不是"按 id 删掉本次并入的条目"**（那条路依赖 id 推导，脆弱）。
- **保留期**：只保留**最近 3 份** `charMemBackup:*`；每次迁移成功 + 校验通过后，清理更早的。
- **纳入「清空全部数据」**：备份里含记忆原文 → 清空时必须一并清除（并入项目 1 的清理清单）。
- 备份键会随前缀扫描进入导出（`store.js:406-420`）—— 这是有意的（回滚要它），但要写进体积提示。

#### 1.4-5 迁移流水线（六步，修订版）

```
1. 上锁          置 migrating（§1.4-3）
2. 读源键        A 组五键 × core.allChars()；+ localStorage 前缀兜底捡孤儿键
3. 生成备份      源键 + 目标 root 键**双份**完整快照 → charMemBackup:<ts>
4. 合并并写目标  按 §1.4-1 / §1.4-2；每个目标键一次 set
5. 校验          数量 / ID 集合 / status / updatedAt / fromCharId / 去重结果；
                 任一不通过 → 用备份**整份恢复** → 不删任何源键 → 记 failed
6. 删源键 + 解锁  校验通过才删源键（含子 map 的键）；落日志；
                 清理过期备份（保留最近 3）；finally 解锁
```

#### 1.4-6 幂等的五个条件（沿用）

1. 重复执行不产生重复条目 → C1 完整字段比较 + 目标键去重校验；
2. 中途失败可用备份恢复 → §1.4-4 完整快照；
3. **旧源键删除前不算迁移完成**；
4. **失败不得删除源键**；
5. 成功后系统不再把旧源键当活跃读取源 → 源键已删 + `loadCharMemory` 归一到 root。

## 3. 项目 1｜清空 / 导入（顺序重写）

### 3.1 导入（七步，按你的顺序）

```
1. 完整解析并校验备份文件 —— **不写入**
2. 备份当前 localStorage（importRollback:<ts>）
3. 开启 wiping gate
4. await memoryVec.wipeAll()
5. wipe 成功后才 store.importAll()
6. import 失败 → 用 importRollback 恢复原 localStorage（并解除 gate）
7. 全部成功 → 解除 gate → reload
```

### 3.2 清空（非原子，必须如实报告）

```
1. 备份（同上，可回滚）
2. 开 wiping gate
3. await memoryVec.wipeAll()
4. store.clearAll()（localStorage）
5. await Sleepy.media.clear()
6. memoryVec.clearCache() 等内存缓存
7. 汇总报告：{ ok:[已清项], failed:[失败项 + 原因] } → UI 逐项列出
   —— **不许只写"重试"**；失败项要指名（例：localStorage 已清、图库失败、向量库失败）
8. 全 ok → 提示完成 + reload；有失败 → 列出清单 + 提供「重试未完成项」
```

### 3.3 成功判据（不许假成功）

- `wipeAll` 在**无 IDB 环境返回 `{ok:false, why:'noidb'}`**（不是 true）；
- 成功后：`await total() === 0`、`vecEpoch` 已变、无 `vecFail:` 残留；
- gate 期间 `blocksOf` / `prefetch` 一律返回空（清理完成前不得使用旧块）。
- **node 只能验接线与游标**；"块数归零"标死为**真机验收**。

## 4. 项目 3｜解散群（入口唯一化 + 顺序）

- **执行顺序（先派生/向量，最后主表）**：
```
1. tombstone：把该群的会话标记结束（groupOfflineSessions 行 status='ended'）
2. 清派生数据：remove('groupPending:'+gid)、remove('groupInner:'+gid)、
               remove('sumCursor:g:'+gid)
3. 清向量：await memoryVec.forget({ groupId })      （失败可见，不吞）
4. 过滤两张线下数组：groupOfflineSessions / offlineHandoffs 按行 groupId
5. **最后**删主表：groups / groupMembers / groupMessages
```
  这样即使 3 失败，**主表还在** → 用户看得见"群还在（没解散成功）"，不会出现"群没了但向量残留"。

## 5. 项目 4｜删除边界（逐格定唯一结论）

> 修正：上一稿引用的「§5.5」不存在 —— 那是笔误，本条即定稿。**所有二选一（解引/转移、清理/归档）已收敛为唯一结论。**

### 5.1 三层

L1 角色私有（物理删）｜L2 共享引用（解引，解引方式见格内唯一值）｜L3 岛级·用户级（保留）。

### 5.3 `purgeChar` 的范围：先算 affectedFaceIds

```
affectedFaceIds = [rootIdOf(目标char)] ∪ core.subChars(rootId).map(c => c.id)
```
- **岛级 NPC（`parentType='sandbox'`）不在其中**（NPC 归岛，不随人删）；
- 挂在该人名下的**老式 NPC**（`parentType='char'`）**延续现有 `removeChar` 行为一并删**（`core.js:560-562`），
  并写进报告（这是与"NPC 归岛"新语义的已知偏差，不藏）。
- `purgeChar` 的所有"`charId ∈ affectedFaceIds`"格，都指这份集合。

### 5.4 `removeUser`：不许一律置 null（唯一结论）

**规则**：删马甲时，其引用一律**转给本岛 `default` 马甲**（`core.defaultUserOfSandbox(sb)`）。
- 若本岛**没有别的马甲** → **禁止删除**，返回 `{ok:false, message:'这座岛至少要留一件马甲'}`；
- 现有全局保护（`core.js:675` `list.length <= 1`）**不够**（它是全局计数），本岛判断是**新增**；
- 涉及字段：`chats.userId` / `links.userId` / `memories.toUserId` / `moments.maskId` / `offlineSessions.userId` /
  `diaries.userId`（user 写的）/ `calEvents.participants`（若有 user 位）。

### 5.5 `removeSub`（删皮套）：置 null + **重建块**，不删 root 池

```
1. `charMem:<root>` 里 fromCharId === 该脸的条目 → fromCharId 置 null（内容留在大脑里）
2. 对这些条目逐条 memoryVec.refreshMem(root, memId)   ← **重建/失效那几条 mem 块**
3. **不**调 forget({charId: root}) —— 不能删掉整个 root 池
4. 该脸自己的 chats/diaries/phones/… 按 §5.2 删
```

### 5.6 `detachChar` 的向量清理：按 `sandboxId` + `source` 精确清

- 依据：块上**已存 `sandboxId`**（`memory-vec.js:875`）；`forget` 目前只支持
  `ownerKey|charId|groupId` + `sourceId`/`ids`（`:502-515`），**没有 sandboxId 过滤**。
- 最小改：`forget` 加一个可选 `sandboxId` 判定（`if (filter.sandboxId && b.sandboxId !== filter.sandboxId) return false;`）。
- 移出岛调用：`forget({ charId: rootOf(该脸), sandboxId: 本岛 })`
  → 只清**该角色在本岛**的 chat / offline / mem / phone 块。
- **不会误删**：
  - 该 root 在**其他岛**的记忆（不同 sandboxId）；
  - **群池块**：`sweepGroup` 的 src 不设 `charId`（`memory-vec.js:940-947`）→ 群块 `charId = null` → `forget({charId})` 匹配不到；
  - 岛池（`island:`）/账号池（`user:`）：ownerKey 不同，不进扫描范围。

## 6. 施工纪律（沿用）

1. 每项目**先给证据 / 复现 → 最小改 → 补回归 + 反向验证**，不合并成一批。
2. 不许把：接线测试当 IndexedDB 真清理；charMem 探针当迁移完成；`check.js` 全绿当功能验证；向量块存在当权限正确。
3. 每项目单独报告：**改动文件与行号 / 数据语义 / 是否需历史迁移 / 新增测试 / 真机待验项 / 失败时的回滚方式**。
4. 不可逆动作（`wipeAll` / `forget` / 迁移删源键）：**先备份或先 tombstone，再执行**；失败必须可见，不许吞。
