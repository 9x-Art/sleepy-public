# 记忆系统地图 · 数据来源 · 设置在哪（2026-09-22）

> 这份是「查得到的图」，不是设计文档。设计在 `docs/方案-向量记忆-v1.md`
> 和 v5（`Sleepy-整体记忆与主动陪伴系统-v5·详细设计.md`）。
> 想知道「角色为什么说了这句话」「某个开关在哪」「某样东西存在哪」，来这份里找。

---

## 0. 一句话

角色的每一轮回复，是把**三层东西**拼起来：

```
固定的      规则 / 身份 / 认知 / 时间 / 文风     ← 每轮都在，不检索
近期的      最近对话原文 + 近期生活动态          ← 有条件但确定，不检索
按需的      已整理记忆 + 向量召回的旧片段        ← 挑出来的，会随话题变
```

三条铁律：
1. **不是「把所有东西塞进去」** —— 每层都有配额，超了就丢（丢的是索引/视野，不是原始数据）。
2. **「能检索到」和「角色知道」是两件事** —— 权限先于注入（见 §5）。
3. **向量只负责「捞候选」** —— 捞出来还要过权限、时间、去重（`memory-vec.js` 的 `rank()`）。

## 3. 数据来源（谁写了什么、怎么进 prompt）

| 存储键 | 是什么 | 谁写 | 进 prompt 的路径 |
|---|---|---|---|
| `charMem:<charId>` | **记忆库**（L0/L2/L3）：条目 + 推测项 | 总结引擎、手动添加、帷境定史写回 | `getMemoryInjection` → K03 |
| `chats` | 对话与消息 | 聊天页 | 近 40 条原文 → K09 |
| `moments` | 朋友圈动态（含赞/评论内嵌） | 朋友圈页、`moments-ai.js` | `life-feed` → K03b（只收我发的 + TA 自己发的） |
| `calendars` / 事件 | 日历事件 | 日历页、帷境定史 | `life-feed` → K03b（**按每条自己的 visibility 过滤**） |
| `diaries` | 日记（`author: user/char`） | 日记页、自动日记 | `life-feed` → K03b（我写的要授权；TA 写的不需要） |
| `todos` | 桌面待办组件 | 桌面 | ❌ 还没进 L1.5（见 §8） |
| `charState:<charId>` | 心绪 + 主动状态 | 心声、主动消息引擎 | 主动消息用它，不进常规对话 |
| `attentionInbox:` / `openLoops:` | 关注队列 / 未完成承诺 | 总结引擎 | 主动消息的候选 |
| `sleepy-vec`（IndexedDB） | **向量索引**（块 id + 向量 + 块原文） | `memory-vec.sweep` | 召回后 → K03c |
| `wjCanon` | 帷境定史审阅（候选/冲突/认知） | 正史审阅台 | 写入后进记忆库（来源「其他 App」） |
| `links` | 角色↔马甲的关系 + 认知模式 + 朋友权限 | 关系配置、剧情 | I01 的 awareness_mode、朋友圈三道闸 |
| `favorites` | 收藏馆（消息 + 帷境票根） | 聊天长按收藏、谢幕票根 | ❌ 不进 prompt（那是给 user 看的） |

**⚠️ 一条重要的边界**：`favorites`、`wallets`、`photos` 这类是**给 user 看的东西**，
不是「角色记得的事」。它们不进 prompt —— 除非哪天做成「角色也能看见」的源（那要走 §5 的授权）。

## 4. 三个时间尺度（为什么不是「固定两百条」）

| 档 | 内容 | 给法 | 现在的量 |
|---|---|---|---|
| **近景** | 最近对话原文 | 无条件全给（保连贯） | 默认 40 条（上限 200） |
| **中景** | 更早的**相关原文块** | 向量召回，按需回填 | top 12 候选 → 重排 → 最多 4 条 |
| **远景** | 压缩后的事实 | 记忆库 + 总结 | 配额 12 条（锚点/约定不吃配额） |

**为什么不全给**：200 条 ≈ 1.5～4 万 token/轮；更要紧的是 **lost in the middle** ——
上下文越长，模型对中段越读不到。**加长度 ≠ 加记忆**，反而会把近处的冲淡。

**召回必须回填原文块**（不是摘要）—— 只给摘要的「准」是假的，
因为摘要里没有当时的语气、也没有话是怎么说的。这是 `memory-vec.js` 里
「块里存一份 text」的原因（方案里写过「向量是索引不是副本」，那里刻意例外）。

## 5. 角色能看到你的什么（授权）

★ **红线：「我能看到」≠「TA 能看到」。** 日历页是上帝视角（你能看全部，
靠 `visText` 标注），给角色看的那份必须另判。

| 源 | 判据 | 在哪改 |
|---|---|---|
| **朋友圈** | 三道闸：⓪ 账号隔离（哪个马甲发的）→ ① 朋友权限（`iHideChar` 我不看他的 / `iHideFromChar` 我不让他看我的 / `charHidesMe` / `charHidesFromMe`）→ ② 动态自己的 `privacy` 四档 | 聊天设置页 →「TA 能知道我的什么」→ 朋友权限抽屉（**这是和你关系最近的地方**） |
| **日历** | **每条事件自带可见性**：`private`（只有你看得到）/ `shared_busy`（**只知道那会儿有事**，不泄露内容）/ `shared_detail` / `participants`。另外 createdBy 是 TA 自己的 → TA 全知道 | 日历里**逐条**选 —— 这就是 v5 要的「细分类别权限」，不用另开全局开关 |
| **日记** | `author:'char'` 的（TA 代笔）天然可见；`author:'user'`（你写的）**默认关**，要授权 | 聊天设置页 →「TA 能知道我的什么」→ 开关「让我写的日记给他看」（存 `lifeShare:<charId>`） |

**为什么日历不给全局开关**：事件级比 App 级更细。你说「明天下午有事」和
「明天下午去心理科」，需要的隐私档位完全不同 —— 四档里的 `shared_busy` 就是干这个的。

**索引也一样受约束**：向量块上带 `rootId / charId / userId / sandboxId`，
召回时按 **core 的同一套规矩**过滤 —— 有认知屏障（`cognitionOf().barrier`）就只给
「同皮套 + 同马甲」，没有屏障才整个大脑互通。**别只按 charId 过滤** ——
那会让孤岛/群岛之间、以及「他不知道是同一个人」的两个马甲之间串记忆。
（判据是纯函数 `memoryVec._pure.visibleTo`，冒烟里守着它和 core 一致。）

## 6. 写入与召回的时机（什么时候调模型）

| 动作 | 什么时候 | 挡不挡聊天 |
|---|---|---|
| **向量写入**（`sweep`） | 每收完一条回复，后台跑；每次最多 2 块 | ❌ 不挡（`setTimeout` + 后台） |
| **向量召回**（`prefetch`） | 发送前，**和主请求并行**；超时 1.5 秒就放弃这轮 | 最多挡 1.5 秒 |
| **总结**（L2） | 手动点 + 周期触发（累计轮数到了） | ❌ 不挡 |
| **朋友权限/授权判定** | 每次装配时实时判（不看缓存） | 不调模型 |

召回是**异步预取 + 同步装配**：`assembleOnline` 是同步函数，
所以 `prefetch` 先把结果落进缓存，槽位再同步读（`page-chat.js requestReply` 拆成了
`requestReply` + `runReply` 就为这个；线下 `requestTurn` + `go` 同理）。

**主动消息是例外**：它没有「当前输入」，所以用**上一次预取**的结果（滞后一轮），
同时把下一次的排上 —— 不 await，不该拖慢 TA 开口。

## 8. 已知缺口（没做的，别以为做了）

**先把「L4 已完成」这句话拆开** —— 三层，别混成一句：

| 层 | 内容 | 状态 |
|---|---|---|
| 基础设施 | API 配置页、`api.embed()`、IndexedDB 库、`memory-vec.js`、槽位 K03c | ✅ |
| 链路已通 | 线上预取 → 后台写入 → 三层装配都读得到 → 按 `rootId + 认知屏障` 隔离 → 索引可重建 | ✅ |
| **端到端待验收** | 下面 1～4 条 | ⏳ |

1. **线下会话还没索引进向量库** —— 只索引线上私聊（`sweep` 只被聊天页调）。
   线下召回**读**是通的（同一份 `prefetch`），只是线下的内容没写进去。
2. **真实召回质量没验** —— 只用**假 embed** 验过整条链路。
   真模型下「召回得准不准」要跑一段时间才知道（要不要补重排的判断标准在方案 §3.5）。
3. **删除 / 编辑不联动** —— 消息删了、改了，对应的块还在库里。
   块记了 `fromId / toId`，但没做反查清理，也**没做「原文变了就重切块」**。
4. **多源索引的权限撤回（现在还没遇到，但早晚会）** —— 索引里现在只有私聊，
   而私聊没有授权开关，所以这个风险**目前不成立**。
   一旦把朋友圈/日记也索引进向量（v5 是这么设计的），就必须在每个块上记
   「写它时的可见性」，并在**注入前回源复核** ——
   **索引只存候选，不存永久可见权**。（L1.5 没这个问题：它是每次实时读的。）
5. **S2 关系罗盘空着** —— 角色会主动找你，但不会「一步步把关系往前带」。
6. **主动消息的 system 是手拼的** —— 不走槽位矩阵，已经漏过两次（外壳、召回）。
   建议做成 `PROACTIVE_SLOTS` 表，顺手能让配置页也显示它。
7. **待办（`todos`）还没进 L1.5** —— 桌面待办是现成的源（v5 列了
   「Todo 的重要完成或延期」），但它属于你的私密内容，要按日记的模式加授权开关。
8. **记忆没有「事件时间」** —— 只有写入时间，所以角色说不清「那是很久以前还是上个月」。
   要做得让总结多输出一个 `when` 字段。
9. **program 槽在预设配置页点不开开关** —— 既有行为（relation/time/life/recall 都一样），
   进去只能看说明。要让用户能关掉某一层，得先给 program 槽做开关。
10. **记忆块上限 500 / 大脑**（`vecCfg.maxBlocks`）—— 超了丢最老的块
    （原文还在存档里，丢的只是索引）。
