# 方案 · 以身入局 v1 —— P0~P3 施工计划

> 依据：`_tmp-yishenruju-zip/` 资料包（需求清单 v1 + 运行时判定协议 v1 + 8 个 Demo）
> 与用户 2026-10-08 晚的五点拍板。本计划只列方案，暂未开工。

## 〇、已拍板的核心口径

1. **名字**：App 就叫「以身入局」（内部 id 沿用已注册的 `yishenruju`，桌面格 v23 已就位）。
2. **user 双席位**：进世界前可选 **老板** 或 **员工**（协议 v1 席位：老板 | 员工 | 代局长，代局长后续再议）。
   - 老板：派遣 / 观察 char 的对白与心理 / 有限干预 / 撤回 / 度假安排。
   - 员工：user 亲自入局占位，可**带一个 char 同行**（= 协议注入块里的「同档员工」，带信任值）。
3. **char 三层身份**（用户原话 a/b/c）：
   - a. 本身的 char（原人设、与 user 的原有关系原样保留）；
   - b. 以身入局员工身份（默认就是本局一员，有自己的想法、会主动左右剧情去完成任务，不是皮套）；
   - c. 穿书所使用的占位身份（领局牌环节选定，知情范围/不知情范围写死在档案）。
   - 注入与行为推演按 a→b→c 叠层：占位身份管权限判定，员工身份管任务目标，本 char 管人格与关系。
4. **岛屿隔离，无跨岛**：以身入局整体按岛打章；群岛里带哪个 char / 派哪个执行任务只在本岛名册里选；员工记忆、世界记忆、人物偏离态、异常度全带岛章。
5. **主题**：复用帷境夜色（`style.css:11801` 起全套 `--wj-*` 变量），不新造色板。
6. **副 API**：以身入局加入 api.js `FEATURES` 功能多选清单（新 feature key，暂定 `book`），可勾选分配给副 API；未勾选走主 API 链，零行为变化。
7. **右上角设置**（游玩页常驻入口）：①使用哪本世界书；②每轮描写多少字（档位制，如 精炼/标准/铺陈）。
8. **Demo 的定位**：8 个 Demo 交互流程是**意图参考**，美化要重做；里面的内容大多是占位，后期由模型真实生成（内置世界包数据本身是静态的，叙事全模型出）。
9. **文案要有意思**：不写说明书腔，按项目一贯口吻（对 user 说话的语气贯穿各页）。

### P1 · 有选择（判定 B + 老板权限）

- 判定 B 物件：随身手机道具库（实物态可用但有可见性后果 / 存档态世界内不存在必须拒绝）；道具取出费与索取。

### P2 · 像个局（判定 C + 封存经济）

- 判定 C 偏离：照本→改口→脱轨，推进条件**且**关系、一轮最多推进一人、代价由状态机校验；改口必须给「原文 vs 现在」对照展示；脱轨结算加成。
- 封存 / 解封 / 冷却（异常度随其他世界委托数衰减、下限 20、封存不能洗异常度、每世界最多封存 2 次、残案结算）。
- 多世界 + 度假线 + 结算多维评分（委托完成度/规则遵守/稳定度/满意度/char 心理负担/老板满意度）。

### P3 · 导入 TXT

- 编码探测（UTF-8 失败切 GB18030）+ 预览确认；章节标题切分（无标题按段落/长度兜底）；手动改章节名 / 选起始章节 / 手填本次委托 / 手动指定 char 占位角色。
- 不做：自动识别人物 / 自动理解整本书 / 自动生成世界观（需求清单 §十明确第一版手动）。

## 五、P0 补充设计草稿（2026-10-09 晚 · 待拍板，未开工）

> 起因：用户指出原方案漏了三件事——模型在哪调、悬浮球体系、char 连续行动怎么看。

### 5.1 模型调用总账（一轮 = 一次调用）

原则：**叙事与判定回判同一次往返**。协议 v1 的 `<判定>` 块本来就挂在每轮正文末尾，同一次调用返回后剥离解析即可；协议 §五「裁判层独立于文风层」指的是判定数据不被文风影响，**不要求裁判二次调用**。账最好算：轮数 ≈ 调用数。

| 调用点 | 触发 | 输入要点 | 形态 |
|---|---|---|---|
| 在场轮 | user 入局说话/行动（员工或老板亲临） | 协议四块注入 + user 本轮言行 | 独立场景调用（同离线页构，不走岛消息流，一次调用=一次 fetch） |
| char 行动轮 | 老板观测时点推进（或自动档循环） | **无 user 输入**：任务记忆+世界状态+char 三层身份+守则+上轮回判写回结果 | 自主行动形态（同 proactive/ta-model 家族），落点=行动日志非消息 |
| 干预 | 老板插话 | **不单独调用**，合并进下一轮注入（局印传话块） | 省账：干预零成本，下次行动轮消费 |
| 结案结算 | 条件达成/失败/撤回 | 任务全记录 | 多维分数由状态机按记录算（不信模型现编数），模型只生成结算叙述：委托者评价+char 感想+评级包装 |

- 走线：全部挂 feature `book`（副 API 可分配；未勾选走主链）。
- 调用预算：建档时按预计轮数估一次总账（Demo 已有此概念），自动档连跑前再提示本次预估。

### 5.2 char 连续行动（老板怎么看 / 在哪生成）

- **观测页主体 = 行动日志（时间线）**，不是聊天气泡。每轮一条：场景 / char 对白 / 心理描写 / 判定徽章（权限·物件·偏离）/ 异常度轨迹。
- **手动档（默认）**：点「看 TA 走一步」→ 生成一轮、日志追加一条，看一步想一步，随时插局印。
- **自动档（可选）**：「让 TA 自己走一段」→ 前端同进程连跑 N 轮，每轮之间回判写回状态机→重组注入→再调；随时可停；char 进入「请求干预」状态**自动刹车**等老板。
- 红线对齐：自动档 = 前端循环**不是后台任务，离开页面即停**（本项目无真后台，界面文案要实话实说）；离线路径一次调用=一次 fetch，无扇出。
- 生成内容落**任务记忆（带岛章）**：中途关页面再回来，观测页从任务记忆续显，不重生成。

### 5.3 悬浮球体系（按席位两套，共三种球）

Demo 现状：只有手机一个球，局印是手机里一个动作，背包不存在。

**A 套 · 在场视角**（user 亲自入局：员工或老板亲临）——三球：
1. 📱 手机 —— 局内系统：任务简报 / 员工守则 / 同档联系 / 局印直送传话入口。
2. 🎒 背包（新增）—— 东西的实体：实物态（世界内可见可用可被索取）与存档态（副本、世界内不存在）分区 + 结案折算预览 + 纪念物。分工：手机管信息，背包管实体。
3. 🪧 局印（重做）—— 老板在场特权：直送传话（不计异常度）/ 发赏 / 盖章（封档、启封授权）。**员工席位时局印置灰**，点了实话实说（「局印认老板，员工的你只能看着」）。

**B 套 · 老板观测视角**（user 不在局内）——三球换装：
1. 🪧 局印（升为主工具）：干预 / 传话 / 发道具 / 撤回。
2. 🧭 观测窗（新）：char 状态（心理负荷/信任/疲劳）、异常度表、任务进度、偏离态名单。
3. 🎒 char 背包（只读）：看 TA 在世界里拿了什么，老板不能替 TA 用。
- 手机在观测视角**不出现**（手机是入局者的），传话能力并入局印 —— 对应「老板看 char 的时候又是不一样的」。

**局印视觉重做方向**：帷境色里一枚**可按下的圆印**（铜/玉质感线稿、印面「局」字），盖章动作 = 下压 + 印泥红圈 + 轻震动，替代档案墙现在那个圆圈加字的 logo 印。P0 先做两套球的静态态 + 盖章动画。

## 六、用户五点反馈的口径修正（2026-10-09 晚）

1. **调用预算 = 拆分分析文本，不是游玩轮数**（用户纠正 5.1）。
   预算管的是**建档期**：导入 TXT → 本地切章节（零调用）→ 只对**选定的起始章节片段**做少量分析调用 → 产出委托提案。游玩轮数另算（或按档位给个范围提示）。

   **委托者与委托怎么定**（导入 TXT 的核心问题）：
   - 需求清单 §十明确第一版不自动理解整本书 → 分析范围收窄到 user 选的起始章节；
   - 建档流程加一步「**局里替你拟委托**」：对选定章节做 1~2 次分析调用，产出
     委托者提案（身份/与世界的关系/表面愿望/真正愿望/愿意付的报酬/不能说的秘密——字段照需求清单 §四）
     + 委托草案（明面目标/隐藏目标/限制/难度/报酬——照 §三结构）；
   - **user 主权**：提案只填表不落库（同「帮我们记」纪律），user 可改可换可手填，确认才封进档案；
   - 委托者不一定是主角（需求清单明说），分析提示词里点名「从章节里挑一个立场有意思的人当委托者」；
   - 内置世界（雾港来信）跳过这步，委托者与委托是现成数据。

2. **想看连贯描写（行动日志之外）→ 复盘模式（成书视图）**。
   行动日志是时间线条目（对白/心理/判定徽章），另给「**读这一局**」视图：
   把各轮叙事（对白+心理+场景）剥掉判定徽章后**本地按序拼成一篇连贯记述**——零调用就能读；
   结案封档时可选一次润色调用，把全篇顺成真正的「本章记述」，存进档案盒（封档本来就要落档案，正好是它的正文）。

3. **干预 = user 说话然后注入指令再调用**（用户确认口径）。
   干预本质上就是一条 user 言行：写进任务记忆、标局印来源，**下一次调用时随注入一起走**，不单独触发调用。与 5.1「干预不单独调用」一致，无需改。

4. **背包是 user 的**（用户纠正 5.3——我原先把背包画给了 char/观测视角只读，错的）。
   - 背包 = **user 自己的跨世界物件袋**（存档态，带岛章）。结案物件折算时二选一：折成能量点 / **不换、带走**；
   - 带到下一个任务里「掏出来用」→ 按协议判定 B 变实物态（取出的代价照付）；
   - **NPC 怎么知道这个道具 / 会不会有反应**：不需要知道来历。协议 §二已有跨界规则——
     「来源世界之外使用时，物件**不自带来历**，没人认得它是邮局的」。NPC 反应的依据是
     **在场看见 + 各自身份**（判定 B 第 2 条可见性后果：看见它、按自己的身份反应、有立场可以索取），
     不是认出它。注入侧在「随身与同档」块标「本轮已取出为实物态（世界内无来历）」，模型照此写反应；
   - 观测视角（老板看 char）时背包显示的是 **char 身上的东西**（只读）——那是另一份数据，user 背包仍归 user。

5. **群声「催更」按不动 → 已修（v207）**。
   根因两个：api.js runChat 非流式分支 `loopP.then` 无 `.catch`，requestOnce executor 同步异常 reject 后链路静默断、onFail 不触发、按钮永久 disabled；催更按钮零反馈（disabled 无样式、无文案，模型生成几十秒看着像没按）。修法：reject 分支转 onFail + 按钮加「催更中…」状态/即时 toast/disabled 样式 + 点击处理器同步异常 try/catch 兜底。双绿后随 v207 部署。

## 七、2026-10-09 晚二轮拍板 + 三个补设计

### 7.1 拍板确认（昨晚剩的 3 点全过）

- 默认档 = **手动逐轮**；自动档可选开。
- 自动档连跑 = **默认 3 轮**，右上角设置可改。
- 老板观测视角三球 = **局印（主工具）/ 观测窗 / char 背包（只读）** —— 认可。

### 7.2 内置世界改占位（P0 范围调整）

- **不用雾港来信当首个内置世界**：档案架第一层「已建档世界」先留**一个空档案盒**（占位、盖「待上架」戳、不可进），世界包定稿后加进去。
- 连锁问题：P0 验收需要端到端跑通游玩闭环，正式架没内容就没法真机验收 → 建议做一个**「局内演练」临时世界**（挂演练戳、不进正式架、可一键删），只用于联调与验收。待用户点头。

### 7.3 退出保存 / 重进

- **自动保存，无手动存档**：每轮回判写回即落库（任务记忆/进度/偏离态/异常度/同档信任全带岛章），中途强退杀页面不丢。
- **退出** = 返回档案架；档案盒状态标「进行中」（第 N 章 · 异常度 x · 最近动态时间）。
- **重进** = 点进行中的档案盒 →「继续任务」：从任务记忆续显行动日志，**不重生成**，接着上一轮走。
- **不提供免费重开**：想重来就走封存（付协议里的代价），防刷。

### 7.4 本书场景图在哪设置

- **建档流程最后一步「贴场景图」**（可选，跳过 = 默认帷境夜色纸纹）；
- 之后随时在**档案盒详情 → 本书设置**里换（与世界书选择 / 每轮字数同组，即游玩页右上角设置的世界书关联项）；
- 图源：相册选择/上传（走 media 库）；生图画师接入后再加「让局里的画师画一张」（P2 后再说）；
- 用途：游玩页头图 + 档案盒封面。

### 7.5 执行任务感 · 顺畅度走查结论

1. **目标必须常驻可见**：观测页顶部固定「当前委托卡」——明面目标 + 条件 checklist（达成划掉），这是「在执行任务」而非「在聊天」的核心载体。
2. **每轮必有进度反馈**：轮末固定显示进度变化（章节 % → %、条件勾选、异常度 delta、能量点变动）——推进感。
3. **席位切换**：入局时定，局内可切（老板亲临 ↔ 回观测席），Demo 已有此交互，保留。
4. **入口不重复打扰**：来源选择（内置/导入）只在架上有空档案盒时出现；建档四步按来源分流（导入走拟委托，占位盒不可进）。
5. **全流程串查**：档案架 →（空位）来源选择 → 席位 → 领局牌 → 建档（委托确认 + 贴场景图）→ 入世 →（退出自动保存）档案架「进行中」→ 重进续玩 → 结算 → 封档（折算或带走）→ 档案盒变「已结案」。闭环无断点。

## 八、2026-10-09 晚三轮拍板（席位锁死 / app 内 API 设置 / 总结记忆系统）

### 8.1 席位：进 app 即定，局内锁死（修订 §7.5-3，以其为准）

- §7.5-3「席位局内可切」**作废**。新口径：**进入以身入局时就选好本次身份**，之后全程不可切换，局内、建档、观测全是这个身份。
- 三种玩法（user 选一）：
  1. **老板 · 纯看**：char 去执行，user 观测 + 局印干预（观测三球：局印/观测窗/char 背包只读）；
  2. **老板 · 亲自参与**：老板席位 + 入局在场（局印特权在手：直送传话/发赏/盖章），带 char 同行；
  3. **员工**：user 自己当员工入局执行任务，char 按局内关系同行/留守（局印置灰：认老板不认员工）。
- 悬浮球套组跟身份走：纯看=B 套（§5.3），亲自参与与员工=A 套（差别在局印可不可用）。

### 8.2 app 内 API 设置（模型连接选择器）

- **位置**：右上角设置组里加「模型连接」（设置组最终 = 模型连接 / 世界书 / 每轮字数 / 本书场景图）。手机悬浮球保持纯局内信息（任务/守则/同档/传话），不放局外设置——一个地方管全部，避免两处入口不同步。若宝宝想搬手机球再说。
- **内容**：连接选择器——列出**主 API 各预设 + 已启用副 API**，按「地址+密钥+模型」去重后做单选；选中可**拉取模型列表**（复用 tts.js 的 OpenAI 兼容 `/models` 口径）下拉选模型。
- **优先级**：app 内指定连接 > feature `book` 副 API 分配 > 全局默认链。指定连接后以身入局的全部调用（在场轮/char 行动轮/结算/拟委托）都走它；清除指定回落 feature 逻辑。报错口径照旧（指定了不回落）。
- 落库：以身入局自己的键（带岛章？连接选择是**设备/局配置**不是岛数据——按 DEVICE_LOCAL 口径走设备本地，不进岛章、不进导出隔离判断之外的通道；实现时对齐 store 现有键分类）。

### 8.3 总结记忆系统（app 记忆连贯，但**绝不进角色记忆**）

- **隔离红线（先写死）**：以身入局的全部记忆（任务记忆/员工记忆/世界记忆/局记忆）只存 app 自己的键（带岛章），**不写进 char 的角色记忆、不进 memory-vec、不进聊天上下文**——char 从岛里聊起「上次任务」时不知道，TA 的局内记忆只在局内生效。char 在局内的连续性由 8.3 的 app 内记忆承担。
- **记忆四层**（协议 §七 + user 老板视角）：
  1. 世界记忆：原始设定/已发生大事/被改节点/稳定度/世界人物对 char 的记忆；
  2. 员工记忆（char）：做过的任务/守则遵守/与老板的经历/对局的看法；
  3. 当前任务记忆：委托目标/前情摘要/最近 N 轮原文/线索/条件勾选/在场关系；
  4. 局记忆（user 老板视角）：局账（能量点流水）/档案架动态/封存档案冷却。
- **长任务滚动总结**（行动日志越滚越长怎么办）：
  - 窗口结构注入：`前情摘要（卷宗）+ 最近 N 轮原文`（同聊天上下文窗口口径），N 与右上角「每轮字数」档位联动考虑；
  - 触发：每 10 轮或章节推进时，1 次调用把本轮次压成「卷宗摘要」追加进任务记忆（摘要列出：关键事件/条件达成/人物关系变化/异常度事件/char 心理转折）；
  - 摘要调用也挂 feature `book` / app 内指定连接，算进调用账。
- **结案沉淀**：结算后「本章记述」= 复盘视图全文（可选润色）落**世界记忆 + 员工记忆**；下一个任务注入时，员工记忆给 char「我做过什么」、世界记忆给世界「发生过什么」——这就是 app 内「记得执行了什么任务」的连贯性来源。
- **实现落点**：自建 `book-memory` 模块管四层键与滚动总结；总结的**函数**可参考 page-summary 的做法但**不共用落库通道**（角色记忆通道一个字节都不碰，冒烟加反向断言）。

## 九、2026-10-09 晚四轮澄清（关系延续 / 贴贴张力 / 卷宗结构）

### 9.1 char 保人设，关系照旧——局内是「带着原关系执行任务」

- char 的 a 层（本身人设 + 与 user 的原有关系）**原样带进局**：岛上是小情侣，局里就还是小情侣——不是重新认识，是**换了个世界继续相处**。局内新增的只有 b 层（员工/老板）和 c 层（占位身份）。
- 注入口径：a 层关系从 **char 档案的设定层**读（人设里写明的关系），**不读岛上的聊天记忆**（§8.3 隔离红线不破——TA 带着关系来，不带岛上的具体回忆来）。

### 9.2 「做任务做一会儿想偷偷贴贴」= 要支持的张力，不是要压掉的 bug

这正是需求清单 §六「双层身份冲突」和协议「char 为了救人违反员工守则」的甜味版，设计上**明确欢迎**：
- char 的感情线会渗进任务：分心、绕路、违规照顾 user、任务间隙想贴贴——模型层不压制，员工守则给的是「纪律」，char 的心给的是「变数」，两者冲突才有戏；
- 机制上天然有后果承接：被世界/同档看见 → 判定 A 记异常度或违规记录；没被抓 → 甜，但结算「规则遵守度」与「char 心理负担」两个维度会诚实反映。贴贴不白贴，也不白甜。

### 9.3 卷宗摘要结构化（修正 §8.3 滚动摘要）

卷宗不是流水账也不是「关系簿」，是**分栏卷宗**，每次压缩按栏更新：
1. **事件与结果**（用户点名补强）：每件「做了什么 → 结果如何 → 付了什么代价」，含失败与意外；
2. 委托条件进度：必达/附加条件勾选状态；
3. 人物与态度：世界 NPC、委托者、同档——关系与立场变化（含对 char 对 user 的）；
4. 与 user 的互动记录（user 可能是老板也可能是员工）：含感情时刻（贴贴史也是任务记录，结算「char 心理负担」和守则记录从这里取材）；
5. 异常度事件：何时擦边/越界/硬越界、当时发生了什么；
6. char 心理转折：动摇、违规冲动、对局的态度变化；
7. 线索与未解：悬而未决的事。
