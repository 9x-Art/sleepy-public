# 方案 · 设定仓库 v1（2026-10-10 拍板）

> 小手机桌面 App：user 把自己的设定分享上去，别人下载导入进自己的岛。
> 定案：锁只用**盲盒档**（加密包+本地解密，UI 不可见可游玩）；**不做代持**——
> user 的内容不经过我们的服务器明文，本地优先的招牌不动。

## 一、包类型（六类，sleepy 自有格式，不收酒馆）

| 类型 | 内容 | 导入去向 |
|---|---|---|
| 角色卡 | sleepy 角色卡（含性格/开场/能力卡引用） | 角色卡导入通路 |
| 世界书 | worldbook 条目 | 世界书注入 |
| 预设 | prompt-engine 预设 | 预设库 |
| 以身入局 | 档案盒 + 委托 + 剧情地图（bookImports 结构） | 新建档案盒 |
| 美化 | 主题/壁纸/灯牌字体外观件 | 外观设置（可选） |
| 整岛包 | 上述的组合 + 岛背景 | **生成一座新岛** |

**整岛包边界（拍板）**：
- **不带**：聊天记录、朋友圈、日记（user-char 的私人记忆不是设定）；
- **照片/媒体不带**；头像由分享者**用 URL 填写**（见 §三）；
- **user 马甲不带**：导入者在新岛里用自己的「我」；
- **API 配置绝不进包**；
- 美化/世界书/预设**可选带入**：导入向导里逐项勾「用我现在的 / 带包里的」。

## 二、锁级（每件独立设置）

- **公开**：明文包，下载即可看可用；
- **盲盒**：上传前本地加密（密钥进包内混淆存放），下载后 UI 只显示
  标题/摘要/封面，不可查看原文；游玩/使用时本地解密注入。挡君子不挡
  工程（内容终会到本地），对分享圈够用，且零服务器成本、离线可玩。
- 代持（服务端拼提示词）**不做**——Privacy 红线：user 内容不落我们的明文。

## 三、头像与媒体：URL 制

- 打包**不带任何图片**；角色/岛的头像由分享者填 **URL**（仓库 App 的
  打包流程里有逐项「头像 URL」输入框，也提供「留空=字母脸」）；
- 导入端存 URL 引用，展示失败回落字母脸（offline 不炸）；
- 世界书/以身入局的场景图同理：URL 或留空。

## 四、仓库 App（小手机桌面 App，第 4 屏家族）

三个板块：

1. **货架（发现）**：卡片流 = 封面/标题/作者/类型标签/锁标/下载量/更新时间；
   按类型筛选 + 关键词搜。**货架可见范围由「门牌」决定**（见 §五）。
2. **我的**：
   - *我上架的*：版本更新（同 id 重传）、下架；
   - *打包发布流程*：从岛里挑件 → 每件设锁级 → 头像 URL 填写 → 提交；
   - *我下载的*：已导入记录、可重导/删除。
3. **门牌**：输入口令进入对应货架（P0 的分享半径，见 §五）。

导入流程：下载 → 校验 manifest → 按类型分发；**整岛包**先进向导：
预览清单（几角色几世界书几档案）→ 勾选美化/世界书/预设「用我的/带包里」
→ 生成新岛（用自己的马甲）→ 完成落浮岛列表。

## 五、分享半径（P0 = 门牌口令制）

- Worker 维护 `gates`（口令 → 货架范围）；user 输入口令后，该货架的
  内容才可见/可下。**没有口令 = 什么都看不到**；
- 为什么先口令制：①内测小圈子，UGC 公开广场的备案/审核责任先不背；
  ②口令天然是「邀请制」，作者愿意放盲盒锁的东西也放心；③实现成本≈一张表；
- 后续想开公开广场：把默认口令换成「公开货架」+ 敏感词/举报/下架
  三件套上线再说，App 结构不用改。

### 门牌传播：链接卡（对外可识别）

- 分享卡必须是**链接**：门牌页一键复制
  `https://<部署域名>/repo/?g=<门牌码>`（正文 = 「【睡岛货架】xxx 的仓库 ·
  口令 xxx」），user 可以甩去任何地方（群/帖/朋友圈）；
- **sleepy 侧识别**两条路：①打开链接 → CF Pages 落到 SPA，启动参数里带
  `g` → 直接拉起仓库 App 门牌页（门牌已填好，点确认进货架）；
  ②门牌页里放「粘贴识别」按钮——从别处复制了链接/口令文本，点一下自动
  抠出门牌（**不做启动时自动读剪贴板**，iOS 会弹权限，体验很差）；
- 门牌码 = 短码（6 位左右），口令文本和链接里是同一个码，两条路等价。

## 六、Worker 架构（薄 API）

- **D1**：`items`（id/标题/作者/类型/锁级/版本/manifest 摘要/下载计数/门牌）
  + `gates`（口令表）+ `reports`（举报，P1）；
- **R2**：设定包正文（加密或明文二进制，key = item id + 版本）；
- **端点**：`POST /publish`（校验 manifest+大小上限 5MB/件）、
  `GET /shelf?gate=`、`GET /item/:id`（下载）、`POST /gate/verify`、
  `DELETE /item/:id`（作者令牌）、`GET /search`；
- 作者令牌：发布时生成，存本地（丢 = 无法管理该件，不找回，方案里写明）；
- 免费额度：内测足够；大小上限单件 5MB（整岛包超了就拆件上架）。

## 七、施工分批

- **P0**：Worker（D1+R2+门牌+发布/货架/下载）+ 仓库 App 骨架
  （货架/我的/门牌）+ **角色卡与整岛包**两种件 + 打包/导入向导
  + 门牌链接卡与识别；
- **P1**：世界书/预设/以身入局/美化四类件 + 盲盒锁（本地加密+锁定 UI）+
  版本更新 + 下载计数 + **轻量身份与「试吃」解锁**（见 §八）；
- **P2**：搜索细化、举报下架、引用与更新提示（岛内检测新版本）。

## 八、「试吃」与甜度（P1 · 条件解锁的口径，用户定调）

**不叫「欠」、不搞催债脸。** 整套机制包装成「试吃 → 投喂」的口味：

- 作者给件设门槛时，user 看到的是一句软话：
  「如果给 xxx 老师一个 repo，她会很开心，您也会获得一点**甜度**」；
- 作者勾了「必须 repo」→ 领取前**事先告知**（透明，不事后设卡）；
- 宽限期提醒的语气：**「您的试吃时间快结束啦，要不要用美味 repo 换
  美味作品呢~」**（甜嘴不施压，按钮是「去交 repo」不是「去还债」）；
- **甜度** = user 的信用值：交一份 repo +1；逾期未交该作者可冻结领取，
  但措辞是「这位老师的试吃名额暂时满了」——系统不说教、不公示、不排名；
- repo 真伪作者人审，宽限期默认 14 天；
- 机制底座照旧：领取 → 服务端记账 → 销账/冻结；user 行为元数据（点赞/
  评论/repo/甜度）上 Worker，**设定包正文永不过服务器**（user 玩的东西
  我们不看，这是定案）。

部署：Worker 与 Pages 同账号（wrangler 部署，不走 GitHub HTTPS）；
仓库 API 域名进 `store` 配置（默认官方门牌由部署者发）。
