# 验收 · 日历「国庆第一天」反馈 + 年缓存跨角色串味 · 2026-10-03

## 一、用户反馈（原话）

> 设置是中国大陆，中国传统节日和国际常见节日，时区上海，结果他说今天是国庆第一天

## 二、结论先说

**「今天是国庆第一天」不是代码生成的。**

全仓库（含 `docs/`、`scripts/`、`_retired/`）搜以下关键词全部零命中：

```
第一天 / 第 1 天 / 假期第 / 放假第 / 假期首日 / 首日 / 第一日
```

`calendar.js` 里给模型的时间事实，国庆区间**逐日**只产出这一行：

```
公共日期（中国大陆）：今天是国庆节（法定放假日）。它只描述客观环境，不代表你一定休息。
```

「第几天」是**模型自己的口语化复述** —— I02 只给了「今天是国庆节」这个事实。
顺带一提：10-03 那天连 `legal_off` 都不是（是周六，`kind='weekend'`），
所以严格说模型说「第一天」连它拿到的客观事实都没对上（那天是假期第 3 天）。

## 四、顺手抓到的真 bug（本轮唯一改动）

### 4.1 现象

`calendar.js buildYear` 的年缓存键是 `year|region`，**漏了 `cultures`**。
而文化节日那层是按 `cfg.cultures` 逐组铺的 → 同一年的缓存被
**第一个来问的 char 定死**。

### 4.2 复现（桩实测）

```
甲 cfg.cultures = ['cn']    乙 cfg.cultures = ['intl']
① 乙先问 12-25  → ["圣诞节"]      ✓ 对
② 甲问 12-25    → ["圣诞节"]      ✗ 甲没选 intl，串味了
③ 甲先问 02-17  → ["春节"]
④ 乙再问 12-25  → []              ✗ 乙的圣诞节被甲的查询挤掉了
```

### 4.3 为什么一直没被测出来

两个原因叠加：

1. 设置页每次点 chips 都调 `c.clearCache()`，**手动改完看着永远是对的**；
2. 既有的冒烟用例（`文化节日多选…`）在两次断言之间**正好夹了一个
   `CAL.clearCache()`** —— 把这条路径绕过去了。

真正漏的是**两个 char 交替问同一年**这条路：聊天 I02 注入（`timeFacts`）
与月历（`page-calendar.js` 的 `dayInfo` 循环）都会走它。

### 4.4 修复（最小）

```js
function cultureKey(cfg) {
  var gs = (cfg && cfg.cultures) || [];
  return gs.slice().sort().join(',');
}
// buildYear: var ck = year + '|' + (cfg.region || 'CN') + '|' + cultureKey(cfg);
```

同键才复用，不同 cultures 各存一份，互不干扰。

## 五、护栏（两条，都有负向对照）

1. `年缓存按 cultures 分桶：两个 char 交替问同一年不互相串味`
   —— **故意不清缓存**，注释里写明「加了 clearCache 就等于没测」。
2. `国庆区间逐日：kind 分得开、不生成「第几天」这类说法`
   —— 钉住 7 天区间逐日的 `kind`、10-08 收尾、10-10 补班，
   并断言注入原文**不含**「第一天/第 3 天/第三天」这类凭空序号。

**负向对照**：把 `cultureKey` 退化成 `return ''`（还原旧行为）后，
第 1 条立刻报红 ——
`✗ … 甲没选 intl 却看见了国际节日（跨角色串味）：圣诞节`；还原后恢复绿。
