## 3. 日历、留痕、主动消息、承诺、长期事项的数据入口

### 3.1 日历（现成，直接复用）
- 事件结构：`addEvent` calendar.js:495-527 — `{ id, ownerCharId, eventType, title, startAt/endAt, status, createdBy:{type,id}, participants, visibility, sourceIds, memoryId, history, createdAt/updatedAt }` + `core().tagScope(ev)` 盖岛章。
- 读取：`eventsOf(charId)` calendar.js:439-448（按 scopeId+角色过滤的**唯一入口**）、`eventsOn` :470、`upcoming(charId, days)` :595（首页「临近事项」直接用）、`timeFacts` :722-807（时间唯一出处）。
- **四档 visibility**：`private / shared_busy / shared_detail / participants`；char 视角判定唯一现成实现 `charViewOf(e, charId)` — life-feed.js:111-125（判据只用 createdBy+visibility，刻意不看 ownerCharId）。`shared_busy` 措辞锚点：life-feed.js:143-147、page-calendar.js:160-166、smoke.js:7816-7830。

### 3.2 留痕 / 近期生活（现成，只读）
- **life-feed.js（251 行）是注入层不是存储层**：`collect()`（:205-213）聚合朋友圈（10天/8条）+ 日历（7天/4条）+ 日记（10天/3条）；出口 `Sleepy.lifeFeed.recent(charId, userId)` :215 → `[{ at, line }]` 带时间戳，**首页「最近在做/最近变化」可直接只读**。现有消费先例：page-we.js:800、949（We 首页「最近时光」就是它）。
- 记忆条目：`charMem:<rootId>`（page-memory.js:156）条目 `{ id, kind, content, sourceRef, evidenceType, status, sourceMessageId, sourceChatId, createdAt, updatedAt }` — 按 updatedAt 排「最近变化」可行；kind='promise' 即「约定」类（page-memory.js:34，5 态 :53-56）。
- 向量库（memory-vec.js）：四种 ownerKey（:24-29）、`visibleTo` :276-287 + `stillVisible` :342-378（fail closed）。⚠️ 召回出口 `lastOf`（:2187-2207）的 items **不带 sourceId/msgIds**，块枚举 `blocksOf`（:392）无公开导出——首页若要「列块+来源」需补只读导出（缺口）。

### 3.3 主动消息 / 心跳（现成，只读）
- 心声：`chat.heartbeats = [{ id, text, at, read }]`（page-heartbeat.js:28、141）；读侧 `sortedChat(chatId)` :280-286。按对话挂、不按角色全局池——首页要遍历本岛该角色 chat。
- 主动消息：消息带 `proactive: true, triggerIds, timestamp`（page-proactive.js:271-278）；`proactiveState:<charId> = { lastAt, day, count, … }` :47-51。「最近一次主动找我」可直接读。
- 总结引擎三键（归 root，page-summary.js:168-180）：`charState:<rootId>`（feelings/readings/unspoken + updatedAt）、`openLoops:<rootId>`（≤6 条，带 updatedAt）、`attentionInbox:<rootId>`（≤4 条）。

## 7. 缺口汇总（v1 要新建的东西）

1. **三张新表**（事项 / 承诺 / 关注）——按 weEntries 同构范式（store.js:160-168 注释 + page-we.js:190-220 写入口）：字段含 `id/createdAt/updatedAt/refCharId/refUserId/sourceType/sourceId/sourceRef/status`；tagScope 盖章、scoped 读取、DEFAULTS + 删房名单双登记。
2. **「此刻」合成逻辑**——v1 建议只读拼装：charState.feelings + lifeFeed.recent 最新一条 + 即将到来的日历事件，**不造 activity 字段、不编生活**（符合设计稿「空状态不自动生成」）。
3. **草稿 NPC 概念**——v1 不做（设计稿第一版不做 NPC 推荐），但首页「身边的人」先只读 `npcsOfRoom + charsOfSandbox + link.relation`，结构留得住后续。
4. **（可选）memory-vec 补只读导出**——若首页要展示「TA 记着的块 + 来源引用」。
