⚠️ **先说清 N2 到底注入了什么**（上一版表述不准）：
我**没有**做过「只单独撤掉 S3」的注入。实际注入的是

所以 N2 报的是「**缺 E**」而不是「缺 S3」：**E 在 S3 之前，遍历先撞到 E**。
这不代表「单撤 S3 会报缺 S3」——**我没测过那个case，不能这么说**。

| # | 实际注入内容 | 结果 |
|---|---|---|
| N1 | 决策层摘掉（`bt = null`），共享外壳整片回退到 shell 卡 | ✗ `共享外壳缺 B 模块` |

**能证明的**：撤掉整段场景注入 → 报红；截断正文 → 报红。

## 三、groupOnline 语义留档（你提的文档点）

**当前报告口径**：`ok=true` · `partial=true` · `pending=[B,P,L,E,S4]`

**这个口径容易被误读成「群线上已有部分行为层」。** 准确含义是：

> **该场景的决策 spec 可识别（`btDecideScene('groupOnline')` 能跑通十步校验），
> 但本批没有注入任何行为正文。**

原因是 `BT_SPECS.groupOnline` 的 `injectShell` 与 `injectScene`
**均为 `false`** —— 决策层跑完校验后**主动不产出任何正文**，
所以 `modules=[]`、五段全部进 `pending`。

**建议 UI / 诊断展示文案区分**：

```
未接线：B/P/L/E/S4
```

而不是泛泛显示「部分接线」——
`partial=true` 在这里容易让人误解成已经接入了一部分。

**代码层面我建议后续加一个显式字段**（本批未做，属新功能）：
`wired: boolean`（`false` = 该场景 spec 可识别但完全未接线）。
这样文案不必靠 `partial` 推断。当前**没有**加，因为你说不再往这批塞新功能。

⚠️ 顺带说明：`groupOffline` 的 `partial=true` 是**另一个意思** ——
它是**真的接了一部分**（B/P/L 已进 system，N/S5 没进）。
两者语义不同，展示时不能共用同一句话。
