## 一、整岛包分享 → 新岛落地（结论：主链路是好的，美化是重灾区）

### ✅ 落地正确的部分
- `importIsland`（repo-core.js:507）：`createSandbox` 建新岛 → 角色换新 id 导入 → `charMap` 记旧→新映射 → `setSandboxChars` 挂岛 → 世界书挂靠角色经 charMap 重指 → 以身入局 box/import 重新盖岛章（sandboxId = 新岛）。链路核对无误。
- 暗铺：不对暗号时暗件跳过不炸（smoke 已覆盖）；`wasHidden` → 世界书 `sealed`、美化 `sealedCss` 标记都在。
- 包里不带聊天/朋友圈/照片/马甲/API（smoke 反向断言在）。

### 🔴 P0：美化导入 = 整档覆盖，不是「应用到新岛」
`repo-core.js:568-576`，choices.theme='pack' 时：
```js
store.set('appearance', ap);   // ap = 打包者的【整个】外观存档
```
外观系统的真实结构（page-appearance.js）是「全局档 + 每岛覆盖 `appearance.desktop.islands[sbId]` + 单 App 覆盖 `appOverrides`」。这一行导致三连：
1. **把领取者自己的全局外观、所有岛的覆盖、appOverrides 全部冲掉** —— 数据破坏，不可逆（没备份）。
2. 美化**全局生效**，不是只落在新岛 —— 和向导里「这座岛会作为新岛落下」的语境矛盾。
3. 导入后**没调 `Sleepy.appearance.apply()`**，要重开 App 才看得见。

### 🟠 P1：打包侧同样错 —— 整个外观档进包
`packIsland`（repo-core.js:129-133）打包的是 `store.get('appearance')` 全档：把**打包者自己其他岛的覆盖、appOverrides、字体 URL** 全带进包里 —— 泄露个人配置 + 冗余体积 + 反过来加重上面那条的破坏。

### 🟠 P1：「摆盘（美化）」「火候（预设）」货架是空架子
铺面六板块（page-repo.js:1035）有 preset/theme 两个货架，但发布页只给三种类型（island/char/worldbook，page-repo.js:651-656）。**用户没有任何入口单独发布一件美化或预设** —— 美化只能搭整岛包的车。

### 🟡 P3：小问题
- `showCssSheet` 读 `themeData.css || themeData.bg`——外观存档根本没有这两个字段，「看 CSS」实际显示的是整份外观 JSON 的 dump。
- 「暗铺美化 = 生效但样式代码不给看」的 sealedCss 语义目前是**虚的**：外观系统没有自定义 CSS 能力，美化件本来就是结构化存档 JSON，无所谓「样式代码」可藏；且 JSON dump 里键名（wall/icons…）照样看得到。

## 二、账密系统（结论：骨架完整、设计正确，可用；几处要收口）

链路：发码页 `/issue`（worker 内置页）→ `/issue/claim`（QQ 唯一，一码一号）→ App「我的授权」页激活/登录 → `/account/*` 全套（me/devices/revoke/password/forget）。`page-license.js` 已挂 index.html，UI/数据层/worker 三层对齐；激活校验码-QQ 一致、PBKDF2 10 万迭代、登录只计失败次数、设备满 3 台 403 带清单 + 前端念清单、解绑连带作废会话、注销脱敏 QQ —— 这些都对。`wrangler.toml` 里 STORE 是 **KV**（不是注释早期写的 R2），所以 `rateHit` 的 `expirationTtl` 限速是真的有效的。

### 🟠 P1：发码页零门槛
`/issue/claim` 只校验 QQ 格式 + IP 限速 10 次/15 分钟。**知道 worker 域名就能给任意 QQ 白领激活码**，没有付款凭证位。内测期靠人工对账能糊，首发前必须收口（发码口令 / 管理端发码 / 订单号校验三选一）。

### 🟡 P2
- 会话 token 服务端**永不过期**（sessions 无 TTL、`sessionOf` 只查 status）—— 只靠踢设备兜底，token 一旦泄露长期有效。建议加 last_seen 空闲过期（如 30 天）。
- 注销后该 QQ 在 `codes` 表的唯一索引仍占位 → 永远领不了新码，只能人工。页面文案已声明「注销后想再用需人工恢复」，口径一致，但要确认这是有意的。
- 作者令牌与账密 token 共用 `X-Repo-Token` 头 —— 端点不交叉所以不冲突，纯属语义易踩坑，记着就行。

### 🟡 P3
- worker comments POST 里领取条件记账有一段死分支（外层 `kind === need || condition==='like'` 与内层判断重复），行为正确但可读性差。
