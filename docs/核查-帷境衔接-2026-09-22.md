## 二、断的（四条）→ 已修三条

### ① 删角色 / 删岛之后，定史会往「幽灵」名下写记忆 ✅ 已修

- **现象**：`cast` 是开帷时**抄下来**的名单（`page-wj-create.js:173` 存的 `name`），
  删岛（`core.js:247` 删 `characters`）或删人（`core.js:557 removeChar`）都**不会**动它。
  于是 `wj-canon.js` 的 `writersOf` 仍把已删角色算作「会写的人」，
  `write()` 会往 `charMem:<已删 id>` 写记忆；谢幕页的 `chatForChar` 也会给
  已删角色**新建一条幽灵对话**（`page-wj-curtain.js`）。
- **影响**：数据层留下永远读不到的脏记录；聊天列表里冒出无主会话。
- **修**：`writersOf` 过滤掉 `core.findChar` 拿不到的人；
  `chatForChar` 对不存在的角色直接返回 null（页面提示改成「这位角色已经不在这座岛上了」）。
- **守住它的断言**：`审计修复：角色删了之后，定史不再往幽灵名下写记忆`。

### ② 删作品不连坐 ✅ 已修

- **现象**：`page-wj-work.js` 的删除只调 `D().remove(w.id)`，同 `workId` 的
  `wjSessions` / `wjCanon` 记录成了孤儿（`wj-data.js:407 removeTicket`、
  `wj-canon.js remove` 早就导出了，但没人调用）。
- **修**：删作品时一并 `wjCoread.removeForWork(w.id)` + `wjCanon.remove(w.id)`
  （新给 `wj-coread.js` 加了 `removeForWork`）。**票根故意不删** ——
  那是「我读过」的凭证，像电影下架了票根还在；收藏馆点它会说「已经不在门厅里了」。
  删除确认文案也照实改了。

### ③ 「稍后再读」的共读邀请成了永久僵尸 ✅ 已修

- **现象**：`settle('later')` 把会话存成 `deferred`（`wj-coread.js:123`），
  而 `activeFor` 只认 `active/paused`（`:87-91`）—— 谁也捡不回来。
  更糟的是谢幕页的幂等检查写的是 `s.status !== 'refused'`，把 `deferred`
  也算成「TA 手上已经有一份邀请了」，**连重发都不给**。
  可共读页自己的文案明写着「TA 想稍后再读。**改天再邀请一次就好**」（`page-wj-coread.js:252`）。
- **修**：谢幕页的幂等判据改成只拦 `invited / active / paused` ——
  `deferred` 和 `sharing_only` 都可以再邀请一次。

### ④ 文风台的「全局四根滑杆」根本没进 prompt ✅ 已修（用户拍板：全局 = 新作品的起点）

- **现象**：文风台把四根滑杆写进全局 `wjStyleCfg`（`page-wj-style.js:355-360`），
  但装配只读**作品级**：`wj-prompt.js:130` → `styleBlock` → `wj-data.js:336 styleOf(work)`，
  而 `styleOf` **从不读 `styleCfg`**。新作品是 `style: null / styleId: '静水'`，
  于是「全局调过的四参数」对**任何一部作品都不生效**。
  只有**全局雷区**真的进了 prompt（`wj-prompt.js:159-161`，检查器也读它 `wj-check.js:82`）。
- **为什么没直接改**：这里有个产品语义要你定 ——
  「全局底座」与「作品自己的文风」谁优先？两种都是合理设计：
  - **(a) 全局是默认值**：作品没自己调过就跟着全局走（改全局 → 所有没动过的作品一起变）；
  - **(b) 全局只是新作品的起点**：开帷时把全局四参数**快照**进作品，以后改全局不影响老作品。
- **建议**：(b) 更符合你「每部作品独立」的既有取向（作品级 styleId 已经在按作品存），
  而且不会出现「我只是调了下滑杆，三个月前那部作品的文风全变了」这种惊吓。
  **等你一句话我就改。**

## 三、另一处「方案不衔接」：选择性读取只有壳 ✅ 已修（用户拍板：先收起来）

方案 §5.2 给 `materialRefs` 定的语义是「`select` 档时逐条勾选的留痕 / 时间线 id」，
要真的有「勾选器 + 勾了的才进 prompt」。现状：

- `page-wj-create.js:275` 选 `select` 时把 `materialRefs` 清空，
  `:280-283` 自己注了「勾选器未实现」；
- `wj-prompt.js:89-92` 对 `select` 明确降级成 `tone`（只读关系与性格底色）；
- 全仓 `materialRefs` 只有定义（`wj-data.js:182`）和「写空」，**没有读取处**。

也就是说：用户在开帷流程里看到「选择性读取 · 逐条勾选可用于本篇的留痕、关系与时间线事实」，
**但那个勾选器不存在**，选了它实际得到的是 `tone` 档。

**修法两条路**（都要你先拍）：
1. **做出来**：开帷流程加勾选器（从 `memoryStore` + 关系里列条目）+ `wj-prompt` 按 id 取内容。
   工作量中等，但这是方案里承诺过的最细一档取材。
2. **改文案**：把这一档暂时收起来（只留 不读取 / 只读底色 / 读取当前世界资料 三档），
   等真要做的时候再放出来 —— 不骗人比留着壳好。

**我倾向 2**（先把承诺收回来，不欠着），但这条得你定。
