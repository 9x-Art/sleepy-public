## 0. 已拍板的决策（2026-09-18，宝宝确认）

1. **入口**：配置 app 放第 2 屏第 5 行，替换「设置」格（`p2-settings`）——设置在第 3 屏还有一份，重复度最高。想换成替换「世界书」格随时说，只动一个格子的 `app` 字段。
2. **锁定模型**：我们内置写的 prompt（共享外壳 / F1 等）标记 `locked`。
   - **开发期**：可见可编辑（调试需要）。
   - **面向用户后**：上锁——用户只知道「有这个注入」，内容不可见不可编辑。
   - 用户能编辑的只有：自己新增的注入卡、人设文本等自有内容。
3. **Token 估算**：必须做，逐槽显示（标注「估算」）。
4. **UI 硬要求**：**不得太多圆角框**——列表 + 分隔线为主，少卡片少框。
5. K01/K02/K03 第一轮用现有数据垫底（角色卡字段、core 记忆条目）；角色卡后续会改版，数据口留薄适配层。
6. `[I01]` 本轮接入，复用 page-switch 的 cognition 映射四态；`suspicion_level` 程序化更新后置。
7. 新旧组装路径共存，设置里留开关（新引擎默认开），可一键切回。
8. 用户随后会出**线上/线下页 demo 和设计**——本轮聊天页渲染改造只做协议层（`||` 气泡 + `[WHISPER]` 解析），不做视觉改版。

## 1. 模块拆分

### P1 · prompt-engine.js（引擎核心，新文件）

- **槽位注册表**：总纲第 5 节的 24 槽 + U01。每槽登记：id、名称、类别（约束/知识/状态/能力/输入）、装配状态（required / conditional / forbidden）、首版预算、裁剪级（P0~P3）、注入位置。
- **装配矩阵**：按调用类型注册三张矩阵（线上 / 线下 / 主动消息）。本轮只实装「线上」；线下、主动消息矩阵登记但整卡标 `未开工`，配置 app 里灰显。
- **装配顺序**：按总纲 6.3 / 14.4——I01 → 约束 → K01/K02/K03 → 动态状态 → 动态知识 → 能力 → K09 近期原文 → C05 输出协议 → U01 当前输入。
- **模块卡体系**：
  - 内置卡：`shell`（共享外壳 15.12 压缩版）、`f1`（F1 v1 全文，含输出格式与禁止行为）、`c05`（输出协议，可并入 f1）、`i01`（马甲标识编译，程序生成不可编辑）。
  - 每张卡：`{ id, title, locked, body, enabled }`，内置卡正文存默认值；用户改动覆盖存 store（`presets.overrides`），可恢复默认。
  - `locked` 卡在用户态只显示「Sleepy 内置注入 · 约N tokens」。
- **数据适配层（薄）**：
  - K01 ← 角色卡字段（page-idcard 现有数据）；
  - K02 ← 马甲资料；
  - K03 ← core 记忆条目按当前 (char,user) 组过滤（沿用 page-switch 的 memoryViewFor）；
  - I01 ← core.cognitionOf 映射：isolated→`char_knows_events`（按马甲隔离）、unaware→`char_sensing`（level 0）、aware→`merged`；`char_pretending` 预留枚举暂无数据源。suspicion 字段输出默认值。
- **Token 估算**：`估算值 ≈ 汉字数×1.6 + 其他字符×0.3`，逐槽汇总显示，界面标注「估算」。

### P2 · 内置预设库（默认文案）

- `shell`：总纲 15.12「共享外壳的最小注入版」六段原文。
- `f1`：F1 卡 v1 全文（你四海里那份的正文，含先判断再回应 / 情绪响应 / Deep Talk / 反伪宠溺 / 禁止行为 / 合规示例）。
- 输出协议改为 `[WHISPER]` 版：气泡 `||` 分隔 + `[WHISPER]…[/WHISPER]`，替代现在 `<心声>` 指令。
- 拍一拍 / 表情包说明书：作为 `conditional` 附加卡挂进矩阵（有表情才注入表情说明书，拍一拍保留但降为低频提示）。

### P3 · page-presets.js（配置 app，新文件）

- 桌面格子：`p2-settings` 的 `app: 'settings'` → `app: 'presets'`，label「预设」；`LAYOUT_VERSION` 11 → **12**，`defaultDesktop` 注释记一笔。
- 页面结构（**列表 + 分隔线，无圆角卡片堆叠**）：
  1. **调用类型**：线上普通回复（实装）／线下普通回复（灰·未开工）／主动消息（灰·未开工）。
  2. **注入序列**：该调用下的槽位列表，按装配顺序排——每行：槽位名 · 开关（required 不可关）· 估算 tokens · 状态（锁定/可编辑/未命中）。点开可编辑的进编辑页（正文 textarea + 恢复默认）。
  3. **自定义注入**：用户新增自有卡（conditional，注入位置选在 K 区或 S 区之后），可编辑可删。
  4. **调试预览**：选一个现有对话 → 引擎实跑一次 `assemble` → 分段渲染完整 prompt，每段标注槽位和估算 tokens。开发期必备。
- 锁定态：设置页加「开发者模式」开关（`store.developerMode`，默认开）。关闭后 locked 卡内容隐藏；开发者模式本身以后跟着「面向用户」的发布开关走。

### P4 · 接入 page-chat.js

- `buildMessages()`：引擎开关开 → `promptEngine.assemble('online', ctx)`（ctx 含 chatId、charId、userId、近期原文窗口）；关 → 旧路径**原样保留**，一行不改。
- **解析渲染**（协议层，不动视觉）：
  - `||` 切分成多条气泡消息（现有消息模型支持，一条 assistant 回复入库仍是一条，渲染层切）；
  - `[WHISPER]…[/WHISPER]` 剥离 → 走现有心声面板（`heartbeats` 挂载不变）；
  - 其余 `[MOOD]` 类标签剥离不展示；
  - **双格式过渡**：解析同时认 `<心声>…</心声>`（旧存档/旧模型输出）与 `[WHISPER]`，流式切割逻辑（约 1077、1370 行两处）同步兼容。

## 3. 风险与备注

1. **流式切割**是最大踩坑点：`<心声>` 时代的「标签后内容不进气泡」逻辑必须同时认新标签，否则流式期间 `[WHISPER]` 会闪现在气泡里。
2. token 估算是近似值，实测后校准系数；界面永远标「估算」。
3. K01 直接拼角色卡原始字段会偏长——第一轮先原文注入 + 预算截断，人设方法论（背景→倾向等转化原则）写进 f1 卡让模型自己消化，不做程序结构化。
4. 用户态锁定只是 UI 隐藏（本地 app 无真保密需求），但结构上 locked 卡的正文不进用户可编辑的 store 覆盖层，为以后「导出脱敏」留干净边界。
5. 用户出线上/线下页 demo 后，渲染层另开一轮——本卡不动聊天页视觉。

## 5. 实施记录（2026-09-18 当晚）

与原方案的偏差与新增发现：

1. **心声说明槽撤了**：模块 E 的 `replySpec` 教的是旧 `<心声>` 写法，和 c05 卡的
   `[WHISPER]` 协议同时进 prompt 会打架。引擎路径只注入 c05；旧路径照旧注入
   `<心声>` 指令。parseReply 两种标签都认，老存档不受影响。
2. **开发者模式开关落点**：设置页「关于 Sleepy」一行，3 秒内连点 5 次切换，
   toast 提示，无任何显眼入口（用户要求「隐蔽一些qwq」）。行原本不带 onClick
   会 self-disable，手动解开了 disabled。
3. **顺手修了一颗上轮埋的雷**：`page-chat.js` 的 `commitMemory` 定义在模块层、
   却引用 chat-detail 闭包里的 `chatId` —— 一调用就 ReferenceError，
   表现是「用户消息入了库、回复永远不来」。已改成显式传 chatId（4 处调用点）。
   这颗雷属于之前未提交的马甲/认知层工作，不是本轮引入的。
4. **教训（给以后）**：`preset-card` 同参 `ctx.open()` 不会重渲染（app.js 的
   sameParams 短路），恢复默认要直接刷 textarea 值。
5. **mock 实测记录**：`D:\tmp\edge-ab\mock-openai.js`（临时，不入库）。
   引擎路径请求：7 段 system（K01→I01→shell→F1→pat→记忆→C05）+ 历史垫底，
   stream/temperature 正常；回复 `嗯||怎么了` 正确拆成两条气泡、
   `[WHISPER]` 心声正确入库。旧引擎路径：3 段 system，`<心声>` 指令照旧。
   开发者模式关 → locked 卡只显示「内容不可见」，无 textarea；连点 5 次可切回。
