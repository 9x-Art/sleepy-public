## ① 点大部分输入框都会上下页面移动

**根因**（`app.js` 旧 671-683）：全局 `focusin` 只要焦点落进 input/textarea，
260ms 后就 `t.scrollIntoView({block:'center', behavior:'smooth'})`。
它跟键盘没关系 —— 只是「把焦点框摆到屏幕正中」，而**最近的那个能滚的祖先是 `.page`
自己**（表单页的 `.page` 就是滚动容器），于是点哪个输入框整页就上下跳一下。

**实测**（探针对照组直接打老那一句）：10 个看得见的输入框里 **7 个被搬走**，
位移 = 该页整段滚动量（settings-mainapi-add 534px、contact-edit **1619px**）。

**改法**：新 `pullIntoView(t)` —— 先算「有没有被盖住」：
```js
var edge = vv.height + vv.offsetTop;   // 键盘上沿（visualViewport 才是会缩的那个）
if (r.bottom + 12 <= edge) return;     // 露得好好的 → 一点都不动（绝大多数情况）
```
真的被盖住，才把**最近的、真能滚的祖先**推 `r.bottom + 12 - edge` 这么多 ——
不居中、不整页滚。另外：`.chat-foot` 里的输入框**整个不归它管**（见 ⑤）。

**验**：同样 10 个输入框 → 聚焦后位移 **0 / 10**；对照组仍 7 / 10（证明用例有灵敏度）。

## ② 多选时点第二个气泡就退出多选

**根因**（`page-chat.js` 旧 `selected[msg.id]`）：选择集合的键是 **msg.id**，
而一条回复会被 `||` 拆成好几个气泡 → 点同一条的第二个气泡＝**取消同一条** →
集合当场变空 → `exitSelect()`。画面上还只把勾标在第一个气泡上（`.is-sel-lead`），
第二个气泡根本「点不着」。

**改法**：键改成 `selKey(msgId, idx)` = `msgId#idx`；`enterSelect(msgId, idx)` 从长按菜单
带上**被长按的那个气泡**；勾改挂 `.msg-bubble.is-selected::after`（每个选中的气泡各一个勾）；
条子上的「已选 N 条」数的就是气泡。CSS 里的 `.is-sel-lead` 已删除干净。

**验**：长按第 1 个气泡 → 多选 → 点第 2 个气泡 → 条子写「已选 2 条」、两个勾；
再点一下只取消它自己（回到 1 条，仍在大选里）。

## ③ 头像没靠在屏幕边边（三种内置外观都要改）

**根因**（`style.css`）：2026-09-22 只把 `.msg-wrap` **自己**的左右内边距 16px→6px，
但外面还压着 `.page-inner` 的 **22px**（跟底栏那次同一个坑）：
**6 + 22 = 28px**，角色头像左边、我的头像右边都停在离屏缘 28px。
（`.chat-foot` 当时用负 margin 抵过这 22px，`.msg-wrap` 漏了。）

**改法**：
```css
.page[data-page="chat-detail"] .msg-wrap,
.page[data-page="chat-detail"] .msg-select-bar{margin-left:-22px;margin-right:-22px;}
```
**三种内置外观都量过**（就是同一个 `.msg-wrap`，皮肤只改颜色/圆角，不动几何）：
classic / 企微 / 捡手机 → 头像与我的头像**都是离屏缘 6px**。

## ④ 引用不要弹 toast

`startQuote` 里那句 `ctx.toast('已引用这一句 · 输入框空着点发送就是让 TA 回这句')` 删掉。
引用条本来就杵在输入框上方写着引了哪一句，再弹一个居中浮层纯属打扰（引用是高频动作）。

## ⑤ 点击输入框键盘起来后页面位移 / 要上下挪几下才贴合键盘

**根因**：两个驱动源同时使劲 ——
① `.chat-foot` 的 `padding-bottom:var(--kb-inset)`（app.js 的 visualViewport 监听写的，
这是**对的**那个）；② 上面 ① 里那个 `scrollIntoView({block:'center', behavior:'smooth'})`
（见 ① 的根因）。键盘弹起的动画期间它俩一帧一帧互推，加上 smooth 的动画，
就是用户看到的「位移 + 要上下挪几下才贴合」。

**改法**：`focusin` 里 `.chat-foot` 直接 return（键盘贴合**只留给 --kb-inset 一个驱动源**）。
**机制本身没动**（也没坏），探针里用「写 `--kb-inset:300px`」模拟键盘量过：
输入行底 = 屏底 −300px（贴合），消息区高度 651 → 351（抬起来是牺牲消息区换的，聊天页没被顶出屏）。

**⚠️ 这一条只能真机复验**（无头浏览器弹不出真键盘）。真机复验标准：
1. 进任一会话 → 点输入框 → 键盘起来时**底栏一次性**抬到键盘上沿，**不出现** 1~2 次来回跳；
2. 点「加号 / 表情 / 引用」这些也在底栏上的按钮 → 页面**不位移**；
3. 关掉键盘（点空白/返回）→ 底栏一次性落回屏底。
若仍有来回跳：下一个旋钮是给 `sync()` 加**短滞回**（键盘动画中间那几帧的 `kb<80`
会被当成「没键盘」而清零）—— 见 app.js 那段的注释，别在真机上瞎改。

## ⑥ 删除按钮一次性删掉整轮所有气泡

**根因**：长按菜单的「删除」走 `removeMsg(msg)` → `dropMessages(chatId,[msg.id])`，
删的是**整条存档消息**，而一条回复的所有气泡就是同一条消息 → 一次全没。

**改法**：新 `removeBubbles(pairs)`（`page-chat.js`），按气泡摘：
- 多气泡的 assistant 文字消息 → 把选中的下标从正文里摘掉、用 `' || '` 重拼，
  **译文（`msg.trans`）按下标整份重排**（少一段就得重排，不能只删自己那格）；
- 摘空 / 一段话 / 附件表情转账 / 用户自己的话 → 才交给 `dropMessages`（它连语音和
  图库里的音频、向量索引一起清）；
- 收口一律走 `patchMessage` / `dropMessages`（它们是索引 forget 的唯一入口）。
确认框也跟着变：多气泡时问「删掉**这一句**？」，否则照旧「删掉这条消息？」。
多选条的删除走同一个 `removeBubbles`。

**验**：M1（4 段）删第 2 段 → 屏幕上 6 个气泡变 5 个、存档里 M1 正好少那一段；
再进多选把 M1 剩下 3 段全选删 → M1 从存档里消失、**别的消息（M2 两段）一根汗毛没动**。
