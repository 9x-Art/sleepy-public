## 三、`buildSingleSubjectExperimentPrompt` 真实源码（imggen.js:649–710）

```js
  function buildSingleSubjectExperimentPrompt(opts) {
    opts = opts || {};
    var mode = VISUAL_EXP_MODES.indexOf(opts.visualMode) >= 0 ? opts.visualMode : 'legacy';
    if (mode === 'legacy') return null;

    var temp = opts.tempSingle === true;
    var subject = null;   /* 真实身份分支用；临时分支保持 null，绝不造一个假主体 */
    var gender = '';
    if (temp) {
      gender = TEMP_SINGLE_GENDERS.indexOf(opts.gender) >= 0 ? opts.gender : '';
    } else {
      var subjects = Array.isArray(opts.subjects) ? opts.subjects : [];
      if (subjects.length !== 1) return null;
      var raw = subjects[0] || {};
      var entityType = (raw.entityType === 'user') ? 'user'
        : (raw.entityType === 'char') ? 'char' : '';
      if (!entityType) return null;
      subject = {
        entityType: entityType,
        entityId: String(raw.entityId || ''),
        name: String(raw.name || ''),
        gender: String(raw.gender || ''),
        faceText: String(raw.faceText || '').trim()
      };
      gender = subject.gender;
    }

    var api = opts.api || {};
    var kind = (api.kind === 'nai') ? 'nai' : 'general';
    var pack = SLEEPY_SINGLE_STYLE[kind];
    var shot = SINGLE_EXP_SHOTS.indexOf(opts.shot) >= 0 ? opts.shot : 'auto';
    /* 临时单人：身份层只有性别 tag；真实身份：走 B0 的 subjectTextForPlan（含 B1 锁脸） */
    var identity = temp ? genderTagOf(gender) : subjectTextForPlan({ subjects: [subject] });

    var positive = joinLayers([
      SLEEPY_VISUAL_STYLE[kind].qualityPositive,
      pack.structure,
      identity,
      singleSubjectGenderAdjustment(kind, { gender: gender }),
      pack.frame[shot] || '',
      opts.description,
      singleSubjectVisualStyleText(kind, shot, mode, opts.customVisualStyle),
      visibleHandsText(kind, opts.hands, mode),
      (opts.extras || []).join(', ')
    ]);
    var negative = joinLayers([
      SLEEPY_VISUAL_STYLE[kind].qualityNegative,
      singleSubjectNegativeText(kind, { gender: gender }, mode)
    ]);
    var debug = {
      mode: mode, kind: kind, shot: shot, hands: opts.hands || 'unspecified',
      subjectSource: temp ? 'temp-single' : 'identity',
      entityType: temp ? '(临时单人，不读身份)' : subject.entityType,
      entityId: temp ? '' : subject.entityId,
      gender: gender || '(未填)',
      faceText: temp ? '(不适用)' : (subject.faceText ? '(有)' : '(空)'),
      positive: positive, negative: negative
    };
    if (typeof console !== 'undefined' && console.info) {
      console.info('[Sleepy][单人视觉实验]', debug);
    }
    return { positive: positive, negative: negative, debug: debug };
  }
```

**两类主体怎么分开的**：临时分支根本不进那个 `else`，`subject` 一直是 `null`；
不装 `entityType:'char'/'user'`、不编 `entityId`（debug 里明确写
`entityId=""`、`entityType="(临时单人，不读身份)"`、`subjectSource="temp-single"`）；
真实身份分支才走 `subjectTextForPlan`（B0）与 `faceTextFor`（B1 锁脸）。
B0 的 `normalizePlan` / `PLAN_*` 白名单**没有改动**。

## 六、男性校准：当前关闭（不变）

`MALE_CALIBRATION_ENABLED = false`（imggen.js:586）。两个函数首行短路返回 `''`，
调用处两处（`imggen.js:687` 与 `singleSubjectNegativeText` 内），**两种模式的正负面同时空掉**。
常量（general 531/532 一带、nai 同名项）与函数原样保留作扩展位置。

理由：只按 `gender === 'male'` 就注入 `facial hair only when specified…` /
`unintended aging` / `thick beard when unspecified` 会**反向覆盖身份事实**；
`when unspecified` 只是把判断丢给模型，不等于程序完成了条件判断。
这是暂停有冲突风险的词，**不是取消「男性不额外老化」的审美目标** ——
真图仍然按年龄感观察，后续拿真图结果定向调整。

## 九、D1 诊断：新增角色后「试一张」不显示 —— 真实原因

**结论：是「选项刷新缺陷」，不是「没加进当前岛」。**

| 检查 | 结果 |
|---|---|
| 数据层：第 2 个角色是否真进了本岛名册 | ✔ 进了（`setSandboxChars` 返回 ok，`charIds` 有它） |
| (a) 重开同一个接口页（同一 params） | ✘ **没出现** |
| (b) 整页刷新后再进 | ✔ 出现 |
| (c) 建一个**不加入本岛**的角色，全新渲染 | ✔ 不出现（岛隔离按设计生效） |

原因链（app.js）：

1. 页面按 id 缓存在 `built` 映射里，DOM 不会因为重新 `open` 而重画（`app.js:418–433`）；
2. `settings-imggen-add` / `settings-imggen-edit` **没有声明 `freshOnOpen`**
   （全仓只有 `page-idcard.js:716` / `:1563` 两处声明了），
   于是 `applyParams` 命中「同参短路」，把**上一次渲染的旧 DOM** 端回来；
3. 旧 DOM 里的「主体」下拉是**第一次 render 时**读的名册快照 ——
   之后新加的角色不会出现。

所以：**「角色没加进当前岛」和「下拉没刷新」是两回事** ——
这次复现里数据层明明已经加进去了，(b) 一刷新就出现，说明只差重渲染。
真实用户遇到的更可能是「加进岛了但重开页面看还是旧列表」，去刷新一次就好。

> 夹具踩点：`core.validateSandboxChars`（core.js:121）规定**孤岛只能有 1 个大号**，
> 要放第二个角色必须开**群岛**。第一次跑这条用了孤岛，`setSandboxChars` 被拒，
> 差点误判成「没出现」。这条已写进脚本注释。

**建议的最小修复（未实施，等确认）**：给 `settings-imggen-add` / `settings-imggen-edit`
两个注册加 `freshOnOpen: true`（与 page-idcard 的表单页同做法）。
代价：重开页面会清掉「想画什么」里没提交的草稿（实验态本身在 localStorage，不会丢）。
